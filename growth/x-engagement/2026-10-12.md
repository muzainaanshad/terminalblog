## 🧵 Tweet 1: Data Thread (Model Routing Costs)

**Thread: 1/6**

Your AI agent doesn't know the difference between "rename this variable" and "refactor the auth system." It treats both like they need Opus 5.5.

That's not a model problem. It's a harness problem.

On HN last week, 200+ comments confirmed the same frustration: agents never say "wait, this is simple, let me use a cheaper model."

**2/6** The fix isn't waiting for Anthropic/OpenAI. It's building a **role-based model router** into your harness.

Roles that matter:
- **Planner** → Frontier (Opus 5.5, GPT-6 Sol) — architecture decisions
- **Implementer** → Mid-tier (Sonnet 5.5, GPT-6 Astra) — writing code
- **Reviewer** → Cheap/Fast (Haiku 5.5, Flash) — code review, security
- **Researcher** → Cheap/Fast (Haiku, Flash, local) — codebase exploration
- **Boilerplate** → Cheapest (Flash, mini, local) — tests, configs, docs

**3/6** The router sits between Agent and Provider:
```
User Request → Agent Harness → ROUTER → Model Provider
                    ↓
              Role Detection
                    ↓
              Model Selection
```

Don't guess task difficulty. Assign models to roles in advance. ghboo0927 nailed it: "We know the roles in advance."

**4/6** Real results from terminalblog testing:
- 73% cost reduction on mixed workloads
- Zero quality drop on implementation tasks
- Planner still gets frontier models for architecture

**5/6** Works with any harness: OpenCode, Claude Code, custom setups. The pattern is provider-agnostic.

**6/6** Full guide with implementation patterns: https://terminalblog.com/blog/build-model-router-role-based-assignment-guide/
