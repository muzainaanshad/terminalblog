## v2.1.318 Highlights — The New Fixes (Nov 4)

### 1. Mod Effort Control — Quick Side Jobs at Low Effort

**New:** A mod's `$.model.fork` now accepts an `effort` option. A quick side job can run at `low` effort regardless of what the main session uses. The result reports the effort actually sent.

```json
// In your mod:
{
  "model": {
    "fork": { "effort": "low" }
  }
}
```

**Why it matters:** You don't need to burn high-effort tokens on quick lookups or validations inside a mod.

---

### 2. AWS `assume_role` for Cross-Account Cost Attribution

**New:** Added `assume_role` on `mantle` upstreams of the Claude apps gateway. This lets you assume a role in another AWS account for per-developer AWS cost attribution.

**Why it matters:** Enterprise teams can now track Claude Code API costs per developer across AWS accounts without manual tagging.

---

### 3. Stored Login Expiry Dates — No More Surprise Sign-Outs

**New:** The date a stored `claude.ai` sign-in ends now appears in:
- `claude auth status` → `loginExpiresAt`
- `claude -p` JSON results → `credential_expires_at`

**Plus:** A one-line stderr warning appears in `claude -p` text output **starting 10 days before** a stored sign-in ends.

**Why it matters:** You get 10 days of advance notice. No more "wait, I'm logged out?" during a critical task.

---

### 4. `--continue` Recovers Conversation After Malformed Tool Calls

**Fixed (regression in 2.1.314):** `--continue` sometimes lost the earlier conversation after a malformed tool call's retries ran out.

**Now:** `--continue` properly recovers the conversation history.

---

### 5. macOS Bash Memory Leak Fixed

**Fixed:** macOS sessions with many running Bash commands were stalling while memory grew unbounded.

**Now:** Memory stays stable during long-running multi-command sessions.

---

### 6. Permission Prompt Key Races Fixed

**Fixed:** Permission prompts were being answered by keys typed just after sending a message, or before a slow prompt appeared.

**Now:** Key handling is synchronized — prompts only respond to intentional input.

---

### 7. MCP Config Lock Safety — No More Silent Config Loss

**Fixed:** `claude mcp add` and `remove` were writing the config without its lock. Changes could be dropped silently when another job saved simultaneously.

**Now:** They wait for the lock or exit 1. Your MCP config changes are atomic.

---

### 8. Plugin Token Refresh — No More Accidental Sign-Outs

**Fixed:** `claude plugin` commands exited before a slow token refresh was saved, which could sign you out on the next run.

**Now:** Commands wait for token refresh to complete.

---

### 9. stdio MCP Server Probe Pinning

**Fixed:** stdio MCP servers that exit on the version probe were being re-probed on every start.

**Now:** A server that dies in under 3s for its own reason is pinned to the legacy handshake for 7 days.

---

### 10. Idle Compaction No Longer Replaces Conversation with Non-Summary

**Fixed:** Idle compaction could replace a conversation with a reply that was not a summary.

**Now:** Compaction properly produces summaries.

---

### 11. "Now Using Usage Credits" Toast Spam Fixed

**Fixed:** The "Now using usage credits" notice reappeared about every 30 seconds while a background subagent was running.

**Now:** Toast appears once.

### 12. Custom Slash Commands in `claude -p` / SDK — No More Silent Failures

**Now:** Errors surface properly.

## The Fixes You'll Actually Notice

### 1. Nested Session ID Leak Fixed — Self-Hosted Runners Finally Work Right

**Before:** You run `claude -p` inside a self-hosted runner session. It **shares that session's ID and transcript**. A restart resumes the wrong conversation. Your session history gets polluted with print-mode noise.

**After (v2.1.317):** Set `CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1` on your self-hosted runner. Now `claude -p` inside a session **creates its own session ID and transcript**. Clean separation. Restarts resume the right conversation.

```bash
# On your self-hosted runner:
export CLAUDE_CODE_DISABLE_NESTED_SESSION_ID=1

# Now:
claude -p "quick task"  # Creates its own session, doesn't pollute parent
```

**Why it matters:** If you run self-hosted runners for CI/CD or automation, this was a silent data corruption bug. Fixed.

### 2. Project & Local MCP Servers No Longer Disconnect After First Turn (Desktop)

**After:** Fixed. MCP connections **stay alive** across turns. Your tools work the whole session.

### 6. Cloud Session Titles No Longer Lost During Generation

**Before:** A new message or Stop arrives while the session title is generating. The title **gets lost**. Cloud and SDK sessions end up with generic titles.

### 7. Screen Readers Stop Announcing Subagent Token Counts Every Change

**Before:** Your network blocks Anthropic (corporate firewall, country block). HTTP 403. Claude says **"sign-in failed"**. You troubleshoot auth. It's not auth.

**Before:** You edit a settings file in the first second after launch. Changes **don't apply** until another settings file changes. Confusing.

**After:** Fixed. Early edits **take effect immediately**. Your config changes work on first try.
