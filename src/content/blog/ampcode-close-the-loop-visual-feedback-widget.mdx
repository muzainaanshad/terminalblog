**AmpCode dropped "Close the Loop" today (November 6)** — and it's the closest thing to telepathy between your website and your agent. You visit your site with `?amp`, click any element, write what you want changed, and **Amp opens a thread and makes the edit**. No screenshots. No copy-paste. No context switching.

---

## The One-Line Summary

**Point at your live website → write instructions → Amp creates a thread and fixes it. The visual feedback loop is finally closed.**

---

## How It Works (It's Stupidly Simple)

### 1. Enable the Widget (One-Time)
In your Amp project settings, enable the **Feedback Widget** and add one script tag to your website:

```html
<!-- Add to your site -->
<script src="https://ampcode.com/feedback-widget.js" data-project="your-project-id"></script>
```

### 2. Visit Your Site with `?amp`
```
https://yoursite.com?amp
```
The annotation widget appears. (After first use, it shows up without `?amp` until you hide it.)

### 3. Click, Write, Send
- Click any element on the page
- Write what you want changed: *"Make this headline larger," "Move this form to /admin," "Fix the alignment"*
- Click **Send**

### 4. Amp Does the Rest
- First time: sign in with Amp, approve consent
- Click **Start in Orb** → Amp opens a new thread in your project with your comments
- The agent reads your instructions, finds the code, makes the change
- You review and ship like any other thread

## Why This Changes Everything

### The Old Way: Context Switching Hell
1. See bug on production → screenshot → open Slack/Notion → describe location → copy CSS selector → explain context → developer reads → opens IDE → finds file → makes fix → deploys → you verify

### The New Way: Point and Speak
1. See bug on production → click it → write *"Make the CTA button higher contrast"* → send
2. Amp thread opens → agent fixes it → you review → merge

**The context never leaves the visual layer.** Your instruction carries the exact element, the exact page, the exact viewport. The agent doesn't guess — it *knows*.

## Real Workflow: From "This Looks Wrong" to "Fixed"

```markdown
# Scenario: Marketing wants the homepage headline changed

**Before (30+ minutes):**

2. You: *opens pricing page, inspects element, copies selector*
3. You: *creates JIRA ticket with screenshot, selector, context*

**After (2 minutes):**
1. You: *visit pricing page with ?amp*
2. You: *click headline → write "Increase font size to 3rem, make it pop more" → Send*
3. Amp: *starts thread, agent finds component, edits CSS/JSX, opens PR*
4. You: *review diff in thread → approve → merged*
```

## What the Agent Actually Sees

When you click an element and write instructions, Amp captures:

| Context | Captured Automatically |
|---------|------------------------|
| **Element** | Exact DOM node, CSS selector, XPath |
| **Page** | Full URL, viewport size, scroll position |
| **Styles** | Computed styles for that element |
| **DOM tree** | Ancestor chain up to meaningful component |
| **Your instruction** | Natural language, attached to the element |

The agent doesn't just get "make the button bigger." It gets **the button, its exact location, its current styles, and your intent.**

---

## The "Orb" Part: Why It's Not Just a To-Do Item

When you click **Start in Orb**, Amp doesn't just create a GitHub issue. It:

1. **Spins up a cloud workspace** (your orb) with the repo cloned
2. **Starts an agent thread** with your visual feedback as the first message
3. **The agent reads the codebase**, finds the component, makes the edit
4. **You see the diff in the thread** — review, request changes, approve
5. **Ship it** — the orb can push to your repo, open PR, run CI

This is **end-to-end**: visual feedback → agent execution → code change → deploy. All in one thread.

## What's Still Manual (Honest Assessment)

- **First-time setup** — add script tag, enable in settings (one-time per project)
- **Sign-in flow** — first feedback requires Amp OAuth (then it's seamless)
- **Complex multi-page changes** — widget is per-page; cross-page flows need multiple comments
- **Non-web projects** — currently web-only (mobile/native not supported yet)
