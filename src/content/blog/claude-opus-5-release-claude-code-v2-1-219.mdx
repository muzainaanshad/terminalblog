Anthropic dropped **five Claude Code releases in five days** — v2.1.284 (Sep 28), v2.1.285, v2.1.286, v2.1.287, and v2.1.288 (Oct 2) — and together they form the **biggest stability wave since Opus 5 launched in July**.

If you've been fighting streaming crashes, losing work on resume, dealing with auto-mode permission floods, or wondering why your Windows keyboard stops working after a restart — **this is the update that fixes it**.

The Opus 5 model (from the July 31 release covered in this post) is still the default. What changed is everything *around* it.

---

## The Headline: Streaming Crashes No Longer Eat Your Work

The single most painful bug in Claude Code has been **mid-response API timeouts silently dropping your answer**. You're in a long refactor, the model is thinking, the stream hiccups — and the entire turn vanishes.

**v2.1.288 fixes this at the root:**

- **Non-interactive sessions and subagents now continue from partial responses** instead of failing the turn
- **Thinking-only responses are retried** instead of being treated as failures
- **A damaged response stream showing raw JSON errors or writing "undefined" into answers is now retried or reported as interrupted** instead of corrupting your transcript

For anyone running `claude -p`, SDK sessions, or long autonomous workflows — this alone is worth the upgrade.

---

## The Resume Nightmare Is (Mostly) Over

`claude --resume` has been a lottery. Five distinct resume failures fixed in one wave:

| Bug | Fixed In | What It Was |
|-----|----------|-------------|
| `--resume` dropping files/context from compaction | v2.1.288 | Restored context vanished after resume |
| Resumed session not saving last response | v2.1.288 | Next `--resume` showed prompt unanswered |
| Resume loading truncated transcript | v2.1.288 | Same session rewrote file during load |
| Pre-2.1.286 conversations losing thinking on resume | v2.1.288 | Earlier model reasoning dropped |
| Folder's CLAUDE.md attaching twice after resume/compaction | v2.1.287 | Duplicate context injection |

**v2.1.287** also fixed a dangerous regression: `rm -rf /` (or home directory) inside `bash -c` running **without a prompt in bypassPermissions mode**. That safeguard is back.

---

## Auto Mode Got Smart (Finally)

Auto mode has been the "enable and pray" feature. This wave makes it actually intelligent:

- **When conversations grow too long for the safety classifier, it now compacts instead of prompting/failing every tool call** (v2.1.288)
- **Auto-mode denials now point at the actual blocked tool** instead of incorrectly blaming Bash (v2.1.288)
- **Bedrock/Mantle sessions no longer fall back to local classifier** after an older model request (v2.1.288)
- **Cloud sessions restarting on a new model no longer reply with the wrong model** (v2.1.288)
- **`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` now actually removes structured outputs** that Bedrock gateways reject (v2.1.287)

The practical result: you can leave auto mode on for real work without babysitting permission prompts.

---

## Cross-Session Messaging: Hardened

The `SendMessage` tool (letting sessions talk to each other) was a security surface. Three hardening fixes:

- **Relayed messages no longer carry user authority** — receivers refuse relayed permission requests, auto mode blocks them (v2.1.288)
- **Claude reporting a message as "delivered" when the target session held it** — now says it wasn't delivered and names the session (v2.1.288)
- **SDK sessions can now learn of undelivered messages mid-turn** (v2.1.288)

If you run multi-agent workflows, this closes a real attack vector.

---

## Windows: Keyboard Works After Restart

**The Windows keyboard bug is fixed** (v2.1.288): the keyboard not working on Windows after Claude Code restarts itself (first sign-in to a Claude apps gateway, provider setup, `/tui`) — resolved.

If you're on Windows, you know this one. It's been there for months.

---

## Screen Reader Mode: Actually Usable Now

A full accessibility overhaul across v2.1.287–288:

- Short announcements (deleted word) now stay on screen until next key press
- Answered questions in dialogs now say "answered" beside their box
- `/permissions` in screen reader mode: typing a rule number now picks it instead of opening search
- Cursor follows typed text in fullscreen transcript search and `/theme` custom color search
- Top lines of second approval prompts, changed `/config` rows, rejected-plan lines no longer cut off
- Times in `claude agents` change at most every 10 seconds (not every second)
- Running-tool dot and spinners respect "Reduce motion" setting

This isn't polish — it's making the agent usable for developers who rely on screen readers.

---

## Model Routing: Opus 5.5 / Sonnet 5.5 Cleaned Up

- **Client-side auto-mode classifier now ignores `ANTHROPIC_DEFAULT_SONNET_MODEL` pin** naming Sonnet 5.5/Opus 5.5, uses Sonnet 5 instead (v2.1.288)
- **Safety-related model switches in pinned-Opus sessions**: on Anthropic API, the API now picks the fallback model per flag type, not the pinned model (v2.1.288)
- **Restarted cloud sessions no longer restore a model the org's enforced model list refuses** (v2.1.288)
- **Picking Fable in `/model` on claude.ai login now saves the version's id** so your default follows newest Fable like Opus/Sonnet do (v2.1.287)
- **Switching between Opus 5.5 and Sonnet 5.5 no longer rewrites earlier MCP tool announcements** (which could drop extended thinking) (v2.1.287)

---

## MCP: No More Silent Failures

- **MCP tool calls sometimes running twice** when remote server result >16MB or unparseable — fixed (v2.1.288)
- **Subagents in Claude Desktop's Code tab getting none of the tools** from a user-configured MCP server named `memory` — fixed (v2.1.288)
- **MCP URL prompts from servers that can't report "done" now wait for "I'm done, continue"** before continuing (v2.1.288)
- **`claude plugin install` failing for GitHub-source plugins on macOS/Linux with no SSH key** — now falls back to HTTPS with notice (v2.1.288)
- **Sandboxed heredocs with unquoted delimiter (`python3 <<EOF`) asking for approval on every run** under sandbox auto-allow — fixed for plain text/simple `$VAR` (v2.1.288)
