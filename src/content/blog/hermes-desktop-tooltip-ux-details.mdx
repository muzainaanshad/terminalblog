The most interesting commits are often the smallest. Case in point: Hermes's fix for the copy button tooltip in the desktop app.

The commit: `fix(desktop): add tooltip and fix scrollbar overlap on tool output copy button`.

Yes, it's a tooltip fix. But it reveals something important about how Hermes thinks about agent output.

## The Problem

When Hermes displays tool output in the desktop app, there's a copy button that lets you grab the output to clipboard. Two issues:

1. **No tooltip** — new users had to guess what the button did
2. **Scrollbar overlap** — the copy button overlapped with the scrollbar, making it hard to click

Both are small UX issues. Both are the kind of thing you can ship with and call "good enough." Hermes fixed both.

## Why This Matters

AI agents generate a lot of output. Tool calls produce JSON, code, logs, errors, and results. The way that output is presented — not just generated — determines whether the agent is useful or overwhelming.

Good UX in an AI agent means:
- **Discoverability** — can users find what they need? (tooltips help)
- **Usability** — can users act on what they see? (buttons that work matter)
- **Clarity** — is the output readable? (scrollbar overlap blocks clarity)

Most coding agents skip this. They dump raw text into a terminal and call it done. Hermes is investing in presentation because presentation determines comprehension.

## The Bigger Picture

This commit is part of a pattern of UX investments in Hermes:
- Auto-scrolling tool windows that follow new output
- Collapsible tool sequences to reduce visual noise
- Theme-aware output formatting that works in light and dark modes
- Console dashboard with WebSocket streaming for real-time monitoring

Hermes isn't just building agent capabilities — it's building an interface that makes those capabilities accessible. The desktop team is iterating on presentation with the same intensity as the core agent team is iterating on features.

The tooltip fix is small. But the philosophy behind it — that agent output should be well-presented, not just present — is anything but.

## What This Means for Agent Builders

If you're building an AI agent, the lesson is clear: **output UX is not optional.** It's the difference between a tool developers tolerate and one they adopt.

Three concrete takeaways:
1. **Audit your copy actions** — every copy button needs a tooltip. Every destructive action needs confirmation.
2. **Test scroll behavior** — long tool outputs need working scrollbars that don't fight with UI elements.
3. **Invest in presentation parity** — if your CLI output is great but your desktop app is an afterthought, users notice.

Hermes's tooltip fix took maybe an hour. The user trust it preserves? Priceless.

## Related Work

This isn't the first time Hermes has prioritized output presentation. The v0.19.1 Quicksilver release brought 80% faster starts and smart approvals — but it also improved how tool output renders in the console. The pattern is consistent: capabilities matter, but *how they feel* matters just as much.

## The Copy Button Isn't Just a Copy Button

Let's look closer at what this fix actually addressed. The copy button sits in the top-right of every tool output block. When you hover it, you now see "Copy tool output" — a tiny detail that eliminates guesswork. The scrollbar fix ensures that on narrow windows, the button doesn't sit directly over the vertical scrollbar thumb.

This is the kind of polish that separates "works on my machine" from "works for everyone." In a desktop app used by developers across screen sizes, OS themes, and window configurations, these edge cases are the product.
