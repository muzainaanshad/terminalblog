You've been hearing about AI coding agents for months. Maybe you've tried Claude Code in the terminal. Maybe you've watched Cursor demos on YouTube. But there's always been a catch: **you had to live in the terminal**.

Today that changes.

OpenHands 1.24 just shipped **Agent Canvas** — a native desktop app for macOS, Windows, and Linux. It's not a VS Code extension. It's not a web wrapper. It's a real, installable application with a proper UI that lets you run autonomous AI agents on your codebase.

If you've been waiting for "the moment AI agents become accessible," this might be it.

---

## What Is Agent Canvas?

Think of it as **Cursor, but fully open source and agent-first**.

Agent Canvas gives you:
- A **visual conversation history** — see every agent turn, every tool call, every file change in a timeline you can actually read
- **Persistent memory** across sessions — your agent remembers context, decisions, and patterns from yesterday
- **Automation scheduling** — set up agents to run on cron, watch repositories, or trigger on webhooks
- **Multi-agent orchestration** — run multiple agents in parallel, each with different roles (planner, coder, reviewer)
- **One-click install** — `.dmg`, `.exe`, `.AppImage`, `.deb` — no Docker, no `npm install`, no configuration hell

You download it. You open it. You point it at a folder. It starts coding.

## Why This Matters for Beginners

Most AI coding tools today assume you already know how to drive them. They give you a blank prompt and say "good luck."

Agent Canvas flips that:

### 1. You Can See What the Agent Is Doing
In the terminal, an agent runs tools and you get a wall of text. In Agent Canvas, you see:
- Which files it read (with diffs)
- Which commands it ran (with output)
- What it's *thinking* before it acts
- A **visual map** of the repository it's exploring

This transparency builds trust. You learn *how* agents work by watching them.

### 2. Conversations Don't Disappear
Close the terminal, lose the context. That's been the norm. Agent Canvas saves every conversation as a first-class object. You can:
- Resume exactly where you left off (even weeks later)
- Share a conversation with a teammate
- Fork a conversation to try a different approach
- Search across all your agent history

### 3. Automations That Actually Run Unattended
You can schedule agents to:
- Review every PR at 2 AM
- Update dependencies every Monday
- Generate tests for new files
- Sync documentation with code changes

These run in the background. You get notifications when they're done (or when they need help).

## The Key Features in 1.24

### Conversation Skills, Hooks & Tools Dialogs (Now Capped at 90vw)
No more giant modals eating your screen. The configuration dialogs for skills, hooks, and tools are now properly constrained — a small but meaningful UX fix that shows the team cares about daily usability.

### OpenAI Subscription Caches Scoped by Backend
If you use multiple OpenAI-compatible backends (OpenAI, Azure, local models via Ollama, etc.), each now gets its own subscription cache. No more cross-contamination or stale model lists.

### Homepage Rewritten Around Daily Engineering Work
The splash screen no longer talks about "autonomous software development" in the abstract. It shows concrete workflows: "Fix a bug," "Write tests," "Refactor a module," "Review a PR." This matters because **beginners need concrete entry points, not vision statements**.

### Shared Automation Conversations (Read-Only on Cloud)
You can now share automation runs with your team in read-only mode. Perfect for: "Hey, look at what the nightly refactor agent did" without giving everyone write access to the agent config.

### ACP Tool-Call Content Blocks in Chat Cards
The Agent Communication Protocol (ACP) is now properly rendered in the UI. Tool calls show structured content blocks — not raw JSON. You see the *intent*, not the wire format.

### OAuth Credentials Persist on Cloud Saves
MCP server OAuth tokens now survive cloud saves and skip consent when tokens are still valid. No more re-authenticating every time you resume a cloud session.

## How to Get Started (5 Minutes)

### 1. Download
Go to [github.com/OpenHands/OpenHands/releases/tag/v1.24.0](https://github.com/OpenHands/OpenHands/releases/tag/v1.24.0) and grab:
- **macOS**: `OpenHands-Agent-Canvas-1.24.0-universal.dmg` (Apple Silicon + Intel)
- **Windows**: `OpenHands-Agent-Canvas-Setup-1.24.0.exe`
- **Linux**: `OpenHands.Agent.Canvas-1.24.0.AppImage` or the `.deb`/`rpm` packages

### 2. Install & Open
Drag to Applications (macOS), run the installer (Windows), or `chmod +x` and run (Linux).

### 3. Connect Your LLM
On first launch, you'll pick a provider:
- **Anthropic** (Claude 3.5 Sonnet, Opus) — best for complex reasoning
- **OpenAI** (GPT-4o, o1) — strong generalist
- **Local via Ollama** — free, private, runs on your machine
- **OpenRouter** — access 100+ models with one key
- **Custom OpenAI-compatible** — your own proxy, Azure, etc.

Enter your API key (stored locally, encrypted).

### 4. Point at a Project
Click "Open Project" and select any folder with code. A Git repo works best but isn't required.

### 5. Start Your First Agent
Type something like:
> "Explore this codebase and tell me the architecture. Then write a README if there isn't one."

Watch the agent:
1. **Read** files to understand structure
2. **Search** for patterns
3. **Write** a comprehensive README
4. **Show you** the diff before saving

You approve each write. Nothing happens without your okay.

## A Real Beginner Workflow: "Fix This Bug"

Let's say you have a failing test. In Agent Canvas:

1. **Paste the error** into chat: "This test fails with `TypeError: cannot read property 'map' of undefined`"
2. **Agent reads** the test file and the source file
3. **Agent identifies** the root cause (missing null check)
4. **Agent proposes** a fix with a diff
5. **You approve** — it applies
6. **Agent runs** the test again to verify
7. **Done** — and the conversation is saved

Next week, you ask: "What did we fix last Tuesday?" Agent Canvas shows you the entire conversation, the diff, the test output. No digging through terminal history.

## The Honest Take: Should You Switch?

**Switch if:**
- You want to *own* your agent setup (no subscription trap)
- You need agents that run unattended on a schedule
- You prefer local models for privacy / cost
- You like tinkering and want to understand how agents work under the hood
- You're on Linux and tired of "macOS-first" tooling

**Stick with Cursor/Copilot if:**
- You need rock-solid IDE integration *today*
- Your team is already standardized on VS Code
- You want the smoothest possible autocomplete (Cursor's tab completion is still best-in-class)
- You need enterprise SSO, audit logs, compliance features

**The middle path:** Install Agent Canvas *alongside* your current setup. Use it for the things it's uniquely good at: scheduled automations, multi-agent workflows, local model experimentation. Keep Cursor for daily editing.
