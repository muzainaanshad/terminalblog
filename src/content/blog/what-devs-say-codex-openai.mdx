OpenAI Codex has changed substantially with the most recent model update. Here is what developers think after spending real time with the new version — where it shines, where it frustrates, and who should actually reach for it.

## What Developers Love

**Sandbox execution is Codex's unique advantage.** Codex runs generated code in isolated containers before showing results. Developers working with untrusted code or experimenting with unfamiliar libraries feel markedly safer with Codex than with an agent that executes directly on their machine. The sandbox isn't just a security feature — it's a workflow enabler. You can paste a sketchy npm package, ask Codex to audit it, and watch it run in a throwaway container without touching your actual environment. For teams doing code review of external contributions, this is a genuine differentiator.

**Subagent orchestration is genuinely strong for complex parallel work.** Codex can spin up many subagents to attack different parts of a problem at once — for example, splitting a large refactor across modules and reconciling the results afterward. For the right workload, that parallelism is a real productivity multiplier. Developers report that breaking a monolithic task into 5-10 parallel subagents can cut wall-clock time by 60-70% on refactoring-heavy work. The key is giving each subagent a well-scoped prompt with clear boundaries — vague prompts just create more chaos.

**The GitHub integration is smoother than most realize.** Codex can open PRs, respond to review comments, and iterate on CI failures without you leaving the chat. For maintainers triaging a backlog, this means "review → fix → push → CI passes" can happen in a single Codex session. The agent actually reads the CI logs and proposes fixes, not just the error messages.

## What Frustrates Them

**Tool-call reliability has been a persistent sore spot after the update.** The model sometimes hallucinates function calls or picks the wrong tool for a step. The community has documented recurring bug reports around this, and it tends to show up most on long, multi-step tasks where one bad tool call cascades. A common pattern: Codex correctly identifies the file to edit, then calls `edit_file` with a malformed diff, then retries with a different malformed diff, then gives up and asks you to do it manually. This is especially painful when you're paying per request.

**Pricing is higher than competitors for heavy usage.** Codex's per-request pricing adds up fast for developers running frequent agentic sessions, and teams doing all-day autonomous work will feel it more than occasional users. At current rates, a developer running 50-100 agent sessions per day can hit $50-150/day — that's $1,000-3,000/month per seat. Compare that to Cursor's $20/mo or Claude Code's included-in-Pro model, and the economics only work if the sandbox/subagent features genuinely save you hours per day. For occasional users, the per-request model is actually cheaper than a subscription.

**Context management still feels manual.** Unlike Cursor's @-mention context or Claude Code's automatic file discovery, Codex often needs explicit "read this file, then that file" guidance. The model doesn't proactively explore your codebase the way its competitors do. This means more prompt engineering overhead per session — you're managing the agent's attention instead of the agent managing yours.

**Windows support lags.** The desktop experience on Windows has historically been behind macOS/Linux — WSL2 workarounds, path translation issues, occasional GPU acceleration failures. If your team is mixed-platform, this shows up as "it works on my Mac" friction.

## The Verdict

**Codex is the best choice for security-conscious developers and teams running untrusted code.** If you're reviewing external PRs, auditing dependencies, or experimenting with code you don't trust, the sandbox is genuinely unique and valuable. The parallel subagent architecture also makes it the strongest option for large-scale refactoring where you can decompose work cleanly.

**For general day-to-day development, Claude Code and Cursor often offer better value.** The context awareness, flat pricing, and native desktop experience mean less friction per session. Most developers don't need a sandbox on every single task — which is why many keep Codex in the rotation rather than making it their only agent.

**The pragmatic approach:** Use Codex for the 20% of tasks where sandbox/parallelism pay off (security reviews, large refactors, untrusted code), and Cursor/Claude Code for the 80% where context awareness and pricing matter more. The multi-agent workflow is real — developers who've adopted it report they'd never go back to single-agent-only tools.
