If you've ever watched an AI agent run a sequence of tool calls, you know the pain. The terminal fills up with JSON blobs, error messages, retry logs, and output dumps. By the time the agent finishes, you've scrolled past 300 lines to find the result.

Hermes just fixed this. For good.

## The Auto-Scrolling Window

The desktop console now collapses long tool-call runs into an auto-scrolling window. Instead of dumping every tool invocation into your terminal as raw text, the console creates a scrollable, collapsible pane for each tool sequence.

You see the agent is working. You see which tool it's calling. You see progress. But you don't see every byte of every response unless you want to.

## What Changed

PR #57913 introduced `feat(desktop): collapse long tool-call runs into an auto-scrolling window`. The implementation is elegant: tool calls within a sequence are grouped, each group gets its own scroll container, and the viewport auto-advances to the latest output.

The change touches three layers:
- **Protocol layer**: Tool calls now emit structured `ToolCallStart`, `ToolCallProgress`, and `ToolCallComplete` events instead of raw stdout dumps
- **Render layer**: A new `ToolCallGroup` component manages the scroll container, virtualizes long output, and handles collapse/expand state
- **Session layer**: The console tracks call depth to group nested invocations (e.g., a `read_file` inside a `delegate_task`) under their parent

## Why It Matters

This isn't cosmetic. When you're monitoring a long-running agent — a code review, a deployment, a multi-file refactor — the difference between "a wall of text" and "a clean, scrollable log" is the difference between understanding what's happening and being overwhelmed.

Consider a typical Hermes delegation: the orchestrator spawns three sub-agents. Each sub-agent runs 5-10 tool calls. Without grouping, that's 15-30 separate tool outputs interleaved in one terminal. With the new window, you see three expandable groups — one per sub-agent — each showing live progress.

## How It Compares

Auto-scrolling tool-call windows are a UX detail that many terminal agents overlook:

| Agent | Tool Output Handling |
|-------|---------------------|
| **Hermes** | Auto-scrolling grouped windows, virtualized, collapsible |
| **OpenCode** | Linear stream with syntax highlighting, no grouping |
| **Mimo** | Inherits OpenCode's linear approach |
| **Kilo** | Minimal — prints tool name + result, no live progress |
| **Claude Code** | Rich TUI with live progress bars per tool |
| **Gitlawb Zero** | TUI with pane-based output, similar grouping concept |

Hermes's implementation stands out for the smooth auto-scroll behavior that keeps the latest tool call visible without manual scrolling, plus the virtualization that handles 1000+ line outputs without freezing the UI.

## Practical Impact

For operators running background jobs via Hermes cron, this means:
- **Dashboard monitoring**: The web console mirrors the same grouped view, so you can check a nightly refactor job from your phone
- **Log aggregation**: Grouped tool calls map 1:1 to structured logs, making post-mortem analysis trivial
- **Interruption safety**: You can collapse a noisy sub-agent's output while keeping the parent orchestrator visible

The feature also enables a new workflow: **selective streaming**. Instead of piping everything to stdout, you can configure the console to only surface tool calls matching a pattern (e.g., `*write*` or `*edit*`) while suppressing read-only operations.
