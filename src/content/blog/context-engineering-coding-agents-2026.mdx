You're not paying for the model. You're paying for **what the model sees**.

Two developers use the same agent, the same model, the same repo. One ships a feature in 20 minutes. The other burns $40 in tokens and gets a hallucinated API that doesn't exist.

The difference isn't the model. It's **context engineering** — the discipline of feeding the agent exactly what it needs, and nothing it doesn't.

This is the skill that matters more than your tool choice. More than your model choice. More than your prompt engineering.

## What Context Engineering Actually Means

Context engineering is not "write better prompts." It's **curate what the model sees.**

Three levers, in order of impact:

| Lever | What It Does | Typical Savings |
|-------|--------------|-----------------|
| **Repo map / file selection** | Only send files relevant to the task | 40-70% token reduction |
| **Conversation pruning** | Drop irrelevant history, keep decisions | 20-40% token reduction |
| **Instruction injection** | Load AGENTS.md, skills, rules at the right moment | Prevents hallucination, not token savings |

Most developers ignore all three. They let the agent "figure it out" by reading everything.

## Lever 1: Stop Sending the Kitchen Sink

### The Naive Approach (What Most Agents Do By Default)

```
Task: "Add rate limiting to the API"
Agent reads: src/auth/, src/api/, src/db/, src/utils/, tests/, docs/, package.json, README, .env.example, 12 config files...
Tokens: ~200K
```

### The Engineered Approach

```
Task: "Add rate limiting to the API"
You provide: src/api/routes.ts, src/api/middleware.ts, src/config/rate-limit.ts, package.json (deps only)
Tokens: ~18K
Result: Working PR in one shot
```

**How to enforce this in your agent:**

**Aider** — uses a repo map automatically. It's the gold standard.

**Claude Code** — use `/compact` aggressively. Explicitly `@` only the files that matter.

**OpenCode / Hermes / Goose** — use skills. A `rate-limiting` skill loads only the 4 files above.

**Cursor** — `@` mention specific files. Don't use `@codebase` unless you're exploring.

Every agent — write an AGENTS.md that lists "Where things live" so the agent *knows* where to look without searching. Our [AGENTS.md complete guide](/blog/agents-md-complete-guide/) walks through exactly what to include.

## Lever 2: Conversation History Is Poison (Mostly)

Agents append the full conversation to every request. A 50-message session = 100K+ tokens of garbage context.

**What to keep:**
- The original task
- Key decisions made ("we use Redis, not in-memory")
- The current plan
- File paths that were actually edited

**What to drop:**
- "Let me try this approach"
- "That didn't work, trying another way"
- Three failed attempts at the same regex
- The agent apologizing for the previous attempt

### How to Prune Without Losing Your Mind

**Manual (works everywhere):**
```
/compact "Keep: task, decision to use Redis, files edited: src/api/routes.ts. Drop: all failed attempts."
```

**Automated (Hermes, OpenCode skills):**
```yaml
# In your skill or AGENTS.md
context:
  max_messages: 15
  preserve:
    - "task"
    - "decision:*"
    - "file:src/**"
  summarize_older: true
```

**Cursor / Claude Code:**
- Use `/clear` or start a new session when the task changes
- Don't treat the agent like a chat history — treat it like a fresh contractor every task

## Lever 3: Load Instructions at the Right Moment

AGENTS.md is useless if the agent loads it *after* it's already hallucinated your stack.

**The loading order that works:**

1. **System prompt** (agent's built-in instructions)
2. **AGENTS.md / CLAUDE.md** (repo rules — *always loaded first*)
3. **Skill / skill file** (task-specific workflow — *loaded when task matches*)
4. **Conversation context** (pruned, see above)
5. **File contents** (only the ones you explicitly selected)

**The mistake:** Putting 500 lines of architecture docs in AGENTS.md. The agent skims it, misses the rule about "no new frameworks," and installs `zustand` when you use `redux`.

**The fix:** AGENTS.md = universal invariants only (< 200 lines). Everything else → `docs/` or skills, loaded on demand. For a practical example of how skills work, see our [Hermes skills system overhaul](/blog/hermes-skill-system-renovate-overhaul/).

## The Context Engineering Workflow (Copy This)

### Before Every Task

```bash
# 1. Checkpoint git (30 seconds, saves hours)
git stash push -u -m "pre-agent-$(date +%s)"

# 2. Identify the 3-5 files that actually matter
# Use your knowledge, not the agent's search
ls src/api/ src/middleware/ src/config/rate-limit.ts

# 3. Launch agent with explicit context
# Claude Code:
claude-code "Add rate limiting to /api/*" @src/api/routes.ts @src/api/middleware.ts @src/config/rate-limit.ts @package.json

# OpenCode/Hermes:
opencode run --skill rate-limiting "Add rate limiting to /api/*"

# Cursor:
# @src/api/routes.ts @src/api/middleware.ts @src/config/rate-limit.ts @package.json
# "Add rate limiting to /api/*"
```

### During the Task

- **Watch the token count** (most agents show it)
- **If it climbs past 50K without progress** — stop, `/compact`, re-aim
- **If the agent reads a file you didn't expect** — ask why. It's usually a symptom of vague instructions.

The token cost tracking mentioned here is something we've covered in our [real cost of AI coding agents](/blog/real-cost-of-ai-coding-agents/) deep dive.

### After the Task

```bash
# 4. Verify what actually changed
git status --short && git diff --stat

# 5. If it touched files you didn't intend, add a rule to AGENTS.md
# "Never modify src/db/ without explicit approval"
```

### Without Context Engineering (Naive)

### With Context Engineering (Engineered)

- Agent sees the exact patterns, extracts cleanly
- Tests pass first run → **$0.03 in tokens**

**413x cost difference. Same model. Same agent. Different context.**

## FAQ

**Q1: Isn't this just "being specific with prompts"?**
No. Prompt engineering is *what you say*. Context engineering is *what the model sees*. You can have a perfect prompt but if the model sees 100K tokens of irrelevant garbage, it will still hallucinate.

**Q2: My agent doesn't support skills or repo maps. Am I stuck?**
No. Explicit `@` mentions work in Cursor, Claude Code, Codex, Copilot CLI. `/compact` works in Claude Code. New sessions work everywhere. The principles are tool-agnostic.

**Q3: How do I know which files to include?**
You're the developer. You know your codebase. If you don't, spend 10 minutes with `grep` or your IDE's "find usages" before launching the agent. That 10 minutes saves hours of agent thrashing.

**Q4: What if the agent needs a file I didn't anticipate?**
It will ask. "I need to see `src/config/database.ts` to understand the connection pool." You `@` it. One extra turn. Better than sending 50 files it didn't need.

**Q5: Does this work for greenfield projects?**
Even more so. In a new repo, *you* define the architecture. Write it in AGENTS.md first. The agent follows your blueprint instead of inventing its own.
