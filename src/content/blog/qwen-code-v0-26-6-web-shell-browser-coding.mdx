## The Feature That Changes How You Work: Web Shell

### What It Is

A **browser-based sidebar activity view** for trusted workspace conversations. Open it in a tab. See everything:

- **Approval/input/error states** — every agent action visible
- **Unread completions** — know what finished while you were away
- **Running work** — live progress, not a spinner
- **Bulk read/archive controls** — manage sessions at scale

### Why It Matters

You're on a train. Phone only. Agent is refactoring a 50-file module back at your desk. Old way: wait, wonder, hope. New way: open Web Shell → see approvals pending → tap to approve → watch it continue. **Your agent runs on your machine. You steer from anywhere.**

```bash
# Start Qwen Code (any provider — local, cloud, OAuth)
qwen

# Web Shell is available at the configured web endpoint
# Default: http://localhost:3000/web-shell (configurable)
# Opens sidebar with: approvals, split view, token usage, workflow chip
```

### Split View — Side-by-Side Sessions

**What it is:** "Add to Split View" in sidebar session menus. Open two sessions side-by-side in the browser. Compare outputs. Copy context. Review in parallel.

**Why it matters:** You're debugging a flaky test in session A. Session B has the passing run. Split view → diff the outputs → find the race condition. No alt-tab. No copy-paste.

### Per-Model Token Usage Charts — See What's Actually Fast

**What it is:** Web Shell Token Usage panel plots:
- **Per-request output speed** (tokens/sec)
- **First-token latency** (ms)
- **Failure details by model** (error type, count)
- **Success rate per model** (%)

**Why it matters:** You're routing between 5 models. One is 3x slower. One fails 12% of the time. The charts *show you*. No guessing. No manual benchmarking.

```json
// Enable in qwen-code config
{
  "experimental": {
    "unifiedAgentLoop": true
  }
}
```

### Workflow Mode Chip — Dismissible, Informative

**What it is:** Composer shows a **Workflow chip** that:
- Turns Workflow mode off (dismissible)
- Warns when tools are unavailable
- Summarizes the mode in the `+` menu

**Why it matters:** Workflow mode = agent proposes goals, you approve. The chip makes it *visible* — you always know which mode you're in. Dismiss → back to direct control.

## The Automation Power-Ups

### Unified Agent Loop for ACP

**What it is:** With `experimental.unifiedAgentLoop: true`, more ACP turns run on the **shared loop**:
- Channel prompts
- Goal-proposal approvals
- Multi-agent coordination

**Why it matters:** Less context fragmentation. Agents share state more naturally. Fewer "wait, which agent has the context?" moments.

### Mods Run `prompt.submit` Hooks in Headless

**What it is:** Mods (user extensions) can now intercept **headless prompts**:
- `-p "prompt"` CLI calls
- `stream-json` user messages

**Why it matters:** CI pipeline sends a prompt → your mod rewrites it for security/compliance → agent sees the clean version. **Automated guardrails at the prompt level.**

```bash
# Example: mod that redacts secrets before submission
# Runs on: qwen -p "deploy with API_KEY=sk-..." 
# Agent sees: "deploy with API_KEY=***REDACTED***"
```
