AmpCode **CLI v1.2.0 dropped October 5** — and it's not a feature release. It's a **build stabilization sprint** that upgrades the entire toolchain to Go 1.27.1, refreshes the login experience, adds (then hides) a validate command, and bumps 20+ dependencies.

If you run AmpCode CLI in production or CI — this is the update that stops random build failures.

---

## The One-Line Summary

**v1.2.0 (Oct 5) → Go 1.27.1, golangci-lint v2, login page refresh, validate command added then hidden, installation health status removed, 20+ dependency bumps. Zero breaking changes. Upgrade for build reliability.**

---

## The Headline: Go 1.27.1 + golangci-lint v2

### What Changed

The entire build toolchain upgraded:
- **Go 1.27.1** (from 1.26) — latest Go release with performance improvements
- **golangci-lint v2** — major linter upgrade with new rules and faster analysis
- **CI pipeline updated** to match

### Why It Matters

If you build AmpCode from source, run it in CI, or package it for distribution — **this release eliminates the "works on my machine" class of build failures**. The dependency graph is current, the linter is modern, the CI passes.

For daily CLI users: you get a binary built with a newer, faster Go toolchain.

## Login Success Page — Brand Refresh

**New:** The login success page updated to match Amp's **new brand** ([#359](https://github.com/amp-labs/cli/pull/359)).

```bash
amp auth login
# Opens browser → you sign in → lands on refreshed success page
# Matches ampcode.com visual identity
```

**Why it matters:** Small UX polish, but it signals the CLI is tracking the product's visual direction. Consistency builds trust.

---

## Validate Command — Added, Then Hidden

### Added: `amp validate`

**New:** `amp validate` command checks your configuration and environment ([#307](https://github.com/amp-labs/cli/pull/307)).

```bash
amp validate
# Checks: config syntax, auth status, runner connectivity, model access
# Returns 0 if healthy, 1 if issues found
```

### Hidden: `amp validate` (same release)

**Hidden:** The validate command was **immediately hidden from help** ([#361](https://github.com/amp-labs/cli/pull/361)).

```bash
amp --help
# validate no longer listed
# But: amp validate still works if you know it exists
```

**Why add then hide?** The command works but isn't fully baked for general use. It's there for power users and debugging — not for the default workflow. This is responsible CLI design: ship the tool, gate the discovery.

---

## Installation Health Status Removed

**Fixed:** Removed `health` status from `amp list:installations` ([#302](https://github.com/amp-labs/cli/pull/302)).

```bash
# Before: showed health status that was often stale/misleading
amp list:installations
# Installation ID    | Status    | Health
# abc123             | connected | healthy  ← often wrong

# After: just the facts
amp list:installations
# Installation ID    | Status
# abc123             | connected
```

**Why it matters:** Health checks on distributed agents are inherently racy. Showing stale "healthy" gave false confidence. Removing it forces you to verify actively (`amp validate` or check the runner directly).
