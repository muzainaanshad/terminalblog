**Qwen Code v0.26.3 dropped October 28, 2026** — and the patch series (v0.26.1 through v0.26.3) takes the managed-agent platform from "operable" to **production-hardened**.

If v0.26.0 gave you **durable managed sessions, desktop app, SSH workspaces, and --check preflight**, v0.26.1–3 give you **persistent workflow mode, generated UI cards that actually persist, 1M-token context auto-detection, XML tool call recovery, and ACP identity preservation across failures**.

For a beginner: this is now an open-source terminal agent that runs **persistent, multi-agent workflows on your own hardware** with the same reliability guarantees as cloud platforms — and the patch series proves the team ships fixes fast.

## The Headline Features (Ranked by "I Can Actually Use This")

### 1. Managed Agent Sessions — Now Durable, Failover-Ready, and Self-Hostable

The managed-agent stack (introduced in v0.24.6, hardened in v0.24.7, platform-ized in v0.25.0) gets **production infrastructure** in v0.26.0:

| Capability | PR | What It Means for You |
|------------|-----|------------------------|
| **Durable remote Shell result delivery** | [#12894](https://github.com/QwenLM/qwen-code/pull/12894) | Shell output survives disconnects, reconnects, machine restarts |
| **Private Hosted MCP runtime (H1)** | [#12946](https://github.com/QwenLM/qwen-code/pull/12946) | MCP servers run isolated per workspace — no cross-contamination |
| **Verified W1a workspace cold restore** | [#13088](https://github.com/QwenLM/qwen-code/pull/13088) | Kill the machine, restart tomorrow — workspace restores exactly |
| **Host Managed sessions in private ACP child (M2)** | [#13131](https://github.com/QwenLM/qwen-code/pull/13131) | Each managed session gets its own ACP child process — isolation by default |
| **Hosted file history & undo** | [#13110](https://github.com/QwenLM/qwen-code/pull/13110) | Full git-like history for agent actions in managed sessions |
| **Hosted Turn takeover & G1 failover E2E** | [#13083](https://github.com/QwenLM/qwen-code/pull/13083) | If an agent dies, another takes over mid-task — zero context loss |
| **Durable Hosted Hooks (H2)** | [#13129](https://github.com/QwenLM/qwen-code/pull/13129) | Pre/post tool hooks that survive restarts — enforce policy always |
| **Offline W1b recovery bundles** | [#13138](https://github.com/QwenLM/qwen-code/pull/13138) | Export/import workspace state for air-gapped or backup scenarios |
| **Broker auth & provisioned writer credentials** | [#13210](https://github.com/QwenLM/qwen-code/pull/13210) | Secure multi-tenant: each workspace gets its own broker credentials |
| **Default durable local-process & trusted reboot recovery ON** | [#13211](https://github.com/QwenLM/qwen-code/pull/13211) | **No config needed** — durability is the default now |

**The kicker:** v0.26.0 adds **systemd units and setup guidance for single-host managed-agent deployments** ([#14633](https://github.com/QwenLM/qwen-code/pull/14633)). Runtime workers stay running when Broker restarts. You can run the **entire managed-agent stack on your own Linux box** — no cloud, no account, no subscription.

### 3. Local and SSH Workspace References — Your Code, Wherever It Lives

**New in v0.26.0:** `feat(managed-agent): support local and SSH workspace file references` ([#14639](https://github.com/QwenLM/qwen-code/pull/14639))

**Before:** Managed agents worked in a sandbox. You had to copy/sync code into their workspace.

**Now:** Point a managed agent at **any local path** or **any SSH host** — it works with those files directly.

```bash
# Local workspace
qwen-code --managed --workspace /home/user/my-project

# Remote workspace via SSH
qwen-code --managed --workspace ssh://user@server:/home/user/my-project

# In the web shell: add workspace → choose "Local" or "SSH" → enter path
```

**For beginners:** This means your agent can work on code that lives on your laptop, your home server, your VPS, or your company's internal git server — all from the same interface. No `scp`, no `rsync`, no Docker volumes.

### 4. Session-Targeted Skill & Extension Refresh

**New in v0.26.0:** `feat(daemon): support session-targeted Skill and Extension refresh` ([#14050](https://github.com/QwenLM/qwen-code/pull/14050))

**Before:** Updating a skill or extension meant restarting the daemon — all sessions lost their loaded skills.

**Now:** Refresh skills/extensions **per session** without touching other sessions.

```bash
# In web shell: Session → Skills → "Refresh for this session"
# Or via API: target a specific session ID
```

**Why it matters:** You're running a long coding session and a security-review session. The security team pushes a new `security-audit` skill. You refresh *only* the security session. Your coding session keeps running uninterrupted.

### 5. Read-Only `--check` Preflight — "Will This Deploy?" Before You Deploy

**New in v0.26.0:** Adds a **read-only `--check` preflight** that prints `PASS`, `WARN`, `FAIL`, or `SKIP` for managed-agent deployment checks and exits nonzero on failure ([#14632](https://github.com/QwenLM/qwen-code/pull/14632)).

```bash
# Run preflight before deploying managed agents
qwen-code --managed --check

# Output example:
# ✅ PASS  Broker reachable
# ✅ PASS  Runtime workers healthy
# ⚠️ WARN  MCP server 'github' not configured
# ❌ FAIL  Systemd unit 'qwen-runtime' not installed
# Exit code: 1
```

**Use in CI/CD:** Gate your deployment pipeline on `qwen-code --managed --check` — if it fails, the deploy stops before anything breaks.

### 6. 8 MiB Attachment Support & Durable Turn Recovery

**New in v0.26.0:**
- Managed Agent submissions accept **up to 8 MiB of attachment input** ([#14628](https://github.com/QwenLM/qwen-code/pull/14628)) — large logs, screenshots, binary data
- Preserves large pending requests across refresh
- Lets users discard unrecoverable drafts
- **Hosted Turn recovery** asks Runtime Broker for execution evidence and treats unprovable outcomes as unknown instead of transient faults ([#14669](https://github.com/QwenLM/qwen-code/pull/14669))

---

### 7. Models.dev Catalog — Zero-Config Model Discovery

**Carried forward from v0.25.0** (PR [#11959](https://github.com/QwenLM/qwen-code/pull/11959)): Model limits and modalities resolved from a **models.dev catalog**.

**What this means:** New models (Gemini 4, Claude Opus 5.5, GPT-6, Nemotron 3 Ultra, etc.) appear **automatically**. No more waiting for Qwen Code releases to get the latest models. The catalog is the source of truth.

## How to Update

```bash
# CLI (npm - recommended)
npm i -g @qwen-code/qwen-code@latest

# Verify
qwen-code --version
# Should show 0.26.3

# Desktop app (separate channel)
# Download from https://github.com/QwenLM/qwen-code/releases/tag/desktop-v0.26.0

# For self-hosted managed agents:
# 1. Check https://github.com/QwenLM/qwen-code/releases/tag/v0.26.3 for systemd units
# 2. Run: qwen-code --managed --check  (validates your setup)
# 3. Follow setup guidance in release notes for single-host deployment
```

**After upgrade:**
1. Run `qwen-code --managed` → explore the Web Shell
2. Settings → Workspaces → **Add Local or SSH Workspace** → point at your code
3. Skills → search "Mem0" → it's bundled, just enable it
4. Try `--check`: `qwen-code --managed --check` → see your deployment readiness
5. Desktop: launch the app → sign in → same workspaces, same agents
6. **New in v0.26.3:** Try `qwen-code --workflow-mode on` → run a persistent multi-step workflow
7. **New in v0.26.3:** Generate a UI card → switch tabs → come back → card is still there with state
