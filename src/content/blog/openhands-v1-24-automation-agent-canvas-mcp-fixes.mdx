OpenHands v1.24.0 dropped September 25, and it's the release that turns the agent from "a thing you chat with" into **a thing that works while you sleep**.

The headline: **conversation automation** — cron schedules and event triggers that run your agent on a timer or when a PR opens, a branch pushes, or a schedule fires. You define it once. It runs forever.

Plus: **read-only shared automations on cloud**, **ACP tool-call rendering in chat cards**, **MCP OAuth that survives cloud saves**, and a wave of fixes that make the Agent Canvas actually usable.

If you've been waiting for the open-source agent to graduate from "cool demo" to "daily infrastructure," this is the version.

---

## 1. Conversation Automation — The Feature You'll Actually Use

OpenHands now lets you attach **automations** to any conversation. Two trigger types:

| Trigger | What It Does | Example |
|---------|--------------|---------|
| **Cron** | Runs on a schedule | "Every Monday 9 AM, review open PRs and post summary" |
| **Event** | Runs on GitHub events | "When PR opened, run security scan and comment results" |

You configure it in the conversation settings. The agent wakes up, runs the task, posts results, and goes back to sleep. No server to manage. No GitHub Actions yaml to debug.

**For beginners:** This is the first time an open-source coding agent ships *native* automation — not "here's a script you can cron yourself." The scheduling, authentication, context loading, and result posting are all handled inside OpenHands.

---

## 2. Read-Only Shared Automations on Cloud

Here's the part that changes how teams work: **you can share an automation conversation read-only on OpenHands Cloud.**

Your teammate opens the link. They see the conversation, the automation config, the run history, the outputs. They *cannot* edit the prompt, change the schedule, or trigger runs manually. It's a living dashboard, not a shared shell.

This means:
- **Security team** shares the "weekly dependency audit" automation — developers see results, can't break the schedule
- **Platform team** shares the "PR review bot" — everyone sees what it catches, only platform edits the rules
- **You** share your "morning codebase health check" — your manager sees the report, you keep the keys

---

## 3. Agent Canvas — The UI Finally Catches Up

The Agent Canvas (OpenHands' visual conversation interface) got a focused fix wave:

- **ACP tool-call content blocks now render in chat cards** — You see what the agent *actually did*, not just the final answer
- **Device verify page and MCP surfaces use theme tokens** — No more broken Tailwind classes that make the UI look like a glitch
- **Conversation Skills/Hooks/Tools dialogs capped at 90vw** — Finally fits on a laptop screen
- **Stale organization selections recover automatically** — No more "wait, which org am I in?" loops
- **Saved LLM profiles warn when models are unavailable** — Before you waste a run on a deprecated model

The canvas was the weak link in v1.23. In v1.24, it's the reason you'll open the web UI instead of the CLI.

---

## 4. MCP OAuth That Actually Persists

If you've used MCP servers with OAuth (GitHub, GitLab, Google, etc.), you know the pain: **re-authenticate every time you save the conversation to cloud.**

v1.24 fixes this: **OAuth credentials now persist on cloud saves**, and **consent is skipped when tokens still work**.

You connect once. The tokens encrypt and travel with the conversation. Next time you (or your teammate) opens it, the MCP servers are already authenticated.

---

## 5. The Fixes That Eliminate Daily Friction

| Area | What Was Broken | What's Fixed |
|------|-----------------|--------------|
| **Automation scheduler** | Single-start stepped cron fields rejected | Now accepted (e.g., `*/5 * * * *` works) |
| **Canvas → cloud proxy** | 405 errors on verification confirm & compact-context | Calls agent-server runtime directly |
| **Settings cache** | Cached wrong backend's answer | Now keyed on the backend that answered |
| **History reload** | Newer failed messages lost | Preserved |
| **Cloud proxy docs** | Outdated Rule 2 in AGENTS.md | Corrected |
| **Node version** | README said 18+, engines requires 24+ | Aligned |

## What This Means for You

**If you're new to OpenHands:** Start with the [OpenHands v1.14 beginner guide](/blog/openhands-v1-12-free-models-clarified-beginner-guide/) — it covers the mental model. Then come back here for automation.

**If you're evaluating agents:** OpenHands is the only open-source agent with *native, cloud-hosted automation* that shares read-only. Codex has schedules but no cloud sharing. Goose has skills but no cron. Claude Code has no automation at all.

**If you run a team:** The read-only sharing + automation combo means you can deploy "agent workflows" like internal tools — audits, reviews, reports — without giving everyone write access to the prompts.

## How to Update

```bash
# Docker (recommended for automation)
docker pull ghcr.io/all-hands-ai/openhands:1.24.0

# Or update your local install
cd openhands
git pull origin main
docker compose up -d --build
```

Cloud users: automations are live on https://app.openhands.ai — no update needed.

## The Big Picture

OpenHands v1.24 isn't a feature drop. It's a **paradigm shift**.

For two years, coding agents were **reactive** — you ask, they answer. v1.24 makes them **proactive** — they wake up, work, report, and sleep.

The open-source agent that runs your repo is now the agent that runs your workflow.

And because it's open-source, you own the automation. No vendor lock-in. No per-seat pricing for "AI workflows." Just code that runs on a schedule you define.
