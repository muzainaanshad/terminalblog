Gitlawb Zero **v0.9.0** landed September 15, and it's the release that finally makes agent sessions *portable* — not just "saved to disk" portable, but **ACP-standard list and resume** portable.

If you've ever lost a 3-hour agent session because the process crashed, or wanted to hand off a half-finished task to another machine (or another agent) — this is the release that fixes that.

## What Zero Is, in One Paragraph

Gitlawb Zero (about 1,200 GitHub stars, MIT-licensed, npm package `@gitlawb/zero`) is a terminal coding agent for people who want to own their tooling. You start it in a project folder, ask for something in plain English, and it plans, edits files, runs commands, and commits — but every permission stays on your machine, and you can point it at any model provider you like (OpenAI, Anthropic, Ollama, OpenRouter, local models via LM Studio, and more).

If you're new to it, our [Gitlawb Zero deep dive](/blog/deep-dive-gitlawb-zero-agent/) covers the architecture. This article is about what v0.9.0 changes.

## 1. ACP Standard Session List and Resume — The Headline

**ACP (Agent Communication Protocol)** now supports listing and resuming sessions natively ([#914](https://github.com/Gitlawb/zero/issues/914)). This isn't a custom format — it's the emerging standard for agent interoperability.

**What this means for you:**
- `zero acp session list` — shows all sessions with metadata (model, working directory, last activity, message count)
- `zero acp session resume <id>` — picks up exactly where you left off: conversation history, tool state, working directory, permissions
- Works across restarts, across machines, across ACP-compatible tools

**Why beginners care:** You stop treating agent sessions as disposable. A session becomes a *project artifact* — you can resume it tomorrow, hand it to a teammate, or fork it for a different approach.

## 2. Richer TUI — Interactive Terminal Attach and Mid-Run Model Escalation

The TUI got two features that change daily workflows:

### Interactive Terminal Attach for TTY Exec Sessions ([#1055](https://github.com/Gitlawb/zero/issues/1055))
When Zero runs a command in a TTY (interactive CLI, `vim`, `htop`, `psql`), you can now **attach to that terminal live** from the TUI. See the output, send keystrokes, detach and reattach — the command keeps running.

No more "I wish I could see what that long-running command is doing right now."

### Mid-Run Model Escalation Behind `--allow-escalation` ([#1019](https://github.com/Gitlawb/zero/issues/1019))
Start a task with a fast/cheap model (GPT-6 Luna, Haiku). Hit a complex reasoning wall. **Escalate mid-run to Opus 5.5 or GPT-6 Sol** without losing context.

```bash
zero --allow-escalation
# In TUI: /model escalate claude-opus-5-5
```

The conversation history, tool results, and working state all transfer. You pay for expensive reasoning *only when you need it*.

## 3. Richer `/resume` Session Browser ([#1047](https://github.com/Gitlawb/zero/issues/1047))
The session picker now shows:
- Preview of the last few messages
- Tool calls made in the session
- Working directory and git branch
- Model and provider used
- Token usage estimate

Pick the right session to resume without guessing.

## 4. ACP: Structured File Changes in Tool Updates ([#999](https://github.com/Gitlawb/zero/issues/999))
Tool results now emit **structured file changes** (create, modify, delete, rename) through ACP. Other ACP-compatible tools can parse what Zero changed without scraping text output.

This is how agents start talking to each other *about code* — not just text.

## 5. ACP: Safe Browser Tool Metadata ([#1000](https://github.com/Gitlawb/zero/issues/1000))
Browser tools (`browser_screenshot`, `browser_pdf`, `browser_click`) now surface safe metadata through ACP: URLs visited, element selectors used, viewport dimensions — without exposing raw DOM or credentials.

## 6. Default Headless Runs to Turn-Budget Ceiling ([#1049](https://github.com/Gitlawb/zero/issues/1049))
Headless runs (`zero run --headless`) now default to the maximum turn budget instead of a conservative limit. Your CI/CD agents stop hitting arbitrary ceilings mid-task.

## 8. v0.7.0 Context — Vision and Planning Mode (August 10)

For completeness, v0.7.0 (Aug 10) added the foundation that v0.9.0 builds on:

- **Image channel for tool results + `view_image` tool** — Agents can finally *look at* the screenshots and PDFs they capture ([PR #843](https://github.com/Gitlawb/zero/pull/843))
- **`PermissionModePlan` — Read-only planning mode** ([PR #853](https://github.com/Gitlawb/zero/pull/853)): Agent refuses mutating tools, local commands, executable hooks. Use `zero --plan` to explore a codebase before letting it touch anything.
- **Sandbox hardening** — Zero can no longer read its own credential stores ([PR #681](https://github.com/Gitlawb/zero/pull/681)); Windows write jail stops honoring "Everyone"-granted paths ([PR #865](https://github.com/Gitlawb/zero/pull/865))
- **Live model lists for OpenRouter and OpenGateway** ([PR #860](https://github.com/Gitlawb/zero/pull/860)) — New models appear without waiting for a Zero update

## How to Update

Zero moves fast (v0.7.0 → v0.8.0 → v0.9.0 in ~5 weeks). To get it:

```bash
npm install -g @gitlawb/zero
```

Then confirm with `zero --version` and run a quick plan-mode session — it's the best way to feel the new read-only safety rail.

```bash
zero --plan
# Explore a repo, get a proposal, review it, then drop the guard
```
