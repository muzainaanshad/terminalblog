GitHub Copilot CLI **1.0.93** landed this week (October 5–7), and it delivers the two things terminal-agent users have been asking for since sandbox mode launched: **sandbox for everyone, no waitlist**, and **MCP configuration that updates without restarting your session**.

If you've been stuck on the sidelines waiting for sandbox access, or frustrated that every MCP server tweak meant a full CLI restart — this release changes your daily workflow.

---

## 1. Command Sandboxing: Now Available to Everyone

**The headline feature:** `/sandbox` and `--sandbox` are no longer gated. Every Copilot CLI user gets command sandboxing out of the box.

### What Sandbox Actually Does

When you run with `--sandbox`, every shell command the agent wants to execute goes through a security review:

| Without Sandbox | With Sandbox |
|-----------------|--------------|
| Agent runs `rm -rf node_modules` instantly | Agent asks: "Run `rm -rf node_modules`? [y/N]" |
| `npm install` pulls from anywhere | Network calls filtered by allowlist |
| No audit trail | Every command logged with approval/denial |

### What 1.0.93 Adds

- **Safe `/user` commands run immediately** during active turns — no prompt for read-only ops like `ls`, `cat`, `git status`
- **Unsafe remote commands rejected automatically** during active turns — no dialog spam, just a clean "blocked"
- **Commands from relay hosts get queued** — you approve them on your schedule
- **Local-network allowlists now include `localhost` and loopback** — local dev servers, databases, and proxies work without extra config

**For beginners:** This is the "training wheels" mode that lets you try an autonomous agent without worrying it'll delete your `.env` or push to production. Turn it on, watch it ask before every write, and gradually relax the rules as you trust it.

```bash
# Try it now
copilot --sandbox
# Or in a session
/sandbox on
```

## 2. MCP Server Config Changes Apply Instantly — No Restart Required

This is the quality-of-life fix that compounds every week.

**Before 1.0.93:** You add an MCP server, realize you forgot an env var, update `mcp.json`, then **restart Copilot CLI entirely** to pick up the change. Your session context, history, and agent state — gone.

**After 1.0.93:** Edit `mcp.json` (or use `copilot mcp add/edit/remove`). The new config applies **between turns**. Your session stays alive. The agent picks up the new tools on its next turn.

```json
// ~/.copilot/mcp.json
{
  "servers": {
    "my-db": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": { "DATABASE_URL": "postgresql://..." }
    }
  }
}
```

Change the `DATABASE_URL`, save, and the next agent turn sees the updated connection. No restart. No context loss.

## 3. Enterprise-Grade Network Boundaries (`permissions.limitTo`)

For teams running Copilot in managed environments, 1.0.93 adds `copilot config set permissions.limitTo <domain-list>`.

```bash
# Restrict all outbound network requests to approved domains
copilot config set permissions.limitTo "github.com,api.github.com,raw.githubusercontent.com"
```

The agent simply cannot reach anything outside that list. MCP servers, package registries, API endpoints — all blocked unless explicitly allowed. This is the control enterprises need to adopt terminal agents without security review bottlenecks.

## 4. Model Picker Now Prioritizes the Models You Actually Want

The model picker's recommended list has been reordered to put the current frontier models first:

1. **GPT-6.1 Sol** (OpenAI) — deep reasoning, complex refactors
2. **GPT-6 Astra / Luna** (OpenAI) — speed-optimized, everyday coding
3. **Claude 5.5** (Anthropic) — 1M context, strong coding

If you've been manually scrolling past older defaults (Claude 3.5, GPT-4o, etc.), you'll now see the best models at the top. No configuration needed.
