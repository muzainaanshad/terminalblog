GitHub Copilot CLI **1.0.92** dropped yesterday (October 1), and it fixes the single most annoying MCP bug in the 1.0.9x series: **MCP tools that stopped working after you reauthenticated with OAuth.**

If you've ever connected an MCP server, worked happily for a while, then had to reauthenticate (token expiry, password change, new device) and watched all your MCP tools go silent — this release is for you.

---

## The Bug: OAuth Reauth Killed Your MCP Tools

Here's what happened before 1.0.92:

1. You set up an MCP server (database, filesystem, GitHub, whatever)
2. You authenticate with OAuth — tools work great
3. Time passes. Your OAuth token expires or you sign in from a new machine
4. You reauthenticate successfully
5. **MCP tools stop working** — they show in the list but every call fails silently

The root cause: when OAuth reauth happened, Copilot refreshed the token but **didn't refresh the MCP tool definitions**. The tools were still registered against the old token's permissions. Calls went out with stale auth and the MCP server rejected them.

You had to restart Copilot CLI entirely to get tools back. In a long coding session, that's a flow-killer.

---

## The Fix: Tool Definitions Now Survive Reauth

**1.0.92 changes one thing:** when OAuth reauthentication completes and the tool definitions haven't changed, Copilot **keeps the existing MCP tool registrations active.**

No restart needed. No tool list refresh. You reauth, you keep working.

```bash
# Before 1.0.92: reauth → tools break → restart CLI → tools work
# After 1.0.92: reauth → tools keep working
```

That's it. One line in the release notes, massive quality-of-life improvement.

---

## Why This Matters for Beginners

If you're new to coding agents, MCP (Model Context Protocol) is how agents connect to external tools — databases, APIs, file systems, GitHub, Jira, you name it. It's the bridge between "AI that only sees your code" and "AI that can actually *do* things."

The problem: **OAuth tokens expire.** It's not a bug, it's security. But every expiry meant your agent lost its tools until you restarted.

This fix means:
- Your MCP-connected workflow survives token rotation
- You don't need to understand the auth plumbing to keep working
- Long-running sessions (overnight monitors, CI pipelines, all-day coding) stay stable

## v1.0.92-3 (October 2) — The Quiet Quality Patch

Just hours after 1.0.92, GitHub shipped **v1.0.92-3** with four practical fixes that make daily usage smoother:

| Fix | What Changed |
|-----|--------------|
| **Ctrl+E environment picker** | Pre-conversation shortcut to switch between local and cloud runs without leaving the terminal |
| **Input responsiveness** | Keyboard, paste, and mouse input stay ordered and responsive during rapid interaction |
| **Sandbox network bypass prompt** | Sandboxed shell commands now offer a bypass prompt whenever the proxy blocks a destination |
| **Git in sandbox** | Sandboxed scripts running Git now authenticate with masked credentials and SSH remote rewrites |
| **Sub-agent auth persistence** | Sub-agents keep working after you replace your GitHub authentication credentials |
| **Model cleanup** | Retired models removed from the picker and CLI selections |

The Ctrl+E picker alone is a workflow upgrade — no more `copilot config` dance to switch environments. You hit Ctrl+E, pick local or cloud, and you're in.
