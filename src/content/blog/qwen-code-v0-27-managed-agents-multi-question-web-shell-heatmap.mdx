## The Headline Feature: Managed Agents Finally Handle Multiple Questions Like Adults

### The Problem: One Question at a Time

Before v0.27, a managed agent session could only hold **one pending "Ask User" question**. If your automation needed security review → compliance check → deploy approval, you got a queue. Answer out of order? Impossible. Draft your deploy answer while security review is pending? Gone.

### The Fix: `multi-child-questions` — Answer in Any Order, Keep Drafts Separate

**New in v0.27:** Managed-agent sessions now support **multiple child questions simultaneously** ([#16484](https://github.com/QwenLM/qwen-code/pull/16484)).

- **Any order** — answer question #3 before #1, no problem
- **Isolated drafts** — typing an answer to "Deploy to prod?" doesn't wipe your "Security review?" draft
- **Separate errors** — if one question fails validation, others stay clean
- **Persists across restarts** — questions survive agent restart, daemon restart, machine reboot

```bash
# Your CI pipeline can now do this:
qwen-code run --managed "
  1. Security review: 'Any secrets in this diff?' [yes/no/abort]
  2. Compliance: 'Does this meet GDPR?' [yes/no/escalate]
  3. Deploy: 'Push to production?' [yes/no/dry-run]
"
# All three questions land. Team answers in whatever order they want.
# Agent resumes each branch independently when answered.
```

**Why this changes team workflows:** You can now model **real approval chains** — security → compliance → deploy — as parallel questions that different people answer at different times. The agent doesn't block. It just waits, remembers, and resumes.

## Web Shell: You Can Finally *See* When Agents Asked for Help

### Task Q&A Heatmap — Your Agent's "Ask" Calendar

**New:** Web Shell's composer now shows a **task Q&A activity heatmap** ([#16037](https://github.com/QwenLM/qwen-code/pull/16037)). Click a day → scrolls transcript to that day's first Q&A → highlights it.

```bash
# In Web Shell (http://localhost:3000/web-shell):
# 1. Open a session with managed agent runs
# 2. See a GitHub-style contribution heatmap in the composer
# 3. Dark green day = lots of "Ask User" questions
# 4. Click Nov 5 → jumps to first question that day
```

**Why it matters:** Before, finding "when did the agent ask for deploy approval?" meant scrolling through thousands of lines. Now: **visual calendar → one click → context**.

---

### "Ask for Details" — Explain the Options Without Answering

**New:** Pending "Ask User Question" panels get an **"Ask for details" action** ([#16458](https://github.com/QwenLM/qwen-code/pull/16458)). Opens a side task that explains what each option *means* without submitting an answer.

```bash
# Agent asks: "Deploy to prod? [yes/no/dry-run]"
# You click "Ask for details" → side panel opens:
# - yes: Full production deploy, traffic shifts immediately
# - no: Cancels deploy, marks PR as blocked
# - dry-run: Runs deploy plan, shows diff, no traffic shift
# You read, understand, THEN click your actual answer
```

**For beginners:** This is the "what does this button do?" safety net. Non-technical stakeholders can understand options before committing.

## GitHub Channel: Repo Allowlists and Blocklists

### Control Exactly Which Repos Trigger Your Agents

**New:** GitHub channel editor adds a **Repository Filter** with **allowlist and blocklist modes**, URL-friendly entries, and skipped-notification timeline rows ([#16493](https://github.com/QwenLM/qwen-code/pull/16493)).

```json
// Channel config example:
{
  "type": "github",
  "repositoryFilter": {
    "mode": "allowlist",  // or "blocklist"
    "entries": [
      "myorg/backend-*",
      "myorg/frontend-main",
      "!myorg/backend-legacy"  // negation works
    ]
  }
}
```

**Why it matters:** Stop agents from spinning up on `myorg/random-fork` or `myorg/archived-repo`. Allowlist = only these repos. Blocklist = everything except these. Skipped notifications show in timeline so you can audit.

## Shell Tool: CRLF and Unicode Finally Safe

### No More Corrupted Edits on Windows Files

**Fixed:** The shell tool's sed simulation now handles **CRLF files and Unicode characters correctly** in substitution patterns ([#15701](https://github.com/QwenLM/qwen-code/pull/15701), [#15836](https://github.com/QwenLM/qwen-code/pull/15836)).

```bash
# Before: Editing a Windows file (CRLF) with Unicode → corruption or failed edit
# After:  Just works. Line endings preserved. Emoji in strings preserved.
```

**Plus:** Cancelled commands now report as **interrupted** (exit code 130) instead of completed, preserving partial output ([#15836](https://github.com/QwenLM/qwen-code/pull/15836)).

## Runtime: Faster, Fewer Deadlocks, Safer

### Managed Agent Performance — Measurable Wins

**Performance improvements** ([#16480](https://github.com/QwenLM/qwen-code/pull/16480), [#16478](https://github.com/QwenLM/qwen-code/pull/16478), [#16376](https://github.com/QwenLM/qwen-code/pull/16376), [#16489](https://github.com/QwenLM/qwen-code/pull/16489), [#16447](https://github.com/QwenLM/qwen-code/pull/16447)):

| Improvement | What Changed | Impact |
|-------------|--------------|--------|
| **Tenant guard locks removed** | Native journal snapshot publication unlocked | Managed agent throughput up, contention down |
| **Storage admission locks via alias keys** | Concurrent storage requests queue instead of deadlocking | No more "session stuck on storage" |
| **Snapshot publication waits for claims** | Reduces failed publications from deadlocks | Fewer 503s on session rename |
| **Local journal reads accept grown prefixes** | Even when timestamps don't change | Prevents unnecessary read failures |
| **Session rename waits for title delivery** | No more 503 errors mid-rename | Reliable session management |

**Translation:** If you run 20+ concurrent managed workspaces, this release feels snappier. Sessions don't stall on storage. Renames work. The "it works at 5 agents but falls over at 20" problem is substantially reduced.

## Security: Credentials Stop Leaking in Error Messages

### Upgrade Refusals and Advisor Errors Sanitized

**Fixed:** Upgrade refusals and Advisor startup errors **no longer expose embedded credentials** ([#16352](https://github.com/QwenLM/qwen-code/pull/16352), [#16083](https://github.com/QwenLM/qwen-code/pull/16083)).

```bash
# Before: "Upgrade refused for model api-key=sk-abc123@provider..."
# After:  "Upgrade refused for model [REDACTED]@provider..."

# Before: Advisor error shows full aux-model selector with secrets
# After:  Sanitized — routing unchanged, secrets hidden
```

**Empty Harness user info rejected** during start and verify — prevents misconfigured agents from starting with no identity.
