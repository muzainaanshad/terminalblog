**OpenClaw v2026.11.3 dropped November 10, 2026** — the third stable release in the 2026.11.x train. This one is pure security and reliability hardening: **credential isolation**, **authentication hardening**, **update recovery**, and **secret redaction**. 34 PRs, zero breaking changes.

If you run OpenClaw with multiple plugins, MCP servers, or cloud workspaces — this is the update that stops your secrets from leaking across connections.

---

## The One-Line Summary

**v2026.11.3 (Nov 10) → Credential isolation for plugins + search, bounded auth at run deadline, secret redaction in config reads, child-process env sanitization, update recovery unstuck, Anthropic usage-cap handling, 30+ fixes. Zero breaking changes.**

---

## The Headline Features: Your Secrets Stay Where They Belong

### 1. Credential Isolation — Plugins and Search Keys No Longer Cross-Pollinate

**What it is:** Plugin results and search credentials are now **scoped to their connection** — they don't leak to other plugins or providers.

**Why it matters:** Before, if you had Firecrawl API key for web search and Exa API key for another search, they could bleed into each other. Same for MCP server credentials. Now:
- **Firecrawl keys** stay with Firecrawl endpoints
- **Exa keys** stay with Exa endpoints
- **MCP credentials** stay with their provider origin
- **Embedding credentials** stay with their destination

```json
// Before: keys could be reused across wrong endpoints
// After: each provider's credentials are isolated
{
  "firecrawl": { "apiKey": "fc-...", "endpoint": "api.firecrawl.dev" },
  "exa": { "apiKey": "exa-...", "endpoint": "api.exa.ai" }
}
// Keys never cross
```

**Fixes:** [#178444](https://github.com/openclaw/openclaw/pull/178444), [#177974](https://github.com/openclaw/openclaw/pull/177974), [#189423](https://github.com/openclaw/openclaw/pull/189423), [#190706](https://github.com/openclaw/openclaw/pull/190706), [#184966](https://github.com/openclaw/openclaw/pull/184966)

---

### 2. Bounded Authentication — No More Stalled Auth at Run Deadlines

**What it is:** Provider authentication now **stops at the run deadline** and propagates cancellation through authentication work.

**Why it matters:** Before, a stalled OAuth flow (expired token, network hang, provider down) could block your agent run indefinitely. Now:
- Auth has a deadline
- If deadline hits → cancellation propagates cleanly
- Run fails with clear error instead of hanging

**Fix:** [#189144](https://github.com/openclaw/openclaw/pull/189144)

---

### 3. Credential Redaction — Secrets Don't Appear in Config Reads or Errors

**What it is:** Inline environment credentials are **redacted from configuration reads**, and search credentials are **redacted from Exa errors**.

**Why it matters:** You run `openclaw config read` or an error gets logged — your API keys used to show in plain text. Now they're redacted:

```bash
# Before: config read shows
{ "anthropic": { "apiKey": "sk-ant-abc123..." } }

# After: config read shows
{ "anthropic": { "apiKey": "[REDACTED]" } }

# Exa errors used to leak search credentials — now redacted
```

**Fixes:** [#190618](https://github.com/openclaw/openclaw/pull/190618), [#178745](https://github.com/openclaw/openclaw/pull/178745)

---

### 4. Child-Process Environment Sanitization — Daemons Don't Inherit Gateway Secrets

**What it is:** Managed Signal daemons and bundled language servers **no longer inherit unrelated Gateway secrets** in their environment.

**Why it matters:** When OpenClaw spawns child processes (language servers, daemons), they used to get the *entire* Gateway environment — including your API keys, tokens, and internal secrets. Now they only get what they need.

**Fixes:** [#179198](https://github.com/openclaw/openclaw/pull/179198), [#179415](https://github.com/openclaw/openclaw/pull/179415)

## The Reliability Fixes (You'll Feel These)

### 5. Authentication Errors Surface Properly

**What it is:** Credential-read failures now **surface as errors** instead of being treated as "missing credentials." Explicitly selected auth profiles belonging to incompatible providers are **rejected** with a clear message.

**Why it matters:** Before: "no credentials found" when the real issue was "can't read the credential file." Now you get the actual error.

**Fixes:** [#173970](https://github.com/openclaw/openclaw/pull/173970), [#181597](https://github.com/openclaw/openclaw/pull/181597)

---

### 6. Update Recovery Gets Unstuck

**What it is:** The update system now **recognizes its own maintenance lock** and **preserves cancellation** when ledger writes are deferred. Update recovery **recovers safely** when the initial package-presence check times out.

**Why it matters:** Crashed/canceled updates used to leave the system in a broken state requiring manual intervention. Now it self-recovers.

**Fixes:** [#177792](https://github.com/openclaw/openclaw/pull/177792), [#187998](https://github.com/openclaw/openclaw/pull/187998), [#181906](https://github.com/openclaw/openclaw/pull/181906)

---

### 7. Anthropic Usage Cap Handling — No Wasted Retry Budget

**What it is:** OpenClaw now **recognizes exhausted plural usage-limit errors** without spending the transient rate-limit retry budget.

**Why it matters:** When you hit your Anthropic usage cap, the agent used to burn retries on a hard limit. Now it stops immediately and tells you "usage cap exceeded" — saving your retry budget for actual transient errors.

**Fix:** [#176186](https://github.com/openclaw/openclaw/pull/176186)

---

### 8. Terminal Sessions — `/reset` Soft Forwards to Gateway

**What it is:** `/reset` in terminal sessions now **forwards a soft reset to the Gateway** instead of hard-resetting the session locally.

**Why it matters:** Hard resets lose context. Soft resets preserve it. You get a clean slate *without* losing your conversation history.

**Fix:** [#172431](https://github.com/openclaw/openclaw/pull/172431)

---

### 9. Git Recovery — Uncertain Failures Preserved

**What it is:** During Git repair, **uncertain command failures are preserved** instead of treating unconfirmed operations as successful.

**Why it matters:** If a Git operation might have failed but we're not sure, OpenClaw now flags it instead of assuming success. Prevents silent corruption.

**Fix:** [#176006](https://github.com/openclaw/openclaw/pull/176006)

## Performance: Faster, More Responsive Gateway

**What it is:** **Reduced startup module-file loading overhead** and **avoided stalls** when abort-command detection encounters long punctuation runs.

**Why it matters:** Gateway starts faster. Long commands with lots of punctuation (regex, JSON, etc.) don't trigger false abort detection.

**Fixes:** [#192217](https://github.com/openclaw/openclaw/pull/192217), [#184433](https://github.com/openclaw/openclaw/pull/184433)

---

## Verified Workspace Connections

**What it is:** **Saved node certificate pins preserved** when an empty fingerprint is supplied. **Workspace-transfer certificates verified** before sending credentials or data.

**Why it matters:** Moving workspaces between machines/nodes now verifies the destination before sending your secrets. Certificate pins survive config updates.

**Fixes:** [#125646](https://github.com/openclaw/openclaw/pull/125646), [#190002](https://github.com/openclaw/openclaw/pull/190002)

---

## Sandboxed Image Access

**What it is:** **Required-sandbox image previews stay inside allowed folders**, even in Full Access mode, while preserving explicit administrator image allowances.

**Why it matters:** Image previews in agent responses can't escape the sandbox. Admin allowances still work for legitimate use cases.

**Fix:** [#176203](https://github.com/openclaw/openclaw/pull/176203)

---

## Visible Tool Failures

**What it is:** **Unanswered tool failures are reported** instead of silently ending a user-addressed turn as a success.

**Why it matters:** Before: tool fails → agent pretends turn succeeded. Now: tool fails → you see the failure.

**Fix:** [#182458](https://github.com/openclaw/openclaw/pull/182458)

---

## Reliable Child-Task Handoffs

**What it is:** Parent can hand off to replacement work after cancelling a child, **without the cancelled child's completion receipt blocking the handoff**.

**Why it matters:** Complex multi-agent workflows don't get stuck when you cancel a subagent and want to spawn a replacement.

**Fix:** [#178893](https://github.com/openclaw/openclaw/pull/178893)

---

## Private Task Results

**What it is:** **Private subagent completions stay out of streamed chat replies.**

**Why it matters:** Internal subagent work doesn't pollute your main conversation stream.

**Fix:** [#188490](https://github.com/openclaw/openclaw/pull/188490)

---

## Scheduled Jobs Hardening

**What it is:** Queued cron storage failures **don't exit the Gateway**. One-shot cleanup clears when a job becomes recurring.

**Why it matters:** Background jobs are more resilient. Gateway stays up even if cron storage hiccups.

**Fixes:** [#175678](https://github.com/openclaw/openclaw/pull/175678), [#168985](https://github.com/openclaw/openclaw/pull/168985)

---

## Channel Safety

**What it is:** Incoming Twitch IRC content **stays out of parser error logs**. Explicit request IDs required when multiple Tlon approvals are pending.

**Why it matters:** Noisy logs cleaned up. Approval flows don't get confused with multiple pending requests.

**Fixes:** [#174552](https://github.com/openclaw/openclaw/pull/174552), [#186243](https://github.com/openclaw/openclaw/pull/186243)

---

## Memory Provider Selection

**What it is:** **Mixed-case `none` and `auto` provider values accepted.**

**Why it matters:** `None`, `NONE`, `Auto`, `AUTO` all work. No more case-sensitivity bugs.

**Fix:** [#186310](https://github.com/openclaw/openclaw/pull/186310)
