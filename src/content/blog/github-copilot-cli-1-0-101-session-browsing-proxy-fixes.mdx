## The Fixes That Change Daily Work (v1.0.103 Focus)

### 1. ACP Sessions Honor Sandbox Settings — Finally Persistent

**What it is:** ACP (Agent Client Protocol) sessions now honor saved sandbox settings and `--sandbox`/`--no-sandbox` flags, including on resume.

**Why it matters:** Before this, ACP sessions would lose their sandbox configuration on resume. You'd start with `--sandbox`, disconnect, resume, and suddenly you're running without sandbox protection. Now the setting sticks — including explicit flags passed at startup.

```bash
# Your sandbox choice survives resume
copilot --sandbox
# ... disconnect ...
copilot --resume
# Still sandboxed. No surprises.
```

---

### 2. Cloud Replies Recover Full Text on Reconnect

**What it is:** When the CLI reconnects after a dropped connection, cloud replies keep their full text instead of truncating.

**Why it matters:** You're in a cloud session. Network blips. Before: you'd reconnect and the agent's last response was cut off. Now: the full response is there, waiting for you.

---

### 3. Sessions Browser Shows Real Titles

**What it is:** The sessions browser shows a session's recorded title instead of a generic "Session N" fallback when available.

**Why it matters:** You have 20 sessions. "Session 14" tells you nothing. "Refactor auth middleware" tells you exactly which one to resume.

---

### 4. GPT-5 Verbosity Applies Correctly

**What it is:** Model-specific default Responses verbosity now applies correctly for GPT-5 models unless session verbosity is explicitly set.

**Why it matters:** GPT-5 models have their own verbosity defaults. Before, these were ignored unless you manually set verbosity per session. Now the model's natural style comes through by default.

---

### 5. .NET/NuGet Sandbox Grants for `dnx` Commands

**What it is:** `dnx` commands can now use existing .NET and NuGet sandbox grants when developer-tool access is enabled.

**Why it matters:** .NET developers using `dnx` (or similar tooling) no longer hit sandbox permission walls for package restore and build operations. The grants you already have for `dotnet`/`nuget` extend to `dnx`.

---

### 6. Windows Dev-Tool Shims Get Same Sandbox Grants

**What it is:** Windows dev-tool shims like `npm.cmd` now receive the same sandbox grants as `npm`.

**Why it matters:** On Windows, `npm` is often `npm.cmd`. The sandbox used to treat them differently. Now they're equivalent — your Windows workflows don't need special handling.

---

### 7. Gemini Schema Validation Fixed — No More 400 Errors

**What it is:** Gemini tool calls now avoid 400 schema validation errors for nullable and enum fields.

**Why it matters:** Gemini's strict schema validation was rejecting valid tool calls with nullable fields or enums. This caused silent failures or confusing errors. Fixed at the schema generation level.

---

### 8. Resume Sessions Under Managed Model Defaults

**What it is:** Resume sessions under mandatory managed model defaults without rejecting saved preferences.

**Why it matters:** Enterprise/organization managed model policies used to conflict with your saved session preferences on resume. Now managed defaults apply cleanly without wiping your config.

---

### 9. Hash Mention Suggestions Auto-Refresh

**What it is:** Hash mention suggestions refresh automatically when the GitHub client becomes ready.

**Why it matters:** Type `#` to mention an issue/PR — suggestions used to be stale until you restarted. Now they refresh when GitHub auth is ready.

---

### 10. MCP Tool Snapshots Cached Across Git Worktrees

**What it is:** Reuse cached local MCP tool snapshots across registered Git worktrees in one repository.

**Why it matters:** You have 5 worktrees for the same repo. Each used to re-fetch MCP tool definitions. Now: one fetch, cached, shared. Faster startup, less API traffic.

---

### 11. Remote Launch Options Clarified

**What it is:** Improved remote launch options with clearer hosting/connection flags; retired legacy `--remote`/`--no-remote` startup flags.

**Why it matters:** The old flags were confusing. New flags make it explicit: where does this run? How does it connect? No more guessing.

## How to Update

```bash
# macOS (Homebrew)
brew upgrade github-copilot-cli

# Windows (winget)
winget upgrade GitHub.CopilotCLI

# Windows (scoop)
scoop update github-copilot-cli

# Linux/macOS (npm)
npm update -g @github/copilot-cli

# Or reinstall latest
npm install -g @github/copilot-cli@latest

# Verify
copilot --version
# Should show 1.0.103
```
