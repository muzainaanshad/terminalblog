**KiloCode v7.8.25 (pre-release) dropped October 28, 2026** — and it ships exactly one user-facing change: **preserving the existing package-manager user-agent when reading npm configuration** ([#15274](https://github.com/Kilo-Org/kilocode/pull/15274)).

That's it. One PR. One fix. But if you work in a corporate environment with registry analytics, audit logs, or custom npm proxies — this fix matters.

---

## The Fix: npm User-Agent Preservation

**What it was:** KiloCode's CLI was overriding the npm user-agent with its own when reading npm configuration, stripping away the original package manager's identity (npm, pnpm, yarn, bun).

**What it is now:** The existing package-manager user-agent is **preserved** when KiloCode reads npm config. Your registry sees `npm/10.x.x` or `pnpm/9.x.x` or `yarn/4.x.x` — not `kilocode/7.8.25`.

**Why it matters:**
- **Corporate registries** (Artifactory, Nexus, Verdaccio) often log/route by user-agent
- **Analytics & audit trails** expect the real package manager identity
- **Custom proxies** may allow/deny based on user-agent patterns
- **Rate limiting** on some registries is per-user-agent

**For beginners:** You likely won't notice this change — and that's the point. It "just works" with your existing npm/pnpm/yarn/bun setup. No config, no flags, no behavior change except the right identity reaching your registry.

## What v7.8.20 (Last Stable) Brought — Context for v7.8.25

Since v7.8.25 is a pre-release, most users are on **v7.8.20** (Oct 22 stable). Here's what you're getting if you upgrade:

### 1. Auto-Compaction Fix — Large Sessions Don't Choke

**Fixed:** Large-session compaction now gets **enough output space for thinking and a complete summary** ([#14976](https://github.com/Kilo-Org/kilocode/pull/14976)). Cut-off summaries are rejected without losing conversation history, with retry guidance.

**Before:** Long sessions would hit compaction, produce truncated summaries, lose context.

**Now:** Compaction has breathing room. If it can't fit, it tells you how to retry — no silent data loss.

### 2. Multi-Process Safety — No More Ghost Replies

**Fixed:** When multiple Kilo processes share a data directory, **replies being written by another process are kept** instead of deleted ([#15515](https://github.com/Kilo-Org/kilocode/pull/15515)).

**Fixed:** **Scheduled wakeups and cron tasks fire once** across processes sharing a workspace ([#15516](https://github.com/Kilo-Org/kilocode/pull/15516)). Cancelled tasks stay cancelled.

**Why it matters:** Team environments, CI runners, desktop + CLI simultaneously — no more duplicate executions or lost messages.

### 3. Background Job Exit Codes — Real Signals

**Fixed:** Background jobs now **preserve the real exit code or signal** instead of recording failed jobs as successful ([#15081](https://github.com/Kilo-Org/kilocode/pull/15081)).

**For automation:** Your CI/CD can now trust Kilo's background job status. `exit 1` means failed. `exit 0` means success. No more false greens.

### 4. Conda CLI Package — Python Environment Management

**Added:** **Conda CLI package** for managing Python environments from within KiloCode ([#15274](https://github.com/Kilo-Org/kilocode/pull/15274) related work).

**For data science / ML workflows:** Create, activate, manage conda environments without leaving the agent.
