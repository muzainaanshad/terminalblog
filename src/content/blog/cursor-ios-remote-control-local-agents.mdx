You're at dinner. Your phone buzzes. It's not a text — it's your coding agent, running on your laptop at home, asking for clarification on a refactor. You tap a reply. The agent keeps working. You finish your meal.

**Cursor's October 6 update just made this real.** The new **Remote Control** feature lets you see and message your *local* agents from the Cursor iOS app. No cloud compute. Your code never leaves your machine. Your laptop just needs to stay on and online.

---

## What Remote Control Actually Does

**Launched October 6, 2026.** Available to everyone except Enterprise orgs (admins can enable it in Org Settings → Security and identity → Remote control).

### The Flow
1. **Install Cursor iOS app** and sign in
2. **Computers on your account appear automatically** — no pairing codes, no QR scans
3. **Tap your computer** → approve the pairing request in the desktop app
4. **Your local agents appear in a list** — tap one to see what it's doing or send it a message

### What You See
- **Agent status**: running, waiting for input, completed
- **Current task**: what the agent is working on right now
- **Live transcript**: the conversation so far
- **Send messages**: steer the agent, approve a diff, answer a question

### What You Don't Get (And Why That's Good)
- ❌ **No cloud execution** — agents run on *your* hardware
- ❌ **No code upload** — your codebase, secrets, build outputs stay local
- ❌ **No new billing** — uses your existing Cursor plan

**The trade-off**: Your computer must stay awake and online. Cursor added a **"Keep this computer awake"** setting (Desktop → Settings → Remote Control) — works when plugged in with lid open.

## Why This Matters More Than Cloud Agents

Cloud agents (Cursor Cloud, GitHub Copilot Workspace, AmpCode Orbs) are powerful. But they require:
- Uploading your codebase
- Trusting someone else's infrastructure
- Paying for compute you might already have

**Remote Control flips the model**: *You provide the compute. Cursor provides the remote interface.*

| Scenario | Cloud Agent | Remote Control |
|----------|-------------|----------------|
| **Code privacy** | Uploaded to vendor | Never leaves your machine |
| **Secrets/Env vars** | Must configure in cloud | Already in your local `.env` |
| **Build/test** | Runs in cloud sandbox | Runs on your actual machine |
| **Cost** | Per-minute/token billing | Your existing electricity bill |
| **Latency** | Network round-trip | Local execution, remote UI only |
| **Offline work** | Impossible | Agent keeps running; you reconnect later |

**For solo devs and small teams**: This is the first time you get "agent on the go" without the privacy/compliance trade-offs of cloud compute.

## FAQ

**Does Remote Control work with Cursor Cloud Agents too?**
No — it's specifically for *local* agents running on your machine. Cloud agents are already accessible from the web dashboard.

**Can I start a new agent from the iOS app?**
Not yet. You can only view and message *already-running* agents. Start them from desktop before you leave.

**What happens if my computer sleeps?**
The agent pauses. When the computer wakes, it resumes. Enable "Keep this computer awake" in Settings → Remote Control to prevent this (requires power + lid open).

**Is my code encrypted in transit?**
Yes — all communication goes through Cursor's encrypted relay. Your code never leaves your machine; only the agent transcript travels.

**Can I use this on iPad?**
Yes — the iOS app runs on iPadOS.

**Enterprise: why is it off by default?**
Compliance. Some orgs prohibit any external connection to developer machines. Admins enable it explicitly in Org Settings → Security and identity → Remote control.
