**Claude Code 2.1.310 dropped October 23** — and it's the release that finally plugs the observability hole in your agent stack.

**The headline:** The **Monitor tool** is now built in, with plugin monitors for **Bedrock, Vertex, and Foundry**. You can see what your agent is doing, what it's costing, and where it's stuck — without wiring up custom telemetry.

Plus: **Cloud Sessions** with Remote Control permissions, gateway request retry logic, 30+ bug fixes across sandbox, compaction, hooks, and Windows. This isn't a patch. It's a platform step.

## 1. The Monitor Tool — Observability That Ships In-Box

**What it is:** A new `Monitor` tool that streams structured events from your agent's execution. Plugins for **Bedrock, Vertex, and Foundry** ship with it — zero config to see model calls, token usage, tool invocations, and latency.

**Why it matters:** Before this, you had two choices: fly blind, or build custom OpenTelemetry wiring. Now you run:

```bash
claude --monitor-plugin bedrock
# or
claude --monitor-plugin vertex
# or
claude --monitor-plugin foundry
```

And you get: model calls, tokens in/out, tool calls with args/results, errors, latency percentiles. In your terminal. In your logs. In your dashboard.

**For beginners:** This is "how much did that cost?" and "why did that take 40 seconds?" answered automatically. No dashboards to build.

**For operators:** The plugin architecture means your enterprise logging stack (Splunk, Datadog, CloudWatch) can ingest this natively. The events are structured JSON — pipe them wherever.

---

## 2. Gateway Request Failures — Fixed at the Source

**The bug:** Requests failing behind certain gateways and compatible servers that reject the `effort-2025-11-24` beta value or mid-conversation system messages.

**The fix:** Claude Code now **retries without them automatically**. You don't see the failure. You don't retry manually. It just works.

This is the kind of fix that separates "works on my machine" from "works behind your corporate proxy." If you've ever had Claude Code stall or error on an enterprise network, **this is the release that stops it.**

---

## 3. Cloud Sessions + Remote Control = Enterprise Ready

**What's new:**
- **Cloud Sessions** now have **Remote Control permissions** in Enterprise custom roles — Owners control access by role
- **Choose file button** to load cloud environment setup scripts from a file
- **Failed saves/archives** now show errors *inside the dialog* (not just toasts)
- **Failed routine API token actions** surface errors in the edit dialog
- **Session start checklist** shows setup script output in a scrolling box
- **Turning on Cloud Sessions/Remote Control** asks for confirmation and lists affected custom roles

**Why it matters:** You can now run agents on GitHub repos in hosted sandboxes, with RBAC, audit trails, and setup-script versioning. This is the "run it while I sleep" workflow with enterprise guardrails.

## 4. Sandbox & Compaction Fixes That Save Your Work

| Fix | Why You Care |
|-----|--------------|
| Background cleanup no longer deletes recent pasted images when `cleanupPeriodDays` is huge | Your screenshots/diagrams survive cleanup |
| Compaction after "Prompt too long" no longer keeps dense text (base64, SVG) that causes repeat failures | No more compaction death spirals |
| File read permission prompts now show where symlinks lead | You know *exactly* what you're approving |
| Nested CLAUDE.md over size limit loads only its start | No more runaway context from massive nested instructions |
| Linux sandbox startup names Ubuntu's AppArmor restriction and how to lift it | Bubblewrap failures become solvable in 30 seconds |

---

## 5. Windows: The Hook Fix You've Been Waiting For

**The bug:** `PreToolUse` and `PermissionRequest` hooks **let tool calls through** when Git Bash is missing and the hook command is only quoted strings (like a quoted path).

**The fix:** Fixed. Hooks now block correctly on Windows even without Git Bash.

**Also fixed:**
- PowerShell permission checks no longer auto-approve `Set-Location`/`cd` to current directory with extra args
- Git commands run faster and show errors in English (regardless of git locale)
- `sed -i` gets standard Bash prompt, runs as written, not restored by `/rewind`
