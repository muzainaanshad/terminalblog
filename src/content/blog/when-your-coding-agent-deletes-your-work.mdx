I keep a terminal open to one of these agents most of the day. Today the feed showed me something that should worry anyone who does the same.

It started with a single Codex bug report, [#32347](https://github.com/openai/codex/issues/32347), filed about an hour ago. The user was running **GPT-5.6 Sol** in Codex Desktop (26.707.31428) on a workspace with several sessions open. When the model finished its task, every modified file snapped back to its previous state — not just in the active session, but in *every other session in the same workspace that had used GPT-5.6 Sol*. The reporter did the obvious thing: checked Git. No `git reset`, no `restore`, no `checkout`, no `revert`. The working directory had been rewound outside of Git entirely. The session logs still held the edits, so they spent nearly **15 hours** hand-restoring files from the transcript. They couldn't reproduce it, and they were careful to say so — but they were equally clear it happened only with GPT-5.6 Sol, never the other models they'd used in the same workspace.

One report is an anecdote. Three in the same three hours is a pattern.

The same window surfaced a Claude Code regression, [#76604](https://github.com/anthropics/claude-code/issues/76604), labeled `data-loss` and `regression`. Since the Chat/Cowork merge rolled out on 8–9 July, the reporter says every project created in Cowork vanishes within roughly 24 hours, reproducibly, while chat-created projects survive. Connector tools silently never load in Cowork sessions. The bot flagged it as a likely duplicate of #75603, #75625, and #76344 — all post-merge Cowork breakage. So this isn't one unlucky account; it's a cluster. The reporter also noted they'd escalated through official support five times with no human response. That's the part that stings: when the agent eats your work, the humans are slow to pick up the phone.

Then there's Hermes [#62490](https://github.com/NousResearch/hermes-agent/issues/62490): the desktop Composer draft leaks across new sessions, and the first Enter after a recent fix is silently ignored. Smaller, labeled P2, `sweeper:risk-session-state` — but it's the same shape. The agent is touching state you didn't explicitly hand it.

The common thread isn't "AI is unreliable." It's that these tools are reaching past the single edit you asked for and mutating the wider session, workspace, or project without a clear undo. Git was supposed to be our safety net. When the revert happens *outside* Git, the net has a hole exactly where we assumed it was strongest.

My take: treat every agent session as something that can rewrite your tree faster than you can `git stash`. Branch before you prompt. Commit early and often, even when "it's just a draft." And if a tool tells you it finished, verify the working directory before you walk away — don't trust the transcript to match the disk. The agents are getting more capable. They're also getting more confident about changes you never asked them to make.
