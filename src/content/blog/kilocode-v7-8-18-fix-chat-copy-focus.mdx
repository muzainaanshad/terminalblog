## The Bug That Made You Swear: Chat Copy Fixed

**What happened:** VS Code 1.143 introduced a regression where copying text from the chat panel (Cmd/Ctrl+C or right-click → Copy) would:
1. Clear your selection immediately
2. Jump focus to the prompt input
3. Make you lose your place in the conversation

**What KiloCode v7.8.18 does:** Fixed in [#15472](https://github.com/Kilo-Org/kilocode/pull/15472). The selection **stays selected**, focus **stays where it is**, and copy **just works**.

```bash
# Before v7.8.18 (VS Code 1.143):
# Select text → Cmd+C → selection gone, focus in prompt → 😤

# After v7.8.18:
# Select text → Cmd+C → selection stays, focus stays → ✓
```

**For beginners:** This is the kind of paper cut that makes you question your tools. It's fixed. Update and copy away.

## Security Updates You Didn't Ask For But Need

### DOMPurify 3.4.17 — Sanitization Fixes

[#15410](https://github.com/Kilo-Org/kilocode/pull/15410) updates DOMPurify to 3.4.17, addressing sanitization issues flagged by Dependabot alerts. If you render any untrusted HTML in the chat/webview, this matters.

### Vite 7.3.7 — CVE-2026-112944 Fixed

[#15412](https://github.com/Kilo-Org/kilocode/pull/15412) updates Vite to 7.3.7, fixing the `launch-editor` CLI flag misinterpretation vulnerability (CVE-2026-112944 / GHSA-r825-w8mm-5pxw). This could allow path traversal in certain dev server configurations.

### MCP TypeScript SDK 1.32.1 — OAuth Redirect Blocking

[#15430](https://github.com/Kilo-Org/kilocode/pull/15430) updates the MCP SDK to 1.32.1, fixing security issues including **MCP HTTP and OAuth requests following cross-origin redirects**.

```bash
# What this blocks:
# - MCP server URL redirects to another origin
# - POST responses with 301, 302, 303 redirects
# - Remote MCP servers that try to bounce your auth flow

# What you should do:
# Use the server's final URL directly (no redirects)
```

This is the same class of fix Claude Code, OpenCode, and Hermes Agent have shipped recently. **MCP OAuth redirects are an attack vector.** KiloCode now refuses them.

## Cloud Sessions Exposed Locally (Big for Plugin Authors)

### What's New

[#15358](https://github.com/Kilo-Org/kilocode/pull/15358) exposes **hosted cloud sessions through the local Kilo API**. Editors can now discover, read, and interact with a hosted session **without ever handling its provider credentials**.

```bash
# Before: You needed cloud provider credentials to manage cloud sessions
# Now: Local API lists/reads/starts cloud sessions → credentials stay with Kilo backend
```

### Why This Matters

- **Security:** Your cloud provider tokens (AWS, GCP, Azure, etc.) never touch the editor process
- **Plugin authors:** Build cloud session UIs without credential management
- **Teams:** Centralized cloud session control, distributed local access

This is the foundation for the Kilo Cloud provider added in v7.8.17 — now actually usable from local tooling.
