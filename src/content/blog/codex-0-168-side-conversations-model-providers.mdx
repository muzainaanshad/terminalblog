**Codex v0.168.0 landed November 13, 2026** — same day as v0.169.0, but this one's the quiet workhorse. The headline: **opt-in side conversation panes** in the TUI (enable `features.tui_workspace`), **model provider browsing and selection** in the config panel, **audio recording support** for voice-capable models, **animated GIF generation**, and **OSC 777 terminal notifications**.

If v0.167 gave you the Command Center, v0.168 gives you a **multi-context terminal workspace**.

## The One-Line Summary

**Codex 0.168.0 (Nov 13) → Side conversation panes in TUI (drag divider, zoom with leader z), browse/switch model providers in config panel, audio recordings with rejection recovery, animated GIF generation, tmux image previews, OSC 777 notifications. Run `cargo install codex --version 0.168.0` or re-run installer.**

## Feature 1: Side Conversation Panes — Your Multi-Context Workspace

**What it is:** Enable `features.tui_workspace` and get a **resizable side pane** beside your main chat. Drag the divider to resize. Press `leader z` to zoom the focused pane. Each pane = independent conversation context.

```bash
# In Codex TUI config:
# Enable: features.tui_workspace = true
# Then: restart Codex
# Open side pane: leader s (or menu)
# Resize: drag divider or leader + arrow keys
# Zoom focused pane: leader z
```

**Why it matters:** Before 0.168, you had *one* conversation. Working on a frontend bug and a backend refactor meant: finish one → clear context → start the other. Now: **main pane = frontend, side pane = backend**. Switch with a keystroke. Context preserved in both.

**For beginners:** Think of it like a split terminal (`tmux` split) but each side is a full Codex conversation with its own history, files, and context. You're not "losing your place" — you're working in parallel.

---

## Feature 2: Model Provider Browsing in the TUI Config Panel

**What it is:** Under **Sessions → Model providers** in the TUI config panel, you can now:
- **Browse available providers** (OpenAI, Anthropic, Google, Azure, Bedrock, GCP Vertex AI, custom gateways)
- **Choose the default provider for new chats**
- **Create custom gateways** with your own endpoints
- **Update gateway, Bedrock, and GCP settings** inline

**Why it matters:** Previously, provider setup meant editing config files or using CLI flags. Now it's **discoverable in the UI**. New users see what's available. Power users switch providers without leaving the TUI.

**For beginners:** If you've ever wondered "which models can I actually use?" — open the config panel, go to Model providers, and *see the list*. No more guessing.

---

## Feature 3: Audio Recording Support (Voice-Capable Models)

**What it is:** Attach audio recordings when using models that support audio input. Codex:
- **Skips confirmed rejected recordings** on later turns (no re-sending what you already said "no" to)
- **Uses clip duration** to keep more short recordings in context
- **Durable rejection recovery** — if a recording was rejected, Codex remembers and doesn't retry it

```bash
# In TUI with audio-capable model:
# 1. Press record shortcut (or menu)
# 2. Speak your prompt
# 3. Recording attaches to composer
# 4. Send → model hears your voice
```

**Why it matters:** Voice coding isn't a gimmick — it's faster for "explain this function" or "write a test for the auth flow." The rejection recovery means you don't get duplicate audio in context when you retry.

---

## Feature 4: Animated GIF Generation

**What it is:** Enable `features.image_generation_animation` to generate or edit **animated GIFs** with optional frame count and timing controls.

```bash
# In TUI config:
features.image_generation_animation = true

# Then in chat:
"Generate a loading spinner GIF: 8 frames, 100ms per frame, blue pulse"
```

**Why it matters:** Quick UI prototypes, loading states, micro-interaction demos — generated in chat, no Figma/After Effects roundtrip.

---

## Feature 5: Fullscreen Image Previews in tmux (Ghostty/Kitty)

**What it is:** Fullscreen Codex now displays **image previews and pets** (the little Codex mascots) in tmux on Ghostty and Kitty with `allow-passthrough all`.

**Why it matters:** If you live in tmux + Ghostty/Kitty, images *just work* in fullscreen. No more "open in browser" to see a diagram.

---

## Feature 6: OSC 777 Terminal Notifications

**What it is:** Set `tui.notification_method = "osc777"` for **terminal-native notifications**. Approval notifications show:
- **Longer command previews** (see what's actually running)
- **Distinction between terminal input vs network access requests**

```bash
# In Codex config:
tui.notification_method = "osc777"

# Requires terminal supporting OSC 777 (Ghostty, Kitty, WezTerm, iTerm2)
```

**Why it matters:** No more guessing "what did I just approve?" — the notification tells you *exactly* what's waiting.
