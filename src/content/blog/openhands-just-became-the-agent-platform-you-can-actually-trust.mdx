**OpenHands v1.40.0 dropped November 12, 2026** — just 24 hours after v1.39.0. That's not a typo. Two substantial releases in 48 hours from a project that used to ship monthly. If you've been watching OpenHands from the sidelines wondering when it would feel *done*, this might be the moment.

---

## The One-Line Summary

**v1.40.0 (Nov 12) → Codex subscription auth guidance, chat echo/deletion fixes, Git real-default-branch detection, Indonesian i18n. v1.39.0 (Nov 11) → Service accounts filter for automations, Paper theme aged-newsprint styling, chat hover timestamps, Stop-hook feedback isolation, verification server mapping. 40+ bug fixes across both. Zero breaking changes.**

---

## Why This Feels Different

OpenHands has always been *capable* — Docker runtime per conversation, Agent Canvas with persistent memory, ACP support, verification skills. But "capable" and "trustworthy" are different things.

The last two releases fix the paper cuts that made you hesitate to recommend it to a junior dev:

- **Chat echoes that deleted your newer drafts** → Fixed (v1.39.0, [#19382](https://github.com/OpenHands/OpenHands/pull/19382))
- **Messages at tied history page boundaries getting lost** → Fixed (v1.40.0, [#19649](https://github.com/OpenHands/OpenHands/pull/19649))
- **Git assuming `main` when your repo uses `master` (or `trunk`, or `development`)** → Fixed: now uses the repository's *real* default branch ([#19604](https://github.com/OpenHands/OpenHands/pull/19604))
- **Codex subscription auth — the "how do I even log in?" problem** → Now has guided setup ([#17194](https://github.com/OpenHands/OpenHands/pull/17194))

These aren't headline features. They're the difference between "it works on my machine" and "I'd put my team on this."

## v1.40.0 (November 12) — The Polish Release

### Codex Subscription: Finally, Clear Guidance

If you've tried using Codex with OpenHands, you know the friction: API keys, subscription vs API, which endpoint, why is it 401ing?

v1.40.0 adds **authentication guidance built into the UI** — the first time OpenHands has treated a commercial provider's auth flow as a first-class setup concern rather than "read the docs." ([#17194](https://github.com/OpenHands/OpenHands/pull/17194))

### Chat That Doesn't Eat Your Work

Two chat bugs that have bitten everyone running long sessions:

1. **Delayed echoes deleting newer drafts** — You send a message, network hiccups, you send again, and suddenly your *second* message vanishes because the first one's delayed response arrived late and overwrote it. Fixed. ([#19382](https://github.com/OpenHands/OpenHands/pull/19382))

2. **Messages at tied history page boundaries** — Pagination edge case where messages exactly at the boundary between pages could disappear from view. Fixed. ([#19649](https://github.com/OpenHands/OpenHands/pull/19649))

### Git That Respects Your Repo

```bash
# Before: OpenHands assumed 'main'
# After: OpenHands detects your actual default branch
```

Whether your default is `main`, `master`, `trunk`, `develop`, or something custom — OpenHands now queries the remote and uses *that*. No more failed PRs because it pushed to the wrong branch. ([#19604](https://github.com/OpenHands/OpenHands/pull/19604))

### Indonesian Translations for Codex Keys

Small but telling: the team added missing Indonesian translations for Codex subscription strings ([#19685](https://github.com/OpenHands/OpenHands/pull/19685)). Internationalization isn't glamorous, but it signals a project thinking beyond English-first users.

## v1.39.0 (November 11) — The Platform Release

### Service Accounts Filter for Automations Dashboard

If you run OpenHands at team scale, automations are where the leverage lives. v1.39.0 adds a **Service Accounts filter** to the automations dashboard — you can now scope dashboard views to specific service accounts, including a "Service Accounts" option in the owner dropdown. ([#19472](https://github.com/OpenHands/OpenHands/pull/19472))

This is the kind of feature that only matters when you have *many* automations running — exactly the inflection point where OpenHands becomes infrastructure instead of a toy.

### Paper Theme: Aged Newsprint Styling

The Paper theme now renders as **aged newsprint** with readable warnings — a deliberate design choice that makes long agent sessions feel less like a terminal dump and more like a document you'd actually want to read. ([#19595](https://github.com/OpenHands/OpenHands/pull/19595))

### Chat Hover Timestamps Moved Closer

Micro-UX win: message hover timestamps now sit closer to their message instead of floating in no-man's-land. ([#19623](https://github.com/OpenHands/OpenHands/pull/19623))

### Stop Hook Feedback Isolation

Stop hook feedback no longer pollutes the chat — it's kept separate so your conversation stays readable. ([#19619](https://github.com/OpenHands/OpenHands/pull/19619))

### Verification Server: Canvas Families Linked to Agent Server Features

The `verify-openhands` server now maps Canvas families to Agent Server features — making it easier to verify that your agent setup actually supports what you're trying to do. ([#18568](https://github.com/OpenHands/OpenHands/pull/18568))

## 40+ Bug Fixes You'll Never Notice (And That's the Point)

Both releases are padded with dependency bumps, dependency-dev bumps, electron bumps, mermaid bumps, tanstack bumps, posthog bumps, lucide-react bumps, react-icons bumps, ws bumps, mdast bumps, eslint bumps, electron-builder bumps, unist-util-visit bumps, @heroui bumps, @shadcn/lint bumps, docker/login-action bumps, i18next bumps, microlink bumps, tanstack bumps...

You get the idea. The changelog is 80% "chore(deps): bump X from Y to Z."

But here's why that matters: **OpenHands is a complex Electron + React + TypeScript + Docker + WebSocket + LLM integration stack.** Every dependency bump is a potential regression. Shipping 40+ fixes across two releases without breaking changes means the test infrastructure is holding.
