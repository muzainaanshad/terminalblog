## 1. One Canvas, Every Agent (The ACP Breakthrough)

**Before v1.27:** OpenHands Canvas ran OpenHands agent. Want Claude Code? Different tool. Want Codex? Different tool. Want to compare them? Open three terminals.

**Now:** Canvas speaks **ACP (Agent Client Protocol)** natively. During onboarding — or anytime in Settings — you pick your agent:

```
Choose your agent:
├── OpenHands (built-in)
├── Claude Code (ACP)
├── Codex (ACP)
├── Gemini CLI (ACP)
├── Pi (ACP) ← NEW
└── OpenCode (ACP) ← NEW
```

**Pi** runs via `npx -y --package=pi-acp --package=@earendil-works/pi-coding-agent pi-acp`
**OpenCode** runs via `npx -y opencode-ai acp`

Both download on first use. Both work on **local backends only** (your machine or self-hosted Agent Server). Neither is pre-baked in the Docker image — Canvas fetches them lazily.

### Why This Changes Everything

You're debugging a gnarly refactor. You spin up **OpenHands** for the architecture view. It suggests a pattern. You switch to **Pi** — it writes the implementation in a single pass. You verify with **Codex** — it catches the edge case OpenHands missed. **All in one Canvas. Same workspace. Same context.**

No context switching. No "which tool has the right model?" You have **all the tools, all the models, one control plane.**

## 2. DigitalOcean Managed Agents: Cloud Sandboxes That Pause

**New Providers tab in Add Backend → DigitalOcean Managed Agents.**

Sign in with a `doctl` personal access token. Create or open an OpenHands agent. Every session launches in an **isolated DigitalOcean sandbox** with its own disk and conversation history.

### The Magic: Pause on Idle, Resume Anywhere

- Agent working on a 3-hour migration → you close laptop → **sandbox pauses, billing stops**
- Next morning on your iPad → open Canvas → **resume exactly where it left off**
- Different device, different network, **same agent, same files, same mind**

```bash
# One-time setup
doctl auth init

# Launch from Canvas → or CLI:
doctl harness-runtime launch --harness opencode --name my-agent
# Drops you straight into chat. Ctrl-D detaches. Reattach anytime.
```

**For teams:** No more "who's running the long task on their laptop?" The cloud sandbox *is* the agent's home. Your laptop is just a window.

## 3. verify-openhands Gets Eyes: Browser Recording

The verification skill (introduced in v1.26) now **records video** of browser interactions:

```bash
control-openhands verify --once --record-video
# Produces: verification-run-2026-10-14.mp4
```

**What you see:** Real browser footage of the agent clicking, typing, navigating, asserting. When a behavior fails, you *watch* the failure — no log spelunking.

**Why it matters:** "It works on my machine" becomes "here's the video of it working on *every* machine." CI/CD for your agent platform's own behaviors, now with receipts.

---

## 4. Automation Setup: From "Fighting Forms" to "Guided Flow"

Automations (Canvas's workflow engine) got a complete UX overhaul:

- **Split-panel setup** — form on left, live preview on right
- **Draft persistence** — close the tab, come back tomorrow, your half-built automation waits
- **Guided flow** — step-by-step instead of one massive form
- **Template parity** — cloud backends now show the same templates as local

**Before:** "Which field goes where? Why did it error? Let me start over."

**Now:** You build. It shows. It saves. It works.

---

## 5. ACP Model Lists: Agents Tell You What They Support

**Old way:** Canvas hardcoded model tables for each ACP agent. New model drops → wait for OpenHands release → update → model appears.

**New way:** `feat(acp): take ACP model lists from the agent instead of hardcoding them`

Canvas asks the agent: "What models do you support?" Agent replies. Canvas shows them. **Zero lag.** New model in Pi? Shows up next Canvas refresh. New model in OpenCode? Same.

This is what "protocol-native" means: the *agent* owns its capabilities. The *platform* just displays them.
