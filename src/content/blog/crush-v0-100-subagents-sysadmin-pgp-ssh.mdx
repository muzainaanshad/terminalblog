## The Headline Feature: Subagents — Your Agent Just Hired a Team

### The Problem: One Agent, One Thread, One Thing at a Time

Before v0.100, Crush was single-threaded. You asked it to refactor the auth module — it did that. You wanted parallel work (tests + docs + migration)? You ran multiple Crush instances. Context didn't share. You managed the coordination.

### The Fix: Subagents That Work While You Watch

**New in v0.100:** Crush can now spawn **background subagents** — little teammates that run independently, report back, and take follow-ups.

```bash
# In Crush:
# 1. Start a task that needs parallel work
"Refactor the payment service: write tests, update docs, create migration"

# 2. Crush spawns subagents for each track
# Subagent 1: Writing tests for payment service
# Subagent 2: Updating API documentation  
# Subagent 3: Creating database migration

# 3. You see live status in the main chat
# ████████░░ Subagent 1 (tests) - running
# ████░░░░░░ Subagent 2 (docs) - waiting for your input
# ██████████ Subagent 3 (migration) - done

# 4. Intervene mid-run
> @subagent-2 "Use OpenAPI 3.1 spec format, not 3.0"
# Subagent 2 adjusts and continues

# 5. Stop or reassign
> @subagent-1 stop
> @subagent-1 reassign-model gpt-6-astra
```

**What you can do with subagents:**
- **Spawn** — delegate a subtask to a background agent
- **Monitor** — see live progress bars in main chat
- **Follow-up** — send mid-run corrections (`@subagent-2 "use TypeScript strict mode"`)
- **Stop** — kill a subagent that went off track
- **Reassign model** — swap the model mid-run (cheap model for grunt work, smart model for architecture)

**Why this changes everything:** You're no longer the typist. You're the **tech lead**. You delegate, review, redirect. The agent handles the parallel execution.

## Feature 2: Sysadmin Mode — Permissions That Make Sense for Servers

### The Problem: Coding Permissions ≠ Server Permissions

Standard agent permissions: "read file," "write file," "run command." Great for code. Terrible for servers where you need: "read /etc/nginx," "restart systemd service," "tail journalctl," "edit sudoers" — each with different risk profiles.

### The Fix: Sysadmin Mode with Granular Permissions

**New:** `--sysadmin` flag (or toggle in settings) enables a **permission profile built for infrastructure work**.

```bash
# Enable sysadmin mode
crush --sysadmin

# Or in chat:
/sysadmin on
```

**Permission tiers:**

| Tier | What It Allows | Prompt Style |
|------|----------------|--------------|
| **Read-only** | `cat`, `grep`, `journalctl`, `systemctl status` | Auto-allow (configurable) |
| **Safe write** | Config files in `/etc`, user crontabs, `.env` files | Single prompt, remember choice |
| **Service control** | `systemctl restart`, `service nginx reload` | Per-command prompt |
| **Privileged** | `sudo`, `/etc/sudoers`, kernel params | Always prompt, audit logged |

**Real example:**
```bash
You: "Nginx is serving 502s. Diagnose and fix."
Crush: 
  1. [Read-only] journalctl -u nginx --since "10 min ago" → auto-runs
  2. [Read-only] cat /etc/nginx/sites-enabled/default → auto-runs
  3. [Safe write] Edit nginx config to fix upstream → prompts once
  4. [Service control] systemctl reload nginx → prompts
  5. [Read-only] curl localhost/health → auto-runs, confirms fix
```

**For beginners:** You don't need to know `systemctl` flags. You say "fix nginx." Crush asks for the right permissions at the right level. You learn the commands by watching.

## Feature 3: PGP/SSH Auth Prompts — Keys Stay in Your Agent

### The Problem: Signing Commits or SSHing Meant Leaving the Terminal

You're in Crush, agent writes code, you want to `git commit -S` (signed) or `ssh prod-server`. Before: exit agent, run command, come back. Context lost.

### The Fix: PGP and SSH Prompts Inside Crush

**New:** When a subagent or main agent needs to sign or SSH, **Crush prompts you in-chat**.

```bash
# Agent needs to sign a commit
Crush: "Commit ready. Sign with your PGP key? [Allow once / Allow session / Deny]"
You: "Allow session"
# Agent runs: git commit -S -m "feat: payment refactor"
# Your key stays in gpg-agent — Crush never sees the private key

# Agent needs to deploy via SSH
Crush: "Deploy to prod? SSH to deploy@prod.example.com [Allow once / Allow session / Deny]"
You: "Allow once"
# Agent runs: ssh deploy@prod.example.com "systemctl restart payment-api"
```

**Security model:**
- Private keys **never leave** your `gpg-agent` / `ssh-agent`
- Crush only requests the **operation** (sign this hash, auth to this host)
- You control duration: once / session / never
- Audit trail in chat: every signed commit, every SSH command visible


```
v0.99        → Hooks everywhere, Catwalk v3, editor integration
```
