I've used eight coding agents this month. All of them can write code. Most of them can refactor, debug, and deploy. None of them can answer this question:

> "What should I build next?"

## The Gap

Coding agents are reactive. You tell them what to do, they do it. They're excellent executors. They're terrible strategists.

An agent that looks at your codebase and says "you have 47 TODO comments scattered across 12 files, there are 3 functions duplicated in different modules, and your test coverage dropped 5% this week" — that agent doesn't exist yet.

But the data is all there. Every agent reads the full codebase. They just don't analyze it holistically.

## What's Possible Today

A codebase-aware agent could ship these capabilities without any new AI breakthroughs:

- **Identify dead code** — functions that are never called, exports that are never imported, routes that have no handlers
- **Find duplication** — similar logic implemented in multiple places (even across different files)
- **Surface technical debt** — TODO/FIXME counts, cyclomatic complexity trends, dependency freshness, security advisories
- **Suggest high-impact improvements** — "this module is getting large, consider splitting it" or "your API latency increased 40% after this change"
- **Detect architectural drift** — modules that violate layer boundaries, circular dependencies creeping in
- **Track test health** — flaky tests, coverage gaps in recently changed code, slow test suites

None of this requires new AI capability. It requires the agent to analyze the codebase systematically and produce insights, not just execute tasks.

## What Agents *Actually* Do Today

Let's be concrete. Here's what happens when you ask current agents for strategic input:

| Request | Claude Code | Cursor | Codex | OpenCode |
|---------|-------------|--------|-------|----------|
| "What's the biggest tech debt in this repo?" | Lists files you recently touched | Summarizes recent commits | Runs grep for TODO | Needs a skill |
| "Which modules should I refactor?" | Guesses based on file size | Shows git churn | No opinion | Needs a skill |
| "Is my test coverage adequate?" | Runs coverage if you ask | Shows coverage badge | Runs if configured | Needs a skill |

They all default to **execution mode**. You have to explicitly ask for analysis, and even then they treat it as a one-off task — not a continuous capability.

## Why Nobody Has Built This Natively

The commercial agents don't have incentives for this feature. It doesn't help you write code faster today. It doesn't close a ticket. It doesn't deploy a feature. It's invisible work that pays off slowly — exactly the kind of work that's hardest to sell.

The open-source agents could build this, but they're focused on matching the commercial agents on core capabilities (edit, run, test, search). Strategic analysis is a differentiator, not a core feature.

## The Workaround: Build It Yourself

You *can* get this today — but you have to build it. Here's how different tools approach it:

**Hermes** comes closest with its skill system. You write a skill that runs on a cron, analyzes your codebase, and reports back. Example skill concept:

```yaml
# skills/codebase-health.yml
name: codebase-health
schedule: "0 6 * * 1"  # Weekly Monday 6am
steps:
  - name: analyze
    tool: bash
    args: |
      # Count TODOs
      rg "TODO|FIXME" --type js --type ts | wc -l
      # Find duplicate functions (simplified)
      ast-grep -p "function $NAME($$$)" --lang javascript
  - name: report
    tool: notify
    args: "Weekly codebase health report ready"
```

**Claude Code** can do this via hooks + custom commands, but it's manual setup per project.

**Cursor** has no native scheduling — you'd need an external cron calling its API.

**OpenCode** is the most extensible — its plugin system could support this natively, but no plugin exists yet.

## What a Native Feature Would Look Like

If an agent shipped this as a one-click feature, the UX would be:

```
> agent health --full

📊 Codebase Health Report — my-project
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔴 Critical: 3 security advisories in deps
🟡 Warning: 12% test coverage drop in auth/
🟡 Warning: Circular dependency: payments ↔ billing
🟢 Info: 23 TODO comments (up 5 from last week)
🟢 Info: 4 duplicate functions in utils/
🟢 Suggestion: Split user-service.ts (847 lines)
🟢 Suggestion: Add integration tests for checkout flow

Top 3 actions this week:
1. Update lodash (CVE-2026-xxxxx)
2. Break circular dependency in payments
3. Add tests for auth middleware
```

This is **not technically hard**. Static analysis tools (SonarQube, CodeClimate, ast-grep, semgrep) already do 90% of this. The missing piece is integration into the agent's daily workflow.

## The Competitive Opportunity

The first agent that makes "codebase health report" a **core, zero-config feature** wins a segment nobody is competing for:

- Every developer needs it
- No agent has it built-in
- It creates daily/weekly engagement (not just when you have a task)
- It positions the agent as a *partner*, not a tool

Hermes could ship this tomorrow via a built-in skill. OpenCode could ship it via a plugin. Claude Code could ship it via a default hook. The moat isn't technology — it's product decision.
