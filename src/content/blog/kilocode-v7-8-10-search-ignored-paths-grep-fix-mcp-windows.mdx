## 1. Search Ignored Paths: Your Glob Results Just Got Usable

**The problem:** You search for `useAuth` and get 200 matches from `node_modules/.pnpm/...`, `dist/`, `.next/`, `build/` — drowning out your actual code.

**The fix:** New **experimental "Search Ignored Paths" setting** (VS Code & CLI). Add folders/files to ignore during glob/grep — *but* the agent can still search inside them when explicitly asked.

```json
// settings.json
"kilocode.search.ignoredPaths": [
  "node_modules",
  "dist",
  "build",
  ".next",
  "coverage",
  "*.log"
]
```

**Before:** Search = noise. You mentally filter every time.
**Now:** Search = your code. The junk stays hidden unless you *want* it.

**Why beginners love this:** You stop learning to "search around the noise." You just search. The tool does the filtering.

---

## 2. grep Finally Handles Legacy Encodings

**The problem:** Your codebase has a few ISO-8859-1 or Windows-1252 files (old Windows projects, generated files, vendor code). `grep` throws **"Invalid ripgrep match output"** and fails the whole search.

**The fix:** v7.8.10 catches non-UTF-8 matches and handles them gracefully. The search completes. You get results. No more crashes.

```bash
# This used to crash on mixed-encoding repos
# Now it just works
kilocode grep "TODO" --include="*.txt"
```

**Why it matters:** Real-world repos aren't clean UTF-8. This fix removes a silent "works on my machine" failure mode.

---

## 3. Mobile: Fork a Session from Any Message

**New CLI capability:** `create_session` now accepts `cloneUpToMessageId`.

```bash
# Fork from a specific message — only transcript up to that point
# Only file edits made BEFORE that message are restored
kilocode create_session --clone-up-to-message-id msg_abc123
```

**Use case:** You're on mobile, reviewing a 50-turn session. The agent went off-track at message 37. Fork from message 36, steer it right, continue on your laptop.

**Why it's clever:** You don't clone the *entire* history. You clone *up to the decision point*. Clean slate, relevant context.

---

## 4. MCP Sign-In Stops Resetting Itself

**The bug:** Automatic OAuth recovery would **clear stored credentials** that another session just refreshed. Signing into a remote MCP server only updated the auth warning in *one* session — others stayed stuck on "sign in required."

**The fix (two parts):**
1. OAuth recovery no longer stomps on credentials another session just saved
2. Sign-in now **syncs the authentication warning across ALL open sessions**
3. Optional MCP stream probe restricted to its own endpoint — can't rewrite OAuth metadata/token responses

**Result:** You sign in once. Every session knows. No more "wait, I just signed in" loops.

---

## 5. Windows: Background Jobs That Don't Hog CPU or Refuse to Die

**Two fixes from @mardausdennis:**

| Issue | Before | After |
|-------|--------|-------|
| CPU usage during background jobs | High | **Reduced** |
| Job stops when command finishes | Sometimes stayed active, treated unrelated programs as part of job | **Stops cleanly** |
| Job won't stop safely | Silent hang | **Fails with error explaining why** |

**In practice:** You run a long build in the background. It finishes. The job *actually stops*. Your CPU drops. If it *can't* stop safely, you get an error message telling you why — not a silent zombie process.
