Oh My Pi **v18.4.3** dropped September 29 — the third release in two days (v18.4.1 Sep 28, v18.4.2 Sep 28, v18.4.3 Sep 29). While other agents batch features into monthly drops, Oh My Pi ships control-plane upgrades within 24 hours.

The headline this wave: **speculative execution that actually preserves your tool calls.**

## 1. `transformAssistantMessagePreservesToolCalls` — Speculation Without the Corruption

This is the architectural fix that makes speculative execution *usable* instead of *theoretical*.

**The problem:** When an agent speculates (starts generating before the full context is ready), the streaming layer would rewrite tool calls in the assistant message. That meant your carefully crafted function calls got mangled mid-stream — breaking the very thing speculation was supposed to accelerate.

**The fix:** `transformAssistantMessagePreservesToolCalls` lets stream speculation and direct speculative candidates run under a `transformAssistantMessage` that **never rewrites streamed tool calls**.

**Why beginners care:** Your agent thinks faster *and* its tool calls arrive intact. No more "the agent started writing code but the function call got corrupted."

## 2. `authorizeLaunch` — Speculative Execution Host Gets a Gate

The speculative execution host now has `authorizeLaunch` — a gate that controls when speculative candidates are allowed to spawn. This prevents runaway speculation from consuming resources on tasks that don't benefit from it.

**Practical impact:** Speculation fires when it helps (complex multi-step tasks), stays quiet when it doesn't (simple Q&A). Your token budget thanks you.

## 3. Tool Execution End Events — Live UI That's Actually Live

v18.4.2 added `tool_execution_end` events that fire as each tool call settles. This means your UI updates *as tools complete*, not in batches.

- Emitted tool result messages in the order of tool calls, preserving call order regardless of completion order
- Reduced repeated token-counting work with a shared cache

For you: the agent's progress bar, token counter, and tool timeline all update in real time — not after the fact.

## 4. Fitted Output Caps Fixed — No More 400s on Strict Hosts

v18.4.1 fixed a subtle but painful bug: fitted output caps were overshooting the context window by a few tokens on strict Chat Completions hosts (e.g., llama.cpp), causing 400 errors. Also fixed native remote compaction sending requests already estimated past the model's context window.

**Translation:** Local models (Ollama, llama.cpp, LM Studio) stop erroring out on long contexts. The agent compacts *before* it hits the limit.
