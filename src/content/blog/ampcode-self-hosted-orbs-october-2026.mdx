## What Are Orbs Again?

Orbs are Amp's **remote agent environments**. Spin one up → it clones your repo → runs setup → agent starts working. You get a clean, isolated Linux box with your codebase loaded.

Previously: Amp hosted them. You paid per orb-hour.

Now: **You host them. Amp just sends `spawn` / `pause` / `delete` events.**

---

## How It Works (Surprisingly Simple)

You run **one command** inside your infrastructure:

```bash
amp orb provider ./dispatch.sh
```

That's it. The `orb provider` connects to Amp, waits for events, and your `dispatch.sh` handles the actual infrastructure calls.

**Amp sends three operations:**
| Operation | What Your Script Does |
|-----------|----------------------|
| `spawn` | Create/resume an orb (start container, create sandbox, etc.) |
| `pause` | Suspend it (stop container, snapshot filesystem) |
| `delete` | Destroy it (rm container, clean up) |

**Your `dispatch.sh` decides HOW.** Docker? Kubernetes? Modal? Vercel Sandboxes? Daytona? E2B? Apple containers? exe.dev? Amp ships examples for all of them.

---

## The Dispatch Script Pattern

Every provider follows the same interface:

```bash
#!/usr/bin/env bash
# dispatch.sh
set -euo pipefail

case "$ORB_OPERATION" in
    spawn)
        # Your infrastructure: start/create the machine
        # Then: docker exec -d --env ORB_TOKEN "$ORB_ID" amp orb bootstrap
        ;;
    pause)
        # Your infrastructure: suspend the machine
        ;;
    delete)
        # Your infrastructure: destroy the machine
        ;;
esac
```

Environment variables Amp passes:
- `ORB_OPERATION` — `spawn` / `pause` / `delete`
- `ORB_ID` — unique orb identifier
- `ORB_TOKEN` — auth token for the orb to call back to Amp
- `ORB_IMAGE` — Amp's pre-built orb image (or your custom one)
- `AMP_URL` — optional, your Amp gateway URL

## Kubernetes: The Enterprise Path

For teams on GKE/EKS/AKS, Amp provides a **Helm chart** that handles everything:

1. Create a Custom Orb Provider in workspace settings → copy token
2. Prep a cluster with worker nodes + snapshot storage (for pause/resume)
3. Download the [Kubernetes bundle](https://ampcode.com/docs/orbs/self-hosted/bundle.zip) — includes Terraform + Helm for each cloud
4. Install chart, test first orb

Paused orbs save to snapshot storage and can resume on *different* worker nodes. True cloud-native elasticity.

## Quick Start: Docker on Your Machine (5 Minutes)

```bash
# 1. Create a workspace at ampcode.com (free)
# 2. Settings → Custom Orb Provider → Create → Copy token

# 3. Save this as dispatch.sh
cat > dispatch.sh << 'EOF'
#!/usr/bin/env bash
set -euo pipefail
case "$ORB_OPERATION" in
    spawn)
        docker start "$ORB_ID" 2>/dev/null || \
            docker run --platform linux/amd64 -d --name "$ORB_ID" \
                "$ORB_IMAGE" sleep infinity
        docker exec -d --env ORB_TOKEN "$ORB_ID" amp orb bootstrap
        ;;
    pause)
        docker stop "$ORB_ID"
        ;;
    delete)
        docker rm -f "$ORB_ID"
        ;;
esac
EOF
chmod +x dispatch.sh

# 4. Run the provider
export AMP_ORB_PROVIDER_TOKEN="<your-token>"
amp orb provider ./dispatch.sh

# 5. New thread → Orb → Self-Hosted → your provider → prompt
```

That's it. Your laptop (or server) is now an Amp compute node.

## The Catch (Honest)

- **Not for beginners** — you need infra knowledge (Docker/K8s/Modal/etc.)
- **No managed SLAs** — Amp supports *their* end; your dispatch script is yours
- **Pause/resume requires snapshot-capable infra** — Docker stop/start works; K8s needs PVC; Modal/Vercel/Daytona/E2B have native snapshots
- **Enterprise support only for Enterprise plans** — community on Discord
