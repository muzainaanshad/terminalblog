How much are you spending on AI? If you're using coding agents regularly, the answer probably is "I have no idea."

Oh My Pi just fixed that. The CLI usage reporting — which tracks token consumption, model costs, and API usage — was verified and corrected in the v16.3 release. This guide covers the usage command, how it compares to other agents, and practical workflows to avoid bill shock.

## The Fix

Two commits addressed reporting in v16.3.4:

1. **`release(cli): documented usage cli reporting fixes`** — the release notes for the fixes
2. **`test(cli): verified reporting logic`** — test coverage to ensure the fixes stay fixed

The changes correct how token counts are aggregated across sessions, how costs are calculated for different providers, and how the CLI displays the results. Before the fix, token aggregation across multi-session workflows could double-count or miss tokens; provider pricing tables were stale for newer models; and the CLI output format was inconsistent.

## What the Usage CLI Shows

After the fix, running `omp usage` (or `omp usage --help` for options) shows:

- **Total tokens consumed** (input + output) across all tracked sessions
- **Token breakdown by model** — which models are eating your budget (Claude Sonnet 4, GPT-4o, Gemini 2.5, local models via Ollama, etc.)
- **Cost estimates** — based on each provider's published pricing, refreshed periodically
- **Session-level details** — which sessions consumed the most, with timestamps
- **Trend lines** — usage increasing or decreasing over time (daily/weekly/monthly views)
- **Provider breakdown** — spend by OpenAI, Anthropic, Google, Groq, OpenRouter, custom endpoints

### Command Options

```bash
# Basic usage summary
omp usage

# Last 7 days with daily breakdown
omp usage --days 7

# Specific provider only
omp usage --provider anthropic

# Export to JSON for scripting
omp usage --format json > usage-report.json

# Monthly projection based on current burn rate
omp usage --project
```

## Why This Matters: The Hidden Cost Problem

Agent usage has a hidden cost problem. Developers try an agent, it works great, they use it more, and then the API bill arrives. Without usage tracking, you don't see the cost until it's too late.

**Typical scenario:** You start with a few small tasks using GPT-4o-mini (cheap). Then you switch to Claude Sonnet 4 for a complex refactor. A week later you're running background subagents on Opus-equivalent models. The bill compounds non-linearly because:
- Subagents spawn their own contexts (more input tokens)
- Reasoning models emit thinking tokens you pay for
- Retry loops on failed tool calls multiply costs
- Background agents run while you sleep

Oh My Pi's usage CLI provides transparent billing directly in the terminal. No dashboard to log into, no separate billing portal — it's right in your workflow.

## Practical Workflows

### 1. Daily Cost Check (30 seconds)
```bash
# Morning: quick burn rate check
omp usage --days 1 --project
# Shows: "Current burn: ~$2.30/day → projected monthly: ~$69"
```

### 2. Weekly Deep Dive (2 minutes)
```bash
# Weekly: which models, which sessions
omp usage --days 7 --format json | jq '.sessions[] | {model, cost, tokens, duration}'
# Identify: "Claude Sonnet 4 sessions = 73% of spend, but only 40% of tasks"
```

### 3. Pre-task Estimation
```bash
# Before a big refactor, check similar past sessions
omp usage --days 30 | grep -i "refactor\|rewrite\|migrate"
# "Last similar task: 180K tokens, $4.20 on Sonnet 4"
```

### 4. Budget Alerts (automation)
```bash
# Cron job: alert if daily spend exceeds threshold
#!/bin/bash
DAILY=$(omp usage --days 1 --format json | jq '.totalCost')
if (( $(echo "$DAILY > 15" | bc -l) )); then
  notify-send "⚠️ AI spend alert" "Today: $${DAILY} (limit: $15)"
fi
```

## Provider Pricing Nuances the CLI Handles

The usage CLI accounts for several pricing gotchas:

- **Reasoning tokens**: OpenAI o1/o3, Claude 3.7+ extended thinking, Gemini 2.5 thinking — all billed as output tokens
- **Cached input**: Anthropic prompt caching, OpenAI cached prefixes — discounted automatically where provider APIs report it
- **Batch vs streaming**: Some providers discount batch; CLI uses the rate matching your request type
- **Custom endpoints**: If you use OpenRouter, LiteLLM, or a local proxy, the CLI reads `OMP_PROVIDER_PRICING_URL` env var for custom rate cards
- **Local models**: Ollama, vLLM, llama.cpp — shows token counts only (cost = $0), but lets you compute your own GPU cost

## Common Pitfalls

| Pitfall | Symptom | Fix |
|---------|---------|-----|
| **Forgetting subagent tokens** | Parent session shows low usage but bill is high | `omp usage` aggregates subagents; check `--include-subagents` (default on) |
| **Stale pricing** | Cost estimates drift from actual bill | CLI auto-refreshes pricing weekly; force with `omp usage --refresh-pricing` |
| **Multiple API keys** | Same provider, different keys = split tracking | Usage aggregates by provider+model, not by key |
| **Session cleanup** | Old sessions inflate "total" | `omp usage --days 30` for rolling window; `omp session prune` to clean |
