OpenCode 2 is here. Not a beta. Not a preview. **v2.0.28 dropped October 13, 2026** and it's the default install on opencode.ai.

If you've been waiting for the "stable" signal before jumping from v1 — this is it. The migration path (`opencode upgrade --major`) has been live since v1.19.0. Now the new architecture is the default.

Here's what actually matters for your daily workflow.

## The Headlines (What You'll Actually Feel)

| Feature | Why It Matters |
|---------|----------------|
| **Per-project auto-accept** | Set `mod+shift+a` per project — no more global "approve everything" or "approve nothing" |
| **Native Windows ARM64** | Surface Pro, Snapdragon laptops — native binaries, no x64 emulation tax |
| **WinGet install** | `winget install Anomaly.OpenCode` — finally a real Windows package manager path |
| **No more auto-updates** | You run `/update` or `opencode upgrade` — runtime never changes mid-session |
| **Built-in worktree tools** | `worktree_create`, `worktree_list`, `worktree_remove` in Code Mode — isolated contexts, normal approval |
| **Release highlights dialog** | Post-update TUI shows what's new once, `/highlights` to reopen |

## 1. Per-Project Auto-Accept: The Permission Model Finally Makes Sense

**Before:** One global setting. Either you approve every edit (dangerous) or you approve nothing (slow).

**Now:** `Settings → Projects → Auto-accept permissions` — override the default **per project**.

Press `mod+shift+a` in any session to toggle for the current project. The TUI shows the active state.

**Why beginners care:** You're experimenting in a throwaway repo? Auto-accept on. Working on production? Strict approval. Your muscle memory doesn't change — the *context* does.

This is the permission model every coding agent should have copied years ago. OpenCode shipped it first.

---

## 2. Native Windows ARM64: No More Emulation Tax

If you're on a Snapdragon X Elite/Plus laptop (Surface Pro 11, Dell XPS 13 2024, Lenovo ThinkPad T14s Gen 6), you've been running x64 binaries under emulation. That means:

- Slower startup
- Higher battery drain
- Native addons (sqlite3, ripgrep) running through WoW64

**v2.0.28 ships native ARM64 CLI, terminal, and desktop binaries.** Download the "Windows (ARM64)" asset from the release page or the new download page selector.

**WinGet makes it one command:**
```powershell
winget install --id Anomaly.OpenCode -e
# or for the desktop app
winget install --id Anomaly.OpenCode.Desktop -e
```

WinGet handles upgrades automatically. No more manual `.msi` downloads.

---

## 3. Auto-Updates Are Dead. Explicit Updates Won.

OpenCode **stopped auto-installing updates** in v1.19.0. v2.0.28 makes it permanent.

**Old way:** Agent restarts mid-session because an update downloaded in background. You lose context. You lose flow.

**New way:** You run `/update` in the TUI or `opencode upgrade` from CLI. **You decide when the runtime changes.**

This is a philosophy shift: *the operator controls the environment, not the agent.* For CI/automation, this is huge — your build pipeline doesn't randomly pull a new runtime.

---

## 4. Built-In Worktree Tools: Isolation Without the Git Hassle

Three new Code Mode tools:
- `opencode.worktree_create` — spin up an isolated worktree
- `opencode.worktree_list` — see what's active
- `opencode.worktree_remove` — clean up (requires edit approval, `force: true` discards changes)

**Why this matters:** You're debugging a flaky test. Spin a worktree, reproduce, fix, merge back. Your main worktree stays clean. The agent handles the git commands — you just approve the edits.

This is **native worktree support** without leaving your agent session. No `git worktree add` memorization required.

---

## 5. Release Highlights Dialog: You'll Actually Read the Changelog

After updating, the TUI home screen shows a **one-time highlights dialog** with the key changes. Run `/highlights` anytime to reopen. Disable with `highlights: false` in `cli.json`.

Small UX win, big impact: you actually know what changed without digging through GitHub releases.

## Should You Upgrade?

| If You... | Verdict |
|-----------|---------|
| Want per-project permission control | **Yes** — the killer feature |
| Run Windows on ARM (Snapdragon) | **Yes** — native binaries = real performance |
| Use WinGet / want managed updates | **Yes** — official packages now exist |
| Run OpenCode in CI/CD | **Yes** — explicit `/update` = predictable runtime |
| Are on v1.19.0 and happy | **Yes** — safe migration, `upgrade --major` works |
| Have custom v1 plugins not yet ported | **Test first** — plugin API changed in v2 |

**Migration from v1:** Run `opencode upgrade --major` (added in v1.19.0). It downloads v2, migrates config/skills/sessions, rolls back on failure. One command.

## How to Install / Upgrade

```bash
# Fresh install (macOS / Linux)
curl -fsSL https://opencode.ai/v2/install | bash

# Fresh install (Windows - native ARM64 or x64)
irm https://opencode.ai/v2/install.ps1 | iex

# Windows via WinGet (recommended)
winget install --id Anomaly.OpenCode -e

# Upgrade from v1.x
opencode upgrade --major

# Upgrade within v2.x
opencode upgrade
# or in TUI: /update
```

**Verify:**
```bash
opencode --version
# Should show 2.0.28+
```

## The Bigger Picture

OpenCode's thesis: **provider-neutral, local-first, skill-driven.**

While Claude Code locks you to Anthropic, Cursor locks you to their IDE, Codex locks you to OpenAI — OpenCode lets you swap models, providers, and backends without rewriting your workflow.

v2.0.28 doesn't change that thesis. It **removes the friction** from owning your environment:
- Per-project permissions = you decide risk per context
- Native ARM64 = your hardware runs at full speed
- WinGet = Windows is a first-class citizen
- Explicit updates = you control the runtime
- Worktree tools = isolation without git gymnastics
- Highlights = you stay informed without effort

This is what "open source agent" looks like when it grows up.
