GitHub Copilot CLI **1.0.95** dropped October 9, 2026. It's the kind of release that doesn't make headlines but fixes the daily friction that makes you question whether the tool is worth keeping.

**Native Microsoft Entra broker auth on macOS.** **Sandbox credential `injectHosts` with shell completion.** **`--context` that finally applies to ACP sessions.** **Managed plugin retries that don't hammer your API on every failure.**

If you've fought macOS browser auth loops, sandbox credential configs that silently failed, or ACP sessions ignoring your context tier — this release is for you.

---

## 1. Native Microsoft Entra Broker Auth on macOS — No More Browser Dance

**The pain:** On macOS, signing into Copilot CLI with a work/school account (Microsoft Entra ID) meant a browser window, device code flow, copy-paste codes, repeat every session.

**The fix:** 1.0.95 uses the **native macOS Microsoft Entra broker** when available. The OS handles the auth handshake. You get a system prompt, approve once, and the token flows directly to Copilot. Browser fallback still works if the broker isn't present.

```bash
# Just works now
copilot auth login
# macOS Entra broker handles the rest
```

**For beginners:** This is "it just works" territory. No more explaining to your team why the terminal agent needs a browser window every morning. Enterprise admins: this respects your Conditional Access policies natively.

---

## 2. Sandbox Credential `injectHosts` — With Shell Completion

Sandbox mode (`copilot --sandbox`) restricts network access. But you *need* certain hosts to work — your internal registry, your database, your secrets manager.

**1.0.95 adds `injectHosts` to sandbox credential config** with **tab completion in Bash, Zsh, and Fish.**

```bash
# Configure which hosts get credential injection in sandbox
copilot config set sandbox.credentials.injectHosts "api.internal.mycorp.com,registry.mycorp.com,vault.mycorp.com"

# Tab completion works:
copilot config set sandbox.credentials.injectHosts <TAB>
# Shows: api.internal.mycorp.com  registry.mycorp.com  vault.mycorp.com  (your configured hosts)
```

**Why this matters:** Before, you edited JSON and hoped the hostnames were right. Now the shell tells you what's configured. Typos caught before they break your CI.

## 3. `--context` Finally Applies to ACP Sessions (New & Resumed)

**The bug:** You ran `copilot --context long_context` expecting extended context for your ACP session. It silently used the default tier. New sessions, resumed sessions — both ignored the flag.

**The fix:** `--context` now applies to **new and resumed ACP sessions** instead of silently using the default or previously saved context tier.

```bash
# This now works for ACP
copilot --context long_context
# Resumed ACP session? Also respects --context
copilot --context long_context --resume <session-id>
```

**What this unlocks:** Long-context models (Claude 5.5 1M, GPT-6.1 Sol) actually get the context window you paid for. No more "why is my agent forgetting the repo structure?" because the flag was ignored.

---

## 4. Managed Plugin Setup Retries Hourly — Not On Every Message Failure

**The old behavior:** Managed plugin setup failed → every subsequent message triggered a retry. API hammered. Logs flooded. You watched the same error scroll by.

**The new behavior:** Retries **hourly or after policy changes** instead of on every message failure.

This is the "be a good citizen" fix. Your org's plugin policy doesn't change every 30 seconds. Neither should the retry loop.
