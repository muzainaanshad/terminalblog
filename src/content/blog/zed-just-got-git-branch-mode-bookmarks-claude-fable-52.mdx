No more `git diff origin/main --name-only` in terminal. No more hunting through the file tree. Click "Compare Against Base" in the Git panel, pick your base branch, and you get a clean, searchable list of every file that changed. Open any file as a diff. Done.

## 1. Git Branch Mode — The Feature You Didn't Know You Needed

### What it is
A new menu in the Git panel's Changes tab: **"Compare Against Base"**. Pick any branch (defaults to `origin/main`). Zed lists **every file changed since that base** — not just staged, not just unstaged, *everything*.

### Why it matters
- **Code review in-editor**: See the full scope of your PR before pushing
- **No context switching**: Stay in Zed, see the diff, make fixes, commit
- **Works on any base**: Compare against `main`, `develop`, a feature branch, a tag — whatever

### How to use it
1. Open Git panel (`Cmd+Shift+G` / `Ctrl+Shift+G`)
2. Click the new menu at top of Changes tab → "Compare Against Base"
3. Type or select your base branch (e.g., `origin/main`)
4. Browse the file list → click any file to open as diff

### The catch (for now)
Files in this mode are **read-only diffs** — you can't stage or restore from here. But for *reviewing*? It's perfect.

## 2. Bookmark Picker — Your Code's Table of Contents

### What it is
`project bookmarks: toggle` (or search "bookmarks" in command palette) opens a searchable, previewable list of **every bookmark in your workspace**.

### Why it matters
- Bookmarks have existed forever but were buried in the UI
- Now they're a first-class navigation tool
- Preview the context around each bookmark before jumping

### For beginners
Set bookmarks on:
- `TODO: refactor this` comments
- Complex logic you'll return to
- API endpoints you touch often
- Then `Cmd+Shift+P` → "bookmarks" → jump instantly

## 3. Configurable Git Dates — Finally, Dates That Make Sense

### What changed
New settings let you control how Git dates appear **everywhere**:

| Setting | Options | Default |
|---------|---------|---------|
| `git.date_format` | `"locale"`, `"iso"`, or strftime like `"%Y-%m-%d %H:%M"` | `"locale"` |
| `git.blame.date_style` | `"relative"`, `"absolute"` | `"relative"` |
| `git.inline_blame.date_style` | same | `"relative"` |
| `git.branch_picker.date_style` | same | `"relative"` |
| `git.stash_picker.date_style` | same | `"relative"` |
| `git_panel.date_style` | same | `"relative"` |
| `git_graph.date_style` | same | `"relative"` |

### Why it matters
- **ISO dates** (`2026-11-15 14:32`) sort correctly in blame view
- **Relative dates** ("2 hours ago") are great for recent work
- **Per-view control**: Blame can be absolute, branch picker relative — your call

### What it is
Zed now supports **Claude Fable 5.2** for Anthropic BYOK (Bring Your Own Key) users, plus **Claude Mythos 5.2** if your org has access.

### Why it matters
- Fable 5.2 = Anthropic's latest coding model (better than Sonnet 3.5 for many tasks)
- Mythos 5.2 = their reasoning model for complex planning
- No waiting for Zed to update — add your key, select the model, go

### How to enable
1. Settings → AI → Anthropic BYOK
2. Add your Anthropic API key
3. Model picker now shows Fable 5.2 / Mythos 5.2
