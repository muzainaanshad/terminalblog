## What This Actually Is

### An Agent = A Project Folder

```
my-bot/
├── instructions.md       # The prompt — what this agent does
├── tools/                # Each file = one typed action the model can call
│   ├── check-deploy.ts
│   └── query-logs.ts
├── skills/               # Procedures the model loads on demand
│   └── security-review.md
├── mcp-connections/      # Tools from MCP servers
│   └── datadog.json
├── channels/             # Where the bot receives/answers messages
│   ├── github-pr.json
│   └── slack-mentions.json
└── package.json
```

**That's it.** No YAML hell. No dashboard-only configuration. The agent *is* code. Version it. Review it. Test it.

## The Commands You'll Use

```bash
# 1. Scaffold a new agent
npx @cursor/agent-sdk init ./my-bot
# Pick template: security-reviewer, owners-policy-approver, PR-autofixer, Linear-triager, Jira-triager

# 2. Develop locally with playground
cd my-bot
agent-sdk dev
# Opens localhost playground → chat with your agent → see tool calls live

# 3. Validate the project
agent-sdk validate
# Checks: instructions.md exists, tools/ are valid TS, skills/ parse, channels/ configured

# 4. See what was discovered
agent-sdk info
# Prints: tools, skills, MCP connections, channels, entry points

# 5. Test with evals
agent-sdk eval
# Sends fixed messages → asserts on: which tools ran, with what input, reply shape

# 6. Replay a REAL GitHub PR as test fixtures
agent-sdk github replay <pr-url>
# Turns real PR into signed webhook payloads → sends to your bot
# --dry-run --fixtures-dir fixtures/ → saves payloads as eval fixtures

# 7. Deploy to Cursor's infrastructure
agent-sdk deploy
# Builds agent → gives URL → starts on Cursor's infra
# Manage secrets/integrations from dashboard
# Same logs, evals, playground available locally
```

## Channels — Where Agents Wake Up

Your agent doesn't poll. It **wakes on events**:

| Channel | Events | Auth |
|---------|--------|------|
| **GitHub** | PR opened, comment, CI events | Via your Cursor account (no public webhook URL) |
| **GitLab** | MR, comment, pipeline | Via Cursor account |
| **Bitbucket** | PR, comment, build | Via Cursor account |
| **Slack** | Mentions, DMs, thread replies | Well-supported out of the box |
| **Webhooks** | Any provider, any payload | App JWT + installation tokens |
| **Cron** | Schedule (any cron expression) | Built-in |

**Each conversation = its own session.** Complete record of every message and tool call. Follow-ups on a PR or Slack thread **resume the same session** — context preserved.

## Evals — Test Like You Mean It

```bash
# An eval = fixed message + assertions
# Example: evals/security-injection.yaml

test: "SQL injection in PR"
send: "Review this PR for SQL injection"
assert:
  - tool: "query_database"
    input_contains: "UNION SELECT"
  - tool: "post_review_comment"
    output_contains: "CRITICAL: SQL injection"
  - reply_contains: "exploitable"
```

```bash
# Run locally
agent-sdk eval

# Run in CI
# GitHub Actions:
# - uses: cursor/agent-sdk-eval@v1
#   with: agent-path: ./my-bot
```

**`agent-sdk github replay <pr-url>`** is the killer feature: **turns a real PR into signed webhook payloads** and sends them to your bot. Test against *real* data without waiting for a push. `--dry-run --fixtures-dir fixtures/` saves the payloads as permanent eval fixtures.

## Real-World Agents You Can Build Today

### 1. Security Reviewer (Template Exists)
- Wakes on: PR opened
- Checks: SQL/command/template injection, auth bypass, secrets, SSRF, deserialization, dependency vulns
- Posts: One review comment per exploitable bug with severity + fix
- Team rules: Add "external calls must go through X" → enforced on every PR

### 2. Rollouts Monitor (Cursor's Own Bot)
- Wakes on: Deploy events
- Reads: Diff + systems touched → writes monitoring plan as PR comment
- Tracks: Each environment separately (staging ✓, production ⚠)
- Reports: Verdict per environment on PR
- Action: Opens revert PR or hands to cloud agent for fix

### 3. Linear/Jira Triager (Templates Exist)
- Wakes on: Issue created, comment, label change
- Reads: Issue context + codebase
- Actions: Categorize, assign, label, comment, link related PRs

### 4. Dependency Upgrade Bot
- Wakes on: Cron (weekly) + Dependabot PRs
- Checks: Changelogs, breaking changes, test results
- Posts: Summary + risk assessment + auto-merge if safe

### 5. On-Call Assistant
- Wakes on: Slack mention + PagerDuty webhook
- Reads: Current incident + relevant runbooks + recent deploys
- Replies: "Last deploy touched payment-service. Runbook: runbook/payment-outage.md. Want me to check logs?"
