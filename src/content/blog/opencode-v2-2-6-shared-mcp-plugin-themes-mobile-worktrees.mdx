**OpenCode v2.2.6 landed this week** — and it's the kind of release that doesn't shout but changes how you work every single day. Shared MCP connection pooling means you stop spinning up duplicate MCP servers. GUI plugins can now add color themes and hook into code blocks. Mobile gets a touch-friendly composer dock. Scripted runs can launch directly in worktrees. And CI sessions finally stay out of your inbox.

If you've been on v2.2.5 (October 30), this is the update you actually feel.

## The Headline Feature: Shared MCP Connections (Finally)

### The Problem You've Been Living With

You have three projects. All three use the same GitHub MCP server. All three use the same Slack MCP server. All three use the same PostgreSQL MCP server.

**Before v2.2.6:** Each project spawns its own MCP connection. Three GitHub processes. Three Slack processes. Three PostgreSQL processes. Memory adds up. Startup slows down. You wonder why your machine feels heavy.

### The Fix: `pool: true`

```json
{
  "mcp": {
    "servers": {
      "github": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-github"],
        "pool": true
      },
      "slack": {
        "command": "npx",
        "args": ["-y", "@modelcontextprotocol/server-slack"],
        "pool": true
      }
    }
  }
}
```

**One connection. Shared across every project with the same config.** Start faster. Use less memory. The MCP server stays alive as long as any project needs it.

```bash
# Before: 3 projects × 3 MCP servers = 9 processes
# After:  3 projects × 1 pooled connection each = 3 processes
```

This is the kind of change you don't notice until you switch machines and realize — *oh, it used to take 15 seconds to start. Now it takes 3.*

## GUI Plugins Got Themes and Code Block Slots

### Color Themes — Your Plugin, Your Palette

GUI plugins can now ship **color themes**. Not "here's a CSS variable, good luck." Actual theme contributions that appear in Settings → Appearance → Themes alongside the built-ins.

```typescript
// In your GUI plugin
export const theme = {
  name: "My Plugin Theme",
  type: "dark",
  colors: {
    "editor.background": "#0d1117",
    "editor.foreground": "#e6edf3",
    "myPlugin.accent": "#58a6ff",
    "myPlugin.warning": "#f85149"
  }
};
```

Users pick it from the theme dropdown. It applies instantly. No config editing. No restart.

### Code Block Render Slots — Your Plugin Owns the Output

Plugins can now **render or add actions to code blocks** in the transcript. This is huge for:

- **Diagram plugins** — render Mermaid/PlantUML inline with interactive controls
- **SQL plugins** — add "Run Query" button to SQL code blocks
- **API plugins** — add "Test Endpoint" to curl blocks
- **Terraform plugins** — add "Plan" / "Apply" to HCL blocks

```typescript
export const codeBlockSlots = {
  mermaid: {
    render: (code, language) => language === "mermaid" ? <MermaidDiagram code={code} /> : null,
    actions: [
      { label: "Export PNG", handler: exportMermaidPNG },
      { label: "Edit in Mermaid Live", handler: openInMermaidLive }
    ]
  },
  sql: {
    actions: [
      { label: "Run Query", handler: runSQLQuery },
      { label: "Explain Plan", handler: explainSQL }
    ]
  }
};
```

### Native Settings and Menu Components

Plugins can now use **native settings components** (toggle, select, text, secret) and **native menu components** — so your plugin's UI feels like it belongs in OpenCode, not bolted on.

## Mobile Composer Dock — Touch-First, Finally

### The Problem: Mobile Was an Afterthought

On phones and tablets, the composer lived at the bottom of a scrolling page. Thumb reach? Terrible. Multiline input? Cramped. You typed with one finger, hunched over.

### The Fix: Composer Dock Above Keyboard

**v2.2.6 adds a Mobile Composer Dock** — composer actions sit in a touch dock **above the keyboard** with 44px targets (Apple's minimum touch target). Larger buttons. Predictable multiline input. Your thumbs actually reach everything.

```bash
# What changes:

# - Model picker: thumb-reachable
# - Multiline input: expands naturally, keyboard stays put
```

This isn't "mobile support." This is **mobile-first**. If you've tried coding on an iPad or phone with OpenCode before, update and try again. The difference is night and day.

## Scripted Runs in Worktrees — `opencode run -w`

### The Old Way: Manual Worktree Dance

```bash
# You want to run a scripted task in a fresh worktree
git worktree add ../feature-auth origin/main
cd ../feature-auth
opencode run "Implement OAuth2 refresh token flow"
# ... wait ...
cd ../main-project
git worktree remove ../feature-auth
```

### The New Way: One Flag

```bash
# Run in a new auto-named worktree
opencode run -w "Implement OAuth2 refresh token flow"

# Run in a named worktree
opencode run --worktree=auth-refactor "Implement OAuth2 refresh token flow"
```

**That's it.** OpenCode creates the worktree, runs the task, and you get the results. The worktree persists — you can inspect it, continue in it, or clean it up later.

### Why This Matters for CI and Automation

```yaml
# .github/workflows/nightly-refactor.yml
- name: Run nightly refactor
  run: |
    opencode run -w \
      --format json \
      "Review all TODO comments in src/, create GitHub issues for each"
```

Clean, isolated, reproducible. No manual git worktree management in your scripts.

## Automatically Archived Runs — Keep Your Inbox Clean

### The Problem: Scripted Runs Clutter Everything

You run `opencode run` for CI, for nightly jobs, for automated reviews. They all show up in your session list. Your inbox becomes a graveyard of "CI run #847" sessions you never open.

### The Fix: `--archived`

```bash
# Scripted run that stays out of your inbox and session list
opencode run --archived "Nightly dependency audit"

# Combined with worktree flag
opencode run -w --archived "Refactor auth module"
```

**Archived sessions:**
- Don't appear in the inbox
- Don't appear in the TUI session list
- Are skipped by `--continue`
- Are still queryable via SDK/API if you need them

```bash
# Still accessible when you need them
opencode session list --archived
opencode session get <archived-session-id>
```

This is the "CI hygiene" feature you didn't know you needed until your session list became unusable.
