**OpenHands v1.34.0 dropped October 27, 2026** — and it's the release that finally makes Agent Canvas feel like a platform you can build on, not just a chat interface.

The headlines: **Docker runtime settings per conversation**, **a dedicated Runtime settings page**, **filter and edit automation tags**, **start new conversations inside existing sandboxes**, plus **15+ bug fixes** and **security hardening** (untrusted markdown can no longer hijack link targets).

If you run OpenHands Agent Canvas — this is the update that lets you isolate workloads properly.

## The One-Line Summary

**Pick a Docker runtime per conversation. See it in Settings. Filter automation tags. Spin up new chats in the same sandbox. Security: markdown can't inject `rel=opener`. Update now.**

---

## 1. Per-Conversation Docker Runtime — Isolation That Matters

**What it is:** Settings → Runtime now lets you configure a **Docker runtime per conversation**. Each chat gets its own isolated container with its own tools, secrets, and environment.

**Why it matters:** Before: all conversations shared the host environment. One rogue `npm install` polluted everything. Secrets leaked across tasks. Now: **every conversation is a clean room**. You pick the image, the resources, the mounted volumes — per task.

```bash
# In OpenHands Agent Canvas:
# 1. Open a conversation → Settings (gear icon) → Runtime
# 2. Choose Docker runtime
# 3. Pick image (e.g., node:22, python:3.12, your custom Dockerfile)
# 4. Set CPU/memory limits
# 5. Mount secrets via env vars (not argv — fixed in this release!)
# 6. Start coding — the agent runs inside that container
```

**For beginners:** This is the "my agent broke my other project" problem, solved. Each conversation = fresh container. Your main machine stays clean.

---

## 2. Runtime Settings Page — Finally Visible

**What it is:** A **new Settings → Runtime page** (OHE-3765) that surfaces Docker configuration, launcher labels, and runtime health checks in one place.

**Why it matters:** Runtime config was buried. Now it's a first-class settings section. You see:
- Default runtime for new conversations
- Per-conversation overrides
- Health status of running sandboxes
- Resource usage per container

**PR:** [#18436](https://github.com/OpenHands/OpenHands/pull/18436) by @VascoSch92

---

## 3. Filter & Edit Automation Tags — Organize at Scale

**What it is:** Automations now support **filterable, editable tags**. You can tag automations by team, project, environment — and filter the list instantly.

**Why it matters:** When you have 50+ automations (scheduled code reviews, dependency updates, incident response), tags are the only way to find what you need. **Edit tags inline. Filter by tag. Stop scrolling.**

**PR:** [#18767](https://github.com/OpenHands/OpenHands/pull/18767) by @VascoSch92

---

## 4. Start New Conversation in Existing Sandbox — Reuse the Work

**What it is:** In the sidebar, each conversation row now has a **"Start new conversation in this sandbox"** action (OHE-3689).

**Why it matters:** You spun up a sandbox, installed deps, configured the environment. Now you want a fresh chat *in that same sandbox* — without re-cloning, re-installing, re-configuring. **One click. Same sandbox. New conversation.**

**PR:** [#18912](https://github.com/OpenHands/OpenHands/pull/18912) by @hieptl

---

## 5. Share Toggle Labels Fixed — "Share with Org Users"

**What it is:** In team organizations, the share toggle now reads **"Share with Org users"** (OHE-3765) instead of the ambiguous "Share."

**Why it matters:** Clarity. You know exactly who gets access. No accidental public shares.

**PR:** [#18986](https://github.com/OpenHands/OpenHands/pull/18986) by @hieptl

---

## 6. Security: Untrusted Markdown Can't Hijack Links

**What it is:** **Fixed** — untrusted markdown (agent outputs, web content) can no longer set `rel="opener"` or arbitrary `target` attributes on links.

**Why it matters:** This was a **tab-nabbing / phishing vector**. An agent could output a link that, when clicked, gave the target page control over your opener tab. **Now blocked at the renderer.**

**PR:** [#17156](https://github.com/OpenHands/OpenHands/pull/17156) by @LeizhenZhang

---

## 7. Secrets Passed via Env (Not argv) — Fixed

**What it is:** Session API keys now passed to static-server via **environment variables** instead of command-line arguments.

**Why it matters:** `ps aux` on the host no longer leaks your session keys. **Process list security = fixed.**

**PR:** [#16420](https://github.com/OpenHands/OpenHands/pull/16420) by @putramkti (first contribution!)

## How to Update

```bash

docker pull ghcr.io/openhands/openhands:1.34.0
# Or latest
docker pull ghcr.io/openhands/openhands:latest

# Verify

# If running from source

git checkout v1.34.0
```

- v1.29: Scoped agents + isolated Docker runtimes → **foundation**
