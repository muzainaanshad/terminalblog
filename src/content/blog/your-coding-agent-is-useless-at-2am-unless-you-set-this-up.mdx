## Step 2: The Safety Checklist (Non-Negotiable)

**Before you run anything unattended, every item below must be ✅.**

### Separate API Keys for Unattended Work

```bash
# NEVER use your main key
export HERMES_UNNATENDED_KEY="sk-or-unattended-..."
export OPENHANDS_AUTOMATION_KEY="sk-or-automation-..."
```

Separate keys = separate rate limits, separate billing, revocable without breaking your interactive work.

### Hard Caps on Everything

```yaml
# Hermes example
cron:
  deps-update:
    schedule: "0 3 * * *"
    max_steps: 50           # Hard step limit
    max_cost_usd: 2.00      # Hard dollar limit
    timeout_minutes: 30     # Hard time limit
    require_approval: true  # Human gate for PR creation
```

No caps = surprise $500 bill or infinite loop that deletes your repo.

### Worktree Isolation (Mandatory)

```bash
# Every unattended job gets its own worktree
git worktree add ../repo-deps-update main
git worktree add ../repo-security-scan main
git worktree add ../repo-doc-gen main
```

Agents sharing a worktree = merge conflicts, corrupted state, "why did my main branch change?"

### Credential Scoping

```yaml
# Hermes credential guard
credentials:
  github_token:
    scope: "repo:read,repo:write"  # NOT admin, NOT delete_repo
    allowed_agents: ["deps-update", "doc-gen"]
    denied_agents: ["security-scan"]  # Security scan doesn't need write
```

Principle: **least privilege per agent per job**.

### Logs That Survive Terminal Close

```bash
# Hermes: logs to ~/.hermes/logs/ automatically
# OpenHands: persisted in conversation + cloud
# Goose: ACP session persistence across restarts

# Verify before trusting:
hermes cron run deps-update --dry-run
# Check ~/.hermes/logs/cron-deps-update-*.log
```

If you can't read yesterday's log, you're flying blind.

### Human Gate for Destructive Actions

```yaml
# Hermes: require_approval: true on any job that can push
# OpenHands: read-only automations for teammates, manual trigger for prod
# Goose: ACP session requires explicit task.handoff with approval
```

Force-push, production deploys, secret rotation — **always human-in-the-loop**.

## Step 3: Three Production-Ready Workflows

### Workflow 1: Nightly Dependency Updates (Hermes)

```bash
# 1. Create the cron job
hermes cron add deps-update "0 3 * * *" \
  --goal "Update all dependencies, run tests, open PR if passing" \
  --max-steps 40 \
  --max-cost 1.50 \
  --require-approval

# 2. Test it dry-run
hermes cron run deps-update --dry-run

# 3. Enable
hermes cron enable deps-update
```

**What it does at 3 AM:**
1. `git worktree add ../repo-deps main`
2. Runs `npm outdated` / `pip list --outdated` / `cargo outdated`
3. Updates `package.json`, `requirements.txt`, `Cargo.toml` conservatively
4. Runs full test suite
5. If green: creates branch, commits, pushes, opens PR with changelog summary
6. If red: logs failure, creates issue with error details, **does not open PR**

**Your morning:** PR ready for review. You merge or request changes. Zero manual work.

### Workflow 2: PR Security Scan on Every Push (OpenHands)

```yaml
# .openhands/automations/security-scan.yaml
name: "Security Scan on PR"
trigger:
  type: "event"
  event: "pull_request.opened"
config:
  read_only: true  # Teammates can see, can't modify
  agent:
    model: "openrouter/nvidia/nemotron-3-ultra:free"
    instructions: |
      You are a security reviewer. Scan the PR diff for:
      - SQL injection patterns
      - XSS vulnerabilities
      - Hardcoded secrets
      - Insecure deserialization
      - Path traversal
      Post findings as PR comments with file:line references.
      Do NOT suggest fixes — only identify risks.
```

**What it does:** Every PR gets an automated security review comment within 2 minutes. Your team sees risks before human review starts.

### Workflow 3: Weekly Codebase Health Report (Hermes + Goose)

```bash
# Hermes cron for the heavy lifting
hermes cron add health-report "0 9 * * 1" \
  --goal "Generate weekly codebase health report: test coverage, complexity, debt, security" \
  --max-steps 60 \
  --max-cost 3.00 \
  --background

# Goose hidden session for the summary
goose session create --name "weekly-health" --hidden
goose session run weekly-health \
  --prompt "Read the health report from Hermes, create executive summary for team Slack"
```

**Monday 9 AM:** Your team gets a Slack message with:
- Test coverage delta (+2.3% this week)
- New TODO/FIXME count (12 added, 3 resolved)
- Complexity hotspots (3 files > 50 cyclomatic complexity)
- Security findings (0 critical, 2 medium)
- Dependency updates pending (7)

## Step 4: The Multi-Agent Fleet Pattern

**Don't run one agent. Run a fleet.**

```text
┌─────────────────────────────────────────────────────────────┐
│                    ORCHESTRATOR (Hermes)                    │
│  Cron scheduler • Provider router • Credential guard • Logs │
└─────────────────────┬───────────────────────────────────────┘
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
┌───────────────┐ ┌───────────────┐ ┌───────────────┐
│  DEPS AGENT   │ │  SEC AGENT    │ │  DOCS AGENT   │
│  (Hermes)     │ │  (OpenHands)  │ │  (Goose)      │
│  Worktree A   │ │  Worktree B   │ │  Worktree C   │
│  Keys: read   │ │  Keys: read   │ │  Keys: write  │
│  + write PR   │ │  + comment    │ │  (docs only)  │
└───────────────┘ └───────────────┘ └───────────────┘
        │             │             │
        └─────────────┼─────────────┘
                      ▼
         ┌───────────────────────┐
         │   HUMAN GATE (You)    │
         │  Review PRs @ 9 AM    │
         │  Merge / Request /    │
         │  Investigate alerts   │
         └───────────────────────┘
```

**Each agent:**
- Own worktree
- Own API key (scoped)
- Own hard caps
- Own log stream
- Single responsibility

**The orchestrator (Hermes):**
- Schedules cron jobs
- Routes to cheapest capable provider (Nemotron free → Ollama local → paid fallback)
- Enforces credential guards
- Aggregates logs to console dashboard

## Step 5: Provider Failover (So It Never Stops)

Free tiers hit limits. Paid APIs go down. Local models crash. **Build failover.**

### Hermes Multi-Provider Config

```yaml
# ~/.hermes/config.yaml
providers:
  primary:
    name: "openrouter"
    model: "nvidia/nemotron-3-ultra:free"
    base_url: "https://openrouter.ai/api/v1"
    api_key: "$OPENROUTER_KEY"
    max_requests_per_minute: 20
    max_requests_per_day: 50

  fallback_1:
    name: "ollama"
    model: "qwen3-coder:7b"
    base_url: "http://localhost:11434/v1"
    api_key: ""
    max_requests_per_minute: 60
    max_requests_per_day: 10000

  fallback_2:
    name: "openrouter-paid"
    model: "anthropic/claude-sonnet-4"
    base_url: "https://openrouter.ai/api/v1"
    api_key: "$OPENROUTER_PAID_KEY"
    max_requests_per_minute: 60
    max_requests_per_day: 10000

routing:
  strategy: "failover"
  health_check_interval: 300
  fallback_on: ["rate_limit", "timeout", "5xx", "circuit_breaker"]
```

**Behavior:** Free Nemotron handles 80% of work. When it 429s, seamlessly fails over to local Qwen. If local OOMs, fails over to paid Claude. You wake up to completed jobs, not failures.

## Common Failure Modes (And How to Avoid Them)

| Failure | Symptom | Prevention |
|---------|---------|------------|
| **No worktree isolation** | Main branch corrupted, merge hell | Mandatory `git worktree add` per job |
| **Shared API keys** | Rate limit kills interactive work | Separate keys per agent per purpose |
| **No hard caps** | Infinite loop, $500 bill | `max_steps`, `max_cost_usd`, `timeout_minutes` on EVERY job |
| **No credential scoping** | Security scan gets write access | Least-privilege per agent in config |
| **No logs** | "It worked yesterday, why fail today?" | Structured logs + retention + alerting |
| **No human gate** | Force-push to prod at 3 AM | `require_approval: true` on destructive actions |
| **Single provider** | Free tier 429 = all jobs stop | Multi-provider failover config |
| **No dry-run** | First run breaks things | `hermes cron run job --dry-run` mandatory |
