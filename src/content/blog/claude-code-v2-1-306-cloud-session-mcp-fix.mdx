Claude Code v2.1.306 dropped **October 21, 2026**. It's a tiny patch — two fixes — but they hit workflows that daily drivers hit constantly.

If you've ever run `claude -p` in a cloud session and got "Not logged in" despite being logged in, or watched an MCP-heavy session compact unnecessarily because an API error got masked as "prompt too long" — this update is for you.

## The Two Fixes (That's It — Two)

| Bug | Symptom | Fixed |
|-----|---------|-------|
| `claude -p` in cloud sessions | Reports "Not logged in" when started without the session's environment variables | ✅ Fixed |
| API error masked as "prompt too long" | Sessions with many MCP tools get unneeded compaction | ✅ Fixed |

That's the whole changelog. But here's why each matters.

---

## Fix 1: `claude -p` in Cloud Sessions — The False "Not Logged In"

**The scenario:** You're using cloud sessions (GitHub Actions, CI, remote runner). You run `claude -p "your prompt"` to execute a quick task. It fails with **"Not logged in"** — but you *are* logged in. The session has valid credentials.

**The root cause:** When `claude -p` starts *without* the cloud session's environment variables (which carry auth context), it couldn't find the session's credentials and incorrectly reported "Not logged in."

**The fix:** v2.1.306 now properly detects the cloud session context even when launched via `-p` without inherited env vars. It finds the session's credentials. The command works.

**Why it matters:** Cloud session users (CI, automation, remote runners) no longer hit false auth failures on quick `-p` invocations. Your scripts just work.

---

## Fix 2: API Error → "Prompt Too Long" → Unneeded Compaction

**The scenario:** You're in a session with **many MCP tools** configured (10, 20, 50+). An API call fails — maybe a timeout, a rate limit, a transient network blip. Instead of showing the real error, Claude Code replaces it with **"prompt is too long"** and triggers a **compaction** (summarizing conversation history to fit context).

**The problem:** The prompt *wasn't* too long. The API just errored. But the compaction runs anyway — dropping context you needed, wasting tokens, breaking your flow.

**The fix:** v2.1.306 stops masking API errors as "prompt too long" in MCP-heavy sessions. Real errors surface. Compaction only triggers when *actually* needed.

**Why it matters:** If you run many MCP servers (common in agentic workflows), you stop losing context to phantom "prompt too long" compactions. Your session history stays intact unless it *genuinely* exceeds limits.
