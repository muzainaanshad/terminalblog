Kilo Code v7.8.27 landed on November 5th, 2026. It's a **critical security patch** — not a feature release. If you're running any version before v7.8.27, you're exposed to multiple high-severity CVEs across the dependency tree.

This isn't theoretical. These are active vulnerabilities in packages Kilo Code bundles: `node-forge`, `brace-expansion`, `js-yaml`, `follow-redirects`, `body-parser`, `zod`, `axios`, `fast-uri`, `fastify`, `fast-xml-parser`, `glob`, `express`, `proxy-addr`, `shell-quote`, and `seroval`.

The release notes read like a CVE greatest-hits list. Every single one of these was flagged by Dependabot as **high or critical severity**:

| `brace-expansion` | ReDoS via crafted input | High |
| `js-yaml` | Arbitrary code execution via unsafe load | Critical |
| `follow-redirects` | SSRF via redirect manipulation | High |
| `body-parser` | Prototype pollution, DoS | High |
| `zod` | ReDoS in regex validation | High |
| `axios` | Prototype pollution, SSRF | High |
| `fast-uri` | ReDoS in URI parsing | High |

## The Supply-Chain Reality

This is what supply-chain security looks like in 2026. Kilo Code bundles **hundreds of transitive dependencies**. A vulnerability in `fast-xml-parser` (used by something that uses something Kilo uses) becomes *your* vulnerability the moment you run `kilo`.

The Kilo team fixed **all 15 flagged advisories in one release**. That's the bar now: when Dependabot screams, you ship a patch within hours, not days.

## What Else Changed

Beyond the security blitz, v7.8.27 includes:

- **OpenShell-ready Docker image** (`ghcr.io/kilo-org/kilocode:<version>-openshell`) — keeps Kilo's sandbox off, skips model catalog fetch, cloud session upload, and presence (which OpenShell blocks)
- **Agent Manager improvements** — continue a local worktree in Cloud from Agent Manager, copy open conversations after branch validation
- **"Show Open Tabs" command** — opens the open-tabs switcher in chat (VS Code)
- **Playwright runtime updated to 1.64.1**
- **Inline images in chat** — images generated by models like Google Nano Banana now render inline

## The Bigger Picture: Why This Keeps Happening

AI coding agents are uniquely vulnerable to supply-chain attacks because they:

1. **Bundle everything** — CLI, language servers, model SDKs, terminal emulators, browser automation, MCP clients, git wrappers, SSH clients
2. **Update fast** — weekly or daily releases mean dependencies rotate constantly
3. **Run with high privileges** — they read/write your codebase, execute shell commands, access your git credentials, SSH keys, and API tokens
4. **Pull from everywhere** — npm, PyPI, crates.io, GitHub releases, Docker Hub, custom registries

A single compromised transitive dependency in `fast-xml-parser` or `shell-quote` gives an attacker **full repository access** — they can exfiltrate source code, inject backdoors, steal API keys, or push malicious commits.

Kilo Code's response time (48 hours from advisory to patched release) is the new baseline. If your agent vendor takes weeks to patch critical CVEs, **switch vendors**.

## What "Fixed" Actually Means

When Kilo Code says "updated dependencies to resolve all remaining high-severity security advisories," they mean:

- **Patched versions pinned** in `package-lock.json` / `pnpm-lock.yaml`
- **SBOM published** (CycloneDX) — verify with `kilo-cli-sbom-evidence.json` from the release assets
- **Reproducible builds** — SHA256SUMS published for every artifact
- **No known CVEs** at `critical` or `high` in `npm audit --audit-level=high`

Verify yourself:

```bash
# Download the CLI artifact
curl -LO https://github.com/Kilo-Org/kilocode/releases/download/v7.8.27/kilo-darwin-arm64.zip

# Verify checksum
sha256sum kilo-darwin-arm64.zip
# Compare to kilo-cli-SHA256SUMS from the release

# Extract and audit
unzip kilo-darwin-arm64.zip
cd package && npm audit --audit-level=high
# Should return: found 0 vulnerabilities
```
