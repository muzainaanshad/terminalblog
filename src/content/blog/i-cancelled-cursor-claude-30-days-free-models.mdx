## Week 1: The Withdrawal Symptoms

**Days 1–2: Muscle memory is a liar.**

I kept reaching for `Cmd+K` in Cursor. It wasn't there. I kept expecting Claude Code's inline diffs in the terminal. Different keystrokes.

The friction wasn't the models. It was **me**.

OpenCode's skill-driven workflow means you describe *what* in a SKILL.md, not *how* in a prompt. First session I spent 20 minutes writing a skill for "refactor React component to use React 19 use hook." Second session: 3 minutes. Third: 30 seconds.

**Day 3: The first real test.**

A legacy TypeScript service needed a validation schema extracted from three duplicated implementations across 12 files. The kind of task I'd normally throw at Claude Opus and walk away.

Nemotron 3 Ultra:
- Planned 4 steps before writing
- Parallel reads across all 12 files
- Clean diff, zero broken imports
- Predicted 2 test failures (both real)
- **47 seconds.**

Claude Opus used to take 3–4 minutes for this. Nemotron was faster *and* the diff was cleaner.

**Day 5: First rate limit hit.**

OpenRouter free tier: 50 requests/day without credits. I hit it at 4 PM on a Tuesday.

The session didn't die — it just queued. I switched to Kimi K3 on OpenHands Cloud, finished the task, came back next morning.

**Lesson:** Free tier isn't "unlimited." It's "unlimited if you have a backup configured." Took 5 minutes to add Kimi as fallback in OpenCode config.

## Week 2: The Surprises

**Nemotron is better than Opus at routine work.**

I said it. For the 80% — bug fixes, tests, single-file refactors, scripts, explaining unfamiliar code — Nemotron 3 Ultra free is indistinguishable from Claude Sonnet 4. Sometimes better because it doesn't over-explain.

The MoE architecture (550B total, 55B active) means it reasons efficiently. No wasted tokens on verbose explanations unless you ask.

**Kimi K3's 1M context is unfair for repo analysis.**

Task: "Explain this 48K LOC monorepo and find the WebSocket memory leak."

Nemotron: Read entry points, found the main leak in `ConnectionManager`, 67K tokens used.

Kimi K3: Ingested the *entire repo in one go*. Found the same leak **plus two more** — an event listener leak in `ReconnectionHandler` and a timer reference leak in `HeartbeatManager`. Produced a Mermaid architecture diagram.

340K tokens. The 1M context isn't marketing. It changes what's possible.

**Qwen 32B local is the only option that matters for sensitive code.**

One client project — financial services, strict data policy. Can't send code to any API.

`ollama pull qwen3-coder:32b` → 24GB VRAM → done.

Quality: 85% of Nemotron on routine tasks. Struggles on novel frameworks (post-2024 training cutoff). But **code never leaves the machine**. That's the feature.

## The One Thing Nobody Tells You

**Free tiers are rented ground.**

- Nemotron free: NVIDIA subsidizing inference to hook developers on their ecosystem
- Kimi free: Moonshot paying OpenHands Cloud bills to build platform moat
- Qwen: The only one you truly own. Alibaba released weights. Nobody can revoke them.

If you're building a workflow for **years**, invest in local deployment (Ollama + Qwen/DeepSeek/Mistral). The free cloud tiers are amazing *right now* — but they're strategic plays, not charity.

## Should You Cancel?

**Yes, if:**
- You're paying $100+/mo for subscriptions + tokens
- You're willing to spend one afternoon configuring fallbacks
- 80% of your work is routine coding (bugs, tests, refactors, scripts)
- You have a GPU for local fallback (or don't mind OpenHands Cloud)

**No, if:**
- Your company pays and you don't care
- You do massive architectural migrations daily
- You need IDE-integrated inline diffs (Cursor's genuine moat)
- You have zero tolerance for any configuration friction
