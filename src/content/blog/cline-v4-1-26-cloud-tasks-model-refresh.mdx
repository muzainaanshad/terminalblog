**Cline v4.1.26 dropped October 26** — and it's the release that finally makes Cline a **cloud-native agent**. The headline: **Cloud tasks with dedicated model selection**, a **massive model catalog refresh**, **GPT-6 fixes on OpenAI/Azure**, and **Kimi K3 max reasoning support**.

If you've been running Cline locally and hitting context limits or compute constraints — this update changes where your agent can run.

The open-source agent that now runs where your code lives.**

## The Headline: Cloud Tasks — Your Agent Gets Its Own Computer

### Before: Everything Local

You run Cline. It eats your RAM, your CPU, your context window. Big tasks = slow machine. You can't close your laptop.

### After: Cloud Tasks Toggle

**Settings > API Configuration** now has a **Local | Cloud toggle** when cloud sessions are enabled.

- **Local** = your machine, your models, your limits
- **Cloud** = remote sandbox, separate model picker, your local machine stays free

```bash
# In Cline settings:
# 1. Enable Cloud sessions (if available for your account)
# 2. See "Local | Cloud" toggle appear
# 3. Switch to Cloud → pick a cloud-specific model
# 4. Start a task → it runs on remote infrastructure
# 5. Your local Cline stays responsive
```

**Starting a cloud sandbox shows a progress card:** repo → branch → steps (start sandbox, clone repository, start agent). It collapses once the agent starts.

**For beginners:** This is the moment Cline stops being "a VS Code extension that runs locally" and becomes **"an agent that runs wherever your code needs it to run."**

## GPT-6 Fixes: OpenAI, Azure, and SAP AI Core

### The Problem

GPT-6 models (`gpt-6-sol`, `gpt-6.1-sol`) were **broken on OpenAI and Azure OpenAI-compatible endpoints**. SAP AI Core rejected requests with:

```
Unsupported parameter: 'max_tokens'
```

### The Fix

Both now use `max_completion_tokens` correctly. GPT-6 models **work on OpenAI, Azure, and SAP AI Core**.

```json
// What changed internally:
// Before: max_tokens (rejected by newer APIs)
// After:  max_completion_tokens (accepted everywhere)
```

**If you've been waiting to use GPT-6 Astra/Sol/Luna in Cline — it works now.**

## Kimi K3 Gets `max` Reasoning (Fixed)

Kimi K3 now gets `max` reasoning for **Extra High and Max** effort levels — instead of an `xhigh` setting it rejects.

```json
// Effort levels that now work:
"effort": "extra_high"  // → max reasoning
"effort": "max"         // → max reasoning
```

## Auto-Compaction Safeguards (No More Runaway Compaction)

### Before: Compaction Gone Wild

- Auto-compaction ran for models with **unknown context limits**
- After first compaction, it ran **again every few tool calls** (7x overestimation bug)

### After: Smart Compaction

- **No auto-compaction** for models with unknown input limits
- After first compaction, size estimate uses **actual sent messages** (tool results truncated)
- Manual and overflow-recovery compaction still work

**Translation:** Your long sessions won't randomly compact themselves into oblivion.

---

## Checkpoint Diffs: 10x Faster on Large Repos

### Before: Thousands of Git Processes

Checkpoint diffs used `git show` per file → **thousands of processes** on repos with many untracked files.

### After: Single Batch Process

```bash
# Now uses:
git cat-file --batch
# One process. Reads all file contents at once.
```

**If you work on large monorepos — checkpoint diffs are now instant.**

## SSH & ProxyJump: Remote Environments Just Connect

- SSH remotes behind **ProxyJump alias** now connect
- Connect budget: 10s → **30s**
- Per-command limit: **60s**
- Tunnel readiness: **40s**
- When ssh exits mid-upload → **real error reported** (not `EPIPE`)
- `LocalForward` on alias no longer collides with tunnel

**If you code on remote servers via jump hosts — this release respects your SSH config.**
