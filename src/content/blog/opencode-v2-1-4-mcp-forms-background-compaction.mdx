If you've been holding off on OpenCode because MCP felt half-baked — this is the release to try.

## MCP Forms: The Fix You've Been Waiting For

Here's the problem that drove everyone crazy: you're using an MCP server (say, a database tool or GitHub integration), it needs you to confirm something or pick an option, and... nothing happens. The tool call spins. Eventually it times out. You have no idea what it wanted.

**v2.1.4 fixes this completely.**

When an MCP server sends an elicitation request during a tool call, OpenCode now renders the form immediately:

- **Text input** — free-form response
- **Number** — numeric values with validation
- **Choice** — single-select from options
- **Multiselect** — pick multiple
- **Boolean** — yes/no confirmation
- **URL** — link input with validation

This works in **Desktop app**, **Web UI**, and **TUI**. The extension ecosystem also got the fix — MCP elicitation forms now appear during tool calls instead of timing out (thanks to contributors @dimitriskourg and @chrischall).

If you've avoided MCP because it felt unreliable, this release changes that.

## Background Compaction: No More Session Freezes

Long sessions hit a compaction threshold. Historically, OpenCode would pause, summarize, then continue — a noticeable stall.

**Now you can opt into background compaction:**

```json
{
  "experimental": {
    "background_compaction": true
  }
}
```

As your session nears the compaction threshold, OpenCode prepares the summary *in the background* on a separate model call. When compaction triggers, the summary is ready — no wait.

**Tradeoff:** Summaries that are never used still cost tokens. But for long-running sessions, the smoothness is worth it.

Other compaction improvements in this release:
- When a compaction request exceeds the provider limit, older tool output and exchanges are shortened *first* — more useful history survives
- More provider context-overflow errors are recognized and handled gracefully

## Security: Bun 1.4.4 Is a Big Deal

OpenCode bundles its own Bun runtime. v2.1.4 upgrades to **Bun 1.4.4**, which includes security fixes across the entire network stack your agent uses every single session:

| Component | Vulnerabilities Fixed |
|-----------|----------------------|
| **Brotli** | Decompression vulnerabilities |
| **TLS** | Certificate validation edge cases |
| **HTTP/1.1** | Request smuggling / parsing issues |
| **HTTP/2** | Header handling / flow control bugs |
| **HTTP/3** | QUIC transport vulnerabilities |
| **WebSocket** | Frame parsing / memory safety |
| **fetch** | Redirect / origin validation flaws |

**Plus:** Root certificates updated to **NSS 3.131.1** — your agent now trusts the current CA bundle, not one from months ago.

Your coding agent makes hundreds of network calls per session: model endpoints, MCP server definitions, GitHub repos, package registries. This update patches the plumbing underneath all of it.

## Faster Code Display: Pierre Highlights

Code blocks, streaming output, file views, and review diffs in Desktop now use **Pierre Highlights** instead of the previous highlighter.

**Result:** Significantly faster highlighting and lower memory use on large files and diffs.

If you've ever opened a 2000-line file in OpenCode Desktop and felt the UI chug — this should feel snappier.

## Voice Models: Experimental but Discoverable

OpenCode's voice features are still experimental, but v2.1.4 makes them discoverable:

- **SDK:** `client.voice.models()` lists available experimental voice models, their availability, and supported WebRTC or WebSocket transports
- **Console workspaces:** Connected OpenCode Console workspaces can host GPT-Live sessions through `client.voice.session()` — sessions expose an ID and support instruction updates via `client.voice.instructions()`

This is groundwork for voice-driven coding agents. If you're building on the OpenCode SDK, it's worth exploring.

## Quality of Life: Free Limits, Free Models, Fresh Installs

### Clear Free-Limit Recovery
When your free messages run out, Desktop and TUI now show:
- **Reset time** — exactly when you get more messages
- **Your prompt restored** — nothing lost, just re-submit
- **Direct actions** — upgrade or switch models from the error screen

No more generic "limit reached" errors that leave you guessing.

### Hide Free Models Entirely
Set `OPENCODE_DISABLE_FREE_MODELS=1` (or `true`) and zero-cost models disappear from:
- OpenCode catalog
- OpenCode Go catalog
- Defaults
- Fallbacks

Useful if you only want paid models in your workflow (or you're managing a team and want to prevent accidental free-tier usage).

### Installer That Just Works
Fresh installs now:
- Create `~/.zshrc` or Fish's `config.fish` if missing
- Add OpenCode to `PATH`
- Tell you to run `exec $SHELL`

No more "command not found" after install. Windows managed services also now use port `28894`, avoiding ranges reserved by Windows and WSL mirrored networking.

## Other Notable Fixes

**Core:**
- Sessions without their own model now use the selected agent's model
- Compaction buffers that leave the model no room are ignored
- ChatGPT sign-in context caps are now a documented built-in plugin (disable with `-opencode.provider.openai-context-caps` in plugins)
- Added `opencode debug heap-dump [--server <url>]` to capture running server heap without restart
- Custom provider `baseURL` settings now override catalog model endpoints correctly
- Legacy `apply_patch` permissions migrate to `edit` permission
- V1 sessions with relative working directories migrate using their project worktree

**TUI:**
- No longer crashes when file watchers are unavailable or system watch limits exhausted
- Unicode direction marks (Hebrew/Arabic text) no longer shift columns on redraw
- After update restart, TUI tells you to start OpenCode again

**Desktop:**
- File change counts appear before labels in review/summaries
- Renaming session tabs pastes plain text (not formatted)
- Dragging scrollbar no longer forces timeline to end
- Linux AppImage executable names no longer end in `.desktop`
- RPM packages no longer conflict with other Electron apps' build-ID links

**SDK:**
- Added `connectClientMcp()` for hosting MCP tools in a client over experimental client MCP WebSocket transport
- MCP OAuth login keeps waiting after unrelated requests hit its callback
- Remote MCP requests stay open past Bun's fetch idle timeout
- MCP servers started during initial reconciliation no longer duplicated; MCP servers stop in parallel on shutdown
- MCP tools with non-root-object output schemas now accepted
- MCP results keep supported media inline, decode textual resources, save unsupported binary resources to files
- MCP instructions/skills/project references send only changed entries (not full list repeats)
