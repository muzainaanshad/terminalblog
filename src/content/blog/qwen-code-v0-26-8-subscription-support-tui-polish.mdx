## The Headline Features (Ranked by "Wait, This Matters")

### 1. Qwen Subscription Support — One Login, Everywhere

**What it is:** **Qwen subscription (the official Qwen/Alibaba Cloud model access) now works across CLI, VS Code extension, and Desktop app** ([#16378](https://github.com/QwenLM/qwen-code/pull/16378)). Sign in once → your subscription models (Qwen3-Coder, Qwen4, etc.) are available in every interface.

**Why it matters:**
- **No more API key juggling** — subscription auth is unified
- **CLI, VS Code, Desktop all see the same models** — no "works in CLI but not Desktop" gaps
- **Team onboarding** — new dev runs `qwen-code login` → gets full model access instantly

```bash
# One login, all surfaces
qwen-code login
# Opens browser → sign in with Alibaba Cloud / Qwen account
# VS Code extension picks it up automatically
# Desktop app picks it up automatically
```

**For beginners:** This is the "it just works" moment for model access. You don't need to understand API keys, endpoints, or provider configs. You sign in. It works.

---

### 2. Ink TUI Runs on the Shared Loop — Smoother Multi-Agent

**What it is:** The **Ink TUI's model rounds and tool batches now run on the shared agent loop** ([#16206](https://github.com/QwenLM/qwen-code/pull/16206), [#16304](https://github.com/QwenLM/qwen-code/pull/16304), [#16365](https://github.com/QwenLM/qwen-code/pull/16365)).

**Why it matters:**
- **TUI sessions participate in the same coordination** as Web Shell, CLI, and background agents
- **No more "TUI goes rogue" moments** — shared loop = shared state, shared cancellation, shared tool queue
- **Concurrent workspace rewinds work in TUI too** ([#16369](https://github.com/QwenLM/qwen-code/pull/16369))

```bash
# In the TUI — you're now on the shared loop
qwen-code
# Model rounds → shared loop round
# Tool batches → shared loop batch
# Stops → TUI's own stops respected
```

**For beginners:** You know how sometimes the terminal agent feels "disconnected" from the web UI? That's gone. The TUI is now a first-class citizen of the platform.

---

### 3. Web Shell Channel Events Link Directly to GitHub PRs/Issues

**What it is:** **Channel events in the Web Shell now link directly to their GitHub PR or Issue** ([#16226](https://github.com/QwenLM/qwen-code/pull/16226), [#16375](https://github.com/QwenLM/qwen-code/pull/16375)). Click a channel event row → opens the PR/issue in GitHub. Click the session link → opens that session in Web Shell.

**Why it matters:**
- **Full traceability** — "this agent action came from *that* PR"
- **Debugging** — see the GitHub context, then jump to the agent session that acted on it
- **Audit trail** — compliance teams love this

---

### 4. Role-Aware Channel Templates + On-Demand Editing

**What it is:** **GitHub bound-session delivery now uses role-aware action templates** ([#16258](https://github.com/QwenLM/qwen-code/pull/16258)), and **you can edit templates on demand** ([#16349](https://github.com/QwenLM/qwen-code/pull/16349)).

**Why it matters:**
- **Different roles = different prompts** — "reviewer" gets code-review prompt, "tester" gets test-gen prompt, "deployer" gets deploy prompt
- **No more one-template-fits-all** — templates adapt to the agent's role in the workflow
- **Edit live** — tweak a template without redeploying

---

### 5. Mods Submit Their Own Prompts in Headless Runs

**What it is:** **A Mod can now submit a prompt of its own in headless (`-p`) runs** ([#16302](https://github.com/QwenLM/qwen-code/pull/16302)), and **those prompts run in the Ink terminal** ([#16373](https://github.com/QwenLM/qwen-code/pull/16373)).

**Why it matters:**
- **Automated guardrails at prompt level** — a Mod sees a risky prompt, rewrites it, submits the safe version
- **CI/CD integration** — `qwen-code -p "deploy to prod"` → Mod intercepts → adds safety checks → submits modified prompt
- **Works in TUI too** — the Mod's prompt appears in the terminal like any user message

```bash
# Mod intercepts and rewrites
# Before: qwen-code -p "delete all prod databases"
# After:  qwen-code -p "delete all prod databases --dry-run --confirm-each"
```

---

### 6. Concurrent Workspace Rewinds

**What it is:** **Managed agents now support concurrent workspace rewinds** ([#16369](https://github.com/QwenLM/qwen-code/pull/16369)). Multiple workspaces can rewind simultaneously without blocking each other.

**Why it matters:**
- **Team scale** — 20 workspaces, each rewinding to a clean state for the next sprint
- **No queue** — rewind is no longer a global lock
