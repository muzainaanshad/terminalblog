Zed **v1.24.4 stable dropped October 20**, and it's the rare release where the headline feature isn't a new button — it's **what disappeared**.

**Binary sizes slashed across the board:**
- **macOS ARM64: 33% smaller** (258MB → 172MB)
- **Windows x64: 28% smaller** (359MB → 256MB)
- **Linux x64: 7% smaller** (317MB → 295MB)

Plus: **Pyrefly** (Facebook's new Python type checker) as an optional built-in LSP, **nested variable inspection in debugger hovers**, and **DWARF debugging for WebAssembly** in the JS debugger.

---

## The One Thing You'll Feel Immediately: It's Just... Smaller

Zed's team spent the last cycle optimizing selected workspace crates for size and hiding Rust exports in macOS bundles. The measurements speak for themselves:

| Platform | Architecture | Before | After | Reduction |
|----------|-------------|--------|-------|-----------|
| macOS | ARM64 | 258 MB | 172 MB | **33.2%** |
| Linux | x86_64 | 317 MB | 295 MB | **6.96%** |
| Windows | x86_64 | 359 MB | 256 MB | **28.5%** |

**Why this matters:** Faster downloads. Less disk. Faster cold starts. On CI/CD where you spin up Zed containers, this compounds. On laptops with 256GB SSDs, you just got 86MB back on Mac.

The optimization didn't sacrifice speed — they explicitly measured and maintained performance. This is the "make it smaller, keep it fast" discipline that separates native editors from Electron apps.

## Pyrefly: Facebook's Python Type Checker, Built In (Optional)

**New in v1.24.4:** Pyrefly as an optional built-in Python language server.

```toml
# In your Zed settings or project config
[languages.python]
language_server = "pyrefly"
```

**What is Pyrefly?** Facebook's open-source Python type checker and LSP — written in Rust, designed for speed. It's not `pyright` (Microsoft) or `basedpyright` (community fork). It's a fresh implementation that Facebook uses internally at massive scale.

**Why optional?** Because Python tooling is religious. Some teams swear by `pyright`, others by `ruff` + `basedpyright`, others by `pyrefly`. Zed gives you the choice without forcing a default.

**For beginners:** You don't need to configure anything. If you want Pyrefly, toggle it on. If you're happy with your current Python LSP, nothing changes.

## Debugger Hovers: Finally See Nested Variables Without Clicking

**New:** Expand and inspect nested variable values **directly in debugger hovers**.

Before: hover a variable → see top-level value → click to open Variables panel → expand → drill down → lose your place in the editor.

Now: hover → **see the nested structure inline** → drill down in the hover itself → keep coding.

```python
# Hover `user` and you see:
user = {
    "name": "Alice",
    "address": {           # ← expand this in the hover
        "street": "123 Main",
        "city": "Boston",
        "coords": {        # ← and this
            "lat": 42.36,
            "lng": -71.05
        }
    }
}
```

**Why it matters:** Debugging is 80% "what's in this object right now?" The fewer context switches between editor and debugger panel, the faster you find the bug.

## DWARF Debugging for WebAssembly: Your JS Debugger Now Speaks WASM

**New:** DWARF debugging for WebAssembly sources in the JavaScript debugger.

If you compile Rust/C++/Go to WebAssembly and debug the output in Zed, **source-level debugging now works**. You set breakpoints in your original `.rs`/`.cpp`/`.go` files, step through WASM execution, and see variables with proper types.

**Why this matters:** WASM debugging has historically been "good luck, here's a hex dump." DWARF support means Zed treats WebAssembly like any other compiled target — because it *is* just another compiled target.
