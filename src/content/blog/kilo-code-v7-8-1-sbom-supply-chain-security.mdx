## The Headline: Every Artifact Now Ships a Tamper-Evident Receipt

**v7.8.1 (Sep 30)** made CycloneDX Software Bills of Materials (SBOMs) standard across **every distribution channel**:

| Artifact | SBOM | Attestation |
|----------|------|-------------|
| CLI Linux/macOS/Windows archives | `kilo-*-sbom.json` / `.cdx.json` | GitHub attestation |
| npm package (`@kilocode/cli`) | Published with provenance | GitHub attestation |
| Container images (`kilocode/kilo`) | Attached via `cosign`/`notation` | GitHub attestation |
| VS Code extension (`.vsix`) | Bundled SBOM | GitHub attestation |
| JetBrains plugin (`.zip`) | Bundled SBOM | GitHub attestation |

**All signed by GitHub Actions during the release workflow. No maintainer keys to manage. No separate signing infrastructure.**

```bash
# Verify the CLI archive you downloaded
gh attestation verify kilo-darwin-arm64.zip \
  --repo Kilo-Org/kilocode \
  --signer-workflow build.yml
```

If the hash doesn't match, the attestation fails. Period.

## Why This Matters for *You* (Not Just Security Teams)

### 1. Your Editor Extension Can't Be Silently Swapped
The VS Code Marketplace and JetBrains Marketplace are generally trustworthy — but they're centralized. If a maintainer's account is compromised, or a marketplace is breached, a malicious update could push to thousands of developers.

With SBOM attestations: **you (or your IT team) can pin the exact artifact hash and verify it before install.** No trust required.

### 2. Container Images Are Now Auditable
```dockerfile
# Before: you pulled kilocode/kilo:latest and hoped
# After: you verify the SBOM attestation for that exact digest
docker pull kilocode/kilo@sha256:abc123...
gh attestation verify kilocode/kilo@sha256:abc123... --repo Kilo-Org/kilocode
```
CI pipelines can now gate deployments on attestation verification. **Supply-chain security becomes a CI check, not a prayer.**

### 3. Compliance Just Got Easier
If your org requires SBOMs for vendor software (EO 14028, EU CRA, FedRAMP, SOC 2) — **Kilo Code now ships them automatically.** No vendor questionnaire. No manual requests. The artifacts *are* the evidence.

### 4. Dependency Drift Is Now Visible
The SBOM lists every transitive dependency with its version and hash. If a future release unexpectedly pulls in a new dependency (or a compromised version of an existing one), **the SBOM diff shows it immediately.** Security teams can diff SBOMs between releases instead of reading changelogs and hoping.

## v7.8.2/v7.8.3: The Daily UX Polish Wave

### Copy Content Button in Documents Viewer (v7.8.3)
The Documents viewer toolbar now has a **copy content button**, and the document tab context menu expands with:
- Copy Path
- Copy Relative Path
- Copy File Name
- Open in Editor

Small thing, used dozens of times a day.

### Manual Fetch Models Button for Custom Providers (v7.8.3)
Custom Provider settings dialog now has a **manual "Fetch Models" button**. No more waiting for auto-refresh or restarting VS Code to see new models from your custom endpoint.

### Multi-Root Workspace @-Mention Support (v7.8.3)
Typing `@` in a multi-root VS Code workspace now **suggests files from every folder** — including folders added through "Add Folder to Workspace..." — without reaching for the file picker. Files outside the session's project still require the usual approval.

### Agent Manager Selection Persistence (v7.8.3)
The **latest Agent Manager selection persists** when another project finishes loading. No more losing your place when switching contexts.

### Browser Preview Resize Fix (v7.8.3)
Agent Manager browser preview **stays visible when you resize its panel**. Previously it would vanish or clip.

### Code Snippet Highlighting on Response Finish (v7.8.3)
Code snippets **highlight when a response finishes** — without requiring a follow-up message. Visual confirmation that the agent produced code.

### Revert Failure Reporting (v7.8.2/v7.8.3)
**Failed reverts/redos now show an error toast** instead of failing silently. The snapshot steps behind it log the git exit code and stderr when they give up. You actually know when something went wrong.

### Keep Latest Agent Manager Selection (v7.8.3)
Selection persists across project loads.

### Collapsed Pastes Preserved in Prompt History (v7.8.3)
Browsing prompt history with arrow keys **keeps collapsed pastes collapsed**. No more accidental expansion.

### View Details Action for Marketplace Suggestions (v7.8.3)
Marketplace suggestion notifications get a **"View details" action** that opens the item in the Kilo Marketplace panel with search prefilled.

### Background Agent Avatar Animation (v7.8.3)
Avatar animation above the prompt input **stays smooth** even under load.

### Prompt Cache Prefixes Preserved Across Goal Turns (v7.8.2/v7.8.3)
Prompt cache prefixes survive **goal turns, compaction, and completion**, and the working timer runs through turn boundaries and rejected commands until the goal stops.

### Stop Single Sub-Agent from Task Card (v7.8.3)
You can now **stop a single sub-agent from its task card**, and follow background agents of the current run next to the working status and session actions. Click opens, stops, or clears them. The background agent bar above the chat is removed; sub-agent running animation is easier to see.

### Apply Pending Autocomplete Edits from Quick-Fix Menu (v7.8.3)
VS Code quick-fix menu now applies pending autocomplete edits.

### CLI: Full Model Output Limit for Claude Sonnet/Opus (v7.8.2/v7.8.3)
Uses the full model output limit for Claude Sonnet, Opus, and Claude-family aliases (e.g., Auto Frontier) to prevent responses from ending early during long reasoning.

### CLI: Scheduled Session Reporting (v7.8.2/v7.8.3)
Sessions asleep on pending wakeup or cron task report as `scheduled` with their wake time.

### CLI: Suggested Next Steps with Clickable Actions (v7.8.2/v7.8.3)
Shows suggested next steps in the CLI with **clickable action buttons**, and shows whether each suggestion was accepted or dismissed.

### CLI: Context-Limit Error Recovery (v7.8.2/v7.8.3)
Recovers from provider context-limit errors by **compacting and retrying** when the provider reports the request exceeded the model's context length.

### CLI: Stop Sending `prompt_cache_breakpoint` to Custom Providers (v7.8.2/v7.8.3)
Custom OpenAI-compatible providers and first-party provider IDs rerouted through custom endpoint overrides no longer receive the unsupported parameter (which caused HTTP 400).

### CLI: Show Kilo Gateway Models Without Supported Parameters (v7.8.2/v7.8.3)
Models like Jev Router that don't report supported parameters now appear in the model list.

### CLI: File Storage Usable After Cancelled Operation (v7.8.2/v7.8.3)
Wakeups, cron tasks, and session fork diffs no longer fail until Kilo restarts after a cancelled operation interrupts first access.

### CLI: Restrict Session PR Linking to CLI Backends (v7.8.2/v7.8.3)
VS Code, Agent Manager, JetBrains, and other clients keep existing PR integrations without running the separate session-link mechanism (including when controlled from mobile).

## How to Update

### VS Code / JetBrains
1. Open Extensions / Plugins
2. Search "Kilo Code"
3. Click **Update** to v7.8.3

```bash

npm view @kilocode/cli@7.8.3 --json | jq '.attestations'
```

```bash

# Verify attestation
gh attestation verify kilocode/kilo:7.8.3 --repo Kilo-Org/kilocode
```
