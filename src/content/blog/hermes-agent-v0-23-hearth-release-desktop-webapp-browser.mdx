**Hermes Agent v0.23.0 dropped November 5, 2026** — and it's the biggest release since v0.22 "Threshold" opened the door. Codename: **The Hearth Release**.

**v0.23.1 followed November 10, 2026** — a stable patch rolling up ~618 PRs merged since v0.23.0 with stability polish for the webapp, gateway, plugins, and desktop.

The headline: **your entire Desktop workspace now opens in a browser tab**, served by your own gateway. Underneath, every conversation lives in one place — a single gateway owns each session, and the CLI, TUI, Desktop, editors, bots, and cron all sit at the same table instead of each running its own agent.

Since v0.22.0: **~10,080 commits · ~1,950 merged PRs · ~8,720 files changed · ~850 issues closed · 666 contributors**.

---

## The Headline Features (Ranked by "Wait, It Does That Now?")

### 1. Your Desktop Workspace in a Browser Tab — The Webapp

**What it is:** A new Webapp that serves the **full Desktop workspace from your own gateway** — same chats, Group Chats, plugins, settings — in any browser on your network, or behind a public URL with sign-in. Docker image and Nix package ship it. Off by default; enable with `webapp.enabled` or "Web Access" in Settings.

**Why it matters:** You no longer need the Desktop app installed to access your full Hermes environment. Open a browser on your phone, tablet, or another machine → your chats, your plugins, your Group Chats, all there. The gateway *is* the workspace now.

**For beginners:** Install Hermes once on a machine (your laptop, a VPS, a home server). Enable the webapp. Now you have a coding agent you can reach from *any browser*, anywhere. No VPN, no SSH tunneling, no "which machine was that chat on?"

---

### 2. One Gateway Owns Every Conversation — No More Split Brains

**What it is:** Before, the CLI, TUI, Desktop, editors (ACP), messaging bots, and cron could each run their own copy of the agent against the same chat. That's how messages got written twice or went missing between surfaces. Now **each machine runs one gateway that owns every session**, and every surface attaches as a client. A chat you open anywhere is the *same* chat — one queue, one history. You can even steer or edit a queued prompt from Desktop without it running twice.

**Why it matters:** This fixes the "which window has the real conversation?" problem permanently. Your CLI session, your Desktop tab, your editor's ACP panel — they're all looking at the same chat. Edit a prompt in one, it updates everywhere. Send a message from another, it appears in all.

**For beginners:** You know how you have a chat in the terminal, then open Desktop and it's... different? Or you send something in VS Code and the terminal doesn't see it? That's gone. One gateway = one truth.

---

### 3. Pictures in the Terminal — Real Pixels, Not File Paths

**What it is:** When you paste an image, or a tool takes a screenshot, the CLI and TUI now **draw it right in the chat**:
- Real pixels in **kitty** and **Ghostty** (CLI and TUI)
- Real pixels in **iTerm2, WezTerm, Konsole** (CLI)
- Coloured blocks everywhere else (fallback)
- Full resolution in **VS Code's terminal** when its image support is on

**Why it matters:** Screenshots, diagrams, UI mockups, error screens — they're *in* the conversation now. No more "opening a file" to see what the agent saw.

**For beginners:** Paste an image (Ctrl+Shift+V in most terminals). It renders. Ask the agent "what's in this screenshot?" — it sees it. Tools that take screenshots (Playwright, browser automation) show results inline.

---

### 4. Rewind a Conversation — The Undo Button You Always Wanted

**What it is:** Press **Esc twice** or type `/rewind` in the TUI or classic CLI, pick an earlier message, then **edit and resend it** or **fork a new session from that point**. The original session stays exactly as it was. The TUI can also start `/new` while a turn is still running; the old one keeps working in the background.

**Why it matters:** Agent went down a rabbit hole? Rewind to before the wrong turn, correct the prompt, go a different direction. Fork a "what if" branch without losing the main thread. This is version control for *conversations*.

**For beginners:** Made a typo in a complex prompt? Agent misunderstood? Don't start over — rewind, fix, resend. It's the "oops" button that actually works.

---

### 5. Every Machine in One Desktop Window

**What it is:** Desktop now keeps **all your gateways connected at once** — your laptop, an SSH gateway, a remote VPS. Switching between them is instant. Terminal tabs run on the host they were opened on. A Group Chat can mix bots from *different machines*.

**Why it matters:** You run Hermes on three machines. Before, you had three Desktop windows (or SSH'd around). Now: one Desktop window, three gateway tabs, one Group Chat that spans all of them.

**For beginners:** Add a remote gateway (SSH or HTTPS) in Desktop settings. It appears as a tab. Done. Your home server, your laptop, your cloud VM — one UI.

---

### 6. Group Chats That Run Themselves

**What it is:** Bot Mode rooms can let a **lead bot** or an **automatic router** pick who answers a message that names nobody. Scheduled jobs can post into a room. Rooms keep a purpose and shared notes. Bots no longer ping each other in endless loops. Rooms look like a normal Hermes chat now, and each bot shows what it's doing live ("scout · terminal · 7s").

**Why it matters:** You can build a "team" of specialized bots (coder, reviewer, researcher, deployer) that coordinate themselves. Drop a task in the room → the right bot picks it up → you watch the live status.

**For beginners:** Create a Group Chat. Add 3-4 bots with different skills (one knows your codebase, one knows AWS, one writes tests). Turn on "auto-route." Drop a message: "refactor the auth module." Watch them collaborate.

---

### 7. Plugins That Keep Themselves Current

**What it is:** `hermes plugins update` updates **everything at once**. An opt-in **Auto-update switch** (CLI, chat, Desktop, dashboard) keeps catalog and git plugins up to date. Updates that would break your setup are **held back instead of applied**. The catalog grew from ~600 to **over 1,050 entries**, and a new **Verified tier** marks plugins built by the vendor itself.

**Why it matters:** Plugin rot is real. This makes "stay current" a one-click (or zero-click) operation, with safety rails.

**For beginners:** Enable auto-update in Settings. Your plugins update themselves. Verified badge = the actual vendor maintains it (Meshy, ElevenLabs, etc.).

---

### 8. Price Tags and Spend Limits for Paid Tools

**What it is:** Paid MCP tools (3D generation, media generation, etc.) can **declare what a call costs**. The approval prompt shows **each call's price** and the **chat's running total**. Hermes asks before a chat goes over its limit — **even in YOLO mode**.

**Why it matters:** No surprise bills. You set a budget per chat. The agent tells you "this call costs $0.12, running total $3.47, limit $5.00 — proceed?" before every paid call.

**For beginners:** Set `spend_limit_usd` in a chat. Use paid tools (Meshy 3D, ElevenLabs audio) without fear. The agent *shows you the receipt* before spending.

---

### 9. New Official Plugins + Smaller Core

**What's new (one-command install):**
- **Meshy** — text and image to 3D
- **ElevenLabs Music and Sound Effects**
- **X Chat** (formerly Twitter)
- **REA** — reverse engineering
- **Bubblewrap sandbox**

**Moved to plugins (auto-install for existing users):**
- Camofox, `mcp-serve`, agent importers, Singularity

**Why it matters:** Core gets leaner. Capabilities arrive as plugins you opt into. The "kitchen sink" problem — solved by making the sink modular.

---

### 10. Choose How Subagents Run — Pluggable Delegation

**What it is:** Delegation is now **pluggable**. Keep the default, or install the official `advanced-delegation` plugin to send each subagent task to a **named model** or into a **separate profile**. Switch with `/delegation`.

**Why it matters:** "Use Opus for architecture, Haiku for boilerplate, GPT-6 for tests" — now a config, not a hack. Each subagent can run on different hardware, different models, different profiles.

**For beginners:** Install `advanced-delegation`. Configure: "planning → Opus 5.5", "coding → Sonnet 5.5", "tests → Haiku 5.5". The agent routes automatically.

---

### 11. Lighter and Faster — Especially When Hermes Runs All Day

**What it is:**
- Recurring cron jobs **share a prompt cache**
- One-shot runs send **~1,570 fewer prompt tokens** per call
- `patch`/`write_file` return in **milliseconds with LSP on**
- Long-lived gateways **let go of closed sessions' memory**
- Desktop sidebar no longer slows down as sessions pile up (one store with ~35k cron runs went from **121s refresh → instant**)

**Why it matters:** Hermes is now a service you leave running for weeks, not a tool you restart daily. Memory stays flat. Latency stays low. The "long-lived agent" problem — substantially solved.

---

### 12. A Leaner Skill Set You Can Lock

**What it is:** Built-in skills went from **58 → 44**. Word, PowerPoint, Excel merged into one `microsoft-office` skill. **`hermes curator lock`** stops the agent from rewriting a skill you curated by hand — through *any* tool, even in YOLO mode.

**Why it matters:** Less bloat. More control. Your custom skills stay *yours*.

## What This Means for You

### If you're new to coding agents:
**v0.23 changes the "first run" entirely.**
1. Install Hermes → `hermes login` → enable Webapp → you have a coding agent in your browser, on your phone, on your tablet.
2. Desktop app = one window for *all* your machines.
3. Terminal images = you *see* what the agent sees.
4. Rewind = mistakes are reversible.
5. Plugins auto-update = capabilities grow while you sleep.

The learning curve just got a ladder.

### If you run Hermes in production (cron, CI, bots):
- **Unified gateway** = no more "which process owns this chat?"
- **Prompt cache sharing** = cron costs drop measurably.
- **Memory release** = gateways don't OOM after weeks.
- **Spend limits** = paid tools in automation = controlled costs.
- **Plugin auto-update (held back on breakage)** = dependencies stay fresh without surprise breakage.

### If you build on Hermes (plugins, integrations, frontends):
- **Webapp** = your UI can be a thin client to the gateway.
- **ACP improvements** = editor integrations get the unified session model.
- **Pluggable delegation** = your plugin can define how subagents run.
- **Verified tier** = vendor-built plugins get discoverability.
- **1,050+ catalog** = distribution channel for your plugin.

## What's Still Missing (Honest Assessment)

- **Webapp auth UI** — Sign-in flow exists but is minimal; no SSO/SAML/OIDC yet
- **Mobile-native apps** — Webapp works in mobile browsers; no iOS/Android apps
- **Visual trace viewer** — W3C trace context emitted; no built-in UI to explore it
- **Plugin marketplace payments** — Spend limits work; no marketplace billing/split
- **Multi-user gateway** — Single-user per gateway; team workspaces = multiple gateways
- **Group Chat persistence export** — No "download room history" button yet

## How to Upgrade

```bash
# CLI / TUI / Gateway
hermes update

# Or re-run the installer
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

# Desktop: auto-updater handles it (check Settings → Updates)
# Docker
docker pull ghcr.io/nousresearch/hermes-agent:latest

# Nix
nix profile upgrade github:NouResearch/hermes-agent
```

**First things to try after update:**

```bash
# 1. Enable the Webapp
hermes config set webapp.enabled true
# Or: Settings → Web Access → Enable
# Then open http://localhost:8765 (or your gateway URL) in a browser

# 2. Paste an image in the CLI/TUI
# Ctrl+Shift+V → watch it render inline

# 3. Rewind a conversation
# In TUI: Esc Esc → pick message → edit → resend
# In CLI: /rewind

# 4. Add a remote gateway in Desktop
# Settings → Gateways → Add → SSH or HTTPS URL

# 5. Create a Group Chat with auto-route
# Desktop → New Group Chat → add bots → enable "Auto-route unnamed messages"

# 6. Try a paid plugin with spend limits
hermes plugins install meshy
# In chat: /spend_limit 5.00
# Ask: "generate a 3D model of a coffee mug"

# 7. Check the plugin catalog
hermes plugins search
# Look for "Verified" badge — vendor-maintained

# 8. Test pluggable delegation
hermes plugins install advanced-delegation
/delegation advanced
# Configure model routing per subagent type
```

## The Bottom Line

**v0.22 got newcomers through the door. v0.23 builds the fire they gather around.**

- **Webapp** = your workspace is a URL
- **Unified gateway** = one truth, no split brains
- **Terminal images** = see what the agent sees
- **Rewind** = conversation version control
- **Multi-machine Desktop** = one UI, all your infrastructure
- **Self-running Group Chats** = agent teams that coordinate
- **Auto-updating plugins** = capabilities that maintain themselves
- **Spend limits** = paid tools without surprise bills
- **Pluggable delegation** = your routing logic, not ours
- **Leaner core, 1,050+ catalog** = opt-in power, not bloat

The pattern holds: Hermes isn't chasing "shiny feature of the week." It's building the **infrastructure layer** for agents that live *with you* — across machines, across surfaces, across days and weeks.

For a beginner, that means **fewer config knobs, fewer "which window?" moments, fewer "where did my chat go?" panics**. For a builder, it means **Hermes is becoming a platform you can ship on top of — securely, scalably, invisibly**.

hermes update
