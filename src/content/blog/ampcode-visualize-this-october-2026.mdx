## What "Visualize This" Actually Does

You describe what you want visualized. Amp:
1. Builds the visualization as a React component (using Amp's internal view kit — 50 KB of components, 55 icons, chart helpers)
2. Renders it **inline in the thread** — interactive, hoverable, clickable
3. Shows **platform variants** (iOS Liquid Glass, Android Material, Web) at real size
4. Lets you **pick a variant** → it appears above the composer → you say "ship it" or "tweak X"
5. Iterates in the same thread — no context switch, no Figma, no Storybook

## How It Works Under the Hood

**Amp's view kit** — ~50 KB of React components built for this:
- Chart primitives (bars, lines, areas, pies, rings, gauges)
- 55 icons (Lucide-based, consistent stroke weight)
- Layout helpers (grids, stacks, responsive containers)
- Platform rendering (iOS Liquid Glass, Android Material, Web)
- Interaction primitives (hover, click, drag, gesture)

When you ask for a visualization, Amp:
1. Writes a React component using the view kit
2. Renders it in a sandboxed iframe in the thread
3. Streams props updates as you iterate ("make the bars thicker," "switch to log scale")
4. The component *stays alive* — you interact with it, not a static image

## Why This Matters for Beginners

**You don't need to know React, Chart.js, D3, or Figma to get production-ready visualizations.**

- **Data exploration** → "Show me the error rate by endpoint over time" → interactive chart appears
- **API design** → "Diagram the request/response flow for this webhook" → sequence diagram renders
- **UI decisions** → "Show me 5 ways to display this status badge" → 5 interactive variants at real size
- **Debugging** → "Visualize the call graph for this function" → interactive graph you can traverse
- **Documentation** → "Build a timeline of this incident" → shareable, interactive timeline

The agent builds the *tool* to understand the data. You use the tool. The tool stays in the thread.

## The View Kit Is Not Public (Yet)

The 50 KB component library powering this is internal to Amp. You can't `npm install` it. But you don't need to — **Amp writes the components for you.** The visualization lives in your thread, built on-demand, thrown away when the thread ends (or kept if you say "save this as a component in my repo").
