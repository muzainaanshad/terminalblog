Writing good commit messages is the chore every developer knows they should do but often skips. "fixed stuff" or "update" litter the history of every project.

Gitlawb Zero just fixed this with a single flag: `--auto`.

## How It Works

When you stage your changes and run `zero --auto`, the agent:

1. Reads the `git diff --staged` output
2. Analyzes what changed and why
3. Generates a conventional commit message with type, scope, and description
4. Applies it via `git commit -m`

The result is messages like:

```
feat(auth): add OAuth token refresh flow for ChatGPT integration
fix(tui): keep profile name on /model switch so stored key resolves
docs(install): recommend bun pm trust for Bun installs
```

Each message follows conventional commits format, making them useful for changelog generation and semantic versioning.

## The Implementation

The `--auto` flag (PR #423) works through Zero's existing git integration. It doesn't replace your editor — it augments it. You can still write custom messages for important commits, but for the routine ones, `--auto` handles it.

The flag is model-agnostic. Zero uses whatever provider you have configured to generate the message, so the quality scales with your model choice.

### Under the hood: the prompt pipeline

The commit message generation isn't a single prompt — it's a small pipeline:

1. **Diff extraction** — `git diff --staged --no-color` captures the exact changes
2. **Context enrichment** — File paths, recent commit history (last 5), and `.gitmessage` template if present
3. **Structured prompt** — A system prompt enforcing conventional commits format, scoped to your repo's patterns
4. **Model call** — Your configured provider (Claude, GPT, local, Copilot, etc.)
5. **Validation** — Regex check for `type(scope): description` format; retry on failure
6. **Apply** — `git commit -m "<message>"` with the validated output

This pipeline runs in ~2-3 seconds on a typical staged diff. The validation step is key — it catches hallucinated formats before they pollute history.

## Configuration Options

The `--auto` flag accepts optional arguments for finer control:

- `--auto --type=<type>` — Force a specific conventional commit type (feat, fix, docs, chore, refactor, test, style, perf)
- `--auto --scope=<scope>` — Set a custom scope instead of auto-detected
- `--auto --dry-run` — Preview the message without committing

```bash
# Preview what --auto would generate
zero commit --auto --dry-run

# Force a specific type for a batch of refactoring commits
zero commit --auto --type=refactor

# Use with a specific model for higher-quality messages
zero commit --auto --model=claude-3-5-sonnet
```

### Advanced: repo-level configuration

You can persist defaults in `.zero/commit.yaml`:

```yaml
auto:
  default_model: "claude-3-5-sonnet"  # Override global model for commits
  template: ".gitmessage"             # Use existing commit template
  max_files: 20                       # Skip auto if diff touches >20 files
  require_scope: true                 # Reject messages without (scope)
```

This lets teams enforce standards — e.g., requiring scopes on all commits, or using a specific model for commit quality.

## When to Use (and When Not To)

**Use `--auto` for:**
- Routine feature work, bug fixes, documentation updates
- Refactoring batches where each commit follows the same pattern
- Keeping history clean on feature branches before PR
- Chores: dependency updates, formatting, renames

**Write manually for:**
- Breaking changes that need detailed rationale
- Security fixes requiring audit trail
- Architecture decisions future maintainers will thank you for
- Multi-file refactors where the "why" isn't obvious from the diff

The 80/20 rule applies: let `--auto` handle the 80% of routine commits, invest your attention on the 20% that matter.

## Real-World Workflow: Feature Branch Hygiene

A common pattern with `--auto`:

```bash
# Start feature
zero session --name "feat/payment-retry"

# Work... make changes... stage incrementally
git add src/payment/retry.ts
zero commit --auto --dry-run    # Preview
zero commit --auto              # Commit: feat(payment): add exponential backoff for failed transactions

git add tests/payment/retry.test.ts
zero commit --auto              # Commit: test(payment): cover retry backoff and max-attempts

git add docs/payment.md
zero commit --auto              # Commit: docs(payment): document retry configuration

# Push and PR — history is clean, messages are useful
git push origin feat/payment-retry
```

Contrast with the typical "commit at the end with 'feat: payment retry stuff'" — the incremental approach gives you bisectable history, meaningful changelogs, and zero cognitive overhead.
