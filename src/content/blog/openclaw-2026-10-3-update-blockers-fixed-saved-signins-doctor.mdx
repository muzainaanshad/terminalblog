## 1. Updates That Don't Strand You (The Big One)

**What it does:** Updates now **clear eligible leftover recovery work** and **archive completed update records** that previously blocked the next upgrade (#168388, #169038).

**In English:** You hit "update." Something interrupts it (Windows elevation prompt, network blip, laptop sleep). **Before:** Stranded install, blocked future updates, manual cleanup. **Now:** Update recovers. Next time you run it, it picks up where it left off or cleanly restarts.

**Also fixed:**
- **Interrupted 2026.9.8 updates** — updated CLI settles aborted records that prevented another update (#169027)
- **FreeBSD package recovery** — recovery helpers repair or retire interrupted npm package updates (#168775)
- **Leftover updater copies** — Doctor removes abandoned npm updater copy that prevents the next update (#170170)
- **Candidate checks with older updaters** — newer candidate no longer rejected solely because Doctor would update version/setup/migration bookkeeping (#170195)
- **Older Node updaters** — avoid unnecessary rollback when time measurement differs (#169915)
- **Updates requested in chat** — fixed Doctor cleanup check that falsely refused permission and rolled back chat-requested updates (#170218)
- **Doctor during updates** — Doctor continues after later process check fails when it already verified the updater (#169563, #169665)
- **Windows service accounts** — updates recognize different Task Scheduler names for same service account (#169481)
- **Windows update/recovery paths** — updater workers recognize short names and different capitalization for same installation folder (#169292, #169397)
- **pnpm service commands** — new/repaired Gateway service commands use pnpm's durable installation link (#170003)
- **pnpm 12 launchers** — fixed native pnpm updates keep `openclaw` command usable after staging cleanup (#170131)
- **Service refresh refusals** — update restarts preserved Gateway service after safely refusing to rewrite its definition (#169658)
- **Busy state databases** — optional progress logging no longer aborts update solely because database is briefly busy (#168210, #169283)
- **Unrelated dependency copying** — updates avoid copying dependencies from unrelated enclosing installations (#168927, #169551)
- **Configured update memory limits** — update commands retain configured Node memory limits (#168889)
- **Repair outcomes and next steps** — unfinished Doctor maintenance reported as pending with useful next action (#167714, #168905)
- **Update handoff reports** — already reported update outcome no longer produces second misleading failure (#168587, #168993)

**Why beginners care:** Updating agent runtimes used to be a "clear your schedule" event. Now it's **fire-and-forget**. This is the difference between "hobby project" and "production infrastructure."

## 2. Saved Sign-Ins Survive Doctor Repairs

**What it does:** An unreadable legacy auth file **no longer causes the affected cleanup to discard saved OAuth profiles** (#170256).

**Before:** Doctor runs a repair → encounters unreadable legacy auth file → **discards ALL your saved OAuth profiles** (GitHub, Anthropic, OpenAI, Google, etc.). You re-authenticate everything.

**Now:** Doctor **identifies the file to inspect or restore before retrying**, while unrelated repairs continue. Previously deleted profiles and retired credential imports are not restored (correctly), but your active sign-ins **survive**.

**Why it matters:** You spend hours setting up model providers, MCP servers, plugin auth. A routine Doctor run shouldn't nuke it. Now it doesn't.

## 3. Mac App Finally Connects on First Run

**What it does:** Fixes that let the Mac app connect during local setup.

**Before:** Install Mac app → open → "Cannot connect to Gateway" → confusion → give up.

**Now:** It just connects. The local Gateway starts, the app finds it, you're working.

**Why it matters:** Mac users are a huge chunk of the coding agent audience. First-run experience = adoption. This removes a major friction point.

## 4. Conversations That Survive Compaction and Interrupted Replies

**What it does:** 
- **Deleting an unfinished conversation** — records cancellation before stopping its unfinished reply, allowing chat clients to receive the cancelled status (commit e115a6a)
- **Interrupted provider replies** — conversations continue after compaction or interrupted provider replies

**Before:** Provider times out mid-stream → conversation context corrupted → you lose the thread.

**Now:** Cancellation is explicit. Chat clients know what happened. Context stays clean.

**Why it matters:** You're in a deep debugging session. Provider hiccups. **You don't lose your place.** The conversation is recoverable.

---

## 5. Windows: Service Accounts, Paths, and pnpm Fixed

**What it does:** Multiple Windows-specific fixes that make OpenClaw behave like a native Windows citizen:

- **Service accounts** — Updates recognize different Task Scheduler names for the same service account and can restart the Gateway without rewriting a service owned by somebody else (#169481)
- **Update/recovery paths** — Updater workers recognize short names and different capitalization for the same installation folder. Recovery snapshots stop rejecting their own Windows temporary directory (#169292, #169397)
- **pnpm 12 launchers** — Fixed native pnpm updates keep the `openclaw` command usable after staging cleanup, including with a symlinked global bin folder (#170131)

**Why it matters:** If you run OpenClaw on Windows (especially in a team with mixed account setups), these were the papercuts that made you consider switching to Linux. Fixed.

---

## 6. Codex Plugin Compatibility & Plugin Package Repairs

**What it does:**
- **Codex plugin compatibility** — Official external Codex packages older than 2026.9.7 are reported unavailable before they break replies. Eligible official updates follow the core release (#170306)
- **Plugin package repairs** — A replacement package can be saved while its data migration is unfinished, allowing Doctor to continue. **Finish `openclaw doctor --fix` before restarting or reloading the replacement** (#170339)

**Why it matters:** Plugin ecosystem reliability. Your custom tools and integrations don't break silently when core updates.
