OpenCode doesn't do press releases. It does patch releases — steady, unsexy, and exactly what you want from infrastructure.

v1.18.35 dropped October 6, 2026. Three bullet points in the changelog. But the signal matters: **OpenCode is becoming the agent you don't have to think about.**

---

## What Actually Changed

### 1. xAI Tool Results Now Show Images

If you're using xAI models (Grok), tool results that return images now actually render them. Unsupported image formats are skipped gracefully instead of breaking the flow.

Community credit: **@Jaaneek** — bumped `@ai-sdk/xai` to 3.0.139 so tool-result images reach xAI properly.

This matters more than it sounds. xAI's Grok models are increasingly competitive for coding tasks, and visual output (charts, diagrams, UI mockups) is becoming a first-class part of the agent workflow. OpenCode treating images as native citizens — not an afterthought — signals provider parity is real.

### 2. Canonical Redirects + Agent-Readable Stats

OpenCode now serves canonical redirects and offers JSON and Markdown data formats for stats. This means:

- **Scripts and agents can read your usage stats programmatically**
- No more scraping HTML
- Clean, versioned data formats

For anyone building dashboards, cost trackers, or automation on top of OpenCode — this is the API you've been waiting for.

Think about what this enables: an agent that monitors its own token spend and switches providers when thresholds hit. A dashboard that aggregates usage across your team without manual exports. A cost guardrail that actually works because the data is structured, not scraped.

### 3. Community Fixes (3 Contributors)

| Contributor | Fix |
|-------------|-----|
| **@dc85** | Added Fledge Alpha Free to Zen docs |
| **@jm0ney337** | Added opencode-supabase to ecosystem plugins |
| **@Jaaneek** | Fixed xAI image support in tool results |

OpenCode's plugin ecosystem is quietly growing. The supabase plugin alone lets you query databases directly from your agent session — no context switching, no copy-paste, just "show me the users table" and it happens.

## Why This Release Signals Maturity

**v1.18.18** (late September) was the "reliability overhaul" — MCP fixes, desktop overhaul, desktop app. **v1.18.35** is the polish on top.

The pattern is clear: OpenCode ships reliability in waves, not features in splashes.

- **No breaking changes** in 17 patch versions
- **MCP stability** improving each release
- **Desktop app** getting native polish
- **Provider neutrality** (the core thesis) holding strong

This is what sustainable open-source velocity looks like. Not the "move fast and break things" theater — the "move fast *because* you don't break things" discipline.

If you've tracked OpenCode since v1.18.0, the trajectory is undeniable:

| Version | Focus |

---

## Should You Upgrade?

**Yes.** Zero risk. Run:

```bash
npm update -g opencode
# or
brew upgrade opencode
```

If you're on v1.18.18+, this is pure upside. If you're older — the MCP fixes alone are worth it.

---

## The Bigger Picture

OpenCode's thesis: **provider-neutral, local-first, skill-driven.**

While Claude Code locks you to Anthropic, Cursor locks you to their IDE, and Codex locks you to OpenAI — OpenCode lets you swap models, providers, and backends without rewriting your workflow.

v1.18.35 doesn't change that thesis. It makes it work better.

The agent-readable stats API is the quiet foundation for the next wave: **agents that manage agents.** When your coding agent can read its own metrics, it can optimize its own spend, route to cheaper providers for simple tasks, and escalate to premium models only when complexity demands it.

That's not a feature. That's infrastructure.
