Your coding agent can now talk to you. Hermes just shipped proper text-to-speech support through its managed audio gateway — and it's surprisingly good.

## What It Does

The TTS feature coerces a direct OpenAI model on the managed audio gateway, meaning Hermes can generate natural speech from any text output. Ask it to explain a concept, read back code, or narrate a debugging session — and it responds with spoken audio.

The commit (`fix(tts): coerce direct-only OpenAI model on the managed audio gateway`) handles the routing complexity: TTS models have different API shapes than chat models, and the gateway needs to recognize when a TTS request is coming in and route it to the right endpoint.

## Why Voice Matters

Voice is the overlooked modality in coding agents. Everyone focuses on vision, tool use, and code generation. But voice is what makes an agent ambient — something you can talk to while doing other things.

With TTS, Hermes can:
- Read error messages aloud while you keep your eyes on the code
- Narrate a code review while you drive
- Explain architectural decisions while you sketch
- Read back documentation while you keep your hands on the keyboard

## The Audio Gateway Architecture

The TTS route goes through Hermes's managed audio gateway, which handles:
- Model selection (OpenAI TTS models are different from chat models)
- Audio format conversion (MP3, WAV, Opus streaming)
- Streaming vs. full-response modes
- Provider fallback (if OpenAI TTS fails, fall back to a different provider)

This is the same gateway that handles image generation and vision — a unified multimedia pipeline.

## How It Works Under the Hood

When you invoke TTS in Hermes (via the `tts` tool or voice-enabled plugins), the request flows through several layers:

1. **Intent detection** — The gateway inspects the tool call and identifies it as a TTS request
2. **Model coercion** — OpenAI's TTS models (`tts-1`, `tts-1-hd`) accept different parameters than chat models. The gateway coerces the request into the correct shape: `model`, `input` (text), `voice` (alloy, echo, fable, onyx, nova, shimmer), `response_format`, and `speed`
3. **Streaming decision** — For long responses, the gateway chunks the text and streams audio back in real-time. Short responses get a single MP3 response
4. **Provider abstraction** — The gateway normalizes responses across providers. If you configure a different TTS provider (ElevenLabs, Cartesia), the same interface works

The audio gateway also handles **caching**: identical text requests return cached audio, reducing latency and API costs for repeated prompts (like reading the same error explanation twice).

## Practical Use Cases

### Debugging Without Context Switching
```bash
# Instead of: cat error.log | grep -A 5 "Error"
# You say: "Hermes, read me the last error"
# It speaks: "TypeError at line 42: Cannot read property 'map' of undefined"
```

### Code Reviews on the Go
Walk through a PR while commuting. Hermes reads the diff summary, highlights breaking changes, and suggests review comments — all without you opening GitHub.

### Accessibility First
For developers with visual impairments or RSI, voice output isn't a nice-to-have. It's the primary interface. Hermes's TTS makes the entire agent pipeline accessible: planning → coding → testing → debugging, all with audio feedback.

### Learning & Documentation
Point Hermes at a complex library's docs. It reads the API reference, explains the pattern, and gives you a spoken summary — like a podcast generated on demand for exactly what you're working on.

## Configuration

Enable TTS in your `AGENTS.md` or project config:

```yaml
audio:
  tts:
    enabled: true
    provider: "openai"  # or "elevenlabs", "cartesia"
    voice: "nova"       # alloy, echo, fable, onyx, nova, shimmer
    speed: 1.0
    streaming: true
```

The gateway respects provider-specific options. For ElevenLabs, you'd add `voice_id` and `model_id` (e.g., `eleven_turbo_v2_5` for low latency).

## What's Next

TTS is phase one. The audio gateway's architecture also supports speech-to-text for voice input, which would let you talk to your agent instead of typing. Voice-activated coding agents aren't far off.

The roadmap includes:
- **Voice commands** — "Hermes, create a new React component for the login form"
- **Interruptible speech** — Stop TTS mid-sentence with a voice command or keystroke
- **Multi-speaker conversations** — Simulate code review discussions with different voices
- **Real-time translation** — Agent speaks in your preferred language regardless of codebase language
