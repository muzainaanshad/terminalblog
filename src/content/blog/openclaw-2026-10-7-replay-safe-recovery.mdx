## The Six Pillars of Continuity

### 1. Replay-Safe Session Recovery

**Before:** Interrupted sessions lost recovery provenance. Unfinished tool outcomes vanished. Rejected Claude CLI drafts polluted final replies. Codex previews blocked replies after context refresh.

**Now:** Sessions retain **recovery provenance** and **unfinished tool outcomes**. Stopped conversations retire terminal recovery residue before accepting the next message. Rejected drafts stay out. Large child-completion batches stay within requester context. Codex previews no longer block.

**Why it matters:** You can crash, restart, and pick up exactly where you left off — including the tool call that was mid-flight.

### 2. Safer Update Activation and Recovery

**Before:** Verified activations could fail on later maintenance or ledger errors. Interrupted package updates left you in limbo. Post-activation Doctor waits were unbounded. Stale receipts could veto valid repairs. Windows deep/8.3 state paths aborted onboarding.

**Now:** Verified activations **remain successful** through maintenance. Interrupted updates **resume safely**. Doctor waits are **bounded**. Stale receipts **cannot veto** valid repairs. Windows deep paths **no longer abort** onboarding/migration.

**Why it matters:** Update, walk away, come back — it works. No more "let me watch the update finish" anxiety.

### 3. Database and Worker Continuity

**Before:** Maintenance could kill peer readers/borrowers. Incompatible retained agent databases caused conflicts. Empty transcript deletions triggered unnecessary archive materialization. Bun admission deadlines weren't thread-local. Worker shutdown raced inventory retirement.

**Now:** Maintenance refusals **preserve peer readers and borrowers**. Incompatible DBs **stay isolated**. Empty transcript deletions **skip archive materialization**. Bun deadlines are **thread-local**. Worker shutdown **completes after** inventory retirement.

**Why it matters:** Your data stays consistent even during aggressive maintenance.

### 4. Backup and State Durability

**Before:** Snapshots didn't retain legacy exec-approval policies. Interrupted R2 verification/restores failed permanently. Config observation lost last-known-good during truncated writes. Failed multi-file patches corrupted earlier files. Memory Wiki re-imports lost human notes.

**Now:** Snapshots **retain legacy policies**. Interrupted R2 **resumes safely**. Config observation **keeps last-known-good**. Failed multi-file patches **preserve earlier files**. Memory Wiki **preserves human-authored notes**.

**Why it matters:** Your backups are actually restorable. Your notes survive re-imports.

### 5. Operator Control Continuity

**Before:** Native computer control died on session expiry. Late-attached GitHub operators couldn't publish PRs. Synchronous node output duplicated as completion wakes. Cron announcements reset CLI chats. History maintenance read payloads before identities.

**Now:** Native control **recovers after session expiry**. Late-attached GitHub operators **can publish PRs**. Synchronous node output **not duplicated**. Cron announcements **preserve CLI chats**. History maintenance **reads identities first**.

**Why it matters:** Your automation doesn't break when sessions expire or cron wakes.

### 6. Provider and Plugin Continuity

**Before:** Model refresh discarded valid setup. Configured-account readiness was flaky. GPT-5.6 tool turns failed. OpenRouter onboarding rejected valid config. Incremental plugin loading lost state. External TypeScript plugin startup was slow.

**Now:** Model refresh **retains current state**. Configured accounts **stay ready**. GPT-5.6 tool turns **work**. OpenRouter onboarding **accepts valid setup**. Incremental plugin loading **retains state**. External TS plugins **start faster**.

**Why it matters:** Switch models, add accounts, install plugins — your working state persists.
