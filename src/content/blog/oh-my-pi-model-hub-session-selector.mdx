oh-my-pi's coding agent got a busy afternoon. Six commits landed in a single hour, and they are almost all about the part of an agent people touch every session: how you pick a model and how you move around the interface.

## A real model hub

The headline is a **model hub for unified management and search**. Instead of a flat list buried in a config file, the agent now presents a searchable hub where models are first-class objects. On top of that, two more commits add **custom role management** inside the hub and **dynamic sidebar reordering** for model hubs. Roles are the interesting one: it suggests you can tag a model with a persona or purpose — "cheap reviewer," "vision-capable planner" — rather than remembering which provider slug maps to which capability.

This is a meaningful shift in how terminal agents handle model routing. Most agents still treat model selection as a config-file chore: you edit YAML, restart, hope it works. The hub makes models discoverable, searchable, and role-aware in the UI. Combined with the [prompt-cache affinity support for Grok models](/blog/oh-my-pi-grok-45-model-support/) added days earlier, oh-my-pi is building a model routing layer that actually respects your token budget.

## Navigation that does not fight you

Three commits are pure UX. **Spatial navigation between sidebar and list panes** means arrow keys move between regions instead of being trapped in one. A **tiered session selector** is described as "accelerated," implying it ranks recent or relevant sessions instead of dumping an unsorted pile. And a TUI fix **constrains mid-prompt skill completion matching** so the autocomplete does not fight you while you are still typing a command.

These sound small, but they compound. If you switch sessions 20 times a day, a selector that surfaces the right one saves minutes per session. If autocomplete interrupts your flow, you lose the thread. The spatial navigation fix addresses a real TUI pain point: in most terminal agents, you're either in the file tree OR the chat OR the tool output — never fluidly between them. oh-my-pi's approach mirrors what [Hermes's TUI deep dive](/blog/hermes-tui-terminal-ui-cli-design-productivity/) identified as "thoughtful terminal UX" — the agent gets out of your way.

## The signal underneath

What these commits tell you is that oh-my-pi is investing in the daily-driver surface, not just the model plumbing. The model hub is also where new providers plug in — a sibling commit in the same window adds an **isolated Grok Build subscription provider**, which lines up with the role-and-hub work.

If you have been treating oh-my-pi as a curiosity, this batch is the point where it starts looking like a tool you could live in. It sits in the same ecosystem as the [open-source coding agents we tracked earlier this year](/blog/state-of-open-source-coding-agents-2026/), and the [Hermes TUI deep dive](/blog/hermes-tui-terminal-ui-cli-design-productivity/) makes a good contrast for what "thoughtful terminal UX" looks like from a different project.

The v17 series that followed (starting mid-July) doubled down on this: the `hub` tool unified messaging, jobs, and process supervision; the `xd://` virtual device protocol made approvals transparent; and `omp compress` / `omp cleanse` gave beginners power tools for context engineering. See the [Oh My Pi v17 guide](/blog/oh-my-pi-v17-hub-tool-xdev-plugins/) for the full picture.
