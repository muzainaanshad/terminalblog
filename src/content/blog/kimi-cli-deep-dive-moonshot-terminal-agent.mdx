Kimi CLI is **Moonshot AI's entry into the terminal coding agent space** — free, open-source, and built on the same skills/MCP architecture that powers OpenCode and Hermes.

If you're tracking the open-source agent ecosystem, this is one to watch.

---

## What Kimi CLI Actually Is

**Kimi CLI** (about 9K GitHub stars, MIT-licensed, npm package `@moonshot/kimi-cli`) is a terminal-based coding agent that:

- **Free with BYO API keys** — Moonshot, OpenAI, Anthropic, OpenRouter, Ollama
- **Skills-driven execution** — runs `.skill.md` files for repeatable coding tasks
- **MCP support** — connects to Model Context Protocol servers for tools
- **ACP IDE integration** — works with VS Code, JetBrains via Agent Communication Protocol
- **Multi-provider routing** — switch models per-task without restarting
- **Open source** — full control, no vendor lock-in

The project is actively maintained by Moonshot AI with community contributions.

## The Moonshot Difference: Native Kimi Models

Unlike most BYO-key agents, Kimi CLI has **native access to Moonshot's Kimi models** — including the **Kimi k2** series (long-context, strong reasoning). If you're already using Moonshot's API, this is the most direct integration.

| Model | Context | Strength |
|-------|---------|----------|
| Kimi k2 | 128K+ | Reasoning, coding, long-context |
| Kimi k1.5 | 200K+ | Ultra-long context, analysis |
| Moonshot v1 | 128K | General purpose, cost-effective |

You can still use any OpenAI-compatible provider — but Kimi models are **first-class citizens** with optimized prompts and tool calling.

## Skills System: Same Pattern You Know

If you've used OpenCode, Hermes, or Groq Code, the skills system is familiar:

```markdown
---
name: "add-tests"
description: "Generate comprehensive unit tests for a module"
---

## Instructions
1. Analyze the target module's public API
2. Generate edge-case tests (null, empty, boundary)
3. Add integration tests for external deps
4. Run test suite to verify
```

Run with: `kimi-cli skill run add-tests`

**Your workflows become portable** — share `.skill.md` files across team, projects, agents.

## MCP + ACP: The Modern Agent Stack

Kimi CLI embraces both emerging standards:

| Protocol | What It Gives You |
|----------|-------------------|
| **MCP** (Model Context Protocol) | Typed, discoverable tools — filesystem, GitHub, databases, browser, custom |
| **ACP** (Agent Communication Protocol) | IDE integration (VS Code, JetBrains), agent-to-agent handoff, session portability |

This means:
- Your MCP servers work out of the box
- You can hand off a session from terminal to VS Code and back
- Multiple agents can collaborate via ACP

---

## Multi-Provider Routing: Use the Right Model for the Task

Kimi CLI lets you **route different tasks to different providers**:

```bash
# Fast/cheap for boilerplate
kimi-cli --provider groq --model llama-3.1-70b

# Deep reasoning for architecture
kimi-cli --provider moonshot --model kimi-k2

# Local/private for sensitive code
kimi-cli --provider ollama --model codellama:34b
```

No restart needed. The agent picks up where it left off with the new model.

## Getting Started

```bash
# Install
npm install -g @moonshot/kimi-cli

# Configure (Moonshot key recommended, but any OpenAI-compatible works)
kimi-cli config set apiKey YOUR_MOONSHOT_KEY
# Or for OpenRouter:
kimi-cli config set apiKey YOUR_OPENROUTER_KEY --baseUrl https://openrouter.ai/api/v1

# Start coding
kimi-cli
# Or in a project:
cd your-project && kimi-cli
```

First run walks you through model selection, skill discovery, and MCP server setup.
