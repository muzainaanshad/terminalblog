**KiloCode v7.8.20 pre-release dropped October 27, 2026** — and while it's labeled "pre-release," the fixes inside are the kind you want *before* they hit stable.

The headlines: **auto-compaction no longer starts early or loops on unknown context sizes**, **zod upgraded to patch a memory-exhaustion vulnerability**, **CLI now available as a conda package on Anaconda.org**, plus **agents can choose their base branch for worktree sessions**.

If you've been bitten by runaway compaction or want `pixi add kilo-cli` — this is the update.

## The One-Line Summary

**Compaction respects your threshold now. No more loops on unknown models. Zod memory bug patched. `pixi add kilo-cli` works. Agents pick base branch for worktrees. Update if you run into any of these.**

---

## 1. Auto-Compaction Fixed — No More Early Starts or Infinite Loops

**The bug:** Auto-compaction was triggering **well before your configured context threshold**. Worse: on models without a known context size (custom endpoints, local models), it would **loop indefinitely** — compact, hit the same wall, compact again. And if you manually stopped a compaction, it would just restart.

**The fix (v7.8.20):**
- Compaction now **respects your configured threshold** — no more early starts
- **No looping on unknown context sizes** — if the model doesn't report a limit, compaction backs off
- **Stopping compaction actually stops it** — no more restart spiral

**PR:** [#15479](https://github.com/Kilo-Org/kilocode/pull/15479) by @WebReflection

**Why it matters:** This was the "my agent keeps pausing to summarize and I can't get work done" bug. If you run local models (Ollama, LM Studio) or custom endpoints — **this fixes your workflow entirely**.

---

## 2. Zod Upgraded — Memory-Exhaustion Vulnerability Patched

**The issue:** The VS Code extension used a zod version with a **memory-exhaustion advisory** when validating oversized constrained collections. A malicious or accidental massive payload could OOM the extension host.

**The fix:** **zod upgraded to a patched release** in the VS Code extension.

**PR:** [#15483](https://github.com/Kilo-Org/kilocode/pull/15483)

**Why it matters:** Supply-chain security. Your editor validates *everything* the agent outputs. A DoS vector in the validator = a DoS vector in your IDE. **Patch applied.**

---

## 3. CLI Now on Conda — `pixi add kilo-cli` Works

**What it is:** The KiloCode CLI is now published as **`kilo-cli` on Anaconda.org** (conda-forge compatible), built with rattler-build for:
- `linux-64`, `linux-aarch64`
- `osx-64`, `osx-arm64`
- `win-64`

**Install:**
```bash
# pixi (recommended)
pixi add kilo-cli

# conda
conda install -c anaconda-cloud kilo-cli

# mamba
mamba install -c anaconda-cloud kilo-cli
```

**Pre-releases** publish to the `rc` label — `pixi add kilo-cli@rc` for bleeding edge.

**PR:** [#14465](https://github.com/Kilo-Org/kilocode/pull/14465) by @zfralish

**Why it matters:** No more `curl | bash`, no more npm global installs fighting with your Node version. **Conda = reproducible, isolated, versioned CLI installs.** Works in pixi environments, Docker builds, CI pipelines.

---

## 4. Agents Choose Base Branch for Worktree Sessions

**What it is:** When Agent Manager starts a worktree session, the agent can now **choose the base branch** instead of defaulting to the repo's default branch.

**Why it matters:** You're on `feature/xyz` branched from `main`. Agent starts a worktree — before it used `main` as base. Now it can use `feature/xyz` (or any branch you tell it). **Worktrees start from where you actually are.**

**PR:** [#15482](https://github.com/Kilo-Org/kilocode/pull/15482)

| **MCP TypeScript SDK** | **1.32.1** | **Security: blocks cross-origin redirects in MCP HTTP/OAuth** |

**The MCP fix** (from v7.8.18, carried forward): Remote MCP servers that redirect to another origin, or answer `POST` with `301`/`302`/`303`, **no longer connect** — use the server's final URL instead. Prevents credential leakage via redirect chains.
