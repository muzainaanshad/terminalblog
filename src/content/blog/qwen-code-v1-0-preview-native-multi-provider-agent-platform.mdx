## v1.0.0-preview.1 Patch Notes (Nov 12)

### Fixed: Subscription Accounts Couldn't Use Models After Sign-In
**The bug:** After signing into a Qwen subscription account, the model catalog didn't update to reflect subscription models. Users had to manually configure providers.

**The fix:** Model catalog now **follows your sign-in state automatically** — no manual provider configuration needed. Sign in, and your subscription models are available immediately.

### Qoder Models: Parallel Tool Calls
**What it is:** Qoder models now support **parallel tool calls** — multi-tool tasks no longer run strictly sequentially and complete faster.

```bash
# Before: tool A finishes → tool B starts → tool C starts (sequential)
# After: tool A, B, C run in parallel where possible
```

This is a meaningful speedup for complex refactoring, multi-file edits, and any task requiring multiple tool invocations.

### Synced with v0.27.x
- Subscription model catalog and thinking-budget mapping synced with Qwen Code 0.27.x
- Clearer error messages for subscription issues

## Multi-Provider: Qwen, Qoder, or Bring Your Own

### The Old Model: One Provider, One Account

v0.27 and earlier: Qwen models via Qwen account. That's it.

### v1.0 Preview: Three Paths, One Binary

| Provider | Account | Models | Use Case |
|----------|---------|--------|----------|
| **Qwen** | Qwen account | Qwen 2.5, Qwen 3, Qwen-Plus, Qwen-Max | Default, best Chinese/English coding |
| **Qoder** | Qoder account | Qoder-optimized models | Qoder's specialized coding models |
| **Custom** | Any OpenAI-compatible endpoint | Anything (Llama, DeepSeek, local Ollama, etc.) | Enterprise, privacy, local-only, cost control |

```bash
# Use Qoder models
qwen-code --provider qoder

# Use custom endpoint (Ollama, LM Studio, vLLM, etc.)
qwen-code --provider custom \
  --endpoint http://localhost:11434/v1 \
  --model qwen2.5-coder:32b \
  --api-key not-needed-for-local

# Use OpenRouter for model variety
qwen-code --provider custom \
  --endpoint https://openrouter.ai/api/v1 \
  --model anthropic/claude-3.5-sonnet \
  --api-key $OPENROUTER_KEY
```

**For beginners:** You're no longer locked to one vendor's models. For enterprises: run entirely on-prem with Ollama + Qwen Code binary. For cost optimizers: route to cheapest provider per task.

## Session Resumption: Your Work Survives Reboots

### The Problem: Lose Context, Lose Momentum

Long-running tasks (refactoring a 50-file module, debugging a flaky test suite, multi-step migrations) die when:
- Your laptop updates overnight
- The binary crashes (rare, but happens)
- You accidentally close the terminal
- CI job times out

### v1.0 Fix: `--resume` Flag

```bash
# Start a long task
qwen-code run --managed "Refactor auth module to use new JWT library, update all tests"

# Session gets interrupted? Resume it:
qwen-code --resume <session-id>

# Or list recoverable sessions:
qwen-code sessions list --resumable
```

**What persists:**
- Full conversation history
- Tool call results (file reads, edits, bash output)
- Working directory state
- Agent context (plans, subagent spawns)
- Pending "Ask User" questions (from v0.27's multi-child questions)

**For automation:** Non-interactive execution means CI/CD pipelines can run Qwen Code tasks, persist sessions, and resume on failure — no human babysitting.

## Non-Interactive Execution: Agents in Your Scripts

```bash
# One-shot task, exits with code (0 = success, 1 = failure)
qwen-code run --non-interactive \
  "Review PR #247 for security issues, post comments on risky patterns"

# With JSON output for parsing
qwen-code run --non-interactive --json \
  "Generate unit tests for src/auth/*.ts" \
  > test-generation-result.json

# In CI (GitHub Actions example)
- name: Qwen Code Security Review
  run: |
    qwen-code run --non-interactive \
      "Scan changed files for: hardcoded secrets, SQL injection, XSS vectors, auth bypasses. Output SARIF."
  env:
    QWEN_CODE_PROVIDER: custom
    QWEN_CODE_ENDPOINT: ${{ secrets.OLLAMA_ENDPOINT }}
    QWEN_CODE_MODEL: qwen2.5-coder:32b
```

**This is the bridge from "chat tool" to "platform component."** Your build pipeline, your deploy hooks, your nightly security scans — they can all invoke Qwen Code as a first-class CLI citizen.
