## The Headline Features (Ranked by "This Changes How Teams Operate")

### 1. Bulk Skill Activation — One API Call for 100 Skills

**What it is:** `PUT /skills/activation` (and `setUserSkillsActivation` SDK method) lets you **enable or disable 1–100 user Skills in a single request** ([#16186](https://github.com/QwenLM/qwen-code/pull/16186)). Preferences saved. Propagation status returned.

**Why it matters:**

- **Team onboarding** — new dev joins → one API call provisions their full skill set
- **CI/CD pipelines** — `qwen-code skill activate --all --config team-skills.json` in your deploy script
- **Environment parity** — dev/staging/prod skill configs version-controlled, applied identically
- **Rollback** — disable 50 skills in one call if a bad one slips through

```bash
# Before: 100 skills = 100 CLI commands or manual UI clicks
# After: One call
curl -X PUT http://localhost:3000/skills/activation \
  -H "Content-Type: application/json" \
  -d '{"activations": [{"skillId": "skill-1", "enabled": true}, {"skillId": "skill-2", "enabled": true}, ...]}'

# Or via TypeScript SDK (see below)
```

**For beginners:** Skills are reusable agent capabilities (code review, test generation, deployment, etc.). Before, you toggled them one by one. Now you manage them like infrastructure.

---

### 2. Daemon APIs for Large Skill ZIPs — Upload, Install, Get Receipts

**What it is:** New daemon routes for **installing large Skill ZIP archives** by upload or host file path, plus **installation receipt lookup after failures** ([#16421](https://github.com/QwenLM/qwen-code/pull/16421), [#16422](https://github.com/QwenLM/qwen-code/pull/16422)).

**Why it matters:**

- **Large skills** (ML models, heavy binaries) no longer hit upload limits — disk-based ZIP handling with recovery-backup protection
- **Failure recovery** — install fails? Query the receipt. Know exactly what succeeded, what didn't, and resume from there
- **Automation-friendly** — CI uploads skill artifacts → daemon installs → receipt confirms → deploy continues

```bash
# Upload a large skill ZIP directly to daemon
curl -X POST http://localhost:3000/daemon/skills/install \
  -F "zip=@my-heavy-skill-v2.3.zip" \
  -F "attemptId=deploy-20261107-001"

# Later, check the receipt
curl http://localhost:3000/daemon/skills/receipt/deploy-20261107-001
# Returns: { status: "completed", skillId: "skill-xyz", version: "2.3", installedAt: "..." }
```

### 3. TypeScript SDK — Programmatic Skill Installs from File, Blob, Bytes, or Path

**What it is:** **First-class TypeScript SDK support** for installing Skill ZIPs from `File`, `Blob`, `bytes`, or host path — with attempt IDs and receipt lookup ([#16423](https://github.com/QwenLM/qwen-code/pull/16423)).

**Why it matters:**

- **Embed Qwen Code in your own tools** — build internal platforms, IDE extensions, CLI wrappers
- **Type-safe** — full TypeScript types for every parameter and response
- **Unified interface** — same SDK works for browser (File/Blob) and Node (fs paths/bytes)

```typescript
import { QwenCodeClient } from '@qwen-code/sdk';

const client = new QwenCodeClient({ baseUrl: 'http://localhost:3000' });

// From a file input in browser
const result = await client.skills.installFromFile(fileInput.files[0], {
  attemptId: 'web-upload-001'
});

// From Node.js filesystem
const result = await client.skills.installFromPath('/artifacts/skill-v2.3.zip', {
  attemptId: 'ci-deploy-001'
});

// Check receipt anytime
const receipt = await client.skills.getReceipt('ci-deploy-001');
console.log(receipt.status); // 'completed' | 'failed' | 'pending'
```

**This is the API layer that lets Qwen Code become a platform, not just a tool.**

### 4. WebShell Skill Upload UI — Drag, Drop, Done

**What it is:** WebShell's Skills page now has **ZIP upload with daemon limits shown and uncertain results checkable** ([#16424](https://github.com/QwenLM/qwen-code/pull/16424)).

**Why it matters:**

- **Non-technical team members** install skills without CLI
- **Visual feedback** — daemon size limits displayed, installation progress shown
- **Uncertain results** — if upload flakes, "Check Result" button queries the receipt

---

### 5. Durable Structured User Questions — Managed Agents That Wait for You

**What it is:** Managed agents now support **durable structured user questions** ([#16433](https://github.com/QwenLM/qwen-code/pull/16433)). The agent pauses, presents a structured question (choices, text, files), persists it, and resumes when answered — even across restarts.

**Why it matters:**

- **Human-in-the-loop at scale** — "Deploy to prod? [yes/no/dry-run]" survives agent restart
- **Audit trail** — every question and answer logged with timestamps
- **Multi-step approvals** — chain questions: security review → compliance → deploy

---

### 6. Managed Agent Automation Enabled by Default

**What it is:** **Automation is now on by default** for managed agents ([#16448](https://github.com/QwenLM/qwen-code/pull/16448)). No config flip needed.

**Why it matters:**

- **Out-of-the-box CI/CD** — `qwen-code run --managed "nightly refactor"` just works
- **Scheduled jobs** — cron, GitHub Actions, GitLab CI all trigger managed runs without extra setup
- **Team adoption** — zero friction to start automating

---

### 7. Performance: Activation Renewals, Lock Reduction, History Caching

**What it is:** Three infrastructure wins ([#16336](https://github.com/QwenLM/qwen-code/pull/16336), [#16410](https://github.com/QwenLM/qwen-code/pull/16410), [#16337](https://github.com/QwenLM/qwen-code/pull/16337)):

| Improvement | What Changed | Impact |
|-------------|--------------|--------|
| **Activation renewals** | Locate lease more efficiently | Faster renewals, less overhead |
| **Tenant guard locks removed** | Native journal snapshot publication unlocked | **Managed agent throughput up, contention down** |
| **Session history caching** | Message bodies cached per process | Hosted turns faster, less repeated reads |

**Translation:** Managed agents at team scale (20+ concurrent workspaces) just got noticeably snappier.
