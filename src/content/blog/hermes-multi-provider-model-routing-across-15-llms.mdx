Most AI tools lock you into one provider. Hermes Agent takes the opposite approach: it supports **15+ LLM providers** and routes each task to the optimal model automatically — without you writing a single config line.

## Why Provider Routing Matters

Different tasks demand different models. A quick file edit doesn't need Claude Opus. A complex architectural analysis benefits from deep reasoning. Why pay for flagship models when a lightweight one does the job?

Hermes solves this with **automatic provider routing** — each task is analyzed and assigned to the best-fit model based on:

- **Task complexity** — is this a simple lookup or multi-step reasoning?
- **Context requirements** — how many tokens does it need?
- **Speed requirements** — does the user need results now, or can it wait?
- **Cost sensitivity** — what's the budget for this task?
- **Capability needs** — does it require vision, code execution, structured output, function calling?

## How It Works Under the Hood

When Hermes receives a goal, it doesn't immediately send it to an LLM. It first runs a **capability assessment**:

```yaml
# providers.yaml (auto-generated, not manual)
routing:
  quick_edit:
    preferred: gpt-4.5-mini
    fallback: claude-haiku-4.5
    max_tokens: 2000
    max_cost_usd: 0.001
    capabilities: [text, code]
  code_generation:
    preferred: claude-sonnet-4.5
    fallback: deepseek-v4
    max_tokens: 8000
    max_cost_usd: 0.01
    capabilities: [text, code, reasoning]
  deep_analysis:
    preferred: claude-opus-4.8
    fallback: gpt-5.5
    max_tokens: 32000
    max_cost_usd: 0.10
    capabilities: [text, code, reasoning, long_context]
  vision:
    preferred: claude-sonnet-5
    fallback: gpt-5.4
    max_tokens: 8000
    capabilities: [vision, text]
  structured_output:
    preferred: gpt-5
    fallback: claude-sonnet-4.5
    capabilities: [json_schema, function_calling]
  search_augmented:
    preferred: perplexity-sonar-pro
    fallback: gemini-2.5-flash
    capabilities: [web_search, citations]
```

This isn't a static config you maintain. Hermes **builds and adapts** this routing table based on:

1. **Provider availability** — if a provider is down, it's removed from rotation
2. **Latency history** — models that return slow get deprioritized for quick tasks
3. **Success rates** — if a model frequently fails on certain task types, it gets reassigned
4. **Token costs** — the routing engine tracks per-task spending and optimizes
5. **Quality signals** — user feedback (accept/reject) refines model-task fit

## Graceful Fallback Chains

The real magic is in fallback behavior. If your preferred model is rate-limited, Hermes doesn't error — it cascades:

```
claude-sonnet-4.5 → gpt-4.5 → deepseek-v4 → local model
```

Each fallback is chosen to match the original's capabilities as closely as possible. If you need vision, it won't fall back to a text-only model. If you need 100K context, it won't fall back to a 16K model. If you need structured output, it won't fall back to a model without JSON schema support.

This fallback chain is **self-healing**. If a provider recovers, Hermes detects it on the next request and resumes routing to it.

### Fallback Priority Logic

```
1. Capability match (must support required features)
2. Context window (must meet minimum tokens)
3. Latency percentile (p50 for quick, p99 for batch)
4. Cost per 1K tokens (ascending)
5. Recent success rate (descending)
6. User preference (if configured)
```

## Custom Provider Support

Beyond the built-in providers, Hermes supports **arbitrary custom providers** via the `custom:<name>` slug system. You can add any OpenAI-compatible endpoint:

```yaml
# .hermes/providers.yaml
providers:
  custom:my-local-model:
    base_url: http://localhost:8000/v1
    api_key: not-needed
    models:
      - llama-3-8b
      - mistral-7b
    capabilities:
      - text
      - code
      - 32k_context
    cost_per_1k_tokens: 0.0001  # estimated for routing
    latency_p50_ms: 500         # estimated for routing
    health_check: true
    health_check_interval: 60   # seconds

  custom:company-internal:
    base_url: https://llm.internal.company.com/v1
    api_key: ${INTERNAL_LLM_KEY}
    models:
      - proprietary-model-v2
      - proprietary-coder-v1
    capabilities:
      - text
      - code
      - reasoning
      - 128k_context
      - function_calling
    cost_per_1k_tokens: 0.002
    headers:
      X-Request-Source: hermes-agent
```

These custom providers participate in the **same routing, fallback, and cost-optimization logic** as built-in ones. Hermes health-checks them automatically and removes unhealthy ones from rotation.

### Local Model Integration (Ollama, LM Studio, vLLM)

For local-first workflows, Hermes auto-detects common local servers:

```bash
# Ollama
ollama serve
# → Hermes detects http://localhost:11434/v1

# LM Studio
# → Enable "OpenAI Compatible Server" in settings
# → Hermes detects http://localhost:1234/v1

# vLLM
vllm serve meta-llama/Llama-3.1-70B-Instruct --port 8000
# → Hermes detects http://localhost:8000/v1
```

No config needed — just start the server and Hermes will route compatible tasks to it (prioritizing local for privacy-sensitive or cost-sensitive tasks).

### Budget Controls

Set hard limits in `.hermes/budget.yaml`:

```yaml
budget:
  daily_limit_usd: 5.00
  weekly_limit_usd: 25.00
  monthly_limit_usd: 80.00
  alert_at_percent: 80
  hard_stop_at_percent: 100
  per_task_cap_usd: 0.50
```

When limits approach, Hermes:
1. Shifts routing to cheaper models
2. Batches non-urgent tasks
3. Prompts for confirmation on expensive tasks
4. Hard-stops at limit (with override flag)

## Provider Health & Reliability

Hermes continuously monitors provider health:

```yaml
# Auto-generated health metrics (not manual)
health:
  anthropic:
    status: healthy
    p50_latency_ms: 1200
    p99_latency_ms: 4500
    error_rate_1h: 0.001
    error_rate_24h: 0.003
    rate_limit_remaining: 8500
    last_check: 2026-11-10T13:45:00Z
  openai:
    status: degraded
    p50_latency_ms: 2100
    p99_latency_ms: 8000
    error_rate_1h: 0.02
    error_rate_24h: 0.015
    rate_limit_remaining: 1200
    last_check: 2026-11-10T13:45:00Z
```

**Degraded providers** are automatically deprioritized. **Unhealthy providers** (error rate >5% or latency >30s p99) are removed from routing until recovery.
