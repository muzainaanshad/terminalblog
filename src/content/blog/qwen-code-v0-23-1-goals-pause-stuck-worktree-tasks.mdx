You leave a coding agent running a "fix all failing tests" goal, come back 40 minutes later, and it's still grinding the same failing test — burning tokens, churning your git history, and getting nowhere. Every agent user has lived this. The newest Qwen Code release (v0.23.1, published September 8, 2026) adds a guardrail that attacks exactly this failure mode: **goals now pause themselves after three autonomous turns that make no progress** ([#11239](https://github.com/QwenLM/qwen-code/pull/11239)).

That one line is worth more than a dozen new features. It is the most honest thing an agent can learn: knowing when to stop is a competency, not a bug.

## Goals that know their budget

Qwen Code's "goals" are long-running autonomous jobs — the agent works through a task over many turns, with checkpoints and verification. v0.23.1 turns goals from a fire-and-forget timer into a monitored budget:

- **No-progress auto-pause.** After three consecutive autonomous turns that make no progress, the goal pauses instead of spinning ([#11239](https://github.com/QwenLM/qwen-code/pull/11239)). You get called back for a decision instead of a surprise token bill.
- **Spend windows.** The web shell now shows what a goal has spent against the window it is allowed ([#11254](https://github.com/QwenLM/qwen-code/pull/11254), [#11248](https://github.com/QwenLM/qwen-code/pull/11248)) — the same accounting in two places, so operators can see burn rate before it becomes a problem.
- **Sized checkpoint verification.** The checkpoint verifier that guards goal claims can now be sized for a full claim list, and operators can set the timeout themselves ([#11305](https://github.com/QwenLM/qwen-code/pull/11305)).

The pattern matters beyond Qwen. Every serious agent vendor is converging on the same realization: autonomous loops need **external brakes** — budget ceilings, stuck-detection, and human checkpoints — or they become cost hazards. Qwen Code just made those brakes first-class features instead of afterthoughts.

## Parallel tasks that can't cross-contaminate

The second headline is **worktree-isolated named tasks** ([#10643](https://github.com/QwenLM/qwen-code/pull/10643)). Each named task runs in its own Git worktree, so you can launch several tasks at once and they edit separate working trees instead of stepping on each other. This is the fix for the classic multi-agent disaster: two tasks editing the same file, one silently overwriting the other's work.

The isolation extends to cleanup: deleting a daemon session now **reaps its owned worktrees** ([#11309](https://github.com/QwenLM/qwen-code/pull/11309)), and named sessions get worktree resets ([#11015](https://github.com/QwenLM/qwen-code/pull/11015)). No more orphaned branches and half-checked-out worktrees accumulating on disk like digital hoarding.

For anyone who has run parallel agents in one repo, this is the difference between "parallel" as a marketing word and parallel that actually works. Pair it with the live subagent status in the transcript ([#10939](https://github.com/QwenLM/qwen-code/pull/10939)) and you can finally *watch* what your background agents are doing instead of guessing.

## Sessions stop fighting each other

A quieter but important theme: v0.23.1 hardens concurrent sessions so they don't corrupt each other.

- **Session leases for conversation writers** ([#10924](https://github.com/QwenLM/qwen-code/pull/10924)) — writers must hold a lease; no more two processes scribbling in the same conversation.
- **Concurrent standalone daemons with session fencing** ([#11207](https://github.com/QwenLM/qwen-code/pull/11207)) — multiple daemons can run side by side without stomping each other's sessions.
- **Bounded turn navigation** — the daemon and SDK now support indexed turn navigation with snapshots and transcript paging ([#10751](https://github.com/QwenLM/qwen-code/pull/10751)), with continuous history in the web shell ([#11208](https://github.com/QwenLM/qwen-code/pull/11208)).

If you have ever had two agent sessions "fight" over state — one deleting the other's transcript, a stale session clobbering a fresh one — this release is aimed squarely at you. Our [coding-agent security checklist](/blog/coding-agent-security-checklist-2026/) has warned about cross-session contamination for months; Qwen is now shipping the plumbing to prevent it at the protocol level.

## Everything else worth knowing

- **Daemon memory**: agents can now write to daemon memory ([#11311](https://github.com/QwenLM/qwen-code/pull/11311)) and delete from it ([#11337](https://github.com/QwenLM/qwen-code/pull/11337)) — persistent memory without restart hacks. This follows the arc we covered in [OpenHands' persistent memory work](/blog/openhands-agent-canvas-1-10-0-persistent-memory-automations/); context that survives sessions is becoming table stakes.
- **Controller tokens**: a user-minted controller token can drive a session without per-message review ([#11090](https://github.com/QwenLM/qwen-code/pull/11090)) — useful for automation, but read the permission implications carefully.
- **`todo_write` is now opt-in** ([#10645](https://github.com/QwenLM/qwen-code/pull/10645)) — the agent no longer writes todo files unless you configure it. Less repo noise.
- **Output styles**: custom output styling from `~/.qwen/output-styles` and `.qwen/output-styles` ([#10761](https://github.com/QwenLM/qwen-code/pull/10761)).
- **DingTalk security fix**: secrets no longer printed to stdout during SDK connect logging ([#10945](https://github.com/QwenLM/qwen-code/pull/10945)).

## The breaking change

One heads-up for teams using Qwen Code's web UI: the `@qwen-code/webui` package is **retired** in v0.23.1 ([#9812](https://github.com/QwenLM/qwen-code/pull/9812)) — its functionality has moved into the main package and web shell. If you installed it separately, update your setup before upgrading, or the build breaks.

## The takeaway

Qwen Code v0.23.1 is not the flashiest release of the month, but it is one of the most mature. No new model, no hype — just the boring, essential infrastructure of trustworthy autonomy: goals that admit when they're stuck, tasks that can't collide, and sessions that can't corrupt each other.

The earlier v0.21.8 release fixed a trust boundary and shared prompt caches ([Qwen Code v0.21.8 breakdown](/blog/qwen-code-v0-21-8-trust-cache-fork-autofix/)). This release fixes something harder: the social contract between you and your agent. You give it a budget, it spends it transparently, and when it runs into a wall, it stops and asks instead of burning your money against the wall.

## And then v0.23.2 landed the next day

The follow-up patch (September 9) was small but sharpens the same autonomy story:

- **Built-in web search is now enabled by default** on ModelStudio Standard/Token plans ([#11348](https://github.com/QwenLM/qwen-code/pull/11348)) — the agent can look things up without you wiring a search provider first.
- **GPT-5 and GPT-6 reasoning-effort configuration** ([#11295](https://github.com/QwenLM/qwen-code/pull/11295)) — the same effort knob Claude Code just added with `maxEffortLevel` ([our breakdown](/blog/claude-code-effort-cap-fable-5-1-cost-control/)); both vendors are converging on letting you cap how hard the model thinks.
- **Goal budgets now carry into the continuation prompt** ([#11257](https://github.com/QwenLM/qwen-code/pull/11257)) — when a paused goal resumes, it remembers what it was allowed to spend.
- **One-command remote start** ([#11172](https://github.com/QwenLM/qwen-code/pull/11172)) — a generated token, same-origin shell access, and a pairing QR, for running Qwen Code on another machine.
- **Split-view session navigation** was improved ([#11250](https://github.com/QwenLM/qwen-code/pull/11250)) and browser task notifications became opt-in ([#11398](https://github.com/QwenLM/qwen-code/pull/11398)).

The pattern holds: Qwen Code keeps shipping *brakes* — self-pausing goals, spend windows, and now effort and web-search defaults you can control. That is what turning an autonomous agent into a trustworthy worker looks like.

## And a desktop app reached 0.3.0

The same day v0.23.2 landed, **Qwen Code Desktop hit v0.3.0** (September 10). It's a desktop shell over the same agent, so the CLI features above apply — with a few desktop-specific notes:

- **Stable 0.3.0 is live; existing installs are not force-moved.** The `desktop-latest` updater feed still points at 0.2.2, so you must install 0.3.0 deliberately if you want it now.
- **Windows shows a SmartScreen warning on first install** — expected, and not specific to this build: Qwen Code Desktop installers have never carried an Authenticode signature (no Windows code-signing cert is configured for the repo). Choose **More info → Run anyway**, and verify the download against `SHA256SUMS.txt` if you want certainty. macOS builds are Developer ID–signed and notarized, so they open normally.
- Under the hood: **pending permission prompts survive session reloads**, Responses-stream error details are preserved, and a Windows PTY worker leak was fixed (the `conout` worker is released after every PTY session).
- The **daemon gained a REST integration entry point** (guarded) — a sign the desktop shell is becoming scriptable.

If you only use Qwen Code in the terminal, nothing changes. If you want the windowed version: grab the 0.3.0 installer, expect (and dismiss) the SmartScreen prompt, and pin your model — the desktop catalog reshuffle behavior applies here too.

## And then v0.23.3 let you hand a turn to Claude Code

Two days later, **v0.23.3 landed** (September 10) with one feature that changes what "open-source" can mean for a coding agent: **you can now delegate a subagent turn to an external agent over ACP — Claude Code first** ([#11003](https://github.com/QwenLM/qwen-code/pull/11003)).

**What it does:** a subagent definition can declare an `executor` block naming an external command. When that subagent is called, the turn runs in that external process instead of in-process — and every event it produces is re-published through the exact same transcript, permission, and Web Shell pipeline Qwen uses for its own agents. Claude Code is the first (and for now, only) external agent wired up.

**Why it matters:** before this, running a second vendor's agent from Qwen Code meant handing the whole session to a different backend — a clunky all-or-nothing move. Delegation flips the model: the parent Qwen session stays authoritative, and a *specific* subagent (say, "deep review" or "refactor specialist") gets dispatched to whatever agent is best at that job. Think contractor, not takeover.

Two details worth knowing before you configure it:

- The executor is **loud about being honored**. If a definition declares an executor the host can't run, the call fails loudly instead of silently falling back to in-process — the old behavior ran the work in-process anyway, *and billed it to the wrong provider*.
- The rest of v0.23.3 is polish around the same autonomy theme: **smarter reasoning presets** for Kimi/Qwen/DeepSeek ([#11349](https://github.com/QwenLM/qwen-code/pull/11349)), **one bounded self-review before an address-review commit** ([#11516](https://github.com/QwenLM/qwen-code/pull/11516)), a **Responses API content generator** ([#8169](https://github.com/QwenLM/qwen-code/pull/8169)), better session-overview navigation in the web shell ([#11238](https://github.com/QwenLM/qwen-code/pull/11238)), clickable URLs in user messages ([#11464](https://github.com/QwenLM/qwen-code/pull/11464)), and a Windows fix that stops orphaned `conhost.exe` processes by hosting PTYs via bundled ConPTY ([#11497](https://github.com/QwenLM/qwen-code/pull/11497)). Also: goal checkpoints that overrun their budget now **retry instead of spending a stall** ([#11365](https://github.com/QwenLM/qwen-code/pull/11365)).

The through-line of the whole v0.23.x wave is the same one this article started with: brakes first, features second — stop when stuck, spend transparently, and hand off a turn when another agent is a better fit.
