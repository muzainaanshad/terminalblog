Oh My Pi just changed how it authenticates with xAI. Instead of requiring users to manage API keys, it now uses device flow — the same authentication method used by GitHub CLI, `gh`, and other developer tools.

## What Changed

`fix(ai-registry): migrated xAI auth to device flow for reliability`

Previously, connecting to xAI required:
1. Getting an API key from console.x.ai
2. Copying the key into Oh My Pi's config
3. Hoping the key didn't expire or get revoked

Now, device flow handles everything:
1. Oh My Pi opens a browser window
2. You log in to xAI
3. You authorize Oh My Pi
4. Done — the token is stored securely

The migration is backward-compatible: existing API keys continue to work until they expire. After that, the device flow prompts you to re-authenticate automatically — no config file edits needed.

## Why Device Flow Is Better

Device flow is the industry standard for CLI authentication. It's better than API keys because:

- **No API key management** — the token is created by xAI, not you
- **Automatic refresh** — tokens expire and refresh automatically
- **Revocable** — you can revoke access from xAI's dashboard without touching a config file
- **Secure** — tokens never leave your machine; no plaintext secrets in config directories
- **Auditable** — xAI's auth system tracks every token it issues, giving you a paper trail

For coding agents that need persistent access to xAI, device flow is the right approach. API keys are fine for scripts and automation. For interactive tools that run dozens of sessions a week, device flow eliminates an entire category of failure.

## The Reliability Angle

The commit message says "for reliability" — and that's the key. API keys fail when:

- They expire silently and you discover it mid-session
- They get rate-limited because the same key is shared across multiple tools
- The provider revokes them after detecting unusual activity
- The user accidentally pastes them into a public repo, a log file, or a shared Slack channel

Device flow eliminates all of these failure modes. The token is managed by xAI's auth system, not by the user. When it expires, the refresh happens behind the scenes. When you want to revoke, you visit one dashboard page.

This matters more for Oh My Pi than for a simple script because Oh My Pi orchestrates multiple providers. If your xAI connection drops mid-refactor, the agent loses context and you lose time. Device flow makes that scenario significantly less likely.

## What This Means for Users

If you're using Oh My Pi with xAI, the upgrade is seamless. Your existing API key will continue to work until it expires. After that, the device flow will prompt you to re-authenticate.

The change also signals that Oh My Pi is maturing its auth infrastructure. As more providers add device flow support — Anthropic and Google already offer it — Oh My Pi will likely adopt it across the board. That means one less config file to manage and one less secret to rotate.

For operators evaluating which coding agent to trust with access to their xAI API credits, this is a point in Oh My Pi's column. Auth that just works is auth that doesn't become a security liability.
