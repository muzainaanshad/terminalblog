## What Happened

A recent study analyzed 718 companies using AI coding assistants (via Jellyfish analytics) and found something surprising: **AI tools increased code output but didn't increase actual software delivery** — measured by Jira epics and issues resolved. The ArsTechnica article "AI coding agents generate more code, but not more software" hit Hacker News and sparked a 290-comment discussion.

The core finding: developers using AI assistants closed more *tickets* (small tasks), but the rate of completing *epics* (major features) didn't change. Ticket scope didn't increase either — AI just helped churn through existing work faster.

For beginners: think of tickets as "fix this bug" or "add this button," while epics are "build the whole payment system." AI helps with the former, not the latter.

## Developer Reactions: The Good, The Bad, The "Wait, What?"

### 1. Code Review Is the New Bottleneck

The most upvoted sentiment: **AI generates code faster than humans can review it.**

> "For the first time a friend of mine left a job because they were fed up that 80% of the job was reviewing Claude submissions. I have to admit that would probably drive me nuts as well." — *PacificSpecific*

Multiple senior engineers confirmed this. One described their workflow shifting from "write code → review" to "prompt → review AI output → fix AI mistakes → review again." The review phase expanded to fill all available time.

> "I initially pivoted to fully automated code reviews, sometimes with a brief skim. I've been shifting back to mostly manual review... I started to run into way too many AI generated messes in codebases. The agents are really good at some things and complete ass at others." — *jghn*

### 2. More Code ≠ Better Code

Developers consistently reported that AI-generated code is **verbose, repetitive, and harder to maintain** — even when tests pass.

> "They tend to generate code that is repetitive. It misses opportunities for extraction and refactoring, the result is bloated and hard to read code... and they tend to over-comment where it doesn't add but is 'safe' because it is obvious (effectively re-writing code as comments) and fail to document where documentation would be essential." — *jacquesm*

Another developer put it bluntly:

> "The amount of slop we need to maintain is becoming very big. There is no other way than to use AI to deal with this. But that creates even more slop." — *holoduke*

### 3. The "Greg the Super-Coder" Problem Got Worse

A recurring theme: **AI makes knowledge silos more dangerous, not less.**

In many teams, one person ("Greg") understands the critical backend systems. Before AI, Greg wrote the code so he knew it. Now AI writes it, Greg reviews it quickly, and *nobody* deeply understands the result.

> "If it is so critical, why don't we have tests and benchmarks for it? Oh right, because 'Greg the super-coder' never wrote any of this down and it lives in his head so he can be the arbiter of change... Your best coder is now Opus or Astra." — *0x20cowboy*

The counterpoint: this was always a process failure. AI just exposed it.

### 4. Tests Pass But Mean Less

Several engineers noted that **AI writes tests that pass but don't actually verify correctness** — they're often whitebox tests tied to implementation details.

> "I dread looking at or dealing with AI written unit tests because of the incredible amount of whiteboxing that goes on... AI testing is almost entirely whitebox testing which fails if some internal details change." — *svachalek*

One commenter summarized the study's metric problem:

> "Note that they define 'more software' by 'more tickets closed.' Make of that what you will... Are the extra tests you write thanks to coding agents represented in the tickets for your work?" — *dcre*

### 5. Small Teams and Startups See Real Gains

Not everyone was negative. **Solo founders and small teams reported 10x throughput** — not because AI writes better code, but because they can validate more ideas.

> "For startups you can be trying/validating 10X the amount of things as before AI." — *mrieck*

> "Maybe not more professional widely distributed software, but personal software of limited scope and use has boomed around me: designers creating a tool for each new project, developers creating art software, super users asking for plugins or custom workflows..." — *juliendorra*

This matches the "HyperCard analogy" — AI enables a new class of builders who previously couldn't ship at all.

### 6. Process Problems Don't Disappear

A strong thread argued that **AI doesn't fix broken team processes** — it amplifies them.

> "The bottleneck is, and has been, the whole team evolving the product... Our process sucks in this industry. We love to make process because we love to make machines but the processes we love to make rarely help us and that is a fundamental problem that AI isn't changing." — *33d3*

Teams with clear vision, small iterations, and good communication benefit. Teams drowning in Jira backlogs and meetings just get more code in their backlogs.

### 7. Accountability Can't Be Automated

Perhaps the most thoughtful thread: **code review isn't just quality control — it's accountability.**

> "A dimension not much discussed here is that code review is not only about quality but accountability and security... The main protection ultimately is a human being willing to put their reputation on the line by saying 'I understand this change and I approve it'." — *jeanpah*

When AI writes the code and another AI reviews it, who's responsible when production breaks?

## The Real Insight

**AI coding agents are a force multiplier for *execution*, not *judgment*.**

The HN discussion reveals a pattern:

| What AI Helps With | What AI Doesn't Fix |
|-------------------|---------------------|
| Writing boilerplate | Architectural decisions |
| Generating tests | Knowing *what* to test |
| Exploring APIs | Understanding business requirements |
| Refactoring small scopes | System-level design |
| Solo/small team velocity | Large team coordination |

The "more code, not more software" finding makes sense: **software is the result of judgment calls about what to build, not just lines of code that compile.**

Developers who treat AI as a "junior developer who types fast but needs constant supervision" report success. Those who treat it as "replace the senior engineer" report frustration.

## What This Means for You

### If You're a Solo Developer or Small Team
- **Use AI aggressively** for exploration, prototyping, and validation
- You'll genuinely ship more *ideas* (not necessarily more production software)
- Invest in learning to prompt well — it's the new debugging skill

### If You're on a Large Team
- **Don't skip code review** — the bottleneck is real
- Invest in **AI-assisted review tools** (not fully automated)
- Document architecture decisions *before* prompting AI — "Greg's knowledge" must leave his head

### If You're a Manager/C-Suite
- **Measuring "tickets closed" will mislead you** — track epic completion, cycle time, and defect rates
- The "fire engineers, prompt Claude" fantasy ignores accountability and system understanding
- Fix your process *first* — AI amplifies whatever you have

### For Everyone
- **Technical debt compounds faster with AI** — schedule explicit cleanup cycles
- **Tests written by AI need human audit** — they're often tautological
- **The skill shifting**: from "writing code" to "directing, reviewing, and integrating AI output"

## Summary

The HN discussion (290+ comments from working developers) validates the study: **AI coding agents increase code volume without proportional increases in delivered software value — *unless* you're a small team validating many ideas.**

The developers who succeed with AI treat it as a **high-speed, low-judgment pair programmer** — not a replacement for thinking. The ones who struggle expect it to handle the judgment too.

The code is the easy part. The software — the *right* code, maintained by people who understand it — remains hard.
