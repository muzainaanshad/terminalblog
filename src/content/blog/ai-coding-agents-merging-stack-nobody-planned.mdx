This wasn't supposed to happen.

The AI coding agent war was supposed to produce **one winner**. One tool. One subscription. One workflow. You pick your horse — Cursor, Claude Code, or Codex — and ride it.

Instead, something weirder is happening. The three biggest tools are **absorbing each other**.

OpenAI shipped an official plugin that runs Codex *inside* Claude Code. Cursor's agents can call any model — including Claude and GPT. Codex runs as a subagent inside Cursor. They're not competing anymore. They're **layering**.

And nobody planned this stack. It emerged from developers solving their own problems.

## The Three Layers Forming Right Now

### Layer 1: The Editor Shell (Cursor)

Cursor started as "VS Code with AI." Now it's an **agent orchestration platform**.

- **Projects**: Coordinator agents that plan, delegate to subagents, maintain context across months
- **Cloud agents**: Run overnight, produce interactive canvases (dashboards, diagrams, test reports)
- **Origin + Marketplace**: 20+ integrations (Vercel, Semgrep, Linear, Datadog) — deploy, CI, security, monitoring inside the editor
- **Remote Control**: iOS app controls your local agents from anywhere

Cursor doesn't care which model you use. Composer 2, GPT-6, Opus 5.5, Grok 4.7 — they're all plug-and-play.

### Layer 2: The Terminal Agent (Claude Code)

Claude Code started as Anthropic's terminal CLI. Now it's an **extensible agent OS**.

- **Mods**: Plugin architecture that rewrites *deeper behavior* — not just tool calls. Hook `agent.spawn`, cache prompt blocks, raise native notifications
- **Remote MCP**: Servers survive container restarts with exponential backoff
- **Security hardening**: UNC path blocking, worktree isolation for git 2.56+
- **OpenAI's own plugin**: `/codex:review`, `/codex:rescue`, `/codex:transfer` — Codex runs *inside* Claude Code

Claude Code doesn't care which editor you use. Terminal, VS Code, JetBrains, desktop app, web, mobile — same agent.

### Layer 3: The Portable Runtime (Codex)

Codex started as OpenAI's terminal agent. Now it's a **composable execution layer**.

- **Mid-response steering**: Correct the agent *while it's generating* — no restart needed
- **Parallel read-only tools**: Skill lookups, memory searches, history retrieval all at once
- **Config UI**: `/config` — searchable preferences, no flag memorization
- **Runs inside both Cursor and Claude Code** as a subagent

Codex doesn't care where it runs. Terminal, browser, embedded in another agent's workflow — same runtime.

## The Plugin That Broke the Mental Model

**OpenAI built a first-party plugin for a rival's product.**

That sentence should not exist in a competitive market. But here it is: `codex-plugin-cc` — Apache 2.0, maintained by OpenAI, installs in Claude Code with `/plugin marketplace add openai/codex-plugin-cc`.

```bash
# Inside Claude Code:
/plugin marketplace add openai/codex-plugin-cc
/plugin install codex@openai-codex
/reload-plugins
/codex:setup
```

What you get:

| Command | What It Does |
|---------|-------------|
| `/codex:review` | Read-only Codex review of current/branch changes |
| `/codex:adversarial-review` | Steerable review that challenges design decisions |
| `/codex:rescue` | Hands task to Codex via subagent to investigate/fix |
| `/codex:transfer` | Exports session to persistent Codex thread |
| `/codex:status` / `/result` / `/cancel` | Manage background Codex jobs |

The plugin **wraps your existing Codex CLI**. No separate runtime. No new login. Same repo, same auth, same config.

OpenAI's docs even warn about the optional "review gate" — a Stop hook that runs Codex review on Claude's response before accepting, blocking if issues found. "Can create long-running Claude/Codex loop and drain usage limits quickly."

This isn't competition. This is **composition**.

## The Security Conversation Just Got Real

### OpenCode's Daemon = New Attack Surface

OpenCode 2.0 runs a **persistent background service** that owns sessions, shell execution, plugin loading, and model credentials.

- `opencode pair` can expose/connect the service to other hosts
- Shared session state across terminal/web/desktop = compromised client could see/influence sessions started elsewhere
- Hot-reloadable plugins = plugin provenance and code-execution trust are live security questions
- Background shell commands/subagents = unattended tasks need careful lifecycle/approval controls

Augmented Software Engineering flagged the client-server redesign and plugin changes as the parts most likely to need careful review before production use.

### Cursor's Managed Approach

Cursor's Agent SDK deploys to managed infrastructure (or self-host). Secrets in dashboard. Channels authenticate via your Cursor account. More familiar security model — but you trust Cursor's platform.

### Claude Code's Mod System

Mods run with deep hooks into agent behavior. Community Mods will handle custom permission gates, compliance checks, specialized review loops. The API is new — expect rapid ecosystem growth *and* supply-chain risk.

## FAQ

### Which AI coding agent had the biggest October 2026 update?

Claude Code's Mods platform is the most architecturally significant — it turns the agent into an extensible OS. Cursor's Remote Control + Rollouts + Security Review + Projects is the broadest product shift. Codex's mid-response steering + config UI + parallel tools is the best daily UX upgrade. OpenCode 2.0's background service + SDK is the deepest architectural shift.

### Should I switch agents based on October 2026 releases?

Only if your workflow maps to a new capability: need iOS remote control → Cursor; need programmable permission model → Claude Code Mods; need embeddable runtime → OpenCode SDK; need git-native day-zero model support → Aider. Don't switch for "features" — switch for **architecture alignment**.

### Is Cursor's Security Review a replacement for SAST tools?

No. It finds *exploitable bugs in PR context* (injection, auth bypass, SSRF, secrets, unsafe deserialization, vulnerable dependencies). It complements SAST — it doesn't replace whole-repo static analysis. Think of it as "security review per change" vs "security audit per codebase."

### What are Claude Code Mods practically useful for today?

The built-in "You Should Know" mod runs a side agent that flags missed edge cases, security issues, and pattern violations. Community Mods will likely handle: custom permission gates, compliance checks, specialized review loops, automated documentation, and workflow enforcement. The API is new — expect rapid ecosystem growth.

### Does Codex's steering feature actually work in practice?

Yes. You type a correction mid-stream, Codex interrupts, re-plans, continues with your direction. It's like grabbing the wheel when your GPS tries to drive you into a lake — except the car actually listens. This alone changes how you trust the agent on long tasks.

### Can I really run Codex inside Claude Code inside Cursor?

Yes. Cursor agent → calls Codex subagent → which could theoretically invoke a Claude Code Mod. The layers are composable. Whether it's *wise* depends on your latency and cost tolerance — but the architecture permits it.
