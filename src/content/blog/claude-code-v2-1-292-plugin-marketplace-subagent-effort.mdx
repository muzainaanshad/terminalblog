Claude Code **v2.1.292 dropped October 6**, three days after the plugin-stability release v2.1.289. This isn't a feature parade — it's the release that makes **plugin discovery universal**, **sub-agents independently tunable**, and **mods actually fast**.

If you've ever wanted to install a plugin from a private registry without jumping through hoops, or wished your background research agent could think harder while your main agent stays fast — **this is the version.**

---

## 1. Plugin Install From Any Marketplace — Finally

**The headline:** `claude plugin install <plugin> --marketplace <source>`

Before: you had to `claude plugin marketplace add <source>` first, wait for it to succeed, *then* install. Two commands, two policy checks, two failure points.

Now: **one command.** It adds the marketplace if needed (same policy checks), then installs. Done.

```bash
# Install from a private/internal marketplace
claude plugin install my-team/plugin --marketplace https://registry.internal.company.com

# Install from a community marketplace
claude plugin install awesome-plugin --marketplace https://plugins.example.dev
```

For plugin authors and teams running private registries — this removes the friction that made custom marketplaces feel like a hack.

---

## 2. Sub-Agents Get Their Own `effort` Level

**New:** The `Agent` tool now accepts an `effort` parameter.

```json
{
  "tool": "Agent",
  "parameters": {
    "prompt": "Deep-dive this legacy auth module and propose a rewrite",
    "effort": "high"
  }
}
```

Your main agent can run at `effort: "low"` for speed, while a spawned research sub-agent runs at `effort: "high"` for depth — **in the same session.**

For beginners: think of it as giving your intern a longer deadline than your senior dev. The model spends more compute on reasoning before answering. This is the first time you can tune reasoning *per sub-agent* instead of globally.

---

## 3. Prompt Caching for Mods — Your Mods Just Got Faster

**New:** `$.model.complete` now supports prompt caching for mods.

```javascript
// In your mod
const result = await $.model.complete({
  prompt: [{ text: hugeSystemPrompt, cache: true }],
  system: [{ text: anotherLargeBlock, cache: true }],
});
```

Blocks marked `cache: true` are cached up to that point. On subsequent calls, the cached prefix is reused — **latency drops, cost drops.**

If you build mods that send the same large system prompt or context on every turn (documentation loaders, codebase indexers, style guides) — this is the optimization you've been waiting for.

---

## 4. Overloaded Retry Control — Stop the 529 Spiral

**New:** `CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS` environment variable.

When Anthropic's API returns 529 (overloaded), Claude Code backs off exponentially. The base delay was hardcoded. Now you control it:

```bash
# Longer base delay = gentler retry, less hammering
export CLAUDE_CODE_OVERLOADED_RETRY_BASE_DELAY_MS=5000
```

For teams running many parallel sessions during peak hours — this prevents your fleet from turning a temporary overload into a cascade of retries.

---

## 5. Prompt Autocomplete Hook — Mods Can Now Extend the Composer

**New:** `prompt.autocomplete` event — a mod can hook this to inject its own rows into the prompt box's autocomplete list.

```javascript
// In your mod
$.on('prompt.autocomplete', (ctx) => {
  if (ctx.query.startsWith('/mycmd')) {
    ctx.addRow({ label: '/mycmd deploy', description: 'Deploy to staging' });
    ctx.addRow({ label: '/mycmd rollback', description: 'Rollback last deploy' });
  }
});
```

Your custom slash commands, template snippets, or frequently used patterns — now discoverable in the same autocomplete your users already know.

---

## 6. Workflow Agents in `agent.spawn` Hook — Mods Can Gate Team Spawns

**New:** Workflow agents (the ones spawned via `agent.spawn` for teammates) now appear in the `agent.spawn` mod hook with their `run` and `index`.

A mod can now **refuse** a workflow agent spawn based on policy, quota, or custom logic.

```javascript
$.on('agent.spawn', (ctx) => {
  if (ctx.isWorkflowAgent && ctx.run === 'expensive-analysis') {
    if (teamQuotaExceeded()) {
      ctx.deny('Team analysis quota exceeded for this hour');
    }
  }
});
```

For enterprise setups — this is the governance hook you needed.
