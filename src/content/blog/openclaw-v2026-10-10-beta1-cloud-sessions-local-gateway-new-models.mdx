## 1. Cloud Sessions: Move Your Work Between Laptop and Cloud

**What it does:** Move sessions between local and cloud **from the session menu**. Organize cloud environments **by repository** with **environment recipes** and **verified Node toolchains**. See **snapshot progress** while sessions start before the first snapshot finishes uploading.

**Before:** Cloud was a separate thing — you picked "cloud" or "local" at session start and that was it. Moving work meant manual export/import.

**Now:** You're coding on your laptop → need more compute → **move to cloud in two clicks**. Come back later → **move back to local**. Environment (Node version, deps, secrets) travels with it via recipes.

**Why beginners care:** No more "which environment am I in?" confusion. Your session *is* the project — it just runs wherever you need it.

---

## 2. Local Gateway in the Desktop App (Finally)

**What it does:** The **Windows desktop app** and **fresh Tauri installs** now run a **local Gateway out of the box**. Fresh macOS installs start in **guided dashboard setup**. First-run setup **chooses inference automatically**. Missing native permissions are guided in chat.

**Before:** You installed the desktop app → still had to run `openclaw gateway` separately → configure ports, auth, tunnels → "why is this so hard?"

**Now:** Install desktop app → **open it → it works**. The Gateway runs inside. No separate process, no port conflicts, no "wait, which terminal had the Gateway?"

**Why it matters:** This is the difference between "developer tool" and "app you give to your team." The Windows desktop app especially — just install and run.

## 3. New Models That Just Appear (No OpenClaw Release Needed)

**What it does:** Pickers **lead with each provider's recommended models**. **Newly listed Claude, ChatGPT, Ollama models appear without waiting for an OpenClaw release**. Pickers stay responsive while catalogs load.

**New in this beta:**
- **Gemini 4 Argon** — new default Gemini model (with Gemini 3.8 Flash)
- **Nemotron 3.5 Super VL** — NVIDIA's vision-language model
- **xAI Imagine Image 2.0** — image generation, no silent fallback
- **Fish Audio Drama 3 preview** — voice/audio
- **Muse Code** (Meta) — runs through the Muse Code CLI agent runtime

**Before:** New model drops → wait for OpenClaw release → update → model appears in picker.

**Now:** Provider adds model → **appears in picker automatically** (recommended ones first).

**Why beginners care:** You always see the **best current options** — no config hunting, no version lag, no "wait, does OpenClaw support this yet?"

## 4. Muse Code: Meta's Agent Runtime Inside OpenClaw

**What it does:** Run **Meta models through the Muse Code CLI agent runtime**. Sign in to Muse Code from **Model Setup** and **Provider Access**. Consented turns run under a **conversation tool policy**.

**Why it matters:** Meta's models (Llama, etc.) now have a **first-class agent runtime** inside OpenClaw — not just "chat with Llama" but "Llama *uses tools, runs code, accesses your repo*." Sign in once, use it like any other provider.

---

## 5. Bun Runtime: Standalone Executables, Faster Startup

**What it does:** Build **standalone OpenClaw executables with Bun**. Add an **opt-in pinned Bun runtime** that rejects unpinnable paths before changing anything. **Gateway starts faster on Bun**.

**Why it matters:** Bun's startup speed + single-binary distribution = **OpenClaw that feels instant**. The pinned runtime means "it works on my machine" actually means "it works on *your* machine too."

---

## 6. Gateway That Stays Fast Under Load

**What it does:** Chat turns, session lists, startup, and idle Gateways do **far less SQLite and main-thread work**. More database work moves onto **worker threads**. Busy hosts and **large agent fleets stay responsive**.

**The experience:** You run 20 agents across 5 repos. **Before:** Gateway becomes the bottleneck — UI lags, turns queue up. **Now:** Main thread stays free. Reads happen in background. UI stays snappy even at scale.

**Why it matters:** As your usage grows, the Gateway **scales with you** instead of becoming the ceiling.

---

## 7. Updates That Actually Finish (And Restart-Safe Replies)

**What it does:** Upgrades from **2026.10.1 and earlier betas complete reliably**. Busy Gateways and slow Doctor steps **no longer refuse or roll back a good update**. Failed updates **no longer leave a half-installed version**. macOS, Windows, and Bun installs **recover from platform-specific failures**.

**Restart-safe replies:** Interrupted and unfinished replies **resume after a Gateway restart**. Watched child results, queued turns, accepted agent updates, and operator tasks **survive restarts instead of disappearing**.

**Why it matters:** This beta continues the "updates don't strand you" work from 2026.10.5-beta.1 — now covering upgrades *from* that release, plus macOS/Windows/Bun edge cases. And your work survives a Gateway restart.

---

## 8. Node 24/26 Compatibility: Installs and Updates Work Again

**What it does:** Node compatibility fixed for `>=24.16.0 <25 || >=26.1.0`. Node 24.22.1 or 26.12.1 is now a **security recommendation** instead of a hard requirement. Node 26 workers **no longer abort when stdin is a file**.

**Before:** Node 24/26 users hit install failures, update failures, or worker aborts on file stdin.

**Now:** Just works. The version check is advisory, not blocking.

**Why beginners care:** You don't need to pin Node versions or downgrade. OpenClaw works on current LTS and current releases.

---

## 9. Gateway Streaming: Tool-Call XML and Partial HTML No Longer Stall

**What it does:** Replies that **contain tool-call-like XML, look like tool calls, or end long HTML at a partial tag** no longer stall the Gateway.

**Before:** Streaming a reply with `<tool>` tags, tool-call patterns, or truncated HTML would freeze the Gateway — turns would queue, UI would hang.

**Now:** Gateway parses through these patterns without stalling. Missing-answer notices no longer follow streamed delivery. Side-question replies no longer disappear or repeat after tool sends. Multiline `/btw`, `/loop`, and `/acp` steer input is preserved. Compaction failures show instead of stale overflow advice.

**Why it matters:** If you run agents that emit structured output or work with HTML-heavy tasks, the Gateway stays responsive. This was a daily paper cut for heavy users.

---

## 10. Update Rollback: Failed Rollback No Longer Strands Packages

**What it does:** A **failed npm rollback no longer strands the installed package**. An **immediate Git rollback keeps operator edits**. An **update whose executor dies recovers its offline state**.

**Before:** Failed update → rollback attempt → rollback fails → package in limbo, operator edits lost, executor dead = session broken.

**Now:** Each failure mode has a recovery path. The package isn't stranded. Your edits survive. The executor recovers.

**Why it matters:** This completes the "updates don't strand you" story from beta.1 — now covering the rollback path itself.

---

## 11. Cron: Missed Slots No Longer Dropped

**What it does:** Missed cron slots with a **stale stored next run time are no longer dropped**. **Startup catch-up runs are admitted after a restart**.

**Before:** If the Gateway was down when a cron should have fired, the slot was silently dropped. Restart didn't catch up.

**Now:** Stored next-run-time is validated. If it's stale, the missed slot fires on startup. Your scheduled agents run when they should.

---

## 12. Security Hardening: HTTPS Allowlist, Browser Proxy Blocking, Credential Redaction

**What it does:** Multiple security boundaries hardened in beta.5:

- **HTTPS allowlist enforcement** — require approval for `test`/`[ -v` operands in exec allowlist mode, refuse browser proxy commands sent through generic node invoke, fail closed when sandboxed spawned children resolve CLI-backed models
- **Browser proxy blocking** — stop crafted Teams HTML from stalling the Gateway before sender checks, refuse embedded Control UI auth on pinned Android Gateway connections
- **Credential redaction** — keep browser pairing credentials out of opener process arguments, mask Google OAuth client secrets in logs, redact credentials from MCP CLI inspection, omit credentials from rejected search endpoint errors, keep malformed piped input from corrupting model credentials
- **Dependency security** — update fast-uri, bound vendored Zod traversal for A2UI and Discord input, scope the patched MSAL for Microsoft Teams, pick up nodemailer sender-parsing fixes for IMAP

**Why it matters:** This is defense-in-depth. Each layer catches what the previous missed. If you run OpenClaw in production or shared environments, these boundaries matter.
