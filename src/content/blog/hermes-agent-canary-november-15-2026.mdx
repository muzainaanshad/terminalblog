## 2. Group Chats — Multi-User, Multi-Agent, One Conversation

**What it is:** Multiple people + multiple agents in one chat. Agents see each other's messages. You @-mention specific agents. Routing rules decide who answers what.

**Why it matters:** 
- Your teammate asks "@hermes analyze this PR" → code review agent answers
- You ask "@planner break this down" → planning agent answers
- Both agents see the full context. No copy-paste. No context loss.

**For beginners:** This turns Hermes from "my personal assistant" into "our team's command center." Start a group chat, add your agents, watch them collaborate.

---

## 3. Plugin OAuth — Plugins Sign You In, Never See Your Tokens

**The old way:** You paste API keys into plugin settings. Plugin sees everything. You trust the plugin author.

**The new way:** 
1. Plugin declares an OAuth client (Google, GitHub, Notion, etc.)
2. You run `hermes auth add <plugin>:<id>`
3. Browser opens → you sign in → you grant permission
4. Hermes attaches the token **only on requests to hosts the plugin declared**

**Why it matters:** 
- Plugin author never sees your token
- Token scope limited to what plugin *needs*
- Revoke in one click from Hermes dashboard

**For beginners:** Install a Notion plugin. Run `hermes auth add notion:my-workspace`. Sign in once. Plugin works. You never touched a token.

## 4. MCP Tool Costs & Spend Limits — Your Wallet Has a Guardian

**What it is:** MCP servers declare what each tool costs. You set a per-chat spend limit. Approval prompt shows cost + running total. Call that would exceed limit → asks first, **even in YOLO mode**.

**Example:**
```
MCP Server: "github.create_issue" costs $0.02
Chat spend limit: $1.00
You've spent: $0.94 this chat
Next create_issue → "This will cost $0.02, total $0.96. Allow?"
```

**Why it matters:** No surprise bills. No runaway agent spending your API credits. Hard guardrails that *work*.

---

## 5. Skill Locking — `hermes curator lock <skill>` = Hands Off

**What it is:** After locking, the agent **cannot** change that skill — not with `skill_manage`, not with file edits, not with terminal writes, not even under `--yolo`. Curator won't archive it either.

**Why it matters:** Your critical skills (production deploy, database migrate, security audit) become **immutable**. Agent can read them. Agent can *use* them. Agent *cannot break them*.

**For beginners:** Lock your "deploy to prod" skill. Sleep better.

## 7. Faster Startup — ~1 Second Saved Every Command

**What changed:** Provider plugins and restart check no longer run `git` on every command. **15 git calls down to 2**.

**Why it matters:** `hermes` feels snappy. `hermes chat` opens faster. Every CLI interaction saves a second. Compounds to minutes per day.

## 8. Desktop Plugin SDK Got Huge

**Desktop plugins can now:**
- Add rows to composer right-click menu
- Add words to spell checker
- Render media from their own tools
- Post cards into their own chat
- Script the preview Browser (with capability + your permission)
- Portable plugins get Settings ▸ Plugins form
- Newly saved API key reaches MCP server **without restart**

**Why it matters:** Desktop plugins are now *first-class citizens* — not second-class webviews.

---

## 9. Multi-Profile Gateway — Plugins Behave the Same Everywhere

**What changed:**
- Classic CLI plugin commands + `pre_command` run in gateway with rest of plugin
- Disabling a plugin closes its WebSockets
- Secondary profile's dashboard plugins run in that profile's own plugin host
- Stdio MCP servers on multi-profile gateway use **their own profile's home**

**Why it matters:** No more "works in CLI, broken in Desktop" or "plugin leaks across profiles." Consistency by default.

---

## 10. Remote Config Backend for Fleets (Opt-In)

**What it is:** Set `HERMES_CONFIG_BACKEND=remote` → fleet agents load each profile's `config.yaml` from central service. Admins can lock keys.

**Why it matters:** Manage 100 Hermes instances from one dashboard. Push config changes. Lock critical settings. Zero SSH required.
