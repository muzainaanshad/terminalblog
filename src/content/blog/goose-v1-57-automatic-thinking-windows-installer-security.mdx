**Goose v1.57.0 dropped October 28, 2026** — and this patch release does three things that matter: **automatic thinking level** (the model picks its own reasoning depth), **HTTPS allowlist with redirect validation** (security hardening for tool calls), and **caller-supplied session IDs** (embedding Goose gets easier).

If v1.56 gave you automatic thinking, resume subagents, Windows NSIS installer, and Boa JS runtime — v1.57 hardens the security boundary and fixes the desktop UX paper cuts.

---

## The Headline Features (Ranked by Impact)

### 1. Allowlist: Require HTTPS & Validate Redirects — Security Boundary Hardened

**What it is:** New allowlist enforcement that **requires HTTPS** and **validates redirects**, blocking on policy failure ([#12619](https://github.com/aaif-goose/goose/pull/12619)).

**Why it matters:** Tool calls that fetch URLs now go through a strict allowlist. HTTP is rejected. Redirects are validated against policy. If a redirect tries to bounce you to a non-allowed domain, it fails closed.

**For beginners:** This is the "safe by default" moment. You don't configure it — it just protects you. Malicious redirects in tool outputs? Blocked. HTTP leaks? Blocked. The agent's network surface is now explicitly governed.

---

### 2. Caller-Supplied Session IDs — Embedding Goose Just Got Easier

**What it is:** External callers can now **supply their own session IDs** ([#13098](https://github.com/aaif-goose/goose/pull/13098)) when starting Goose sessions via the API.

**Why it matters:** If you're building an IDE plugin, CI bot, or custom frontend on Goose, you no longer need to track Goose's internal session IDs. You pass your own ID, Goose uses it. Your orchestration layer stays the source of truth.

**For builders:** This unlocks clean embedding patterns. Your session management + Goose's execution = clean separation.

---

### 3. Automatic Thinking Level (Carried from v1.56, Now Default)

**What it is:** Goose supports **automatic thinking level operation** ([#12237](https://github.com/aaif-goose/goose/pull/12237)). Instead of you setting a fixed "thinking budget," the model decides how much reasoning a task needs.

**Why it matters:** Simple edits get fast responses. Complex architecture decisions get deep reasoning. Set `GOOSE_CLI_SHOW_THINKING=1` and watch it adapt per turn.

**For beginners:** Stop managing sliders. The agent becomes adaptive — Claude Sonnet 5.5, Haiku 5.5, GPT-6 Sol, Opus 5.5 all pick their own depth.

## What This Means for You

**If you're new to coding agents:** Goose v1.57 doesn't change the "first run" much — but the **security hardening** compounds. HTTPS allowlist means tool calls can't leak to HTTP. Redirect validation means malicious links in tool output hit a wall. The agent feels **secure by default**, which is the feature beginners appreciate most once they realize what's at stake.

**If you're embedding Goose (IDE plugin, CI bot, custom frontend):** Caller-supplied session IDs = your orchestration layer owns the session identity. No more mapping tables. ACP error propagation = your error handling gets real signals. Windows build fix = your Windows CI passes again.

**If you use OpenRouter:** Variant suffixes (`:free`, `:nitro`) now resolve correctly. No more "model not found" on free tiers.

**If you're on Linux:** Window icons are back. The desktop app looks native again.

## The Bottom Line

**v1.55 hardened the runtime. v1.56 made the agent intelligent about its own intelligence. v1.57 hardens the security boundary and fixes the embedding story.**

- **HTTPS allowlist + redirect validation** = tool call network surface is governed
- **Caller-supplied session IDs** = clean embedding for IDE plugins, CI bots, custom frontends
- **Linux icons + Windows build fix** = desktop is a first-class citizen everywhere

The pattern holds: Goose isn't chasing "shiny feature of the week." It's hardening the **security layer**, the **embedding layer**, the **desktop layer**, and the **thinking layer** — the things that matter when you run agents in production, not just in a terminal.

For a beginner, that means **fewer config knobs, fewer security surprises, fewer "why did it do that?" moments**. For a builder, it means **Goose is becoming a platform you can ship on top of — securely**.
