Claude Code **v2.1.287** dropped October 1, and it's the first release where **plugins stop being cosmetic and start changing how the agent thinks**.

The headline: **Claude Mods** — a plugin architecture that lets extensions modify *deeper agent behavior*, not just add slash commands. And it ships with a built-in mod called **"You Should Know"** that runs a silent side agent watching your session and flagging things you or Claude might miss.

If you've ever thought "Claude Code is great but I wish it could..." — this release is the answer.

---

## 1. Claude Mods — Plugins That Actually Change Behavior

Until now, plugins were mostly slash commands and UI tweaks. Mods are different.

**Mods hook into the agent's decision loop.** They can:
- Intercept and modify tool calls before execution
- Inject context the agent wouldn't see otherwise
- Run parallel "watchdog" agents that review the main agent's work in real-time
- Alter how the agent plans, reasons, or responds

This isn't "add a command." This is "change how the agent thinks."

### How to Enable Mods

```bash
# Enable the built-in watchdog mod
/plugin enable cc-plugin-you-should-know@builtin

# List available mods
/plugin list

# Install community mods (when they exist)
/plugin install <mod-name>
```

**Requires first-party session with telemetry on** — the watchdog mod needs telemetry to function. This is a deliberate design choice: the side agent needs visibility to be useful.

---

## 2. "You Should Know" — The Side Agent That Has Your Back

This is the killer feature. You enable it, and a **second agent runs silently alongside your main session**. Its only job: *watch for things going wrong*.

What it catches:
- **Security issues** — hardcoded secrets, unsafe patterns, permission overreach
- **Architecture drift** — you said "don't touch auth" but the agent is editing auth files
- **Missed context** — you mentioned a constraint three turns ago; the agent forgot; the watchdog didn't
- **Token waste** — the agent is about to burn 50k tokens on a rabbit hole
- **Silent failures** — a tool succeeded but did the wrong thing

It surfaces flags as **non-blocking notifications** — you see them, decide if they matter, keep going. No interruption unless you want it.

### Why This Matters for Beginners

You're learning. You don't know all the failure modes. The watchdog *does* (it's trained on millions of sessions). It's like having a senior dev looking over your shoulder — except it's always there, never tired, and doesn't judge.

---

## 3. New Agent View Filters — Finally Find That Session

The agents view (your session dashboard) gets two filters that should've existed years ago:

| Filter | Syntax | What It Does |
|--------|--------|--------------|
| **Name/Task filter** | `n:<text>` | Matches session names AND task descriptions |
| **Prompt text filter** | `prompt_text:<text>` | Searches inside the actual prompts you sent |

**Behavior:** Filter shows matches in collapsed sections. Press `Enter` on a match → opens that session directly.

No more scrolling through 50 sessions trying to remember which one had the "fix the webhook bug" conversation.

---

## 4. `prompt_text` Field — Your Prompts Are Now Queryable

Related to the filter above: every session now stores `prompt_text` as a first-class field. This means:
- Programmatic access to your prompt history
- Better session search/resume
- Future mods can analyze your prompting patterns
