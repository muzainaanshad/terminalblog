AmpCode shipped a deceptively simple feature on October 12 that changes how you review every pull request: **the Changes pane now automatically puts files in intelligent order**.

Not alphabetical. Not chronological. **By importance to the change**.

## What Just Landed

### The Problem: Alphabetical Is Useless for Reviews

You open a 47-file PR. The Changes pane lists them `a-config.yaml` through `z-util.ts`. You scroll, hunt, guess which files actually matter. The business logic is buried in `services/payment/processor.ts` but it's sandwiched between `services/payment/adapters/stripe.ts` and `services/payment/types.ts`.

### The Fix: Amp Reads the Diff and Orders for You

Now when you open a PR in Amp, the Changes pane **automatically surfaces the essential files first**:

- Entry points the change touches
- Core logic modifications  
- Test files for the changed behavior
- Config/schema updates
- Peripheral changes last

```bash
# No command needed — it's automatic in the Changes pane
# Click the ordering button (blue dot = updated order available)
```

**If the diff changes** (new commits pushed), Amp recomputes the order without rearranging files while you're reviewing. A blue dot appears on the ordering button — click to apply the updated order.

### Speed Comparison: Old vs New

| Metric | Alphabetical | Intelligent |
|--------|-------------|-------------|
| Time to find core logic | ~3-5 min | **Instant** |
| Missed critical files | Common | **Rare** |
| Review context switching | High | **Low** |
| "Wait, what does this file do?" | Constant | **Almost never** |

## Why This Matters for Beginners

### You Review Like a Senior, Not a Novice

Beginners review linearly. Seniors review **strategically** — they find the architectural decisions first, then verify the implementation. Intelligent ordering **gives you senior review instincts automatically**.

### Works With the GitHub Webhooks You Just Set Up

If you read the [AmpCode GitHub Webhooks article](/blog/ampcode-github-webhooks-pr-automation/), you know Amp now subscribes to PR comments, reviews, and CI. **Intelligent ordering makes those in-thread reviews actionable instantly**:

1. Reviewer comments on `processor.ts` → shows in thread
2. You open Changes pane → `processor.ts` is **already at the top**
3. You fix, push, thread updates → order refreshes with blue dot

### No Config, No Learning Curve

It just works. The feature is **on by default**. You can optionally click the ordering button to go back to alphabetical if you're into that kind of pain.

## The Bigger Picture: Amp Is Building Review Infrastructure

This isn't a standalone feature. It's part of a **review loop** Amp is closing:

| Loop Stage | Amp Feature |
|------------|-------------|
| **Write code** | Agent writes, opens PR |
| **Monitor** | GitHub Webhooks → comments/CI in-thread |
| **Review** | **Intelligent file ordering** (this release) |
| **Fix** | Agent acts on feedback, pushes |
| **Verify** | CI results in thread, order updates |
| **Merge** | You click merge (or configure auto-merge) |

Intelligent ordering is the **review acceleration layer** that makes the rest of the loop feel fast instead of frustrating.

## Honest Limitations

- **Not perfect**: Heuristics can misjudge "importance" on unusual architectures
- **Alphabetical fallback**: One click if you disagree
- **PR-only**: Doesn't apply to local uncommitted changes (yet)
- **Web UI + CLI**: Works in both, but the visual pane is where it shines

## Quick Test to Feel the Difference

1. Open a PR with 20+ files in Amp (web or CLI)
2. Look at the Changes pane — notice the top 3-5 files
3. Ask yourself: "Would I have found these first alphabetically?"
4. Click the ordering button → alphabetical → feel the pain
5. Click again → intelligent → feel the relief
