GitHub issue [#77147](https://github.com/anthropics/claude-code/issues/77147) documents a disturbing failure mode: **Claude Code sessions are bleeding content into each other**. This includes remote sessions — meaning context from a session on another machine, another user, or another project can leak into your current session and trigger actions you never authorized.

If you run Claude Code with broad system access (filesystem, network, shell), this is the failure mode you actually fear.

## What Happened

The issue reporter noticed that after running a session on a remote machine via SSH, their local session started:
- **Confabulating instructions** from the remote session as if they were given locally
- **Acting on tool results** from the remote session without being asked
- **Leaking file paths, commands, and outputs** across the session boundary

The bleed appears bidirectional: local context can leak into remote sessions, and remote context leaks back. The reporter confirmed this happens with the official Anthropic SSH integration, not a custom setup.

## Why This Is Critical

This isn't a UI glitch. It's a **trust boundary collapse**.

## Reproduction (From Issue #77147)

```bash
# On remote machine
ssh user@remote
claude
> "Read the SSH private keys in ~/.ssh"
# Agent reads and displays keys

# On local machine (new, separate session)
claude
> "What files did I just ask you to read?"
# Agent ANSWERS with the remote session's file paths and content
# It may even OFFER to read them locally
```

The agent confabulates the remote session's interaction as if it happened in the current session.

## Workarounds (Until Fixed)

### 1. Use Explicit Session Isolation
```bash
# Start each session with a clean context marker
claude --session-id "$(uuidgen)" "Your prompt here"
```

### 2. Avoid Broad Permissions in Shared Environments
- Don't run with `--dangerously-skip-permissions` on shared machines
- Scope API keys per-session where possible
- Use separate user accounts for separate workloads

### 3. Monitor for Unexpected Context
Watch for:
- Agent referencing files/commands you didn't mention
- Tool results appearing without corresponding tool calls
- Sudden knowledge of remote paths, hosts, or credentials

### 4. Restart Between Sensitive Tasks
```bash
# Hard reset between contexts
claude --clear-history
# Or kill and restart the CLI entirely
```

## The Root Cause (Speculative)

The bleed likely stems from how Claude Code manages its **conversation state** across the CLI ↔ daemon ↔ model pipeline. Possible vectors:

1. **Shared daemon state** — The background daemon caches conversation history globally, not per-session
2. **Prompt cache reuse** — Anthropic's prompt caching (enabled by default) may reuse cached prefixes across sessions
3. **Session ID collision** — Session identifiers aren't properly namespaced for remote vs local
4. **MCP server state** — If MCP servers maintain state, they become a cross-session bridge

Anthropic has acknowledged the issue and labeled it `bug`, `has repro`, `area:core`, `severity:high`.

## FAQ

**Q: Does this affect all Claude Code users?**
The issue is confirmed with the official SSH integration. Local-only sessions may also be affected if the daemon shares state.

**Q: Is my data exposed to other users?**
If you share a machine or use a shared daemon, yes — your session context can leak to other users' sessions and vice versa.

**Q: Can I disable prompt caching to prevent this?**
Not currently exposed as a CLI flag. The bug is in the session isolation layer, not just caching.

**Q: What's the fix timeline?**
No public ETA. Track [#77147](https://github.com/anthropics/claude-code/issues/77147) for updates.
