## 1. Cloud Workspaces From Your Terminal (v7.8.21 Pre-Release — Oct 28)

**The feature:** The local Kilo CLI (`kilo`) now has a **session-host API** that can list, create, read, check status, and delete **hosted cloud workspaces**. You can start a cloud session, follow its preparation events through a local system feed, and run another session in the same workspace — all without leaving your terminal.

```bash
# List available workspace profiles
kilo cloud workspace list-profiles

# Create a hosted workspace
kilo cloud workspace create --profile=standard --repo=github.com/you/project

# List sessions in that workspace
kilo cloud workspace sessions <workspace-id>

# Start another session in the same workspace
kilo cloud session start --workspace=<workspace-id>

# Follow preparation/status events locally
kilo cloud feed --workspace=<workspace-id>
```

**Why it matters:** You get the compute of cloud agents (bigger context, parallel workers, persistent environments) **controlled from your local CLI**. No dashboard clicking. No context-switching. Your terminal becomes the control plane for both local and cloud work.

**PR:** [#15351](https://github.com/Kilo-Org/kilocode/pull/15351) — adds internal Session Host registry and built-in Kilo Cloud provider.

## 2. Auto-Compaction Finally Works on Local Models (v7.8.20 Pre-Release — Oct 27)

**The bug:** Auto-compaction triggered **early** (before your configured threshold). Worse: on models without a known context size (Ollama, LM Studio, custom endpoints), it would **loop infinitely** — compact, hit the same wall, compact again. Stopping it manually just restarted it.

**The fix (v7.8.20):**
- Compaction now **respects your configured threshold** — no early starts
- **No looping on unknown context sizes** — if the model doesn't report a limit, compaction backs off
- **Stopping compaction actually stops it** — no restart spiral

**Why it matters:** If you run local models — **this fixes your workflow entirely**. You can finally use Ollama/LM Studio/custom endpoints without the agent pausing every 3 minutes to summarize.

**PR:** [#15479](https://github.com/Kilo-Org/kilocode/pull/15479) by @WebReflection

## 3. CLI Now on Conda — `pixi add kilo-cli` Works (v7.8.20)

**What it is:** The KiloCode CLI publishes as **`kilo-cli` on Anaconda.org** (conda-forge compatible), built with rattler-build for:
- `linux-64`, `linux-aarch64`
- `osx-64`, `osx-arm64`
- `win-64`

```bash
# pixi (recommended)
pixi add kilo-cli@rc        # pre-release
pixi add kilo-cli           # stable (when promoted)

# conda
conda install -c anaconda-cloud kilo-cli

# mamba
mamba install -c anaconda-cloud kilo-cli
```

**Why it matters:** No more `curl | bash`, no more npm global installs fighting your Node version. **Conda = reproducible, isolated, versioned CLI installs.** Works in pixi environments, Docker builds, CI pipelines.

**PR:** [#14465](https://github.com/Kilo-Org/kilocode/pull/14465) by @zfralish

## 4. Stable v7.8.18 (Oct 26) — The Platform Release You're On

If you're on stable, you already have these (but might not know):

| Feature | What It Means |
|---------|---------------|
| **Chat copy fix for VS Code 1.143** | Copy-paste in chat works again |
| **DOMPurify 3.4.17** | XSS vector in markdown rendering patched |
| **Vite 7.3.7** | CVE in dev server patched |
| **MCP SDK 1.32.1** | **Security: blocks cross-origin redirects in MCP HTTP/OAuth** — remote servers that redirect to another origin or answer `POST` with `301`/`302`/`303` no longer connect |
| **Hosted cloud sessions via local API** | Foundation for v7.8.21's full workspace management |

**The MCP redirect fix alone is worth the update.** Your editor validates everything the agent outputs. A redirect chain leaking credentials = supply chain compromise. **Patched.**

## 5. v7.8.23 Pre-Release (Oct 28) — The "Stop Breaking My Session" Fixes

- **Background jobs preserve real exit codes** — no more "failed job recorded as successful"
- **Large-session compaction gets enough output space** — thinking + complete summary, no cut-off summaries losing history
- **Multi-process reply handling** — if another Kilo process is writing, it keeps the reply instead of deleting it
- **Scheduled tasks fire once across processes** — no duplicate cron runs when multiple Kilo processes share a data directory

**Why it matters:** These are the "my agent just died/lost context/did something weird" fixes. If you run long sessions or multiple Kilo instances — **this is the pre-release to test.**

## The Pattern: Eight Releases, Zero Fluff

October 2026 wasn't a feature parade. It was **footgun removal**:

- **v7.8.15**: Browser prompt fix — *usability*
- **v7.8.17**: Browser MCP security — *security*
- **v7.8.18**: Chat copy + DOMPurify + Vite CVE + MCP redirect fix + cloud sessions foundation — *stability + security + platform*
- **v7.8.20**: Compaction logic + zod memory + conda CLI + agent-chosen base branch — *core reliability + distribution*
- **v7.8.21**: Cloud workspace CRUD + system feed from local CLI — *platform maturity*
- **v7.8.23**: Background job fidelity + compaction output + multi-process safety — *session reliability*

**Six releases in six days.** Each one removes a specific failure mode: compaction loops, memory DoS, redirect leaks, broken copy-paste, lost exit codes, cut-off summaries, duplicate crons. The conda package and cloud workspace API are the bonuses — **distribution and platform maturity**.

**If you're on v7.8.18 stable and happy — stay. If compaction drives you crazy, or you want cloud workspaces from your terminal — grab the pre-release. The fixes are real.**
