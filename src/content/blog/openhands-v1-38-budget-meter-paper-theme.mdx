## v1.40.0 (Nov 12) — Agent Canvas Goes Desktop

### Official Desktop Installers

This is the headline: **Agent Canvas now has native desktop packages** — no more "how do I run this locally?" friction.

| Platform | Artifact | Install |
|----------|----------|---------|
| **macOS (Apple Silicon)** | `OpenHands-Agent-Canvas-1.40.0-universal.dmg` | Drag to Applications, then `xattr -dr com.apple.quarantine "/Applications/OpenHands Agent Canvas.app"` |
| **macOS (Intel)** | Same universal DMG | Same |
| **Windows x64** | `OpenHands-Agent-Canvas-Setup-1.40.0.exe` | Run installer |
| **Linux x64** | `OpenHands.Agent.Canvas-1.40.0.AppImage` | `chmod +x && ./OpenHands.Agent.Canvas-1.40.0.AppImage` |
| **Linux (Debian/Ubuntu)** | `agent-canvas_1.40.0_amd64.deb` | `sudo dpkg -i agent-canvas_1.40.0_amd64.deb` |
| **Docker (all)** | `ghcr.io/all-hands-ai/openhands:1.40.0` | `docker pull ghcr.io/all-hands-ai/openhands:1.40.0` |

> **macOS Gatekeeper note:** The app isn't signed with an Apple Developer ID yet. After moving to Applications, run:
> ```sh
> xattr -dr com.apple.quarantine "/Applications/OpenHands Agent Canvas.app"
> ```
> This clears the "damaged" warning once. Signing + notarization tracked in [#16774](https://github.com/OpenHands/OpenHands/issues/16774).

### Codex Subscription Authentication Guidance

If you use OpenHands with a **Codex subscription** (the ChatGPT coding agent plan), v1.40 adds clearer guidance during setup — no more guessing which API keys go where.

## v1.39.0 (Nov 11) — Dashboard & Theme Polish

### Dashboard Filter by Owner (Service Accounts)

The Automations dashboard now has a **filter by owner** with a **Service accounts** option. If you run automations as service accounts (CI, scheduled jobs, bots), you can now isolate their runs from human-triggered ones.

### Chat Timestamp UX

Message hover timestamps now sit **closer to their message** — less eye travel, faster context.

### Stop Hook Feedback Stays Out of Chat

When a `Stop` hook runs (e.g., on `/compact`), its feedback no longer pollutes the chat transcript. Clean separation.

### Paper Theme: Aged Newsprint Look

The **Paper theme** (added in v1.38) now renders with an **aged newsprint aesthetic** — readable warnings, warm tones, easier on the eyes for marathon sessions. It's not just a color swap; it's a considered reading experience.

### Automation Fixes

- **Event Key dropdown** in automations now opens populated by default (no more clicking twice)
- **Backend profile selection** respected — automations don't override your profile choice

### Setup Guide Polish

- Tour starts in an open dialog, ends when that dialog closes
- Unanswered close questions dropped when guide hides — no zombie prompts

## v1.38.0 (Nov 10) — The Features That Change Daily Work

### Conversation Budget Meters (The Killer Feature)

**A visual meter in the chat UI showing token/context usage** — semantic fills (green → yellow → red). You finally see the "fuel gauge" *before* the agent starts hallucinating or truncating.

**Why it matters:** Before, you'd hit a context limit and wonder why the agent forgot the first half of the conversation. Now you see the meter creeping up. You can `/compact` proactively, start a fresh session, or just know "okay, one more big task then I reset."

**For beginners:** It's a fuel gauge. Green = plenty of room. Yellow = think about compacting. Red = the agent is running on fumes.

### Automation-Aware Installs (`mode=automation`)

`mode=automation` + `POST /plugin-spec` lets you install OpenHands configured for automation *without* the full interactive setup. Plugin specs can be pre-configured and deployed programmatically.

**Why it matters:** CI/CD pipelines, fleet deployments, "give every developer the same agent config" — now scriptable. No more "run the wizard on 50 machines."

**For beginners:** If you manage a team, bake your standard agent setup (plugins, models, permissions) into a deployable spec. New hire runs one command → gets your exact setup.

### Agent-Profile-Scoped Automations

Automations (prompt presets, plugin presets) can now run **from a specific agent profile** instead of always using `default`.

**Why it matters:** Have a "code-review" profile with strict permissions and a "feature-dev" profile with broader access. Automations pick the right one. No more permission collisions.

### Docker Workspace Persistence

**Conversation workspaces now live in a persisted volume** — your work survives container restarts. No more "where did my files go?" after `docker restart`.

### Focus-Stealing Fixed

Launch view no longer yanks focus when you navigated away. Type in chat, don't fight the UI.

### Other Notable Fixes (v1.38)

| Fix | Impact |
|-----|--------|
| Composer stop interrupts agent (not pausing Cloud sandbox) | `Stop` means *stop* |
| Fail fast on unwritable Docker bind mounts + documented fix | Clear error instead of mysterious permission denied |
| Reconcile active LLM profile against backend model (race fix) | Model picker stays in sync |
| Diff viewer: release models after editor teardown | Memory doesn't leak when you close diff tabs |
| Hide agent profile switch when self-hosted turns Agent Profiles off | UI respects your config |
