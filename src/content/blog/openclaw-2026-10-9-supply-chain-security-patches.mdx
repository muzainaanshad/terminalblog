## The Supply Chain Security Patches (The Headline)

### 1. fast-URI 4.2.3 — Malformed URI Rejection in MCP Validation

**What it is:** `fast-uri` upgraded to **4.2.3**. It now **rejects malformed URI schemes and hosts** during MCP schema validation.

**Why it matters:** MCP tool calls pass URIs for resources, tools, prompts. A malformed URI (crafted scheme, weird host) could previously slip through validation. Now it's rejected at the schema layer.

```bash
# Before: malformed URI in MCP tool call → might pass validation
# After: fast-uri 4.2.3 → "Invalid URI scheme" / "Invalid host" → rejected
```

**For beginners:** This is supply chain hardening. You didn't write the URI parser. `fast-uri` did. Now it's stricter. Your MCP surface just got smaller.

---

### 2. Zod Oversized Collection Rejection — Early Bailout

**What it is:** **Oversized Zod collections are rejected early** in A2UI and the Discord embedded app SDK.

**Why it matters:** Zod schemas define your data shapes. An attacker sends a 10MB array where you expect 10 items. Old behavior: parse it all, then validate. New behavior: **reject at collection size check, before parsing.**

```typescript
// Your schema
const items = z.array(itemSchema).max(100);

// Attack: 10,000 items
// Before: Zod parses all 10k → then checks .max(100) → OOM risk
// After: Collection size checked FIRST → rejected immediately
```

---

### 3. nodemailer 10.1.4 — IMAP Sender Spoofing Blocked

**What it is:** IMAP sender parsing now uses **nodemailer 10.1.4**. **Spoofed senders cannot pass the sender token gate.**

**Why it matters:** Email-based agents (receiving tasks via IMAP) now validate the *actual* sender cryptographically. `From:` header spoofing? Blocked. The token gate requires valid DKIM/SPF alignment.

---

### 4. MSAL Node 7.1.1 — Microsoft Teams Authentication Hardened

**What it is:** Microsoft Teams integration uses **patched MSAL Node 7.1.1**.

**Why it matters:** Token acquisition flows for Teams are now on a version with known auth bypass fixes. If your agent talks to Teams, this matters.

---

## The Recovery & Reliability Fixes (The "Save Your Ass" Features)

### 5. Safe Failed Update Rollbacks — Git + npm

**What it is:** Two rollback fixes that actually work:

**Git-source rollbacks:** Preserve **operator edits** instead of resetting the checkout. You edited a config during an update? It survives the rollback.

**npm rollbacks:** Retry **transient Windows denials** (file locks, AV interference) and **report the exact move** that restores a bootable install — no more "stranded package root" where you don't know what broke.

```bash
# Before: update fails → rollback → your edits gone / package root stranded
# After: update fails → rollback → your edits preserved / exact restore move logged
```

---

### 6. SQLite Tokenizer Change Recovery — Databases + Indexes Survive

**What it is:** Agent databases and **stale full-text indexes recover after SQLite tokenizer changes**, including **update snapshots**.

**Why it matters:** SQLite tokenizer changes (e.g., upgrading FTS5) used to corrupt full-text search indexes. Now: **auto-recovery on startup**. Your conversation history, memory, skills — all searchable after upgrade.

---

### 7. Full-Disk Survival — Agent Recovers When Space Returns

**What it is:** Agents **recover after a full disk once space becomes available**, **without requiring a restart**.

**Why it matters:** Disk fills up (logs, cache, downloads). Agent pauses. You clear space. **Agent resumes automatically.** No restart. No manual intervention.

---

### 8. Large Transcript Migration — No More Node.js String Limits

**What it is:** **Migrate large transcript archives without exceeding Node.js string limits.**

**Why it matters:** Your 50MB conversation history? The migration script used to hit `RangeError: Invalid string length`. Now: **streaming migration**. No memory spike. No crash.
