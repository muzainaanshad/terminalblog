Google **Agents CLI v1.9.0** dropped **October 6** — and it's the release that makes your agent deployments **auditable, encrypted, and validatable before you commit**.

The headline: **usage telemetry is now on by default** (one log entry per command to your own Google Cloud project — command name, exit code, error class, duration, versions; never arguments or file contents). Opt out with `AGENTS_CLI_TELEMETRY=0` or `DO_NOT_TRACK=1`.

But the real power: **CMEK encryption for Agent Runtime** (`deploy --key`), **dry-run deployment validation** (`deploy --dry-run` checks APIs, IAM, secrets before real deploy), **new ADK project defaults** (enterprise GenAI, Go formatters), and **Terraform log sink fixes** that stop log deletion on re-apply.

If you deploy agents to Google Cloud — this is the update that makes it production-grade.

## 1. Usage Telemetry: Your Analytics, Your Project

**What it does:** Each command writes **one log entry to your own Google Cloud project** with: command name, exit code, error class, duration, CLI/Python/OS versions. **Never arguments or file contents.** Purpose: analytics on your tool use, process efficiency, issue diagnosis.

**Opt out:**
```bash
export AGENTS_CLI_TELEMETRY=0
# or
export DO_NOT_TRACK=1
```

**Check status:**
```bash
agents-cli info
# Shows whether telemetry is on
```

**Why it matters:** You get **observability on your own agent operations** — which commands fail, how long they take, what errors repeat — without sending sensitive data to Google. It's *your* telemetry in *your* project.

---

## 2. CMEK Encryption: Customer-Managed Keys for Agent Runtime

**What it does:** `agents-cli deploy --key <kms-key>` encrypts an **Agent Runtime agent with a customer-managed Cloud KMS key (CMEK)**. Works in projects enforcing `constraints/gcp.restrictNonCmekServices`. Key can only be set at agent creation. `deploy --list` shows it in a new **Encryption column** (#83).

**Why it matters:** **Compliance-ready deployments.** Regulated industries (finance, healthcare, gov) often require CMEK. Now Agent Runtime supports it natively — no workarounds, no "encrypt at rest later."

---

## 3. Dry-Run Deploy: Validate Before You Commit

**What it does:** `agents-cli deploy --dry-run` checks an Agent Runtime deployment against Google Cloud:
- Enabled APIs
- Target engine
- IAM permissions
- `actAs` on service account
- Secrets

**Behavior:** Definite problem → exits code 1. Check that cannot run → warns only. **Read-only network calls** — no actual deployment.

**Why it matters:** **Catch config errors before they hit production.** CI pipelines can run `--dry-run` as a gate. No more "deploy failed after 5 minutes because IAM was missing."

---

## 4. New ADK Project Defaults: Enterprise-Ready From `init`

**What changed:**
- **Python projects:** `GOOGLE_GENAI_USE_ENTERPRISE=true` (replaces deprecated `GOOGLE_GENAI_USE_VERTEXAI`). Existing projects keep working — `deploy` respects whichever your `.env` sets.
- **Go projects:** `gofmt` and `goimports` formatters enabled → `agents-cli lint` reports formatting issues, `lint --fix` fixes them.
- **Agent card:** No longer appends duplicate `JSONRPC 0.3` interface on every request to `.well-known/agent-card.json` (#84).

**Why it matters:** **New projects start with enterprise defaults.** No "forgot to set env var" surprises. Go projects get formatting hygiene from day one.

---

## 5. Terraform Log Sink Fix: Stop Deleting Your Logs

**What it does:** Re-applying Terraform generated by this release (e.g., `agents-cli infra single-project` or `infra cicd`) **no longer replaces BigQuery log sink tables once logs have arrived.**

**Before:** Re-apply → log sink table replaced → **all exported logs deleted.**

**Now:** Logs stay. `completions_view` also gains a `service_version` column with deployment revision. Run `agents-cli scaffold upgrade` to get this in existing projects.

**Why it matters:** **Log retention is non-negotiable for production.** This fix makes Terraform re-apply safe for audited environments.

---

## 6. Windows Tool Errors That Make Sense

**What it does:** A tool that exists but cannot run (e.g., `uv.exe` blocked by AppLocker) now **fails with a clear error naming the tool and the OS reason** instead of a `PermissionError` traceback (#61).

**Before:** `PermissionError: [WinError 5] Access is denied` — "which tool? why?"

**Now:** "`uv.exe` blocked by AppLocker on Windows" — **immediately actionable.**

**Also:** Installed extensions no longer print a warning on every command. Notice appears **only when a command overridden by an extension runs** (#91).
