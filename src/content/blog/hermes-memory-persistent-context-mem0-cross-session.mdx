One of the most frustrating things about coding assistants is starting from scratch every session. "I just told you my preferred test framework yesterday. Why are you asking again?"

Hermes Agent solves this with **mem0** — a persistent memory layer that spans every session, every conversation, every context. This isn't a simple key-value store; it's a semantic memory system that understands what matters for your current work.

## What mem0 Actually Stores

mem0 captures five categories of memory that compound over time:

- **User preferences** — "User prefers pytest with xdist for parallel testing"
- **Project conventions** — "This project uses named exports not default exports"
- **Past decisions** — "We chose PostgreSQL over MongoDB for this schema"
- **Environment details** — "The CI pipeline uses Node 22 and pnpm"
- **Workflow patterns** — "Always run lint before commit in this repo"

When you start a new session, mem0 surfaces the most relevant memories automatically — not everything, just what matters for the current context.

## Memory Types and Prioritization

Not all memories are equal. mem0 uses a tiered system with explicit priority:

1. **User profile** — Who the user is, their role, their preferences (highest priority)
2. **Project context** — Conventions, architecture decisions, tech stack
3. **Session notes** — Decisions made in this session
4. **Procedural knowledge** — How to do things (lower priority, replaced by skills)

The system has a **character budget** — only the most relevant memories fit in context. When the budget is full, mem0 evicts the least useful entries, not the oldest ones. This is critical: a memory about "last week's refactor" naturally deprioritizes, but your preference for named exports stays.

## Memory Maintenance: Replace, Remove, Decay

Over time, memories can become stale. mem0 handles this with three mechanisms:

- **Replace** — Update in place when preferences change ("Actually, we switched to vitest")
- **Remove** — Delete obsolete entries entirely
- **Temporal decay** — Memories about recent work naturally deprioritize as they age

The agent can also ask "should I remember this?" before saving, giving you control over what gets stored. This prevents polluting the memory with one-off requests or experimental approaches.

## Setting Up mem0 in Hermes

mem0 is enabled by default in Hermes Agent. No additional configuration needed — it starts learning from your first session. The memory is stored locally in `~/.hermes/memory/` and is never sent to external servers.

### Viewing Your Memories

```bash
# List all stored memories
hermes memory list

# Search for specific memories
hermes memory search "test framework"

# View memory for current project
hermes memory project
```

### Managing Memories

```bash
# Remove a specific memory
hermes memory remove "memory-id"

# Clear all memories for a project
hermes memory clear --project

# Export memories for backup
hermes memory export > memory-backup.json
```

## Why Memory Matters for Autonomous Agents

Without memory, every session is a fresh start. You repeat your conventions, re-explain your preferences, re-establish context. With memory, the agent **builds a relationship** with your codebase over time.

**Session one:** "Format with Prettier, not dprint."
**Session ten:** The agent just does it. No reminder needed.

This compounds. By session fifty, the agent knows your architectural patterns, your team's conventions, your debugging workflows. It stops being a tool you prompt and starts being a collaborator that anticipates.

This is what makes an autonomous life assistant feel like it actually knows you — not a chatbot that forgets everything the moment you close the window.

## Memory vs. Skills: The Distinction

A common question: "Isn't this what skills are for?"

**Skills** = reusable, shareable capabilities (how to do things)
**Memory** = personal, contextual knowledge (what matters for *your* work)

Skills are portable across users and projects. Memory is personal and project-specific. They complement each other: a skill teaches the agent *how* to run tests; memory teaches it *which* test command your project uses.

## FAQ

**Q: Is my memory data private?**
Yes. mem0 stores everything locally in `~/.hermes/memory/`. Nothing leaves your machine unless you explicitly export and share it.

**Q: Can I disable memory?**
Yes. Set `memory.enabled: false` in your Hermes config. But you'll lose the compounding benefits.

**Q: How much memory can it store?**
Practically unlimited locally. The character budget only limits what's injected into context per session — typically 2-4KB of the most relevant memories.

**Q: Does it work across different projects?**
Yes. Memory is scoped by project path. Switching projects automatically loads the right context.

**Q: Can I share memories with my team?**
Export/import works: `hermes memory export` and `hermes memory import`. Team-shared memory files are on the roadmap.
