## The Feature: Puck MCP — Your Meta-Agent Goes Where You Go

AmpCode's Puck has always been the meta-agent — the thing that manages your agents. Finds previous work. Delegates coding. Inspects repositories. Tracks development. Coordinates agents. Automates workflows. Manages Amp. Communicates through connected services.

Now Puck speaks **MCP**.

That means you can talk to Puck from:
- **ChatGPT** (paste the MCP URL, sign in)
- **Claude** (click "Add to Claude" in settings)
- **Any MCP client** — Cursor, Windsurf, custom tools, whatever comes next

Two tools exposed:
- `puck` — interact with your Puck in Amp (delegate, query, coordinate)
- `orbs` — see an interactive view of your running orbs with portal links

**Same Puck. Same context. Different front door.**

## What's Still Missing (Honest Take)

- **Write access from external agents**: Currently read-heavy. Puck can *receive* tasks via MCP but the orchestration depth is asymmetric.
- **Multi-workspace routing**: If you have personal + work Amp workspaces, MCP doesn't yet let you specify which Puck gets the message.
- **Voice → Puck → Orb → Voice**: The loop closes but latency varies. Not yet real-time conversational.

## FAQ

**What exactly is Puck?**
Puck is AmpCode's meta-agent — your helper that manages agents, summarizes threads, coordinates work, finds previous work, and automates workflows. Think of it as your engineering manager that lives in the terminal.

**Do I need an AmpCode subscription?**
Yes — you need an Amp account with orbs/runners set up. The MCP connection authenticates to your Amp workspace.

**Can I use this with the free tier?**
Yes. If you're on Amp's free tier (bring your own compute + model keys), Puck MCP works the same way.

**Does this work with Cursor's agent / GitHub Copilot / Zed?**
Any MCP client can connect. Cursor, Copilot (via MCP), Zed (via MCP), custom scripts — if it speaks MCP, it can talk to Puck.

**Is my data leaving Amp?**
MCP calls go to `https://ampcode.com/mcp` — your Amp backend. The external agent (ChatGPT, Claude) sends the request, Amp processes it, returns the response. Your code stays in your Amp infrastructure.
