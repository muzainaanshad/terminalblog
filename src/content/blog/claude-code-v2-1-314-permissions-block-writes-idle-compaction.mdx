## The Headline: `permissions.blockWritesOutsideWorkingDirectories` — The Boundary You've Been Waiting For

### What It Does

Add this to your settings:

```json
{
  "permissions": {
    "blockWritesOutsideWorkingDirectories": true
  }
}
```

**Result:** Write, Edit, and NotebookEdit tools **refuse any path outside your working directories** — in *every* permission mode. Even `auto` mode. Even if you explicitly allow it.

### Why This Matters

Before v2.1.314, the permission system had a gap:

| Scenario | Old Behavior | New Behavior |
|----------|--------------|--------------|
| `auto` mode + `Write(/etc/passwd)` | ❌ Allowed (you said auto) | ✅ **Blocked** |
| Malicious prompt injection writes to `~/.ssh/id_rsa` | ❌ Possible | ✅ **Blocked** |
| Accidental `Edit(../../../package.json)` | ❌ Allowed | ✅ **Blocked** |
| Subagent tries to escape project root | ❌ Possible | ✅ **Blocked** |

This is a **hard security boundary**, not a permission prompt. The tool call fails before it reaches the filesystem.

### Who Should Enable This

- **Everyone running in `auto` mode** — this is the missing safety net
- **Teams with shared Claude Code configs** — prevents one project's agent from touching another
- **CI/CD pipelines** — hard guarantee the agent can't escape the workspace
- **Anyone using MCP servers** — supply chain attacks often try filesystem escape

### The Catch

Legitimate cross-project workflows (monorepos, shared configs) need explicit working directory setup:

```bash
# Add multiple working directories
claude config add workingDirectories '["/home/user/project-a", "/home/user/project-b"]'

# Or per-session
claude -p --working-directory /home/user/project-a --working-directory /home/user/shared-config
```

## Idle Compaction Finally Works in VS Code & Claude Desktop

### The Problem Before

Conversations over 200K tokens would:
- Slow down responses
- Burn through context windows
- Require manual `/compact` (which you'd forget)

### What v2.1.314 Ships

**Automatic idle compaction** in VS Code extension and Claude Desktop's Code tab:

1. Conversation hits **200K+ tokens**
2. You leave it **idle** (no messages for a while)
3. Claude Code **summarizes it in the background**
4. Next message uses the **summary** — if prompt cache expired

No manual trigger. No UI interruption. It just works.

### The Fine Print

- Only in VS Code extension + Claude Desktop Code tab (not terminal CLI yet)
- Requires prompt cache expiry to kick in (otherwise cached context is used)
- Summary preserves: key decisions, file changes, task context
- Subagents get their own compaction windows (configurable via `autoCompactWindow`)

## Effort Cap Handling — No More "Invalid Effort Level" Loops

### The Bug

Organizations using admin policies to cap model effort (e.g., "max Haiku effort") would hit:

```
Invalid effort level
```

...turn after turn. The agent couldn't proceed, couldn't explain, just failed.

### The Fix

Claude Code now:
1. **Detects** the org's effort cap
2. **Lowers** effort automatically (Opus → Sonnet → Haiku)
3. **Retries** the request
4. **Tells you** which level it's using

Transparent fallback. Zero session breaks.

## MCP Authentication Fixes — The Silent Session Killers

### Fixed: "Needs Authentication" Ghost State

MCP servers that **work without sign-in** (public servers, local tools) would show "needs authentication" after their stored sign-in expired or broke.

**Now:** They work signed out. No phantom auth prompts.

### Fixed: `claude mcp logout` Lying to You

Over SSH with locked macOS keychain, `claude mcp logout` reported success but **didn't actually remove the sign-in**.

**Now:** It reports the real status. If keychain is locked, it says so.

### Fixed: Extra Sign-in Renewals

Multiple sessions sharing an Anthropic profile login would hammer the credentials lock with redundant renewals.

**Now:** Coordinated renewal — one session refreshes, others wait.

## v2.1.316 (Oct 31) — Pooled Budgets, Subagent Effort, UltraThink Kill Switch

### 1. Pooled Group Budgets for Claude Apps Gateway

**New:** `pooled_budget` on the spend limits admin API — one monthly budget shared across a group's members, on top of each member's own limit.

```json
// Admin API
{
  "pooled_budget": 50000  // $500 shared monthly budget for the group
}
```

**Why it matters:** Teams no longer need to micromanage individual budgets. Set a group ceiling; members draw from their personal limit first, then the pool.

---

### 2. Independent Subagent Effort Control

**New:** `CLAUDE_CODE_SUBAGENT_EFFORT` environment variable — set the effort level subagents run at when nothing else names one, instead of inheriting the session's effort.

```bash
export CLAUDE_CODE_SUBAGENT_EFFORT=high
# or low, medium, xhigh
```

**Why it matters:** Main agent runs at `xhigh` for planning; subagents run at `medium` for execution. No more subagents burning `xhigh` budget on simple file edits.

---

### 3. UltraThink Kill Switch

**New:** `CLAUDE_CODE_DISABLE_ULTRATHINK` — completely disables the `ultrathink` keyword.

```bash
export CLAUDE_CODE_DISABLE_ULTRATHINK=1
```

**Why it matters:** Some orgs want deterministic effort levels. `ultrathink` forces `xhigh` — this turns it off entirely.

---

### 4. Layered Policy Mode (Claude Apps Gateway)

**New:** `managed.policy_mode: layered` — every policy that matches a developer applies, each merged over the ones below it, not just the first match.

```json
{
  "managed": {
    "policy_mode": "layered"
  }
}
```

**Why it matters:** Stack org-wide base policy + team overrides + user exceptions. Cleaner than priority-based single-match.

---

### 5. Bedrock Guardrail Input Tagging

**New:** `guardrail.input_tagging` on Bedrock upstreams — wraps prompts in input tags that Bedrock guardrail's prompt attack filter needs. `all_messages_and_system` also tags the system prompt.

```json
{
  "guardrail": {
    "input_tagging": "all_messages_and_system"
  }
}
```

**Why it matters:** Bedrock guardrails can now actually inspect the full conversation for prompt injection — including system prompts.

---

### 6. Opus 4.8 Fast Mode Deprecation

**Notice:** Fast mode for Opus 4.8 deprecated as of **October 30, 2026**; removed **November 30, 2026**. After removal, fast mode requests on Opus 4.8 return an error (no fallback to standard Opus 4.8). Migrate to **Opus 5.5** to keep the speedup.
