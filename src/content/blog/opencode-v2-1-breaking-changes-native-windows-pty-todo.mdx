OpenCode v2.1 dropped **October 20, 2026**. It's not a patch. It's a **deliberate breaking release** that rewrites the SDK, HTTP message/event contracts, and plugin APIs so provider replay data and compaction use consistent names and shapes.

The team calls it "the cost of admission for a stable platform." Here's what actually changed and why it matters for your daily workflow.

---

## The Headlines (What You'll Actually Feel)

| Feature | Why It Matters |
|---------|----------------|
| **Persistent Windows PTYs** | Windows x64 + ARM64 now get the same terminal workflow as macOS/Linux — no more session death on disconnect |
| **Todo Lists in TUI** | Enable `{ "experimental": { "todo": true } }` and models get `todowrite` tool — task lists render in session + sidebar |
| **Reliable Long-Running Commands** | Plugin commands, shell calls, and TUI requests survive beyond Bun's 5-minute fetch deadline |
| **Unified `native` replay field** | One field replaces `providerState`, `providerResultState`, `state` across all surfaces — cleaner replay, easier debugging |
| **Credential setup moves to `metadata`** | `configuration` removed from keys; setup answers go in `metadata` — consistent with rest of platform |
| **Summary compactions reference kept messages** | No more duplicated `recent` text — compactions store `metadata.keepID` pointing to first retained message |
| **Breaking: SDK/HTTP/plugin contracts** | Integrations **must** adopt new fields. Stored sessions/credentials import fine via compatibility decoders |

## 1. Persistent Windows PTYs: Windows Finally Catches Up

**The problem:** Windows terminals died on disconnect. Background the agent, lose the session. macOS/Linux had persistent PTYs for ages.

**The fix:** v2.1 brings **persistent PTY support for Windows x64 and ARM64** ([#56245](https://github.com/anomalyco/opencode/pull/56245)). Same workflow as Unix: detach, reattach, session survives.

**Why beginners care:** You're on a Surface Pro or Snapdragon laptop. You close the lid. You open it tomorrow. Your agent session is *still there*. No "where was I?" reconstruction.

---

## 2. Todo Lists in the TUI: Models That Track Their Own Work

**The problem:** Models forget what they're doing mid-session. No visible task list. You babysit.

**The fix:** Enable experimental todo support:

```json
// settings.json
{
  "experimental": {
    "todo": true
  }
}
```

Models get `todowrite` tool accepting `{ todos: [{ content, status }] }`. The TUI renders the list in-session and in the sidebar. Models *track their own work*.

**Why it matters:** You give a complex task. The agent breaks it down, updates the list as it goes. You see progress at a glance. No more "what is it doing now?"

---

## 3. Long-Running Commands That Don't Die at 5 Minutes

**The problem:** Bun's default fetch deadline kills plugin commands, shell calls, and TUI requests at 5 minutes. Long builds, test suites, migrations — all silently fail.

**The fix:** v2.1 **disables Bun's fetch idle timeout for provider requests** and keeps long-running TUI/`run`/`mini` requests connected ([#55149](https://github.com/anomalyco/opencode/pull/55149)). Commands run to completion.

**Why it matters:** You run `cargo test` or a 20-minute integration suite. It finishes. You get results. Not a timeout error.

## 4. The Breaking Changes: One `native` Field to Rule Them All

This is the big one. **v2.1 intentionally breaks public contracts** so replay data is consistent everywhere.

### What Changed

| Surface | Before | After |
|---------|--------|-------|
| Text/reasoning parts | `state` | `native` |
| Assistant/compaction messages | `providerState` | `native` |
| Tool lifecycle events | `state` | `native` |
| Step ended/failed, compaction ended | `providerState` | `native` |
| Tool success/failed | `resultState` | `native` |
| Exported replay schema | `SessionMessage.ProviderState` | `SessionMessage.Native` |
| Plugin compaction hook result | `SessionCompactionResult.providerState` | `SessionCompactionResult.native` |

### Tool Calls: One `native` Instead of Two Fields

```diff
 tool
-  providerState?
-  providerResultState?
+  native?
   state
```

Success/failure events shallow-merge their `native` into the call's existing `native`. Missing result data preserves call data; result values win on duplicate keys.

**Why this matters:** You debug a session replay. One field. Consistent keys. No more "which providerState is this?" guesswork.

### Credentials: `configuration` → `metadata`

```diff
 { type: "key", key: "...",
-  configuration: { account: "example" }
+  metadata: { account: "example" }
 }
```

Old stored credentials and `opencode auth import` still work — legacy `configuration` merges into `metadata`. But public writes **must** use `metadata` going forward.

### Compaction: References, Not Duplicates

**Old:** Compaction stored full `recent` text duplicate.

**New:** Compaction stores `metadata.keepID` pointing to first message retained verbatim. History reconstructs from there. Forks remap the reference. Pre-2.1 compactions keep `metadata.recent` for compatibility.

**Why it matters:** Smaller storage. Cleaner forks. No drift between "what happened" and "what compaction saved."

## 5. Windows ARM64: Native Binaries, Not Emulation

v2.1 bundles **native ARM64 terminal and CLI binaries** in Windows ARM64 desktop builds. Emulated x64 installations migrate to native ARM64 updates automatically ([#54689](https://github.com/anomalyco/opencode/pull/54689), [#54983](https://github.com/anomalyco/opencode/pull/54983)).

If you're on Snapdragon X Elite/Plus — this is the release where Windows becomes a first-class citizen, not an emulation afterthought.

## 6. Official WinGet Packages

```powershell
winget install --id Anomaly.OpenCode -e
# or desktop app
winget install --id Anomaly.OpenCode.Desktop -e
```

WinGet handles upgrades. No more manual `.msi` downloads. Windows package management finally works for OpenCode.

---

## 7. Gemini + Vertex: Automatic Response Continuation

Long Gemini/Vertex Gemini responses split by the provider now **continue automatically as one response**, including recovery from dropped streams after continuation checkpoints ([#55056](https://github.com/anomalyco/opencode/pull/55056)).

No more "response truncated" — the agent stitches it back together.

---

## 8. Remote Pairing: Safer by Default

First `opencode pair --remote` now **warns it will expose your server** and asks for confirmation. Non-interactive? Pass `--yes`/`-y` ([#54561](https://github.com/anomalyco/opencode/pull/54561)).

Security hygiene baked in.

---

## 9. Web App Installable

Chrome/Edge **Install** button works for OpenCode web app — including behind authenticating proxies ([#53905](https://github.com/anomalyco/opencode/pull/53905)). PWA-style install without the PWA hassle.

---

## 10. Clear Session Failures

Desktop and TUI timelines now show **execution errors that happen before or between model steps** instead of ending without explanation ([#53826](https://github.com/anomalyco/opencode/pull/53826)). You see *why* it stopped.

## v2.1.2 (October 21): Free-Limit Recovery, Hide Free Models, Fresh Install Fixes

**v2.1.2 dropped October 21** — a focused patch that polishes the v2.1 breaking release with quality-of-life fixes you'll actually notice.

### Clear Free-Limit Recovery (Desktop + TUI)

**The problem:** You hit your free message limit. The agent just errors out. You lose your prompt. You don't know when it resets.

**The fix:** Desktop and TUI now show the **reset time inline**, **restore your submitted prompt**, and offer direct **Upgrade** or **Switch Model** actions instead of a generic error ([#57466](https://github.com/anomalyco/opencode/pull/57466), [#57467](https://github.com/anomalyco/opencode/pull/57467), [#57471](https://github.com/anomalyco/opencode/pull/57471)).

The TUI shows an animated "Free limit reached" dialog with **Subscribe**, **Dismiss**, and **Don't show again** buttons. Subscribing to OpenCode Go now updates the current session's model instead of opening another draft.

### Hide Free Models: `OPENCODE_DISABLE_FREE_MODELS=1`

**The problem:** Free models clutter the catalog. You want only paid/pro models visible.

**The fix:** Set `OPENCODE_DISABLE_FREE_MODELS=1` or `true` to remove zero-cost models from OpenCode and OpenCode Go catalogs, defaults, and fallbacks ([#57478](https://github.com/anomalyco/opencode/pull/57478)).

```bash
# In your shell config or before launch
export OPENCODE_DISABLE_FREE_MODELS=1
```

### Configurable Location Unloading

**The problem:** Inactive location services (language servers, MCP connections) stay loaded forever, consuming memory.

**The fix:** Set `experimental.location_idle_timeout` to a duration like `"4 hours"` or `false` to disable unloading entirely ([#57476](https://github.com/anomalyco/opencode/pull/57476)).

```json
// settings.json
{
  "experimental": {
    "location_idle_timeout": "4 hours"
  }
}
```

Locations now stay loaded while sessions wait for input, run long tools, or own background jobs ([#57416](https://github.com/anomalyco/opencode/pull/57416)).

### Reliable Fresh Installs (zsh + Fish)

**The problem:** Fresh installs on machines without `~/.zshrc` or `config.fish` failed to add OpenCode to `PATH`. You got "command not found."

**The fix:** The installer now creates the shell config file when missing, adds OpenCode to `PATH`, and tells you to run `exec $SHELL` ([#57348](https://github.com/anomalyco/opencode/pull/57348)).

### Other v2.1.2 Fixes

- **Legacy console credentials forwarded** — Old `console.opencode.ai` credentials now forward to `opencode.ai/console` ([#57588](https://github.com/anomalyco/opencode/pull/57588))
- **SDK: `retryAfterMs` on session errors** — Clients can display provider-supplied retry timing ([#57146](https://github.com/anomalyco/opencode/pull/57146))
- **Code Mode async jobs fixed** — No more interleaving writes mid-statement while preserving concurrent tool calls ([#54276](https://github.com/anomalyco/opencode/pull/54276))
- **TUI: Only shows "location unavailable" when server explicitly reports it** ([#57594](https://github.com/anomalyco/opencode/pull/57594))

## Should You Update?

| If You... | Verdict |
|-----------|---------|
| Build integrations/plugins/SDK consumers | **Must update** — breaking contract changes |
| Run OpenCode on Windows (x64 or ARM64) | **Yes** — persistent PTYs = game changer |
| Want models to track their own tasks | **Yes** — enable experimental todo |
| Run long commands (>5 min) | **Yes** — fetch deadline fixed |
| Use Gemini/Vertex heavily | **Yes** — auto-continuation |
| Are on v2.0.x and happy | **Yes** — but test integrations first |
| Have custom plugins not yet ported | **Test first** — plugin API changed |

**Migration:** Stored sessions, credentials, and V1 imports remain readable via compatibility decoders. No database migration required. But **public SDK/HTTP/plugin writes must adopt new fields**.

## How to Update

```bash
# Fresh install (macOS / Linux)
curl -fsSL https://opencode.ai/v2/install | bash

# Fresh install (Windows - native ARM64 or x64)
irm https://opencode.ai/v2/install.ps1 | iex

# Windows via WinGet (recommended)
winget install --id Anomaly.OpenCode -e

# Upgrade from v2.0.x
opencode upgrade
# or in TUI: /update

# Upgrade from v1.x
opencode upgrade --major
```

**Verify:**
```bash
opencode --version
# Should show 2.1.0+
```

## The Bottom Line

OpenCode v2.0 made the agent *yours* (per-project control, explicit updates, native platforms).

**OpenCode v2.1 makes the platform *stable*.** The breaking changes aren't arbitrary — they unify replay data, credential handling, and compaction into consistent shapes so the foundation doesn't crack under scale.

Persistent Windows PTYs. Todo lists models actually use. Commands that run past 5 minutes. Native ARM64. WinGet. A single `native` field replacing three inconsistent ones.

This is what "open source agent infrastructure" looks like when it grows up.
