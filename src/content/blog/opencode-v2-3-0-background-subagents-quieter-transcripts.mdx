**OpenCode v2.3 dropped today (Nov 13)** — and the headline change is simple but profound: **subagents now run in the background by default.** You fire one off, it returns immediately with a session ID, and reports back when it's done. You keep coding. It keeps grinding.

---

## The Big Shift: Background Subagents by Default

### What Changed

Before v2.3: You spawn a subagent → you wait → it finishes → you get the result.

After v2.3: You spawn a subagent → **you get the session ID instantly** → you keep working in the parent session → subagent reports back when idle.

```bash
# In OpenCode TUI
/subagent "refactor the auth module"
# Returns immediately: "Subagent started: session_abc123"
# You continue editing. Subagent works in background.
# When done: notification appears with summary
```

### Why This Matters for Beginners

**Parallelism without the mental overhead.** You don't need to think "should I use a subagent here?" — the answer is increasingly "yes" because it doesn't block you. Spawn three subagents for three different files. Keep writing tests in the main session. Come back to summaries.

This is **multi-agent orchestration without YAML, without config, without framework ceremony**. Just `/subagent` and go.

---

## Quieter Transcripts by Default

### The Problem

OpenCode's transcript used to show every tool call, every thought, every intermediate step. For a 20-turn session, that's a wall of noise.

### The Fix

v2.3 defaults to **`verbosity: low`** — each run of tools + thoughts collapses into **one collapsible activity row**.

```
┌─ Activity: edited auth.ts, updated tests ────────────┐
│  ▸ read_file auth.ts                                 │
│  ▸ edit auth.ts (3 changes)                          │
│  ▸ write test/auth.test.ts                           │
│  ▸ bash "npm test"                                   │
└──────────────────────────────────────────────────────┘
```

Click to expand. Or set `session.verbosity: "medium"` / `"high"` in your TUI config if you want the old firehose. Your existing setting is preserved.

## Jump to Message — Finally, Session Search That Works

**Desktop app only (for now):** `Cmd+Alt+G` (Mac) / `Ctrl+Alt+G` (Windows/Linux) opens **Jump to message** — searches *all prompts* across the current session, including ones not yet loaded in the timeline.

No more scrolling up for five minutes to find that prompt from three hours ago. Type a keyword, jump instantly.

- Plugin replacement stopping on cleanup failure — fixed

- GitHub Copilot wrong endpoint before models load — fixed

- Exhausted rate limits treated as terminal — fixed
- Retryable provider streams losing work on interrupt — fixed

## What This Means for You

**If you're new to OpenCode:** v2.3 is the version where the agent feels *concurrent*. You're not waiting on subagents. You're not drowning in transcript noise. You can actually run multiple things at once.

**If you're coming from Claude Code:** OpenCode's background subagents are the closest thing to "fire and forget" in the terminal agent space right now. No permission prompts per subagent. No blocking.

**If you run a team:** The Recent sessions sidebar (experimental) + background subagents + quieter transcripts = less context-switching tax. Developers stay in flow longer.

---

## The Bigger Picture

OpenCode has been iterating fast — v2.2.7 was Nov 10, v2.3 is Nov 13. The velocity is real. But v2.3 isn't just "more features." It's a **UX philosophy shift**:

- **Concurrency by default** (background subagents)
- **Signal over noise** (quiet transcripts)
- **Discoverability** (jump to message)

These compound. A beginner who tries OpenCode today gets an agent that respects their attention. That's rare.
