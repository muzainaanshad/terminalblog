Qwen Code **v0.24.7** dropped September 29, just three days after the massive v0.24.6 managed runtime release. This isn't a feature drop — it's **the stabilization patch that makes the managed runtime work in the real world**.

The headline fix: **daemon extension settings were leaking across processes**, corrupting shared state. If you ran multiple Qwen sessions or had the daemon running alongside CLI invocations, settings from one bled into another. v0.24.7 isolates those loads.

Plus: Enter key no longer gets swallowed while completions load, cross-directory tool approvals are finally honored, and Code Mode text aligns with lazy tool discovery. The "it works on my machine" managed runtime just became "it works on your machine too."

---

## 1. Daemon Settings Isolation — The Bug That Made Config Unreliable

**PR [#13022](https://github.com/QwenLM/qwen-code/pull/13022)** fixes the root cause of "why does my config work sometimes but not others?"

**The problem:** The daemon loads extension settings into shared process state. When multiple CLI instances or the daemon itself accessed settings concurrently, they stomped on each other. Your `qwen-code` in terminal A would mysteriously inherit settings from terminal B's session.

**The fix:** Daemon extension settings loads are now isolated from shared process state. Each invocation gets its own clean settings snapshot.

**Why this matters for you:** If you run Qwen Code in multiple terminals, in CI, or have the daemon running for managed runtime — **your config is finally deterministic**. No more "it worked yesterday" debugging sessions.

---

## 2. Enter Key No Longer Swallowed During Completions

**PR [#13015/#13021](https://github.com/QwenLM/qwen-code/pull/13015)** fixes one of the most frustrating UX papercuts: **typing Enter while completion suggestions are loading would silently drop the keystroke.**

You'd type a command, hit Enter to execute, and... nothing. The completion loader was eating the key event. Now Enter is properly handled regardless of completion state.

**For beginners:** This was the "is it lag or is it broken?" moment that made the CLI feel unpolished. Fixed.

---

## 3. Cross-Directory Permission Approvals Finally Work

**PR [#12987](https://github.com/QwenLM/qwen-code/pull/12987)** honors approved cross-directory tool calls.

Previously, if you approved a tool call that accessed files outside the current working directory, the approval wasn't persisted correctly. Next time, you'd get prompted again. Now the approval sticks — the permission model respects your "yes, I meant that" across directory boundaries.

---

## 4. Code Mode Text Aligns With Lazy Tool Discovery

**PR [#12990](https://github.com/QwenLM/qwen-code/pull/12990)** aligns the Code Mode display text with the new lazy tool discovery system.

**What this means:** The UI now accurately reflects which tools are *actually* available vs. which are *discoverable*. No more seeing a tool listed that isn't loaded yet, or missing one that is. The mental model matches reality.
