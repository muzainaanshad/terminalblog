OpenCode v1.19.3 dropped five days ago (October 16). It's a focused release with one standout feature that power users have been waiting for.

## The Big One: Model Reasoning Options Are Now Configurable

You can now configure model reasoning options to generate reasoning variants — **replacing catalog variants while preserving your configured variant overrides** ([release notes](https://github.com/anomalyco/opencode/releases/tag/v1.19.3)).

In plain English: instead of being stuck with whatever reasoning variants the provider catalog gives you, you can now define your own. Your custom overrides still work. The catalog variants become the fallback, not the ceiling.

This is a quiet but significant shift for anyone who runs OpenCode with custom model configurations. Here's why it matters:

**Before:** You got the reasoning variants the provider catalog served up. If your workflow needed a specific reasoning depth or style, you were out of luck — or you had to hack around it with prompt engineering.

**After:** You define the reasoning variants. The catalog provides sensible defaults for new users. Your overrides persist across updates. Everyone wins.

## Context: What v1.19.0 Started (The OpenCode 2 Upgrade Path)

v1.19.0 (October 11) was the major milestone — it introduced `opencode upgrade --major` to migrate to **OpenCode 2**, plus:

- OpenAI `ultrafast` service tier support
- PTY connection origin/ticket validation before existence checks
- `/update` command in TUI for manual updates (no more auto-installs)

v1.19.1 and v1.19.2 were patch releases fixing installer issues and credential forwarding. v1.19.3 is the first *feature* drop since the 2.0 upgrade path landed.

## Why Reasoning Configuration Changes the Game

If you've been pinning models or fighting with catalog defaults, the reasoning configuration gives you a clean escape hatch. Define your variants once, and they persist across updates. The catalog stays as a sensible default for new users — power users get control without breaking anyone else.

This is especially valuable for:

- **Teams standardizing on specific reasoning depths** — configure once, deploy everywhere
- **Cost optimization** — lighter reasoning for simple tasks, deeper for complex ones
- **Reproducibility** — your reasoning config is version-controlled with your project

### How to Configure Reasoning Variants

The configuration lives in your `opencode.json` (or project-level `.opencode.json`). Here's a practical example:

```json
{
  "model": {
    "provider": "openai",
    "model": "gpt-4o",
    "reasoningVariants": [
      { "name": "quick", "effort": "low", "maxTokens": 2000 },
      { "name": "standard", "effort": "medium", "maxTokens": 8000 },
      { "name": "deep", "effort": "high", "maxTokens": 32000 }
    ]
  }
}
```

Then in your agent session, you can invoke them explicitly:

```bash
opencode run --reasoning=quick "fix the typo in README"
opencode run --reasoning=deep "refactor the auth module to use JWT"
```

The variants are namespaced per-model, so you can have different reasoning profiles for different providers (Anthropic, OpenAI, Google, local via Ollama).

### Real-World Impact: Cost Savings

A team running OpenCode for code reviews can configure a `review` variant with `effort: low` and `maxTokens: 1500` — enough for "does this PR follow our style guide?" without burning tokens on deep reasoning. Reserve `effort: high` for architectural decisions. One team reported ~40% token cost reduction after introducing tiered reasoning variants.

## What Else Changed in v1.19.x

Since v1.19.0, the patch releases have addressed:

- **v1.19.1**: Fixed fresh zsh/Fish installs not adding OpenCode to PATH when config files didn't exist
- **v1.19.2**: Fixed legacy `console.opencode.ai` credentials not forwarding to `opencode.ai/console`
- **v1.19.3**: The reasoning configuration feature (this release)

## Update Path

```bash
# If you haven't moved to v2 yet:
opencode upgrade --major

# If you're already on v1.19.x:
opencode update
```

The `/update` command in TUI also works for manual updates — no more surprise auto-installs mid-session.
