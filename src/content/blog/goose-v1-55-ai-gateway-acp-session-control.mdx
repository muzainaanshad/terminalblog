Goose v1.55.0 dropped **October 16, 2026** — and it's the kind of release that matters more for *what you're building on top of it* than what you see in the chat window. The headline: **AIgateway declarative provider config**, **W3C trace context across ACP calls**, **adaptive thinking fixes for Claude 5.5**, and a **Stop button that actually saves your work**.

If you're using Goose as your daily driver, you'll feel the session control improvements. If you're embedding Goose in an IDE plugin, CI bot, or custom frontend — this is the release that makes that architecture cleaner.

---

## The Headline Features (Ranked by Impact on Your Workflow)

### 1. AIgateway Declarative Provider Config — Define Providers in Code, Not YAML

**What it is:** A new `AIgateway` provider type (#12528) that lets you declare model providers programmatically instead of wrestling with config files.

**Why it matters:** Before this, adding a custom provider meant editing YAML, restarting, debugging typos, repeat. Now you define providers in code — type-safe, version-controlled, testable. This is huge for teams standardizing model access across projects.

```goose
# Conceptual — you define providers in your project config
providers:
  - name: "my-claude"
    type: "anthropic"
    models: ["claude-sonnet-5.5", "claude-haiku-5.5"]
    env: ANTHROPIC_API_KEY
  - name: "my-gpt"
    type: "openai"
    models: ["gpt-6-sol", "gpt-6-luna"]
    env: OPENAI_API_KEY
```

**For beginners:** You don't need this *yet*. But when you hit "I wish I could share my model setup with the team," this is the answer.

---

### 2. W3C Trace Context Propagation — Your Observability Finally Works Across Agents

**What it is:** Goose now propagates `traceparent` and `tracestate` headers from ACP prompts through to MCP tool calls (#12697).

**Why it matters:** If you're running Goose in production (CI bots, automated reviews, scheduled agents), your distributed traces were breaking at the agent boundary. Now a single trace ID follows the request from your orchestrator → Goose → MCP server → external API. Your Datadog/Honeycomb/Jaeger dashboards finally show the full picture.

**For beginners:** If you don't know what distributed tracing is, you don't need this yet. When you do, you'll be glad it's there.

---

### 3. Adaptive Thinking Fixes for Claude 5.5 — The Model Decides, Not You

**What it is:** v1.54 introduced adaptive thinking (model picks reasoning depth per-turn). v1.55 fixes the edge cases (#12761) — specifically for **Claude Sonnet 5.5 and Haiku 5.5**.

**Why it matters:** The feature now works reliably. Simple edits get fast responses. Complex architectural decisions get deep reasoning. You stop managing the "thinking budget" slider.

**Also fixed:** `GOOSE_CLI_SHOW_THINKING` now accepts *any* truthy value — set it once, see reasoning blocks everywhere.

---

### 4. Stop That Actually Saves Work — No More Lost Progress

**What it is:** `Stop` now ends the run promptly and saves what was produced (#12765).

**Why it matters:** Before: you hit Stop mid-task, the agent kept churning in the background, and you lost the partial output. Now: Stop → agent finishes current tool → saves state → exits cleanly. Your partial refactor, half-written test, or incomplete search is preserved in the session.

**For beginners:** This feels obvious. It wasn't. Now it is.

---

### 5. Provider x-request-id on Responses — Debugging Distributed Calls Just Got Easier

**What it is:** Goose surfaces the provider's `x-request-id` on both responses and errors (#12587).

**Why it matters:** When a model call fails silently or returns garbage, you used to guess. Now you have the exact request ID to paste into your provider's dashboard (Anthropic, OpenAI, OpenRouter, etc.) and see *exactly* what happened.

---

### 6. Leaner Agent Loop — Background Subagents Removed, Doctor Now Session-Only

**What it is:** The legacy agent loop is gone (#12760). Background subagents and the orchestrator are removed. Doctor (the self-diagnosis tool) runs only in-session, not as a background process.

**Why it matters:** Less moving parts = fewer failure modes. The unrolled state machine (#11216 from v1.53) is now the *only* loop. If you're embedding Goose, the mental model is simpler: one loop, one session, deterministic transitions.

---

### 7. Bedrock: No Retry on Non-Context Validation Errors

**What it is:** Bedrock provider no longer retries `ValidationException` on `converse_stream` unless it's a context-length issue (#12710).

**Why it matters:** Prevents infinite retry loops on genuine config errors (wrong model ID, bad params, region mismatch). You get the error fast instead of a timeout.

---

### 8. OpenRouter: Transforms Field No Longer Set Unconditionally

**What it is:** Fixes a bug where Goose sent `transforms` to OpenRouter even when not needed (#11374).

**Why it matters:** Some OpenRouter models reject requests with unexpected fields. This silently broke certain models. Now fixed.

---

### 9. Long-Context Price Tiers in Cost Estimates

**What it is:** Cost estimates now apply the correct price tier for long-context models (#12787).

**Why it matters:** If you're using 100k+ context windows (GPT-6 Sol, Opus 5.5, etc.), your cost estimates were wrong. Now they're right.

---

### 10. Finish Pending Tools Before Enforcing Max Turns

**What it is:** Goose now lets in-flight tool calls complete before hitting the `--max-turns` limit (#12702).

**Why it matters:** Your agent was getting cut off mid-tool-call. Now it finishes the current operation, then respects the limit. Cleaner session boundaries.

## What This Means for You

**If you're new to coding agents:** Goose v1.55 doesn't change the "first run" experience much. The improvements are under the hood — but they compound. Sessions that stop cleanly. Traces that don't break. Models that pick their own thinking depth. The agent feels more *reliable*, which is the feature beginners appreciate most once they hit their first weird failure.

**If you're embedding Goose (IDE plugin, CI bot, custom frontend):** This is the release you've been waiting for. AIgateway = declarative provider config. W3C trace context = observability that works. Leaner loop = smaller binary, simpler integration. The ACP-only binary from v1.53 + these v1.55 improvements = Goose as a proper runtime, not just a CLI.

**If you're on Claude 5.5:** Adaptive thinking now works reliably. Set `GOOSE_CLI_SHOW_THINKING=1` once and forget it.

## What's Still Missing (Honest Assessment)

- **Desktop HTML export** — CLI only for now (v1.53 added it, Desktop coming)
- **Android Remote Control** — iOS only (same as Cursor/Claude Code)
- **Visual trace viewer** — You get the headers, but no built-in UI to view them
- **AIgateway UI** — Declarative config is code-first; no visual builder yet
