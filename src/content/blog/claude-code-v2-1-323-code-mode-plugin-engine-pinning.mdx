**Claude Code v2.1.323 landed November 12** — and the headline is **Code Mode**, an experimental opt-in that fundamentally changes how Claude interacts with tools. Instead of native tool calls, Claude writes JavaScript to call its tools. This is the biggest architectural shift since the agent launched.

---

## The Headline: Code Mode — Claude Writes JavaScript Now

### What Is Code Mode?

**Code Mode** is an experimental opt-in where **Claude writes JavaScript to call its tools** instead of using the native tool-calling protocol. Think of it as: the model generates code that runs in a sandbox, and that code makes the actual tool calls.

```bash
# Enable Code Mode (experimental)
# See https://code.claude.com/docs/en/code-mode for full docs
claude --code-mode
```

### Why This Changes Everything

| Before (Native Tools) | After (Code Mode) |
|----------------------|-------------------|
| Model outputs structured tool calls | Model writes JavaScript that calls tools |
| Fixed tool schema | Flexible — model can compose, loop, conditionally call |
| One tool call per turn | Model can batch, retry, transform results in JS |
| Hard to debug | Full JS stack traces, console.log, breakpoints |

**For beginners:** This is like giving the agent a REPL instead of a button panel. It can write a loop to edit 50 files, catch errors and retry, transform data between calls — all in JavaScript you can read and debug.

### The Tradeoffs

- **Experimental** — opt-in only, not default
- **Organizations can disable** — `codeMode: false` in managed settings
- **Learning curve** — model needs to write correct JS, not just pick tools
- **Performance** — slight overhead vs native calls

But the ceiling is higher: **the agent becomes programmable**.

## Plugin System: Engine Version Pinning + TypeScript Validation

### Plugins Now Pin Their Claude Code Version Range

`plugin.json` gets a new field: `engines["claude-code"`. Plugins outside their stated range **won't install, update, or load**. Install/update picks the newest version that fits.

```json
// plugin.json
{
  "name": "my-plugin",
  "engines": {
    "claude-code": ">=2.1.300 <3.0.0"
  }
}
```

**Why it matters:** No more mystery breaks when a plugin assumes APIs that don't exist yet. The version contract is explicit.

### `claude plugin validate` Now Type-Checks TypeScript Hooks

Run `claude plugin validate` (or `--strict` to fail on warnings) and it will type-check your plugin's TypeScript hooks module. Each finding is a warning; `--strict` fails the build.

### Mods: `$` Nouns from `engine.create` Now Visible in Validation

The validate command now shows what `$` nouns a mod's `engine.create` hook adds, withholds, or replaces — so you know exactly what the mod exposes before installing.
