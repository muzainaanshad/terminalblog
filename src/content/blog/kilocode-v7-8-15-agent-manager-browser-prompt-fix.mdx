## 1. Agent Manager: Your Primary Agent Finally Chooses the Delegate

**The problem:** You start an Agent Manager session expecting your custom agent (with its tailored edit/bash/MCP permissions) to run the work. Instead, it falls back to the workspace default agent. Your carefully scoped `edit: { "secrets/**": "deny" }` rules? Ignored.

**The fix (v7.8.13 → v7.8.15):** A primary agent can now **choose which agent runs an Agent Manager session it starts**.

```json
// Your custom agent config
{
  "name": "security-reviewer",
  "edit": { "secrets/**": "deny" },
  "bash": { "allow": ["npm test", "git diff"] }
}
```

When this agent starts an Agent Manager session for a named agent, **it runs that agent with its own permission rules** — not the workspace default.

**Why beginners love this:** You configure permissions *once* on your agent. Every delegation inherits the right rules automatically. No more "why did it just delete my .env?" moments.

---

## 2. browser_open: The Permission Prompt That Finally Learns

**The problem:** Every time the agent wants to navigate the integrated browser, you get a permission prompt. Click "Allow." Next navigation — another prompt. Ten clicks later you're wondering why there's no "remember this" checkbox.

**The fix:** The `browser_open` permission prompt now **offers the current origin and all origins as always-allow rules**.

```bash
# Auto-approve settings now include browser_open
kilocode auto-approve list
# browser_open  →  you can allow Integrated Browser navigation without answering each request
```

**In practice:** Allow once for `github.com` → all future GitHub navigations proceed silently. Allow all origins → never see the prompt again. Your call.

---

## 3. Provider Failures: No More Silent Disappearances

**The problem:** A provider (OpenRouter, Anthropic, Google, etc.) fails to load — rejected credentials, network error, misconfigured endpoint. It just **vanishes from the model picker**. You're left guessing: "Did I mistype the key? Is the API down? Did I hit a rate limit?"

**The fix:** The CLI, TUI, and VS Code model picker now **surface the reason** and offer to sign in again when credentials were rejected.

```
⚠ Provider "openrouter" failed to load:
   → Credentials rejected (401)
   → [Sign in again] [Dismiss]
```

**Why it matters:** Debugging "missing provider" used to mean checking logs, restarting, re-entering keys blindly. Now the tool tells you *what* failed and *how to fix it*.

---

## 4. Late-Arriving Reasoning Tokens: No Longer Dropped

**The problem:** Models like Gemini (via OpenRouter) send thought signatures and reasoning details *after* the initial response chunk. Kilo used to drop these — so follow-up requests in the conversation lost the reasoning context.

**The fix:** v7.8.15 **keeps Gemini thought signatures and other OpenRouter reasoning details** that arrive late, so later requests replay them correctly.

**Why it matters:** If you're using models with thinking/reasoning modes, the full reasoning chain now persists across turns. Your agent "remembers" how it thought through the problem.

---

## 5. MCP OAuth: Expired Tokens Auto-Recover

**The problem:** An MCP server rejects an expired access token with `403` (not `401`). The connection gets stuck on "authentication required." New worktree or project session? You have to sign in again manually.

**The fix:** **Refresh expired MCP OAuth tokens automatically.** Servers that reject with `403` no longer leave the connection stuck — a new session reconnects without asking you to sign in again.
