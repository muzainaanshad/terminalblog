On October 2, 2026, a comprehensive security audit of **NousResearch/hermes-agent** dropped — 15,136 files, ~1.1M lines, 64 deep-read passes. The result: **403 findings**, including **6 HIGH-severity vulnerabilities** with working reproductions.

The audit team didn't just find bugs. They **built fixes**. A 695-file local patch against commit `0a374d16` with a re-apply guard. Every fix has byte-level probes, negative controls, and regression tests.

**Three weeks later, zero of those fixes have been merged.**

## What the Fixes Actually Do

The audit team shipped a **local deployment** with all fixes applied. Here's what they change:

### #131563 — Hardline Blocklist Bypass (Zero-Approval Execution)
**File**: `tools/approval_detection.py`

Adds four recursive payload extractors that feed discovered payloads back through the full hardline pipeline:
- `_git_alias_shell_payloads` — extracts `!shell` payloads from git aliases
- `_option_command_payloads` — handles `bash -c'payload'` attached-quote form
- `_system_call_string_payloads` — catches `awk 'BEGIN{system(...)}'`, `find -exec`, `su -c`
- `_find_exec_command_payloads` — recursive wrapper unwrapping for `timeout`, `nice`, `sudo`, `eval`, `env`, `screen`, `tmux`, etc.

**Result**: Hardline battery 6/26 → 26/26. Wrapper battery 3/15 → 15/15. End-to-end `check_all_command_guards` 7/7 BLOCKED. 35 benign commands unchanged (zero false positives).

### #131565 — OSC-8 Terminal Escape Injection
**Files**: Three render sinks in `ui-tui/`

Shared `sanitizeOsc8Url()` strips C0, DEL, C1 controls (including CSI U+009B) at **every sink** before embedding. Sanitizes display text too (autolink `<url>` branch renders raw URL as text node). Byte-level probes green with negative controls.

### #131564 — Skill Scanner Trusts Bundle's Own `.skillignore`
**File**: `tools/skills_guard.py`

**Never honors bundle-supplied ignore files during scanning** — every file takes both passes. Reports every ignore file found as `skill_ignore_file` finding. Bumps `SCANNER_VERSION` so cached "safe" verdicts are invalidated and re-scanned.

### #131562 — Stored XSS via Bot Name
**File**: `apps/desktop/src/plugins/hermes-bots/avatar.tsx`

`escapeHtmlAttr()` (escape `& < > " '` to entities) before attribute interpolation. Regression tests with hostile names. Also fixes CSS-selector twin in `profile-ops.ts`.

### #131561 — WSL `openExternal` Command Injection
**File**: `apps/desktop/electron/external-open.ts`

Two-tier `buildCmdStartArgs(url)`:
1. Fail-closed reject for unescapable characters (`"`, `%`, `!`, whitespace/controls)
2. Caret-escape remaining metacharacters
3. Keep scheme allowlist

20-case probe suite: 9 attack URLs fully escaped, 7 unescapable rejected, clean URLs unchanged.

## Why This Matters: The Fixes Exist. They Work. They're Not in Your Build.

This isn't a "waiting for a fix" situation. The fixes are **written, tested, and proven**. They sit in open PRs (or haven't been opened yet) while every Hermes installation runs vulnerable code.

**If you run Hermes Agent today, you are affected by at least some of these:**

- **Hardline bypass (#131563)**: Affects **everyone**. Any prompt-injected model or malicious context can execute `timeout 1 rm -rf /` with zero approval prompts.
- **OSC-8 injection (#131565)**: Affects **all TUI users**. Model output with a crafted markdown link injects terminal escapes on *render* — no click needed.
- **Skill scanner bypass (#131564)**: Affects **anyone installing skills**. A single `*` in `.skillignore` masks everything except `SKILL.md`.
- **Stored XSS (#131562)**: Affects **Desktop app users with bots**. Bot names propagate via gateway registry.
- **WSL injection (#131561)**: Affects **Windows+WSL Desktop users**. Clicking a malicious link executes arbitrary commands.
- **43 medium findings (#131566)**: Include TTS shell injection (`Popen(shell=True)`), path traversal in memory approve, SSRF in media relay, open redirect in dashboard auth, credential logging in BlueBubbles, plugin validation bypass, cross-user session attach, unauthenticated credential proxy, SSRF filter bypass, EPIPE killing TUI.

## What You Can Do Right Now

### 1. Check Your Version
```bash
hermes --version
```
If you're on any v0.22.x or v0.21.x — you have **all six HIGH vulnerabilities**.

### 2. Apply Mitigations Immediately
```bash
# Restrict API server to localhost only
grep -r "0.0.0.0" ~/.config/hermes/ 2>/dev/null
# If found, change to 127.0.0.1 in your config

# Audit installed skills for .skillignore
find ~/.config/hermes/skills -name ".skillignore" -o -name ".clawhubignore" 2>/dev/null
# If any exist with broad patterns (*), remove or re-scan those skills

# Check bot configs for suspicious names
find ~/.config/hermes -type f \( -name "*.json" -o -name "*.yaml" \) 2>/dev/null | \
  xargs grep -h "bot" 2>/dev/null | \
  grep -E 'name.*["<>\\']' 2>/dev/null

# Avoid clicking/rendering untrusted links in Desktop/TUI until OSC-8 fix lands
```

### 3. Watch the PRs

## The Uncomfortable Question: Why Aren't They Merged?

Three weeks. Six HIGH findings. Local fixes with full test coverage. Zero merges.

Possible reasons:
- **Maintainer bandwidth**: The project moves fast (6,080 PRs in the v0.22.0 window). Security PRs may not be prioritized.
- **Review complexity**: These touch core security boundaries — `approval_detection.py`, TUI render sinks, skill installation, Electron IPC. Review takes time.
- **Release train**: v0.22.3 (Oct 21), v0.22.4 (Oct 21), v0.22.5 (Oct 22) were patch releases focused on stability/QoL. Security fixes may wait for v0.23.0.
- **Labeling signals**: `P3Low — cosmetic, nice to have` on 4 of 6 issues sends the wrong priority signal to reviewers.

Whatever the reason, **the clock is ticking**. The audit is public. The issues are public. The reproduction scripts exist. Attackers have the same information.

## The Pattern: Hermes Shows Its Work — For Better and Worse

This is the second major security audit for Hermes in 2026:
- **August 2026**: 5 HIGH findings ([#82591](https://github.com/NousResearch/hermes-agent/issues/82591)) — fixed in subsequent releases
- **October 2026**: 6 HIGH findings — **fixes ready, not merged**

The difference: **October's audit came with a complete local patch set**. The team didn't just report problems — they solved them. The fixes are *done*.

This transparency is rare and valuable. Most projects quietly patch and disclose later (or never). Hermes shows the work.

But transparency cuts both ways: **attackers can read the same issues**. Every day these stay open is a day the exploit window widens.
