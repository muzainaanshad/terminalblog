Claude Code **v2.1.293 dropped October 7**, one day after the plugin-marketplace release v2.1.292. This isn't a feature parade — it's the release that **swaps the default fast model**, **fixes the context compaction bug that made you redo work**, **plugs an MCP memory leak**, and **stops Chrome TUI from disconnecting**.

If you've ever watched your agent redo a refactor it already finished after a compaction, or had your Chrome-based TUI session die mysteriously — **this is the version.**

---

## 1. Haiku 5.5 Is Now the Default Fast Model

**The headline:** `claude-haiku-5-5` replaces the old Haiku as the default.

| Spec | Old Haiku | Haiku 5.5 |
|------|-----------|-----------|
| Context | 200K | **1M** |
| Input (≤100K) | $0.25/M | **$0.10/M** |
| Output (≤100K) | $1.25/M | **$0.50/M** |
| Input (>100K) | $0.25/M | **$0.50/M** |
| Output (>100K) | $1.25/M | **$2.50/M** |

For beginners: Haiku is the "fast/cheap" model Claude Code uses for quick tasks (file edits, simple searches, formatting). Haiku 5.5 gives you **5× more context** at **60% lower cost** for typical prompts. Your quick tasks just got cheaper and can handle larger files.

```bash
# Verify you're on the new default
claude --version
# 2.1.293

# Model is auto-selected for appropriate tasks
# No config change needed
```

---

## 2. Context Compaction No Longer Redoes Finished Work

**The bug:** When a long session hit its context limit, Claude would compact (summarize older messages). But it sometimes **forgot** it had already completed recent actions — so it would redo edits, re-run searches, or retract changes that were *done*.

**The fix:** Compaction now correctly preserves the "done" state of recent actions. Your agent won't redo the refactor it just finished.

<details>
<summary>Why this matters for beginners</summary>

Context compaction happens silently in long sessions. Before this fix, you'd see your agent "go backward" — re-applying a fix, re-reading a file it already read, undoing a change it made 5 minutes ago. Now it remembers: *done stays done.*
</details>

## 3. HTTP MCP Memory Leak — Plugged

**The bug:** An HTTP-based MCP connection kept **every request it ever sent** in memory until the connection closed. Long-running sessions with MCP servers (GitHub, Slack, custom tools) would leak memory steadily.

**The fix:** Requests are now released after response. No more unbounded growth.

For teams running Claude Code as a daemon with MCP integrations — this was the silent killer. Your memory graph should flatten now.

---

## 4. Chrome TUI (`--chrome`) Disconnects Fixed

**The bug:** Running `claude --chrome` (Claude Code in Chrome via TUI) would randomly disconnect. Also `--no-chrome` was ignored.

**The fix:** Both issues resolved. Chrome-based TUI sessions stay connected; `--no-chrome` is respected.

---

## 5. Subagent Tool Permissions — Finally Consistent

**The bugs fixed:**
- Subagents and `--agent` sessions were told a built-in tool was disabled for the *whole session* when only *their* tool list excluded it
- Sessions (including resumed ones) were told to continue or message subagents with `SendMessage` even when a host, permission rule, or `--tools` list removed that tool
- `claude agents` offered bypass permissions that background sessions ignored when consent was saved only in `.claude/settings.local.json` or a `--settings` file — now it asks for consent first

**The result:** Subagent tool permissions now behave predictably. What you allow/deny at the session level matches what subagents see.
