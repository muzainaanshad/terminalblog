Anthropic has extended its Claude Code weekly-limit promotion: eligible plans now get a 50% higher weekly usage limit, and the offer now runs through July 19, 2026. No action is required — if you're on a qualifying plan, the boost is applied to your account automatically. The 5-hour usage limit is not affected.

## What the promotion actually does

From May 13 through July 19, 2026, your **weekly** usage limit in Claude Code is 50% higher than standard. The increase applies to Claude Code only, everywhere you use it: the CLI, IDE extensions, desktop, and the web. Usage limits for other Claude products — the main Claude web/desktop/mobile app and Claude Cowork — are unchanged.

Critically, the promotion touches **weekly** limits, not the **5-hour** limit. If you're hitting the shorter rolling window, this boost won't help; it only stretches the weekly budget.

The promotion is automatic for eligible plans — you don't opt in. You can run `/usage` in the CLI to see your updated weekly limit reflected. After July 19, weekly limits return to their standard levels with no change to your plan or billing.

## How to use the extra headroom

The 50% weekly bump is most useful for people who do bursty, heavy agent work — long refactors, multi-agent sweeps, or big code-generation pushes that would otherwise tap out the weekly meter. A few practical notes:

- **Don't confuse it with the 5-hour limit.** The weekly boost does nothing for short-window throttling. If you're rate-limited on the 5-hour window, the promotion won't change that.
- **Watch subagent fan-out.** A 50% bigger weekly pool is easy to burn if you fan work out to many subagents, each of which pays its own bootstrap. The extra headroom is a budget, not a license to ignore cost.
- **Verify with `/usage`.** Because the increase is automatic, confirm it's applied on your account rather than assuming. If your meter looks unchanged, check that your plan is in the eligible column above.

## What Happens After July 19: Planning Your Usage

The promotion expires at 11:59 PM PT on July 19, 2026. After that, weekly limits snap back to standard levels. If you've been relying on the extra 50% headroom for a specific project or sprint, plan accordingly:

- **Audit your weekly burn rate now.** Run `/usage` daily for a week to see your actual consumption pattern. Most developers overestimate how much they use.
- **Front-load heavy work.** If you have a major refactor or code-generation push planned, schedule it before July 19.
- **Consider plan tier changes.** If you're on Pro and consistently hitting the weekly limit even with the boost, the promotion period is a risk-free window to evaluate whether Max or Team makes sense for your workflow.
- **Don't build workflows that depend on the boost.** Any automation, CI pipeline, or team process that assumes the higher limit will break when it expires.

## Comparing to Other Agents' Limits

The Claude Code promotion is notable because most coding agents don't have transparent, published usage limits at all:

| Agent | Weekly Limit | Transparency | Notes |
|-------|-------------|--------------|-------|
| **Claude Code (promo)** | +50% weekly | High (`/usage` command) | Pro/Max/Team only; expires Jul 19 |
| **Claude Code (standard)** | Plan-dependent | High | 5-hour rolling limit always applies |
| **OpenCode / Codex CLI** | None (local) | N/A | Your GPU/cloud bill is the limit |
| **Cursor** | Request-based | Medium | Pro/Business tiers; opaque quotas |
| **Windsurf** | Request-based | Low | Free tier has daily caps; paid is vague |
| **AmpCode** | Token-based | Medium | Pay-as-you-go via API keys |

The local-agent advantage (OpenCode, Codex with local models, Hermes) is zero marginal cost per token — your hardware or API key budget is the only constraint. Cloud agents like Claude Code, Cursor, and Windsurf all have some form of rate limiting, but Anthropic is the only one publishing concrete numbers and running explicit promotions.

## Practical Tips for the Promotion Window

1. **Run `/usage` at the start of each session.** Make it a habit. The CLI output shows weekly used / weekly limit, so you can pace yourself.
2. **Use subagents strategically.** Each subagent invocation adds bootstrap overhead. For the promotion period, consider fewer, longer-running subagent tasks instead of many short ones.
3. **Batch related work.** The weekly limit resets on a rolling 7-day window, not calendar weeks. If you know you'll be heavy this week, go lighter next week.
4. **Check IDE vs CLI parity.** The promotion applies everywhere — CLI, VS Code extension, JetBrains plugin, desktop app, web. Usage aggregates across all surfaces.
5. **Team plans: monitor seat usage.** If you're on a Team plan, the weekly limit is per-seat. The promotion applies to each eligible seat independently.
