**July 2026:** "Which open-source coding agent should I pick?"

**November 2026:** "Which open-source *platform* should I build on?"

The question changed because the products changed. In four months, every major open-source coding agent shipped the same five infrastructure layers — orchestration, shared compute, marketplace, remote access, and quality gates. The model war ended. The platform war is the only war left.

This article maps the November 2026 landscape: who the contenders are, what they actually ship now (not what their README promises), and how to choose based on your constraints.

## How to Choose: The Three Questions That Matter

The feature matrix is a starting point. The decision actually hinges on three questions:

### 1. Do you need it to run unattended?

| If YES → | If NO → |
|----------|---------|
| **Hermes** (cron, missed-run policies, background delegation, mem0 memory) | **OpenCode** (best terminal UX, persistent terminals, worktrees) |
| **pi.dev** (managed platform, Helm, systemd, knowledge graphs) | **Cursor** (best editor + platform, Projects, Marketplace) |
| | **AmpCode** (best team infrastructure, Service Accounts, Artifacts) |
| | **Zed** (best memory discipline, compaction that works) |
| | **Goose** (voice, cost tracking, ACP) |
| | **Kilo** (lightweight multi-model orchestrator) |
| | **Oh My Pi** (vision + browser automation) |
| | **Gitlawb Zero** (radical ownership, decentralized) |

**Why this question decides it:** Unattended execution requires cron, missed-run handling, background delegation, and persistent memory. Only Hermes and pi.dev ship this as a first-class, tested feature. Everything else treats background work as secondary.

---

### 2. Do you need it to see or drive a browser?

| If YES → | If NO → |
|----------|---------|
| **Oh My Pi** (Puppeteer browser automation, best-in-class) | Everything else |
| **Mimo** (vision in the loop, OpenCode base) | |
| **Gitlawb Zero** (vision + readonly + plan mode) | |
| **Hermes** (vision via plugins, browser automation via plugins) | |

**Why this question decides it:** Browser automation and vision are architectural commitments. Oh My Pi built its core around Puppeteer. Mimo forked OpenCode to add vision. Hermes added it via plugins. If this is your daily workflow, pick the one that made it a first-class citizen.

---

### 3. Do you care about swappable models / no vendor lock-in?

| If YES (multi-provider essential) → | If NO (single provider OK) → |
|-------------------------------------|------------------------------|
| **Hermes** (15+ providers, model_overrides, routing profiles) | **Claude Code** (Opus 5.5/Sonnet 4.5/Haiku 5.5, polished) |
| **OpenCode** (provider-neutral, LiteLLM, any OpenAI-compatible) | **Cursor** (Dial routes, but default is Anthropic/OpenAI) |
| **Kilo** (500+ models in Agent Manager) | **AmpCode** (Dial, but team features need paid) |
| **Goose** (any provider, cost tracking per model) | **Zed** (multi-provider via ACP/extensions) |
| **pi.dev** (any provider, managed platform) | |
| **Oh My Pi** (model hub, 16+ providers) | |
| **Gitlawb Zero** (multi-provider, decentralized) | |

**Why this question decides it:** If a single provider outage or price hike blocks your team, you need multi-provider routing as a core feature, not an afterthought. Hermes, OpenCode, and Kilo make this a first-class design principle.

## The Security Reality Check (Read Before You Run Anything Unattended)

Open-source agents run with your credentials and write to your filesystem. That power is the point — it's also the risk.

**Minimum baseline before any unattended run:**

1. **Scope API keys to least privilege** — no admin keys in agent configs
2. **Run in a sandbox where feasible** — bubblewrap, Docker devcontainers, Hyperlight micro-VMs
3. **Review what subagents can read** — Hermes credential guard, Gitlawb Zero local-only are the two ends of the spectrum
4. **Gate destructive operations** — force-push, prod changes, secret access behind human approval
5. **Write an AGENTS.md** — tell the agent your security rules, files to avoid, commands that need approval

**Hermes-specific:** Credential guard scopes secrets per-subagent. OS keychain vault (v0.23). Per-skill locks (`hermes curator lock`).

**OpenCode-specific:** No built-in sandbox. Use devcontainers or bubblewrap wrapper.

**AmpCode-specific:** Team credentials via Service Accounts. Orbs run in your infra if self-hosted.

**Cursor-specific:** Enterprise has audit logs, SSO, policy enforcement. Pro/Teams lack some gates.

**pi.dev-specific:** Helm deployment with network policies, zero-secrets sandbox, ephemeral VMs.

See the full [Coding Agent Security Checklist 2026](/blog/coding-agent-security-checklist-2026/) for the complete audit framework.

## AGENTS.md: The Highest-Leverage File You'll Write

Regardless of which agent you pick, a well-written `AGENTS.md` in your repo root is the single highest-ROI thing you can add. It turns a generic agent into one that respects your build, test, and review workflow.

**Template:**

```markdown
# AGENTS.md — Instructions for Coding Agents

## Project Overview
- **Type:** [web API / CLI / library / monorepo]
- **Language:** [TypeScript, Python, Go, Rust...]
- **Framework:** [Next.js, FastAPI, Gin, Axum...]
- **Key directories:** `src/`, `tests/`, `infra/`, `docs/`

## Build & Test Commands
- **Install:** `pnpm install` / `pip install -e .` / `go mod tidy`
- **Build:** `pnpm build` / `cargo build --release`
- **Test:** `pnpm test` / `pytest` / `go test ./...`
- **Lint:** `pnpm lint` / `ruff check .` / `golangci-lint run`
- **Typecheck:** `pnpm typecheck` / `mypy .`

## Conventions
- **Naming:** [camelCase for vars, PascalCase for types, kebab-case for files]
- **Imports:** [absolute from root, grouped: external → internal → relative]
- **Error handling:** [Result<T, E> / exceptions / error values — be specific]
- **Logging:** [structured JSON, levels: debug/info/warn/error]
- **Git:** [conventional commits, squash merges, branch naming: feat/fix/chore]

## Security Rules
- **NEVER commit:** `.env`, `*.pem`, `*.key`, `secrets/`, `.aws/`, `.gcp/`
- **NEVER run:** `curl | bash`, `npm install -g` without review, `kubectl apply` on prod
- **REQUIRE approval for:** database migrations, infra changes, secret rotation, force-push
- **Sandbox:** all file writes under `src/` and `tests/` only

## Agent-Specific Notes
- **Hermes:** Use `hermes cron` for scheduled tasks. Memory persists via mem0.
- **OpenCode:** Skills live in `.opencode/skill/`. Use `/plan` for multi-step.
- **Cursor:** Agent SDK projects in `.cursor/agents/`. Run `agent-sdk eval` in CI.
- **AmpCode:** Service Account threads survive offboarding. Artifacts for runbooks.
- **Zed:** ACP agents in `.zed/agents/`. Enable `git.auto_fetch.enabled: true`.
- **All:** Read this file at session start. Update it when conventions change.
```
