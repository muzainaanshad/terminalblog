Terminal UI is hard to get right. Terminal UI that works with everyone's keyboard preferences is even harder. Gitlawb Zero just solved this the right way: make everything configurable.

## What Changed

Zero's TUI shortcuts were hardcoded. Arrow keys for navigation, enter for selection, escape for cancel — standard choices, but not everyone's preferences. The commit `Make shortcuts reconfigurable via the config file` changes that.

Every keyboard shortcut in Zero's TUI is now remappable through the config file. You can bind any action to any key combination.

## What's Configurable

All of Zero's interactive modes support custom shortcuts:

- **Provider picker** — search, select, filter, cancel
- **Model selection** — switch models, view details
- **Session browser** — navigate sessions, delete, export
- **Permission prompts** — approve, reject, inspect
- **General navigation** — scroll, search, exit
- **Diff viewer** — next/prev hunk, expand/collapse, copy
- **Command palette** — open, navigate, execute

The config uses a declarative format:

```json
{
  "shortcuts": {
    "provider_picker": {
      "search": ["ctrl+f", "/"],
      "confirm": ["enter"],
      "cancel": ["escape", "ctrl+c"],
      "page_down": ["ctrl+d", "pagedown"]
    },
    "model_selection": {
      "filter": ["ctrl+f", "/"],
      "select": ["enter", "ctrl+enter"],
      "details": ["ctrl+i", "i"],
      "back": ["escape", "ctrl+q"]
    },
    "session_browser": {
      "navigate_up": ["k", "up"],
      "navigate_down": ["j", "down"],
      "delete": ["d", "delete"],
      "export": ["e", "ctrl+e"],
      "search": ["/", "ctrl+f"]
    },
    "permission_prompt": {
      "approve": ["a", "enter", "y"],
      "reject": ["r", "n", "escape"],
      "inspect": ["i", "ctrl+i"],
      "always_approve": ["shift+a", "A"]
    },
    "global": {
      "command_palette": ["ctrl+p", "ctrl+shift+p"],
      "help": ["?", "f1"],
      "quit": ["ctrl+c", "ctrl+q"]
    }
  }
}
```

Each action accepts an array of key combinations, so you can have multiple bindings for the same action (e.g., both vim-style `j/k` and arrow keys for navigation).

## Why This Matters for Power Users

Customizable shortcuts might seem like a niche feature, but they're a signal of a tool designed for power users. Developers spend hours every day in their terminal tools. The difference between a default keybinding and a personalized one might be milliseconds per action — but over thousands of actions, it adds up.

Zero's approach — reconfigurable via config file — is the right one for a CLI tool. It doesn't require a GUI preferences panel. It integrates with your dotfiles. It's version-controllable.

### Real-World Scenarios

**Vim users** can map everything to hjkl and modal bindings:
```json
{
  "shortcuts": {
    "global": { "command_palette": [":"] },
    "session_browser": { "navigate_up": ["k"], "navigate_down": ["j"] }
  }
}
```

**Emacs refugees** get their ctrl/meta combos:
```json
{
  "shortcuts": {
    "global": { "command_palette": ["ctrl+x", "ctrl+f"] },
    "provider_picker": { "search": ["ctrl+s"] }
  }
}
```

**Accessibility needs** — single-hand operation, sticky keys, or alternative layouts (Dvorak, Colemak) — just work because the config is pure data.

## How It Compares

| Agent | Shortcut Customization |
|-------|----------------------|
| **Gitlawb Zero** | Full declarative config, all modes, multiple bindings per action |
| **Hermes** | Skill-based, scriptable via `SKILL.md` hotkeys |
| **OpenCode** | Plugin-based, community plugins like `opencode-vim-bindings` |
| **Claude Code** | Limited — some slash commands, no TUI key remapping |
| **Kilo** | Config file with basic keybind section |
| **Mimo** | Inherits OpenCode's plugin approach |

Zero's approach is the most comprehensive for a pure TUI agent — every interactive mode is covered, and the config is a single JSON file you can drop in your dotfiles repo.

## Migration from Hardcoded Keys

If you've been using Zero since before this change, your muscle memory still works. The defaults match the old hardcoded bindings exactly:

| Mode | Old Default | New Config Equivalent |
|------|-------------|----------------------|
| Provider picker search | `/` | `"search": ["/", "ctrl+f"]` |
| Confirm/select | `Enter` | `"confirm": ["enter"]` |
| Cancel/back | `Escape` | `"cancel": ["escape", "ctrl+c"]` |
| Command palette | `Ctrl+P` | `"command_palette": ["ctrl+p", "ctrl+shift+p"]` |

No migration needed — just add overrides for what you want to change.

## What's Next

The shortcut system is extensible. Future additions on the roadmap:
- **Chord sequences** (e.g., `g` then `g` for "go to top")
- **Mode-specific overrides** (different keys in diff view vs session browser)
- **Import/export** shortcut profiles (share your perfect setup)
- **Conflict detection** (warn when two actions share a binding)

This is one of those features that experienced developers immediately appreciate and casual users might never notice. But that's who Zero is for.
