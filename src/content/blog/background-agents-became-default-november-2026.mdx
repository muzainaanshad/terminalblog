**November 2026 will be remembered as the month the chat session died.**

In a single month, five major coding agents — OpenCode, Codex, Cursor, Qwen Code, and Hermes — all shipped background/async execution as a first-class workflow. Not as an experiment. Not behind a flag. As the **default way you work**.

This wasn't coordinated. It happened because the same constraint hit every team: **developers can't wait anymore.**

---

## The Old Model Is Broken

For two years, every coding agent worked the same way:

```
You prompt → Agent works → You wait → Agent finishes → You read result → Repeat
```

This is synchronous. Serial. One thing at a time.

If you're refactoring auth, you can't also ask the agent to write tests. If you're debugging a flaky CI, you can't also have it update docs. You're blocked on the agent's single thread of execution.

**That model just ended.**

## OpenCode v2.3: Background Subagents Without Ceremony

OpenCode's implementation is the most accessible. You type `/subagent "refactor the auth module"` and **get a session ID back instantly**. The subagent works in the background. You keep coding in the main session. A notification appears when it's done.

```bash
# In OpenCode TUI
/subagent "refactor the auth module"
# Returns immediately: "Subagent started: session_abc123"
# You continue editing. Subagent works in background.
# When done: notification appears with summary
```

**Why it works:** No YAML, no config, no framework ceremony. Just `/subagent` and go. The v2.3 release also added quieter transcripts (collapsible activity rows) and Jump-to-message search (`Cmd+Alt+G`) so you're not drowning in noise when you *do* check results.

**Best for:** Terminal-first developers who want concurrency without leaving their editor.

---

## Codex 0.169: Multiple Contexts, One Terminal

Codex took a different angle: **multiple side-chat tabs in the terminal workspace**. Each tab = independent conversation context. Switch with `Ctrl+Tab`. Restart Codex — your side chats persist.

```bash
# In Codex TUI (terminal workspace)
# 1. Open a new side chat: Ctrl+Shift+N
# 2. Switch tabs: Ctrl+Tab / Ctrl+Shift+Tab
# 3. Each tab = independent conversation context
# 4. Restart Codex → your side chats are still there
```

Plus searchable task history from the command center (`codex agents --no-daemon`) and collapsible turn details in full-screen transcripts.

**Why it works:** It mirrors how developers actually think — multiple parallel threads of work, not one linear chat. Tab 1 = frontend bug. Tab 2 = backend refactor. Tab 3 = docs update. Switch instantly. Context preserved.

**Best for:** Developers who juggle multiple tasks in one terminal session.

## Cursor Build Live Apps: Agents That Ship Software

Cursor's November 5 release is the most ambitious. Cloud agents don't just write code — they **build full web apps, spin up Postgres databases, configure auth, deploy to live URLs**, and hand you a link. All from one chat thread.

```
You: "Build a dashboard for sales showing pipeline by region"
Agent: 
1. Scaffolds Next.js + TypeScript + Tailwind
2. Spins up Postgres
3. Configures Cursor SSO auth
4. Provisions hosting
5. Asks for secrets only if needed
6. You pick subdomain → live `your-app.cursor.app` link
```

The agent works in the cloud. You're free to do anything else. When it's done, you get a working app, not a code snippet.

**Why it works:** It closes the loop from "AI writes code" to "AI ships software." The bottleneck moves from engineering capacity to "how fast can you describe what you need."

**Best for:** Teams that want non-engineers (sales, ops, legal) to build internal tools without filing tickets.

## Qwen Code v1.0: Scriptable Agents That Survive Reboots

Qwen Code's v1.0 preview (Nov 11) removed the last friction point: **no Node.js required**. Native binaries for macOS/Linux/Windows. But the real workflow shift is `--non-interactive` + `--resume`:

```bash
# One-shot task, exits with code (0 = success, 1 = failure)
qwen-code run --non-interactive \
  "Review PR #247 for security issues, post comments on risky patterns"

# With JSON output for parsing
qwen-code run --non-interactive --json \
  "Generate unit tests for src/auth/*.ts" \
  > test-generation-result.json

# Session interrupted? Resume it:
qwen-code --resume <session-id>
# Or list recoverable sessions:
qwen-code sessions list --resumable
```

**What persists:** Full conversation history, tool call results, working directory state, agent context, pending "Ask User" questions.

**Why it works:** Agents become first-class CLI citizens. Your build pipeline, deploy hooks, nightly security scans — they all invoke Qwen Code as a scriptable component. If the session dies, you resume it. No human babysitting.

**Best for:** Automation-first teams, CI/CD integration, air-gapped environments.

## Hermes v0.23: The Platform Approach

Hermes has had background execution since v0.21 (Pantheon), but v0.23 "Hearth" (Nov 5) made it a **complete platform**:

- **Unified gateway** — one session across CLI, TUI, Desktop, editors, bots, cron
- **Cron jobs** — missed-run policies, stop buttons, per-skill locks
- **Background delegation** — subagents route to named models/profiles
- **Multi-machine Desktop** — laptop + SSH gateway + VPS in one window
- **Self-running Group Chats** — lead bot / auto-router coordinates specialized bots
- **Webapp** — full Desktop workspace in any browser

```bash
# Enable the webapp
hermes config set webapp.enabled true
# Open http://localhost:8765 in browser → your full workspace

# Create a Group Chat with auto-route
# Desktop → New Group Chat → add bots → enable "Auto-route unnamed messages"
# Drop a message: "refactor the auth module" → right bot picks it up
```

**Why it works:** Hermes treats background execution as *infrastructure*, not a feature. Cron, delegation, memory, plugins, Telegram ops — all unified under one gateway that you can reach from anywhere.

**Best for:** Developers who want a local-first platform that runs unattended for weeks.

## The Pattern: Why Now?

Three forces converged in November 2026:

### 1. Context Windows Got Cheap Enough
You can now afford to spin up multiple agent contexts simultaneously. The token cost of running 3 background subagents is lower than the *opportunity cost* of you waiting on one.

### 2. Developers Hit the "One Thing at a Time" Wall
Every team using agents seriously ran into the same problem: **the agent is faster than you can feed it tasks.** You become the bottleneck. Background execution lets you stay ahead.

### 3. The "Chat" Metaphor Was Always Wrong
Coding isn't chatting. It's **parallel workstreams**: refactor + test + docs + review. Agents that force serial chat sessions fight the actual work. Agents that embrace parallelism match it.

## What This Means for Your Workflow Tomorrow

### If you're solo:
**Start with OpenCode v2.3 or Codex 0.169.** Both give you background concurrency in your existing terminal today. Zero setup. Fire a subagent, keep coding, check results when notified.

### If you're a team lead:
**Evaluate Cursor Build Live Apps for internal tools.** The "non-engineers build their own tools" pattern is real. Sales builds dashboards. Ops builds runbooks. Legal builds contract reviewers. All without eng tickets.

### If you run automation:
**Qwen Code v1.0 or Hermes v0.23.** Qwen for scriptable one-shots in CI. Hermes for persistent cron fleets with memory, plugins, and multi-machine reach.
