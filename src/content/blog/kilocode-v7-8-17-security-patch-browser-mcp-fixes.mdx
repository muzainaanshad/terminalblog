KiloCode **v7.8.17 dropped October 23, 2026** — and it's a **security patch release** you should not skip.

**The headline:** KiloCode now **blocks compromised eMudhra certificate chains** with a fixed, pinned Bun runtime across all CLI platforms. ## The Security Fix: eMudhra Certificate Compromise

**What happened:** eMudhra (a certificate authority) had its signing keys compromised. The October 2026 Node.js/Bun security releases revoke trust in certificates signed by those keys.

**What KiloCode did:** v7.8.16 (pre-release) and v7.8.17 **pin the Bun runtime** across all CLI platforms to block compromised certificate chains. This is enforced at the runtime level — no configuration needed.

| Platform | Runtime | Protection |
|----------|---------|------------|
| **All CLI platforms** | **Pinned Bun runtime** | eMudhra cert chains blocked |
| **Nix CLI builds** | Compatible with pinned runtime | No regression |

**If you use the CLI distributions:** They bundle the patched runtime. Just update.

---

## Browser Links & MCP OAuth: HTTPS Only

**Before:** Browser links and MCP OAuth authorization URLs could be any scheme — including `file://`, `data://`, or custom schemes that could leak local paths or trigger unwanted behavior.

**Now:** **Restricted to HTTP(S) only.** Any non-HTTPS URL in these contexts is rejected.

```bash
# What this blocks:
# - file:///etc/passwd in browser links
# - custom-scheme://oauth-callback in MCP
# - javascript: URLs anywhere

# What still works:
# - https://github.com/login/oauth/authorize ✓
# - http://localhost:3000/callback ✓ (for local dev)
```

This is a defense-in-depth measure: even if an attacker compromises an MCP server or injects a malicious link, they can't escape the HTTPS boundary.

---

## MCP Prompt Shell Injection: Blocked

**The vulnerability:** MCP servers can send prompts that contain shell expressions like `$(rm -rf /)` or \`cat /etc/passwd\`. If the client treats these as executable, you have remote code execution.

**The fix:** KiloCode now **treats shell expressions in MCP prompts as literal text** — they display as written, never execute.

This is the same class of fix that Claude Code, OpenCode, and Hermes Agent have shipped recently. The pattern is clear: **MCP prompts are data, not code.** Never execute them.

## Quality-of-Life Fixes That Matter

### Session PR Badges Restored When Remote Control Disabled

**The bug:** If you disabled Remote Control in settings, session pull request badges (the little indicators showing PR status in the session list) disappeared entirely — even for local sessions.

**The fix:** Badges now show correctly regardless of Remote Control setting. Your local workflow isn't penalized for a cloud feature you don't use.

### Kilo Cloud Provider: Built-In Session Host Registry

**New:** An internal **Session Host registry** and the **built-in Kilo Cloud provider** that lists, reads, starts, and describes cloud-hosted sessions.

This is the foundation for:
- Cloud session management from the CLI
- Mobile app session forking (introduced in v7.8.15)
- Future: distributed agent fleets across your infrastructure

The provider is opt-in — you enable it when you want cloud sessions. Local-first remains the default.

## The Bottom Line

**v7.8.15 made the platform capable. v7.8.17 makes it secure.**
