Claude Code **v2.1.322** dropped today (Nov 10). The headline: **fast mode now works on Vertex AI** in global, US, and EU regions — with automatic fallback to standard speed if Vertex refuses it.

## Why This Matters

If you run Claude Code on Google Cloud via Vertex AI, you've been stuck on standard speed. Fast mode (which uses optimized serving paths) was only available on Anthropic's direct API. Now it works on Vertex too — and gracefully falls back if something goes wrong.

## What's in v2.1.322

**Headline feature:**
- Fast mode on Vertex AI (global, us, eu regions) with automatic fallback

**Notable fixes (50+ total):**
- Fixed MCP OAuth requests leaking secrets (refresh tokens) to other hosts on redirect
- Fixed read-only Bash commands running outside sandbox without permission prompts
- Fixed deny rules not applying to `cp`/`mv` into directories
- Fixed `/config` showing "Manual" as default permission mode when sessions start in auto mode
- Windows: Fixed `FileChanged` hooks stopping after first shell command with lowercase drive letters
- Fixed plugin auto-updates downloading plugins again for each worktree
- Fixed auto mode losing background subagent reports during compaction
- Fixed project skills disappearing after folder removal/restore (e.g., `git stash`)
- Fixed high memory in long sessions reading single lines from large files
- Fixed fast mode losing replies/switching models when rate-limited — now tries standard speed first
- Fixed background agents reported as "stopped by user" when service interrupted the session
- Fixed `claude -p` exiting silently on Linux when NFS export fails — now prints error and exits 1
- Fixed a turn ending with "API Error: EPROTO: TLS handshake failed" when connection broke mid-reply
- Fixed cloud sessions telling Claude a host is probably not allowed when it is allowed
- Fixed MCP server showing as connected with no tools after reconnection
- Fixed Bash commands running in wrong folder when Claude sent several at once
- Fixed files from cloud/Remote Control sessions failing on HTTP 507 — now gets a second try
- Fixed new messages not being saved when memory ran out during transcript read
- Fixed sign-in/token refresh/logout waiting indefinitely on stalled TLS handshake
- Fixed sub-agent progress summaries running to end after model replied with tool call

## The Bigger Picture

This continues the v2.1.3xx stability wave. Since v2.1.300, Anthropic has been shipping **daily micro-releases** focused on reliability over features. v2.1.322 is the 22nd release in this series.

If you're on Vertex AI, update now — fast mode can meaningfully reduce latency for coding tasks.

```bash
claude update
# or reinstall via your package manager
```
