Plus: **OpenAI ultrafast service tier support** and **PTY connection validation** that stops phantom terminal errors.

Then came **three rapid patches in two days** (Oct 15-16) that made the release line production-ready:

- **v1.19.1** (Oct 15): Removed session sharing entirely — clean break from deprecated feature
- **v1.19.2** (Oct 16): Locked 1.x installs to 1.x updates (no accidental 2.x jumps), fixed yarn/Homebrew/Chocolatey upgrade paths

## What Actually Changed (Full v1.19 Changelog)

### v1.19.0 (Oct 11) — The Upgrade Path Opens

### 1. `opencode upgrade --major` — The OpenCode 2 Migration Command

This is the headline. OpenCode 2 has been in the works for months (new architecture, better plugin system, revised TUI). v1.19.0 makes it **one command away**.

```bash
opencode upgrade --major
```

**What it does:**
- Downloads and installs OpenCode 2
- Migrates your config, skills, and session data
- Handles breaking changes automatically
- Rolls back if something goes wrong

**Why beginners care:** Major version upgrades are usually where things break. Config formats change. Plugin APIs shift. Sessions don't restore. OpenCode 2's migration command **handles the scary parts for you**. You run one command, coffee break, come back to a working OpenCode 2 setup.

### 2. `/update` Command Now Installs Updates (No More Auto-Updates)

OpenCode **stopped auto-installing updates**. Instead, you run:

```bash
/update
```

in the TUI, or `opencode upgrade` from CLI.

**Why this matters:** Auto-updates mid-session are the classic "why did my agent just restart?" moment. Explicit updates mean **you decide when the runtime changes** — not your agent in the middle of a debug session.

### 3. OpenAI Ultrafast Service Tier — Speed for ChatGPT Subscribers

If you use OpenAI models through OpenCode, the **`ultrafast` service tier** is now supported.

**What it is:** OpenAI's lowest-latency inference tier (available to ChatGPT subscribers on certain plans). Responses arrive ~2-3x faster than standard.

**Why it matters:** For coding agents, latency = flow. Waiting 8 seconds for a model response breaks your train of thought. Ultrafast brings it down to 2-3 seconds. If you have access, enable it in your provider config and feel the difference immediately.

### 4. PTY Connection Validation — Goodbye Phantom Terminal Errors

OpenCode now **validates PTY connection origins and tickets** before checking if a PTY exists.

**In English:** Those weird "PTY not found" errors that appeared randomly when your terminal session got into a weird state? **Fixed at the source.** OpenCode now verifies the connection is legitimate before trying to use it, eliminating a whole class of spurious terminal errors.

### v1.19.1 (Oct 15) — Clean Break from Session Sharing

### Session Sharing Discontinued

- Existing share links and session-sharing commands are no longer available
- Importing sessions from share URLs is unsupported
- This removes a deprecated feature that was causing confusion and maintenance burden

**Why this matters:** Session sharing was a half-baked experiment. Removing it cleanly means the codebase is simpler and the team can focus on core agent capabilities. If you were using it, export your sessions manually before upgrading.

---

### v1.19.2 (Oct 16) — 1.x Update Isolation (Critical for Stability)

This is the **most important patch for anyone staying on 1.x**.

**OpenCode 1 now stays on the 1.x release line:**
- Update checks use only the npm `opencode-ai` latest version
- 1.x installs are **never offered a 2.x build** as a regular update
- Upgrading to OpenCode 2 remains a separate, explicit choice through the 2.0 offer in `/update` or `opencode upgrade --major`

**Additional fixes:**
- Fix upgrades for installs managed by yarn
- Skip 1.x updates for Homebrew Core installs (which now track OpenCode 2)
- Check tap and Chocolatey availability before offering an update
- The install script refuses to install 2.x versions

**Why this matters:** Before this patch, a `brew upgrade` or `npm update` could silently jump you to OpenCode 2 with breaking changes. Now **you choose when to migrate** — not your package manager.

---

### v1.19.3 (Oct 16) — Model Reasoning Controls

### Configure Model Reasoning Variants

- Configure model reasoning options to generate reasoning variants
- Replaces catalog variants while preserving your configured variant overrides
- Gives you fine-grained control over how models "think" without losing your custom settings

**Why this matters:** Different coding tasks need different reasoning depths. A quick bug fix needs minimal reasoning; a complex architecture decision needs deep thinking. Now you can configure this per-model, per-task, without the catalog overriding your choices.

## How to Upgrade

```bash
# To v1.19.3 (safe, patch-level — RECOMMENDED for 1.x users)
npm update -g opencode
# or
brew upgrade opencode
# or
opencode upgrade  # from within TUI via /update

# To OpenCode 2 (major migration — when ready)
opencode upgrade --major
```

**Verify:**
```bash
opencode --version
# Should show 1.19.3 (or 2.x.x after --major)
```
