Goose shipped **two releases in one week** — v1.53 (October 2) and v1.54 (October 8) — and they quietly solved problems beginners didn't even know they had. The headline features: **HTML session export with an interactive viewer** and **adaptive thinking for Claude Sonnet/Haiku 5.5**. But the wave behind them is what matters for your daily workflow.

Here's what changed, what it means for beginners, and why this is the release cycle to pay attention to.

---

## 1. HTML Session Export — Your Sessions, Finally Portable

v1.53 added **HTML session export with an interactive viewer** (#11977). This is bigger than it sounds.

**What it does:** Export any Goose session to a standalone `.html` file. Open it in any browser — no Goose installed, no server, no dependencies. The viewer lets you:
- Browse the full conversation history
- See tool calls, outputs, and thinking blocks
- Filter by turn, tool, or model
- Search across the entire session

**Why beginners care:** You can finally share a debugging session with a teammate, save a reference implementation for later, or hand off context to someone who doesn't use Goose. No more screenshots. No more "run this agent to see what I did." One file, works everywhere.

**How to use it:**
```bash
goose session export --format html --output my-session.html
# Or from the CLI session menu
```

---

## 2. Adaptive Thinking for Claude 5.5 — The Model Decides How Hard to Think

v1.54 added **adaptive thinking for Claude Sonnet 5.5 and Haiku 5.5** (#12761).

**What it does:** Instead of you picking "low/medium/high" reasoning effort, the model now **decides per-turn** how much thinking to allocate based on task complexity. Simple edits get fast responses. Complex architectural decisions get deep reasoning. Automatically.

**Why beginners care:** You stop managing the model's brain. The "right" thinking depth becomes the model's problem, not yours. This is the direction all frontier models are heading — reasoning as a dynamic capability, not a static slider.

**Also in v1.54:** `GOOSE_CLI_SHOW_THINKING` now shows thinking blocks for *any* truthy value (not just specific ones). Set it once, see reasoning everywhere.

---

## 3. Model Discovery from models.dev — Always Current, Never Stale

v1.53 added **live model metadata fetching from models.dev with a bundled fallback** (#12560).

**What it does:** Goose now pulls the latest model catalog (pricing, context windows, capabilities) from [models.dev](https://models.dev) at runtime. If the network fails, it falls back to a bundled snapshot. Your model picker is never outdated.

**Why beginners care:** New models drop weekly. With Goose, you see them in the picker *the same day* — no waiting for a Goose release. The catalog includes Opus 5.5, GPT-6 Sol, GPT-6 Luna, and every other frontier model as they launch.

---

## 4. Meta Muse Code Provider — A New Free Coding Model Family

v1.53 added the **Meta Muse Code provider** (#11765).

**What it is:** Meta's new coding-specific model family (Spark 1.1, Glimmer 30B) — free, open-weight, and surprisingly good at code. Goose now has a native provider for them.

**Why beginners care:** More free options. If you're cost-conscious or offline-first, Meta Muse joins the local/Ollama tier as a credible coding model you can run without API keys.

---

## 5. Lean ACP-Only Binary — For When You Don't Need the Kitchen Sink

v1.53 introduced a **lean ACP-only Goose binary** (#11961).

**What it is:** A stripped-down Goose build that *only* speaks the Agent Client Protocol (ACP). No TUI, no Desktop, no built-in providers — just the protocol layer for embedding in other tools.

**Why it matters:** If you're building an IDE plugin, a CI bot, or a custom frontend on top of Goose, this binary is ~60% smaller and starts faster. It's Goose as a library, not an app.

---

## 6. Resizable PiP for MCP Apps — Desktop Quality of Life

v1.53 added a **resizable Picture-in-Picture window for MCP Apps** (#12417).

**What it does:** When an MCP app (like a browser, database UI, or design tool) opens in Goose Desktop, it now floats in a resizable, draggable PiP window instead of taking over the sidebar.

**Why beginners care:** You can keep the MCP app visible *while* chatting with Goose. Reference the browser, query the database, tweak the Figma — all without context switching.

---

## 7. Session Rename in CLI — Finally

v1.53 added a **session rename command in the CLI** (#12236).

```bash
goose session rename <old-name> <new-name>
```

**Why it matters:** Sessions used to be stuck with auto-generated names. Now you can organize them like files. "debug-auth-flow" beats "session-20261008-143022" every time.

---

## 8. Working Directory in Session Remove — No More Guessing

v1.53 shows the **working directory in the session remove command** (#12232).

```bash
goose session remove
# Now shows: "my-project (~/code/my-project)" instead of just "my-project"
```

Tiny fix. Saves you from deleting the wrong session when you have multiple projects with similar names.

---

## 9. GPT-6.1 Sol Effort Aliases — Hyphens Now Work

v1.54 supports **hyphenated GPT 6.1 Sol effort aliases** (#12689).

```bash
# These now all work:
goose --model gpt-6.1-sol-high
goose --model gpt-6.1-sol-medium
goose --model gpt-6.1-sol-low
# Previously only underscores worked
```

---

## 10. System Node.js in Windows npx Wrapper — Fewer "Command Not Found" Errors

v1.54 uses the **system Node.js in the Windows npx wrapper** (#12176).

**What it fixes:** On Windows, `npx goose` now uses your installed Node.js instead of bundling its own. Fixes version mismatches, PATH issues, and the dreaded "node not found" when Goose tries to spawn subprocesses.

## What This Means for You

**If you're new to coding agents:** Goose v1.53+v1.54 makes the "try it once" experience genuinely smooth. HTML export means you can show someone what the agent did without them installing anything. Adaptive thinking means you don't need to learn prompt engineering for reasoning depth. Model discovery means the newest models just appear.

**If you're evaluating agents:** This wave reinforces Goose's thesis — **provider-neutral, protocol-first, embeddable.** The ACP-only binary proves it: Goose isn't just a CLI, it's a runtime you can build on. Claude Code is Anthropic-first. Codex is OpenAI-first. Goose is *every-model, every-interface, every-embedding*.

**One caution:** The adaptive thinking feature is Claude 5.5 only (for now). If you're on other models, reasoning effort still works the old way. And the HTML export is CLI-only for now — Desktop export comes next.
