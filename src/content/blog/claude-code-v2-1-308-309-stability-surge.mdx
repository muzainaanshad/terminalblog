## The Fixes You'll Actually Feel

### Sandbox Escapes Finally Plugged

- **Bash startup files**: Sandboxed commands on macOS/Linux were running shell startup files *outside* the sandbox before each command. Fixed.
- **Symlink `denyWrite` bypass**: macOS sandbox glob patterns didn't apply at a path's real location when reached through a symlink. Fixed.
- **MCP config modification**: Auto-accepted edits and sandboxed commands could modify the MCP config file passed with `--mcp-config`. Fixed.
- **Profile store symlink bypass**: Write protection didn't apply when config directory reached through symlink. Fixed.
- **Background command write-deny lift**: Linux sandbox write denies lifted when background command outlived session. Fixed.

**Translation**: The sandbox is actually a sandbox now. Not "mostly a sandbox with creative workarounds."

### The Dangerous `rm`/`rmdir` Prompt — Fixed

In bypass-permissions mode (Desktop app and VS Code), the dangerous `rm` and `rmdir` prompt now **denies the command at once with a rewrite hint** instead of prompting. Unattended sessions keep going instead of hanging on a delete confirmation.

This is the kind of fix that prevents "I came back and my agent deleted the wrong folder" stories.

### HTTP MCP Double-Call Fix (From v2.1.307, Reinforced)

When an HTTP MCP connection dropped mid-call, write tools were sent **twice**. Double file writes, double API calls, double charges. v2.1.307 limited retries to read-only/idempotent tools. v2.1.309 reinforces: write-type tools that lose connection **fail instead of retrying**. Handle the failure explicitly in your MCP servers.

### PowerShell Hooks — No More Silent Fail-Open

`PreToolUse` and `PermissionRequest` hooks with `"shell": "powershell"` were **failing open when Git for Windows isn't installed**. Now they block properly (exit code 2 respected). If you run hooks on Windows, verify Git for Windows is present or they'll silently approve everything.

### Git Performance on Windows — Actually Fast Now

"Improved the speed of many git commands Claude Code runs for itself on Windows; on every platform, errors from those commands now show in English even when git is set to another language."

If you've watched Claude Code sit on `git status` for 30 seconds on Windows — this is for you.

### VS Code Extension — The Quality-of-Life Wave

- **Blank panel recovery**: Cached incomplete files no longer leave the Claude panel blank — it recovers or tells you what went wrong
- **Empty session spam**: "Untitled" sessions no longer fill history when starting without sending a message
- **Long message folding**: Slash commands like `/goal` now fold behind "Show more" like other prompts
- **Edit/Write speed**: Wait for new problems after each edit dropped from 1–1.5s to **0.75s in most cases**
- **Ctrl+J behavior**: No longer always inserts newline — respects keybindings.json
- **Plugin label overlap**: "From the … plugin" label no longer draws over slash command/@-mention menus

### Model Alias `[1m]` — No More Cryptic Errors

Using `opus[1m]` or similar aliases with `CLAUDE_CODE_DISABLE_1M_CONTEXT` no longer causes "model not found" errors. The alias resolves correctly.

### MCP Server "Needs Authentication" — No More Mystery

When macOS keychain is locked, MCP servers now show **"needs authentication"** reason instead of generic failure. Unlock keychain, next run reconnects.

### MCP Servers Don't Stay "Failed" After Sleep/Wake

Headless runs recover cleanly. No more manual restarts after laptop sleep.

### `/clear` Conversations Stay Cleared

Cloud/self-hosted restarts no longer resurrect cleared conversations. Your context actually stays cleared.

### Subagent Transcripts — Real Token Usage + Stop Reasons

Cost tracking and debugging actually work now. You get real numbers, not estimates.

### Self-Hosted Runner Checkout Hooks — 30 Min Timeout

Default 30 min (SIGTERM → SIGKILL). If your repo fetch takes longer:

```bash
claude self-hosted-runner --checkout-hook-timeout-min 60
```

Or `0` for no limit.

### `axScreenReader` Settings Location Changed (Breaking)

Since v2.1.305, `axScreenReader` and `CLAUDE_AX_SCREEN_READER` in `settings.env` **only apply from**:
- User settings (`~/.claude/settings.json`)
- Managed settings
- `--settings` flag

**Project settings (`.claude/settings.json`) and local settings (`.claude/settings.local.json`) are ignored.** Move your accessibility config or it stops working.

## v2.1.310 (Oct 23): Monitor Tool + Gateway + Compaction + Enterprise

### New: Monitor Tool for Bedrock, Vertex, Foundry

The **Monitor tool** is now available on Anthropic Bedrock, Google Vertex AI, and AWS Foundry — and when telemetry or nonessential traffic is disabled. Long foreground sleeps are also blocked on those platforms now. This gives enterprise operators visibility into agent activity where they couldn't see it before.

### Gateway Compatibility Fixed

- Requests failing behind gateways/compatible servers that reject the `effort-2025-11-24` beta value or mid-conversation system messages now **retry automatically without them**.
- No more mysterious failures when your corporate proxy or gateway strips headers.

### Compaction Memory Fixes

- Fixed compaction after "Prompt is too long" errors keeping too much dense conversation (base64, SVG) — next request would fail again.
- Improved memory use of non-interactive sessions (`-p`, Agent SDK) during compaction with very large transcript files.

### Background Cleanup Fix

- Fixed background cleanup deleting recent files (like pasted images) when `cleanupPeriodDays` is set to a very large value.

### Windows: Hook Reliability

- Fixed `PreToolUse` and `PermissionRequest` hooks letting a tool call through when Git Bash is missing and the hook's command is only quoted strings (e.g., a quoted path).

### Auto Mode Prompt Improvement

- Auto mode's prompt before the first read outside working directories now **says when blocking those reads makes shell commands ask for permission** — clearer context for the user.

### VS Code Fixes

- Fixed pressing Enter on the plan review card's "Send feedback and keep planning" button approving the plan instead of sending comments back.
- Fixed panel showing "Something went wrong" after "Switch branch & continue" on a cloud session opened from Session history's Web tab.

### Cloud Sessions: Enterprise Controls

- Cloud sessions and Remote Control permissions added to **Enterprise custom roles** — Owners can control access by role.
- Choose file button to load cloud environment's setup script from a file.
- Failed saves/archives in cloud environment edit dialog now show errors inside the dialog.
- Failed routine API token actions show error in the routine edit dialog (not just a toast).
- Session start checklist shows cloud environment's setup script output in a scrolling box.
- Turning on Cloud sessions or Remote Control in admin settings now asks for confirmation and lists custom roles with that permission.
- Cloud environment dialog opens network access, setup script, and env vars from rows instead of listing every editor at once.

### Claude Tag Fixes

- Fixed treating `!` commands (`!restart`, `!help`) as ordinary messages when sent in bold/italic/strikethrough.
- Fixed admin channel/workspace pages replaced by load error when background bundle list refresh fails.
- Fixed spend limits page reporting "no channels match filter" while channel names still loading.

### Code Review Fixes

- Fixed admin section hiding repositories/switches after failed repository list refresh.
- Improved admin section to retry first load and show one "Try again" banner when it still fails.

## Breaking Changes Checklist

1. **`axScreenReader`**: Move from project/local settings → user/managed/`--settings`
2. **Self-hosted checkout hooks**: Increase timeout if >30 min needed
3. **HTTP MCP write tools**: Handle connection-drop failures explicitly (no auto-retry)
4. **API 2026-10-21** (from v2.1.307): Remove `temperature`/`top_p`/`top_k` from Messages API calls
