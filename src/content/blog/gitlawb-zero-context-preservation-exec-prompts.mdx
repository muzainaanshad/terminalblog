The most requested feature for Gitlawb Zero just landed: context preservation in exec prompts.

PR #460 is titled "fix: preserve conversation context in exec prompts" — but it's more than a fix. It's a fundamental upgrade to how Zero works.

## Before vs After

**Before:** You ask Zero a question, it answers. You ask a follow-up — it has no idea what you just said. Every interaction was stateless. This was by design — Zero's philosophy is minimalism. But it made multi-turn conversations impossible.

**After:** Zero now preserves conversation context across exec prompts. Ask a question, get an answer, ask a follow-up, and Zero connects the dots. The session persists in memory, carrying the conversation thread forward.

## Why This Matters

This is the feature that transforms Zero from "a CLI that answers questions" to "an AI assistant that holds conversations." It's the same transition that every coding agent goes through — and Zero just crossed that threshold.

For users, it means:
- No repeating context in every prompt
- Multi-step reasoning actually works
- Conversations feel natural instead of robotic
- Complex tasks can be broken into multiple prompts

## How It Works

Zero's session store now maintains conversation history between turns. Each exec prompt includes the relevant context from the previous exchange — not the full history (that would blow the context window), but enough to maintain coherence.

The implementation is intentionally lightweight. Zero doesn't have a memory system like Hermes's mem0 or a knowledge graph like pi.dev. But context preservation is the foundation that more advanced memory features will build on.

### Technical Implementation Details

Under the hood, Zero's session store (located at `~/.local/share/gitlawb-zero/sessions/`) now maintains a rolling conversation buffer per session. When you invoke `zero --exec "your prompt"`, the CLI:

1. Loads the session file for the current working directory (or creates one)
2. Extracts the last N conversation turns (default: 5, configurable via `context_window` in `~/.config/gitlawb-zero/config.json`)
3. Prepends the extracted context to your new prompt before sending to the model
4. Appends the new turn to the session after receiving the response

The context window is token-aware — Zero estimates token counts and trims older turns to stay within the model's context limit. This is critical for local models (Ollama, LM Studio) with smaller context windows (4k-8k tokens) versus cloud models (128k-200k).

```json
// ~/.config/gitlawb-zero/config.json
{
  "context_window": 5,
  "max_context_tokens": 4000,
  "session_persist": true
}
```

### Comparison: How Other Agents Handle Context

| Agent | Context Mechanism | Persistence | Cross-Session |
|-------|-------------------|-------------|---------------|
| **Gitlawb Zero** | Rolling buffer in session store | Local file (JSON) | ✅ Yes |
| **Claude Code** | Full conversation in context | In-memory only | ❌ No |
| **Codex** | Thread-based, cloud-synced | Cloud (OpenAI) | ✅ Yes |
| **Hermes** | mem0 semantic memory + session logs | Local (SQLite) | ✅ Yes |
| **OpenCode** | Session files + optional mem0 | Local file | ⚠️ Plugin |
| **Kilo** | Minimal (last turn only) | In-memory | ❌ No |

Zero's approach is distinct: it's the only fully local-first agent with persistent cross-session context that doesn't require a cloud account or external memory service. The session files are portable — copy `~/.local/share/gitlawb-zero/` to another machine and your conversation history travels with you.

## Practical Examples

### Multi-Step Refactoring

```bash
# Step 1: Understand the codebase
zero --exec "Analyze the authentication module in src/auth/ and explain the token refresh flow"

# Step 2: Plan the change (context preserved)
zero --exec "Now propose a refactor to extract the refresh logic into a reusable service"

# Step 3: Implement (context preserved)
zero --exec "Implement the AuthTokenService class with the interface we discussed"
```

Each step builds on the previous one without you copying context manually.

### Debugging Across Turns

```bash
# First encounter the bug
zero --exec "Why is the WebSocket connection dropping after 30 seconds in production?"

# Follow up with logs
zero --exec "Here are the server logs from the last incident: [paste logs]. What pattern do you see?"

# Get a fix
zero --exec "Implement the fix you suggested and write a test for it"
```

## What's Next

With context preservation in place, Zero can now support multi-turn workflows, gradual task decomposition, and actual conversations. The decentralized coding agent just became a lot more useful.

The roadmap includes:
- **Cross-session messaging** (merged to main August 2026) — live Zero sessions discover each other and exchange messages under an explicit accept/hold/refuse inbound policy
- **Persistent session goals** — tell Zero "always keep dependencies pinned" and it stays active across sessions
- **Summarization for long sessions** — automatic summarization when context window pressure builds
