Claude Code v2.1.294 dropped today — October 8, 2026. The release notes are two bullet points, but the second one is a **security fix you need to understand**.

## The Vulnerability (Plain English)

You know how you can write hooks like this?

```json
{
  "hooks": {
    "Prompt": "Block commands that delete files"
  }
}
```

**That hook was broken.** When written as natural language instructions ("Block commands that..."), the hook **allowed what it was supposed to block**.

The model would read "Block commands that delete files" and... not block them. It treated the instruction as a suggestion, not a rule.

## What Are Hooks? (Beginner Primer)

If you're new to Claude Code: **hooks are your safety net.** They're plain-English rules you write in your settings that Claude follows *before* it runs any command.

Think of them as guardrails:

- `"Block commands that modify production databases"`
- `"Ask before running git push --force"`
- `"Deny any command containing 'rm -rf'"`
- `"Carry on if the build is broken — don't stop on red tests"`

Before v2.1.294, hooks written this way (as natural language instructions) were **advisory, not enforced**. The model "knew" what you wanted but didn't treat it as a hard constraint.

## What v2.1.294 Fixes

1. **Fixed `prompt` and `agent` hooks written as instructions** — they now actually block what you tell them to block
2. **Improved how `prompt` hooks on Stop and SubagentStop are judged** — when written as instructions like "Carry on if the build is broken," Claude is less likely to stop early

## Why This Matters for Beginners

**This bug meant your safety net had holes.** The agent could ignore your "block" instructions because it misunderstood them as polite requests.

Real-world example: You write `"Block any deployment command on Friday"`. Before this fix, Claude might deploy anyway because it read your instruction as "hey, FYI, maybe don't deploy on Fridays." After the fix, it treats it as a hard rule: *Friday deployment = blocked.*

## How Hooks Actually Work Now

Hooks run at specific points in the agent lifecycle:

| Hook Type | When It Fires |
|-----------|---------------|
| `Prompt` | Before every user prompt / model turn |
| `PreToolUse` | Before any tool executes |
| `PostToolUse` | After any tool completes |
| `Stop` | When the agent wants to stop |
| `SubagentStop` | When a subagent wants to stop |

You can write them as **instructions** (natural language) or **structured rules** (JSON with matchers). v2.1.294 makes the instruction form reliable.

## Verify the Fix Works

After updating, test a simple hook:

```json
{
  "hooks": {
    "Prompt": "Block any command containing 'rm -rf'"
  }
}
```

Try asking Claude to run `rm -rf /tmp/test`. It should now refuse with a clear message.

Test a Stop hook:

```json
{
  "hooks": {
    "Stop": "Carry on if the build is broken — don't stop on red tests"
  }
}
```

Run a failing build. Claude should continue instead of stopping.
