**AmpCode announced "Spaces" today (November 6, 2026)** — and it's the feature that finally makes agent teams feel like *teams*, not a pile of disconnected threads. Spaces are a **new, higher-level way to work with many agents and teammates**. One workspace. Multiple Orbs. Shared context. Unified monitoring. Zero context switching.

If you've ever juggled five Orb tabs, lost track of which agent was doing what, or wished your team could see the same agent work — Spaces is the answer.

## The One-Line Summary

**Spaces = shared workspaces for agent teams. Multiple Orbs, multiple humans, one persistent context, unified view. The "Slack for agents" moment.**

## What Are Spaces?

Think of a Space as a **team workspace for agents**. Instead of each person running their own Orbs in isolation:

- **Multiple Orbs** live in one Space — backend, frontend, infra, QA, docs
- **Multiple teammates** join the Space — everyone sees the same agents, same threads
- **Persistent context** — AGENTS.md, secrets, MCP servers, environment shared across all Orbs
- **Unified monitoring** — one dashboard shows every agent's status, logs, progress
- **Shared resources** — one GitLab/GitHub connection, one cloud credentials, one portal fleet

```bash
# Before Spaces (today)
# You: 3 Orb tabs open
# Teammate: 2 different Orb tabs
# No shared context, no shared view, copy-paste coordination

# After Spaces (now)
# Team creates "backend-api" Space
# Adds 4 Orbs: api, worker, migration, test
# Everyone joins → sees everything → coordinates in real-time
```

## Why This Changes Everything

### The Old Way: Agent Isolation Hell

1. You spin up Orb for backend → teammate spins up Orb for frontend
2. You both configure AGENTS.md separately → drift happens
3. You share secrets via Slack → security nightmare
4. You monitor agents by switching tabs → context switching hell
5. Teammate asks "what's the backend agent doing?" → you screenshot → they guess
6. Handoff = "here's a thread URL, good luck"

### The New Way: Shared Agent Workspace

1. **Create Space** → name it → invite team
2. **Add Orbs** → each with its role (api, worker, migration, test)
3. **Shared config once** → AGENTS.md, secrets, MCP, GitLab, cloud creds
4. **Everyone sees everything** → real-time agent status, logs, portals
5. **Handoff = @mention in Space** → "backend agent needs review on PR #42"
6. **History persists** → new team member joins → sees full agent history

## Core Space Features (What You Get)

### 1. Multiple Orbs, One Space

| Orb Role | What It Does | Shared With Team |
|----------|--------------|------------------|
| **api** | Main backend service | ✅ Code, logs, portals |
| **worker** | Background jobs | ✅ Queue monitoring |
| **migration** | DB schema changes | ✅ Migration status |
| **test** | CI/CD pipeline | ✅ Test results |
| **docs** | Documentation agent | ✅ Live preview |

Each Orb keeps its own working directory, but **shares the Space's context**.

### 2. Shared Context (Configure Once)

```yaml
# Space-level config (one time setup)
space:
  name: "backend-api"
  agents_md: ".amp/AGENTS.md"          # Shared across ALL Orbs
  secrets:                             # Shared secrets
    - DATABASE_URL
    - REDIS_URL
    - AWS_ACCESS_KEY
  mcp_servers:                         # Shared MCP
    - github
    - slack
    - datadog
  git:                                 # Shared Git
    provider: gitlab
    project: "team/backend-api"
  cloud:                               # Shared cloud
    provider: gcp
    project: "prod-backend"
```

**Add a secret once → every Orb in the Space has it.** Update AGENTS.md once → every agent follows new conventions.

### 3. Team Membership & Roles

| Role | Can Do |
|------|--------|
| **Owner** | Create/delete Space, manage members, all permissions |
| **Admin** | Add/remove Orbs, manage integrations, approve production access |
| **Member** | Start/stop Orbs, view portals, comment on threads, request reviews |
| **Viewer** | Read-only: view portals, threads, logs |

### 4. Unified Monitoring Dashboard

One view shows **every Orb in the Space**:

```
┌─────────────────────────────────────────────────────────────┐
│ Space: backend-api                    [🟢 4 active Orbs]   │
├──────────────┬──────────────┬──────────────┬──────────────┤
│     api      │    worker    │  migration   │     test     │
│   🟢 running │   🟡 idle    │   🔴 failed  │   🟢 passing │
│  PR #42 open │  queue: 3    │  rollback?   │  247/250 OK  │
│  [Portal]    │  [Logs]      │  [Portal]    │  [Portal]    │
└──────────────┴──────────────┴──────────────┴──────────────┘
```

Click any Orb → instant portal, logs, thread history. No tab switching.

### 5. Cross-Orb Coordination

**Orbs in a Space can talk to each other:**

```bash
# In api Orb thread:
> "Hey migration Orb, run the new schema migration on staging"
# → Creates task in migration Orb → migration Orb executes → reports back

# In test Orb thread:
> "API Orb just deployed PR #42 to staging, run integration tests"
# → Test Orb pulls latest staging → runs tests → posts results in Space
```

This is **agent-to-agent coordination** mediated by the Space — not copy-paste.

## Real Team Workflows

### Workflow 1: Feature Branch → Production

```
1. Dev creates feature branch locally
2. Dev: "Space, spin up review Orb for PR #42"
3. Space creates review Orb → clones PR → runs tests → posts results
4. Dev shares Space link with reviewer → reviewer sees live portal
5. Reviewer: "Looks good, Space promote to staging"
6. Space triggers migration Orb → runs migration → api Orb deploys
7. Test Orb runs smoke tests → posts ✅ in Space
8. Dev: "Space promote to production"
9. Space coordinates: migration → api → test → done
10. Whole team sees: "PR #42 live in production" in Space feed
```

### Workflow 2: Incident Response

```
1. Alert fires: "API latency p99 > 2s"
2. On-call: "Space, spin up debug Orb for production"
3. Debug Orb gets production read access (approved by admin)
4. Debug Orb: runs queries, checks logs, profiles CPU
5. Debug Orb posts findings in Space: "GC pressure in worker pool"
6. On-call: "Space, spin up fix Orb with worker pool tuning"
7. Fix Orb: makes change, deploys to canary, monitors
8. Fix Orb: "Latency normal, promoting to full fleet"
9. Space logs entire incident timeline — postmortem writes itself
```

### Workflow 3: Onboarding New Team Member

```
1. New dev joins → added to "backend-api" Space
2. New dev sees: all Orbs, all threads, all portals, full history
3. New dev: "Space, spin up sandbox Orb for me"
4. Sandbox Orb: clones repo, installs deps, runs dev server
5. New dev codes in portal → sees live app → asks agents questions
6. No "here's the setup doc" — the Space IS the setup
```

## How to Get Started

```bash
# 1. Create a Space (web UI or CLI)
amp space create backend-api --team my-team

# 2. Add Orbs to the Space
amp space orb add backend-api api --role backend
amp space orb add backend-api worker --role worker
amp space orb add backend-api migration --role migration
amp space orb add backend-api test --role test

# 3. Configure shared context (one time)
amp space config backend-api \
  --agents-md .amp/AGENTS.md \
  --secret DATABASE_URL \
  --secret REDIS_URL \
  --mcp github \
  --mcp slack \
  --git gitlab:team/backend-api

# 4. Invite team
amp space invite backend-api @teammate1 @teammate2 --role member

# 5. Team joins
amp space join backend-api
# Now they see all Orbs, portals, threads, shared config
```
