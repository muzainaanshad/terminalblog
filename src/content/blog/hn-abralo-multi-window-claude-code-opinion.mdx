Earlier this week, someone posted **Abralo** on Hacker News — a tool that lets you run several Claude Code agents in a single window. It got 27 points and 19 comments. Not viral, but the discussion tells you everything about where coding agents are today.

## What Abralo Does

The creator explained it well:

> "I've been using Claude Code for almost everything lately. I tend to have a few Claude Code agents running at any one time for coding. I used to create a split terminal to manage them, but found working in the terminal all day pretty depressing."

The tool gives you a web-based panel. Each Claude Code agent gets its own view. You can see what each agent is doing without juggling terminal tabs.

Simple premise. But the comments reveal a deeper divide in how developers think about agents.

## The Two Camps in the Comments

**Camp 1: "Just use tmux"** — A few commenters pointed out that tmux + split panes already solves this. You can run multiple Claude Code instances in your terminal today. Why a web UI?

**Camp 2: "Web UI is the right call"** — Others argued that tmux is fine for developers who live in the terminal, but coding agents are increasingly used by non-terminal-native developers. A web UI lowers the barrier.

Both camps are right. And both camps are wrong.

## What Everyone's Missing

The Abralo thread assumes the hard part is *displaying* multiple agents. It's not. The hard part is *orchestrating* them.

Running two Claude Code agents side-by-side is easy. Getting them to work on the same codebase without conflicting, sharing context, or stepping on each other's changes — that's the unsolved problem. No amount of window management fixes that.

This is exactly where Hermes Agent's MOA (Mixture of Agents) system and subagent architecture is ahead of the curve. Hermes doesn't just let you see multiple agents — it lets you delegate tasks TO subagents and get back results. The display problem is solved. The orchestration problem is what matters.

## The Honest Take

Abralo is well-built. If you're managing 3-4 Claude Code sessions and tmux feels clunky, try it.

But if you're running enough agents that you need a window manager for them, you've already outgrown single-agent tools. You need something with subagent support, not a prettier terminal.

The real signal from this HN thread isn't "there's demand for a multi-window Claude Code manager." It's "people are hitting the limits of single-agent workflows and looking for the next thing."

That next thing isn't a window manager. It's multi-agent orchestration — and Hermes, Codex, and Devin are the ones building it.
