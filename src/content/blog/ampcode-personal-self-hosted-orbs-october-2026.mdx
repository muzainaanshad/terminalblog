## The One-Line Summary

**Run Amp orbs on your laptop, server, or cloud account. One command connects your infra. Amp sends spawn/pause/delete events; your script handles the rest. Free for individuals and teams. No admin approval needed.**

## The 5-Minute Setup (Docker on Your Machine)

```bash
# 1. Create a workspace at ampcode.com (free)
# 2. Settings → Custom Orb Provider → Create → Copy token
#    (This is in YOUR personal settings, not workspace admin)

# 3. Save this as dispatch.sh
cat > dispatch.sh << 'EOF'
#!/usr/bin/env bash
set -euo pipefail
case "$ORB_OPERATION" in
    spawn)
        docker start "$ORB_ID" 2>/dev/null || \
            docker run --platform linux/amd64 -d --name "$ORB_ID" \
                "$ORB_IMAGE" sleep infinity
        docker exec -d --env ORB_TOKEN "$ORB_ID" amp orb bootstrap
        ;;
    pause)
        docker stop "$ORB_ID"
        ;;
    delete)
        docker rm -f "$ORB_ID"
        ;;
esac
EOF
chmod +x dispatch.sh

# 4. Run the provider (keeps running in terminal)
export AMP_ORB_PROVIDER_TOKEN="<your-token>"
amp orb provider ./dispatch.sh

# 5. New thread → Orb → Self-Hosted → your provider → prompt
```

That's it. Your laptop is now an Amp compute node.

## What Your `dispatch.sh` Receives

Amp passes four environment variables:

| Variable | Description |
|----------|-------------|
| `ORB_OPERATION` | `spawn` / `pause` / `delete` |
| `ORB_ID` | Unique orb identifier |
| `ORB_TOKEN` | Auth token for the orb to call back to Amp |
| `ORB_IMAGE` | Amp's pre-built orb image (or your custom one) |

Your script decides **HOW** to spawn/pause/delete. Docker? Kubernetes? Modal? Vercel? Daytona? E2B? Apple Containers? exe.dev? Amp ships example scripts for all of them.

## Supported Infrastructure (Copy-Paste Ready)

Amp provides ready-to-copy `dispatch.sh` examples for:

| Platform | Best For |
|----------|----------|
| **Docker** | Laptop, single server, simple start |
| **Kubernetes (GKE/EKS/AKS)** | Team clusters, auto-scaling, Helm chart included |

| **exe.dev** | Lightweight VMs over SSH |

**Bring your own image** if you need custom dependencies — just ensure `amp orb bootstrap` runs in it.

## Why This Matters for Beginners

### You Don't Need to Understand Kubernetes

The Docker example above runs on **any machine with Docker**. Your laptop. A $5 DigitalOcean droplet. A Raspberry Pi (ARM64 image available). No cluster required.

### Your Code Never Leaves Your Machine

When the orb spawns, it clones your repo *on your machine*. The agent runs *on your machine*. Amp's orchestrator only sends control events (`spawn`, `pause`, `delete`) over an outbound WebSocket. No inbound ports. No data egress.

### Free Forever for Individuals & Teams

> "We built self-hosted orbs for enterprises that *can't* use the orbs we host — regulations, internal networks, custom hardware. If you're on Enterprise, let us know and we'll help you set it up." — Amp team

**Translation:** If you're not Enterprise, this is free infrastructure orchestration. Forever.

## The Catch (Honest)

- **You need Docker (or K8s/Modal/etc.)** — not for total beginners
- **No managed SLAs** — Amp supports *their* end; your dispatch script is yours
- **Pause/resume needs snapshot-capable infra** — Docker stop/start works; K8s needs PVC; Modal/Vercel/Daytona/E2B have native snapshots
- **Enterprise support only for Enterprise plans** — community on Discord

| You Are... | Verdict |
|------------|---------|
