Your coding agent now fits in your pocket. Gitlawb Zero just added full Android support for Termux — the terminal emulator for Android.

## What Was the Problem

Zero ships as both an npm package (`@gitlawb/zero`) and a native binary for Linux, macOS, and Windows. On Android (via Termux), users could install the npm package, but the native binary detection didn't include Android as a supported platform. The fix: `fix: add android platform support for Termux npm install`.

## How It Works

On a phone with Termux installed:
```bash
npm install -g @gitlawb/zero
zero
```
That's it. Zero detects the Android environment, downloads the correct ARM64 binary, and runs.

## What You Can Do

The Android version of Zero has the same capabilities as the desktop version — minus features that require a desktop environment (like CDP browser automation):
- Full conversational TUI
- Multi-provider model support
- Durable local sessions
- Git operations
- File editing and code generation
- Sub-agent spawning

## Why This Matters

Mobile coding agents are about to become a thing. Developers increasingly work from tablets and phones, especially for:
- Code review on the go
- Quick fixes and deployments
- Monitoring and debugging
- Learning and exploration

Zero is among the few coding agents with explicit Android support. Hermes runs on Windows, macOS, and Linux but does not have a dedicated Android client. Claude Code runs on macOS and Linux. Oh My Pi does not currently advertise mobile support.

It's a niche feature today. But as developer workflows become more mobile, it's the kind of forward-looking investment that pays off. ## Real-World Usage Notes

### Termux Setup Prerequisites
```bash
pkg update && pkg upgrade
pkg install nodejs git
termux-setup-storage  # Optional: access shared storage
```

### Known Limitations (September 2026)
- **No CDP browser automation** — Playwright/Puppeteer require desktop Chrome
- **ARM64 only** — Older 32-bit Android devices not supported
- **Termux:API integration experimental** — Notification/sensor access not fully wired
- **Background execution** — Android battery optimization may kill long-running sessions; use `termux-wake-lock`

### Performance Profile
On a Snapdragon 8 Gen 2 device (Samsung S23 / Pixel 8 class):
- Cold start: ~3s (binary download + init)
- Warm start: ~800ms
- Memory: ~120MB base + model context
- Battery: ~8-10%/hr active use (similar to Termux + vim)

### Daily Workflow Tips

**Keep sessions alive:** Wrap long tasks with `termux-wake-lock` before starting Zero, and `termux-wake-unlock` after. This prevents Android from suspending the Termux process mid-session.

```bash
termux-wake-lock
zero
termux-wake-unlock
```

**Use SSH for comfort:** Pair Termux with a Bluetooth keyboard and connect to a remote dev machine via SSH. Zero runs locally on the phone but operates on your server — latency is near-zero on LAN.

```bash
# On phone: run Zero locally, point at remote repo via SSH
zero --ssh user@devbox:~/project
```

**Storage access:** After `termux-setup-storage`, your shared storage mounts at `~/storage/shared`. You can `cd ~/storage/shared/Download` and have Zero edit files there directly — useful for reviewing PR diffs downloaded from GitHub mobile.

**Offline-first sync:** Zero's durable sessions persist locally. Start a task on the train, close the app, resume at your desk. The session state (conversation, file edits, git status) survives process death because it's written to `~/.zero/sessions/` on every turn.

|-------|---------------|---------|-------|
| **Gitlawb Zero** | ✅ Native ARM64 | ❌ | Best mobile support |
| **Claude Code** | ❌ | ❌ | macOS/Linux only |
| **OpenCode** | ⚠️ Via npm (slow) | ❌ | No native binary |
| **Hermes** | ❌ | ❌ | Desktop only |
| **Aider** | ⚠️ Python-based | ⚠️ Via iSH | Heavy, no native binary |

Zero's native ARM64 binary is a genuine differentiator — most "mobile" agents are just Python scripts running in Termux, which is painfully slow for token-heavy workloads.
