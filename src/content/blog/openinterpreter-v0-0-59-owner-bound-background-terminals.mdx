## What Actually Changed: Background Terminal Infrastructure

### The Feature: Background Terminals That Don't Leak

**What it is:** The app server now supports **owner-bound, read-only background-terminal status** with:

1. **Owner binding** — background terminals are tied to their creating session. They cannot outlive their owner.
2. **Bounded metrics** — terminal metrics (CPU, memory, output size) are capped. No runaway resource consumption.
3. **Fail-closed thread ownership** — thread ownership defaults to secure. If ownership can't be established, the terminal doesn't start.
4. **Read-only status** — you can *see* background terminal state, not mutate it from outside.

**Why it matters:** Background agents are the difference between "toy" and "tool." You start a 30-minute refactor in the background, switch to another task, come back to results. But if background terminals leak, orphan, or eat resources — you stop trusting them.

This release makes background terminals **boring in the good way**: they start, they run, they report status, they die when their owner dies. No ghosts. No leaks. No surprises.

```bash
# What this enables (conceptually)
interpreter
> /background "refactor auth module to JWT"
# → spawns owner-bound background terminal
# → you see: "Background terminal #3: running (CPU: 12%, mem: 245MB)"
# → you keep coding in main session
# → background finishes → status: "completed"
# → you /background list → see results
```

## Why This Matters for Local-First Agents

### The Background Agent Problem

Cloud agents (Claude Code, Cursor, Codex) have managed infrastructure. Your background tasks run on their servers, their isolation, their billing.

**Local-first agents run on YOUR machine.** Every background terminal is:
- Your CPU
- Your RAM
- Your disk
- Your process table
- Your responsibility

If a background terminal:
- **Orphans** → zombie process eating resources
- **Leaks memory** → your machine slows down
- **Outlives its session** → security boundary crossed
- **Reports unbounded metrics** → monitoring useless

**You feel it immediately.** There's no cloud team to clean up.

### What 0.0.59 Fixes

| Problem | 0.0.59 Fix |
|---------|------------|
| Background terminal outlives parent session | **Owner binding** — terminal dies with owner |
| Runaway CPU/memory in background | **Bounded metrics** — capped, reported, controllable |
| Thread ownership ambiguity | **Fail-closed** — secure by default, explicit opt-in |
| External mutation of background state | **Read-only status** — observe, don't interfere |

This is **operational maturity**. The kind that lets you say "yeah, I run background agents locally" without crossing your fingers.
