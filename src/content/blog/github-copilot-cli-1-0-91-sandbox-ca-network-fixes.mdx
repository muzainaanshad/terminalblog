GitHub Copilot CLI **1.0.91** dropped October 1, and if you've ever fought with sandbox certificates, Windows network permissions, or wondered why your telemetry never sent — this is the release you've been waiting for.

The headline: **complete sandbox CA overhaul**, **Windows npm EACCES bypass**, **legacy Windows sandbox support**, and **guaranteed telemetry flush on exit**. No flashy models. Just the plumbing that makes daily terminal work *reliable*.

---

## 1. Sandbox CA Management — Finally a Real CLI

The old `/sandbox ca install` was a black box. You ran it, hoped it worked, and prayed when it didn't.

**1.0.91 replaces it with five explicit commands:**

| Command | What It Does |
|---------|--------------|
| `copilot sandbox ca check` | Verifies current CA trust status |
| `copilot sandbox ca create` | Generates a new proxy CA |
| `copilot sandbox ca trust` | Installs CA into system trust store |
| `copilot sandbox ca rotate` | Rotates CA (create + trust in one step) |
| `copilot sandbox ca remove` | Removes CA from trust store |

**Windows gets unattended setup** — `rotate` works non-interactively for automation/CI. No more manual certificate dialog clicks.

**Why this matters:** Sandboxed commands (running `gh`, `git`, `npm` inside Copilot's isolated environment) need a trusted CA to intercept HTTPS. If the CA isn't trusted, every outbound request fails with certificate errors. Now you can diagnose (`check`), fix (`rotate`), and clean up (`remove`) without guessing.

---

## 2. Windows npm EACCES — The Socket Denial Fix

You're in a sandboxed terminal. You run `npm install`. **EACCES: permission denied on socket.**

This happened because Windows sandbox denied raw socket creation for npm's internal communication. 1.0.91 adds a **network bypass option** specifically for this:

```bash
# Enable socket bypass for Node/npm in sandbox
copilot sandbox network bypass --enable
```

The bypass lets npm's internal sockets through while keeping the rest of the sandbox intact. It's targeted, not a "disable all security" switch.

---

## 3. Legacy Windows Sandbox Support (With a Warning)

Sandboxed commands now run on **Windows versions without filesystem enumeration support** (older LTSC builds, some Server editions).

**The catch:** PowerShell's current location (`Get-Location`) may report wrong paths in this mode. Copilot warns you upfront. If you're on modern Windows 10/11, you won't notice — but if you're on a locked-down enterprise build, sandbox finally *works* instead of hard-failing.

---

## 4. Clean Shutdown = Guaranteed Telemetry Flush

Ever kill Copilot CLI and wonder if your usage data sent? **1.0.91 flushes pending telemetry before exit** with a bounded delay during initialization.

No more lost sessions. No more "why isn't this showing in my dashboard?" The CLI waits (briefly) for the telemetry pipeline to drain, then exits cleanly.

---

## 5. Smarter Pipeline Execution Evidence Review

**Read-only, statically analyzable shell pipelines** (like `cat file | grep pattern | head -10`) can now enter **execution-evidence review** automatically — no explicit approval needed.

**Incomplete or unbound pipelines** (anything with variables, subshells, or dynamic commands) still require explicit approval. The line is clear: if Copilot can prove the pipeline is safe at parse time, it flows; if not, you approve.
