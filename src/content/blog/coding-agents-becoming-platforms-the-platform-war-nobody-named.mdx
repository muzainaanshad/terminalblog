In September 2025, the question was "which model completes code faster?"

In November 2026, the question is "which platform runs my agents?"

The shift happened quietly. No press release. No keynote. Just five consecutive months where every major coding agent — Cursor, AmpCode, Hermes, Zed, OpenCode, Goose, Kilo, pi.dev — shipped the **same five infrastructure layers**:

| Layer | What It Is | Who Shipped It |
|-------|------------|----------------|
| **Orchestration** | Multi-agent delegation, shared context, coordinator patterns | Cursor Projects, AmpCode Pucks, Hermes MOA, OpenCode subagents |
| **Shared Compute** | Runners/workspaces you spin up once, whole team connects | AmpCode Shared Runners, Cursor Self-Hosted Machines, Hermes Cloud, Zed remote projects |
| **Marketplace** | Plugin/app distribution with auth, webhooks, secrets management | Cursor Origin Marketplace, AmpCode Orb ecosystem, Hermes skill catalog, Zed extensions |
| **Remote Access** | See and steer agents from phone/tablet | Cursor iOS Remote Control, AmpCode mobile, Hermes Telegram/Slack |
| **Quality Gates** | Automated security review, deployment monitoring, policy enforcement | Cursor Rollouts/Security Review, AmpCode assignments, Hermes cron/gates |

They didn't coordinate. They **converged** — because the model layer commoditized, and the only moat left is the platform layer.

## The Convergence Is Measurable

**Cursor** (Oct 2026): Projects + Cloud Agents + Origin Marketplace + Remote Control + Rollouts + Security Review

**AmpCode** (Sep-Oct 2026): Shared Runners + Mac App as Runner + Multi-Puck + Self-Hosted Orbs + Android + Origin integrations

**Hermes** (Oct-Nov 2026): v0.22.0 Threshold Release → v0.22.6 (776 PRs) adding webapp on gateway, per-skill locks, prepared compaction, cron control, OS-keychain vault, group chat mentions

**Zed** (Oct 2026): v1.27.0-pre adding Go 1.27 syntax, AI commits from your history, 30% agent memory reduction, OpenCode compatibility

**OpenCode** (Oct 2026): v2.2.0 breaking changes → v2.2.5 adding worktree shortcuts, quote-send, percentage compaction, persistent terminals, artifacts, Claude Agent provider

**Goose** (Oct 2026): v1.56 automatic thinking + resume subagents + Windows NSIS installer → v1.57 HTTPS allowlist + caller-supplied session IDs + Linux icons

Every single one added **orchestration**, **shared compute**, **distribution**, **remote access**, and **quality gates** in the same quarter.

This isn't copying. It's **inevitable architecture** — the same way every cloud provider converged on compute/storage/network/identity.

## Why the Model War Ended

For two years, the marketing was:

> "Our model scores 89% on SWE-bench."
> "Our model handles 200K context."
> "Our model is 40% cheaper."

Then three things happened:

1. **OpenRouter / aiFiesta / LiteLLM** made model switching a config line, not a commitment
2. **Claude Opus 5.5, GPT-6 Sol, Sonnet 5.5, Haiku 5.5** all hit "good enough for 90% of coding tasks"
3. **Router patterns** (Cursor Dial, AmpCode Dial, Hermes multi-provider, OpenCode provider-neutral) made the model a **runtime decision**, not a platform choice

The model is now **infrastructure**. You don't pick an agent for its model. You pick a model for your agent.

## The Platform Layers (And What They Actually Do)

### 1. Orchestration: From "Agent" to "Agent Teams"

**Old model:** One agent, one thread, you babysit every turn.

**New model:** Coordinator agent plans → delegates to subagents → brings finished work back.

| Platform | Coordinator Pattern | Shared Context | Persistence |
|----------|---------------------|----------------|-------------|
| **Cursor Projects** | Coordinator agent in cloud | Syncs across cloud/local machines | Months of work |
| **AmpCode Pucks** | Multiple Pucks in parallel | Global skills across workspace | Cross-session |
| **Hermes MOA** | Mixture-of-Agents routing | Persistent memory via mem0 | Cross-profile |
| **OpenCode** | Subagents via Code Mode | Session snapshots | Per-session |
| **Zed** | Agent Panel with parallel agents | Thread history | Per-thread |

**The pattern:** You describe the **outcome**. The platform handles the **choreography**.

---

### 2. Shared Compute: "Your Laptop Is Not a Server"

**Old model:** Agent runs on your machine. Close laptop → agent dies.

**New model:** Spin up a runner once. Team connects. Threads persist.

```bash
# AmpCode
amp run --share              # Your Mac becomes team runner
amp connect <runner-url>     # Teammates connect

# Cursor
# Self-hosted machines: AWS Lambda, Coder, Cloudflare, Daytona, Modal, Vercel, E2B
# Team pools: named queues, auto-scale, hibernate idle

# Hermes
hermes cloud workspace create --profile=standard --repo=github.com/you/project
# Controlled from local CLI, runs on cloud infra
```

**The shift:** Compute became **shared infrastructure**, not personal tooling.

---

### 3. Marketplace: The Distribution Layer You Didn't Know You Needed

**Old model:** Copy-paste prompts. Share scripts. Hope they work.

**New model:** Install an app. It wakes on your events. Posts findings as PR comments.

| Marketplace | Apps | Auth | Events |
|-------------|------|------|--------|
| **Cursor Origin** | 20+ (Cloudflare, Vercel, Linear, Sentry, Semgrep, Socket, CodeRabbit...) | App JWT + installation tokens | GitHub PR/comment/CI, Slack, webhooks, cron |
| **AmpCode Orbs** | MCP servers, skills, plugins | Workspace-scoped | GitHub, Linear, Slack, custom |
| **Hermes Catalog** | 600+ plugins, skills, toolsets | Profile-scoped, `requires_hermes` enforced | Cron, webhooks, Telegram, Slack |
| **Zed Extensions** | Language servers, AI providers, tools | Per-extension | LSP, ACP agents |

**The kicker:** These marketplaces **are the agent SDKs**. Cursor Agent SDK agents deploy to Origin. AmpCode Orbs are deployed agents. Hermes skills are installable agents.

---

### 4. Remote Access: Agents in Your Pocket

**Old model:** You sit at your terminal. Agent runs there.

**New model:** Agent runs on your machine/remote. You steer from iOS/Android.

| Platform | Remote Access | What You See | What You Can Do |
|----------|---------------|--------------|-----------------|
| **Cursor** | iOS app (default on) | Local agent list, live activity | Send messages, approve/deny, keep computer awake |
| **AmpCode** | Mobile web + Slack | Threads, Orbs, Puck | Steer, review, approve |
| **Hermes** | Telegram/Slack + webapp | Sessions, cron, skills, memory | Trigger jobs, view logs, manage skills |
| **Zed** | Remote projects (SSH/WSL) | Full editor + agent panel | Code, run agents, debug |

**The pattern:** The agent doesn't move. **You connect to it.**

---

### 5. Quality Gates: The Last Mile of Shipping

**Old model:** Human reviews PR. Human watches deploy. Human catches security bugs.

**New model:** Bots do the last mile. Humans get signal.

| Bot | What It Does | Where It Runs |
|-----|--------------|---------------|
| **Cursor Rollouts** | Monitors deploy health per environment, writes PR comment plan, opens revert PRs | Teams/Enterprise |
| **Cursor Security Review** | Scans every PR for SQL/command/template injection, auth bypasses, secrets, SSRF, vulnerable deps | Teams/Enterprise |
| **AmpCode Assign** | Mention/assign issue to Amp in Linear → works it in a thread | All plans |
| **Hermes Cron/Gates** | Scheduled automation with missed-run policies, stop buttons, per-skill locks | All profiles |

**The shift:** Quality gates became **platform features**, not custom pipelines.

## What This Means for You (By Persona)

### If You're a Solo Dev

**Stop copy-pasting prompts.** Build one agent as code. Test it with evals. Deploy it. It works on every PR forever.

```bash
# Cursor
npx @cursor/agent-sdk init ./my-security-reviewer --template security-reviewer
cd my-security-reviewer
agent-sdk dev     # local playground
agent-sdk eval    # automated tests
agent-sdk deploy  # runs on every PR

# AmpCode
# Skills are global now — one skill follows you everywhere
amp --skill my-team-linter "review this PR"

# Hermes
# Cron jobs with missed-run policy + stop button
hermes cron add --missed-policy=run_immediately "security-scan" "scan for vulns"
```

Your "security reviewer" becomes **infrastructure**, not a chat session.

### If You're a Team Lead

**The platform choice is now the infrastructure choice.**

| Need | Platform That Leads |
|------|---------------------|
| **Multi-agent orchestration with shared context** | Cursor Projects |
| **Team compute on existing hardware (Macs, VMs)** | AmpCode Shared Runners |
| **Automation with cron, skills, Telegram ops** | Hermes |
| **Editor-first with parallel agents + memory discipline** | Zed |
| **Provider-neutral terminal agent you can embed** | OpenCode |
| **Security review on every PR without custom pipeline** | Cursor Security Review |
| **Deployment monitoring that opens revert PRs** | Cursor Rollouts |

**You don't need all of them.** You need the **one that matches your workflow** — and you need to stop evaluating on "which model is default."

---

### If You're Building Developer Tools

**The Agent SDK + Marketplace is your distribution channel.**

1. Build an agent as code (`instructions.md` + `tools/` + `skills/` + `evals/`)
2. Deploy it (`agent-sdk deploy` / `amp run --share` / `hermes skill publish`)
3. Publish to marketplace (Origin / AmpCode Orbs / Hermes Catalog)
4. Teams install it. Platform handles auth, webhooks, secrets, logging, evals.

**You build the logic. The platform handles the plumbing.**

## The Bottom Line

**The model war is over. The platform war is the only war left.**

- **Cursor** bet on: Editor + Cloud Agents + Marketplace + Quality Gates
- **AmpCode** bet on: Orbs + Shared Runners + Multi-Puck + Free Tier
- **Hermes** bet on: Local-first + Cron + Skills + Memory + Telegram Ops
- **Zed** bet on: Editor substrate + Parallel agents + Memory discipline + Language support
- **OpenCode** bet on: Provider-neutral + Skill-driven + Embeddable SDK

They all converged on the **same five layers** because that's what **running agents in production** actually requires.

**For you, the operator:** Pick the platform whose workflow matches yours. Write an `AGENTS.md`. Wire up the security basics. Build one agent as code. Deploy it. Let it run while you sleep.

**The agent wars aren't about completions anymore. They're about what happens after the code is written.**

Every major platform just built that layer. The war nobody named is already over — **the platforms won.**
