**What is a coding agent?** A coding agent is an AI-powered tool that can autonomously write, edit, and reason about code across multiple files in a codebase. Unlike simple autocomplete (GitHub Copilot), agents can execute terminal commands, navigate project structure, run tests, and complete multi-step tasks from a high-level prompt.

## The Real Decision: Control vs Convenience

The open vs commercial debate usually frames itself as "free vs paid" or "ideology vs pragmatism." For operators running agents on production code, the actual tradeoff is **who owns the failure domain when something breaks at 2 AM.**

| Dimension | Open Source (Hermes, OpenCode, Goose, Aider, OpenClaw) | Commercial (Claude Code, Cursor, Codex, Copilot CLI, AmpCode) |
|-----------|--------------------------------------------------------|--------------------------------------------------------------|
| **Sandbox isolation** | You configure it (Docker, firejail, VM, worktrees) | Built-in, vendor-managed, opaque |
| **Permission model** | You define allow/deny lists per agent | Vendor default + limited customization |
| **Model routing** | Multi-provider by design (any OpenAI-compatible) | Single vendor or limited partners |
| **Cron/automation** | First-class (Hermes, Goose) or DIY | Limited (Codex cloud, some CI) |
| **Cost predictability** | API keys you control; zero marginal license | Per-seat + token overages; can spike |
| **Support escalation** | Community / self-serve / paid consultants | Vendor SLA (if enterprise) |
| **Audit trail** | You build it (logs, hooks, CI gates) | Vendor provides (varies by tier) |
| **Escape hatch** | Fork, pin version, self-host | Vendor deprecation risk; data export varies |

## When Open Source Wins

### 1. You Need Multi-Provider Routing
If your workflow demands switching between Claude, GPT-4, Gemini, and local models (Ollama, vLLM) based on task type, open harnesses are the only ones architected for this. Hermes, OpenCode, and Goose all support provider-agnostic routing out of the box. Commercial tools lock you to their model partnerships.

### 2. Automation and Cron Are Core Workloads
Hermes has first-class cron jobs, background tasks, and bot-to-bot messaging. OpenCode can run headless via CLI. Goose supports MCP for tool chains. If you run nightly refactors, scheduled security scans, or automated PR reviews, commercial CLIs are not built for unattended fleets—they're interactive pair programmers.

### 3. Sandbox Requirements Are Non-Negotiable
Regulated environments, air-gapped networks, or strict data residency rules mean you must control the execution environment. With open source, you choose the isolation layer: Docker, gVisor, firejail, micro-VM, or dedicated hardware. Commercial tools run in their cloud or a black-box local sandbox you cannot audit.

### 4. Team Size Justifies the Setup Investment
The "free" in open source is free-as-in-puppy. You pay in:
- Initial sandbox/permission/config hardening (2-5 days for a team of 5)
- Ongoing model key management and rotation
- Custom audit logging and CI gates
- Internal documentation (your AGENTS.md)

For a solo dev, this overhead often exceeds a $20/month subscription. For a team of 10+, the per-seat savings compound fast.

### 5. You Need to Extend the Harness
Custom skills (Hermes), plugins (OpenCode), MCP servers (Goose), or AGENTS.md instructions that encode your team's specific patterns—open harnesses expose extension points commercial tools keep private.

## When Commercial Wins

### 1. Zero-Setup Velocity Matters Most
`npm i -g @anthropic-ai/claude-code` → auth → working in 90 seconds. Cursor: install extension → sign in → done. Copilot CLI: `gh extension install github/gh-copilot` → auth. If you need a working agent *today* without reading sandbox docs, commercial wins.

### 2. IDE Integration Is Non-Negotiable
Cursor's inline edits, repo-aware chat, and tab completion are battle-tested in VS Code. Copilot CLI lives in your terminal but shares context with the IDE extension. OpenCode has a VS Code extension but it's younger. If your team lives in the IDE 6 hours/day, the UX gap is real.

### 3. Enterprise Compliance Requires Vendor SLAs
SOC 2, HIPAA, FedRAMP, or vendor questionnaire requirements often demand a contract with a named entity. Open source has no vendor—you *are* the vendor. Some commercial tools (Cursor Enterprise, Copilot Enterprise, Claude Code Enterprise) offer the paperwork compliance teams need.

### 4. You Want Managed Sandbox Isolation
Claude Code's local sandbox, Codex's cloud VMs, Cursor's isolated workspaces—the vendor handles the hard problem of "run this untrusted code without it reading my SSH keys." Doing this correctly yourself takes security expertise most teams don't have in-house.

### 5. Token Economics Favor Bundled Pricing
Heavy users (6+ hours/day) on Claude Code Pro ($100/mo) or Cursor Pro ($20/mo but high token volume) often spend less than BYO-key open source at scale. The crossover depends on your actual token burn—measure it before deciding.

## Security: The Hidden Cost Center

**Open source shifts security left—you own it.**
- Session isolation: You configure Docker/gVisor/worktrees
- Permission prompts: You write the allow/deny lists
- Audit logs: You pipe stdout/stderr to your SIEM
- Kill switches: You build the timeout/circuit-breaker logic
- Credential hygiene: You inject only scoped, rotating tokens

**Commercial shifts security right—you trust the vendor.**
- Ask for: sandbox architecture doc, pen test results, data retention policy, subprocessor list
- Verify: Can you disable telemetry? Export full session logs? Run air-gapped?
- Test: Try to exfiltrate a file from the sandbox. Try to spawn a child process that escapes.

**Neither is "more secure" by default.** A misconfigured open-source agent with full filesystem access is worse than a commercial agent with a vetted sandbox. A commercial agent with a silent sandbox escape (see: [Claude Code subagent permission bypass](/blog/beware-claude-code-disallowedtools-not-inherited-by-subagents/)) is worse than a locked-down open-source setup.

## Escape Hatches: What Happens When the Vendor Changes Terms

| Scenario | Open Source Response | Commercial Response |
|----------|---------------------|---------------------|
| Model deprecation | Swap provider in config; same harness | Wait for vendor update or migrate |
| Price 5x increase | Switch API keys; same harness | Pay, reduce usage, or migrate |
| Feature removal | Fork/pin version; community maintains | Accept or migrate |
| Acquisition/shutdown | Code is yours; self-host indefinitely | Migration forced; data export varies |
| License change (rare) | Fork last permissive version | N/A (proprietary) |

**Practical test:** Can you run a full workday on a pinned version from 6 months ago without internet? Open source: yes. Commercial: usually no (auth, model endpoint, license checks).

## Decision Checklist

Before standardizing, answer these for your team:

1. **Primary workflow:** IDE (Cursor/Copilot) vs Terminal (Claude Code/OpenCode) vs Automation (Hermes/Goose)?
2. **Budget reality:** $0/mo (BYO keys only) vs $20-100/mo vs $200+/mo?
3. **Risk tolerance:** Vendor dependency OK? Data leaving your network OK? Audit requirements?
4. **Team size:** Solo (low setup budget) vs 5-10 (setup amortizes) vs 50+ (enterprise features)?
5. **Ecosystem:** GitHub-heavy (Copilot) vs GitLab/self-hosted (open) vs cloud-agnostic (open)?
6. **Model needs:** Single best model (Claude Code) vs multi-provider routing (Hermes/OpenCode) vs local models (Aider/Ollama)?

## Bottom Line

**Open source = you own the harness, you own the risk, you own the evolution.**
**Commercial = you rent the harness, the vendor owns the risk (mostly), the vendor controls the evolution.**

Most productive teams run a hybrid: commercial IDE agent for daily speed, open-source terminal agent for deep work and automation, and a pinned local model for experimentation. The "one agent to rule them all" search is a category error—the harness is commoditizing; the instructions you feed it (AGENTS.md, skills, MCP) are the differentiator.
