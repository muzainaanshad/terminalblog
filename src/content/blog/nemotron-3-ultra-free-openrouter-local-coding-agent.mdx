NVIDIA dropped Nemotron 3 Ultra — a 550B parameter model with 55B active parameters — on OpenRouter for free. No credit card. No rate limits that matter. Just `nvidia/nemotron-3-ultra:free` in your model picker and you're coding.

This is not a quantized shadow of the real model. It's the full MoE architecture that beats GPT-4 on coding benchmarks, served from NVIDIA's own infrastructure through OpenRouter's gateway. For developers who have been waiting for a frontier-class model without the frontier price tag, this is the moment.

## Why This Model Is Different

Nemotron 3 Ultra uses a Mixture-of-Experts architecture: 550B total parameters, but only 55B activate per token. That's the same approach DeepSeek V3 and Llama 4 use to deliver massive model quality at a fraction of the inference cost. NVIDIA trained it on 20 trillion tokens with a heavy emphasis on code, reasoning, and instruction following.

The benchmarks tell the story: it scores 92.1 on HumanEval, 89.4 on MBPP, and beats GPT-4 Turbo on LiveCodeBench. For a coding agent, that means it can handle multi-file refactors, write tests that actually pass, and reason through architectural decisions — not just autocomplete boilerplate.

## What "Free" Actually Means Here

OpenRouter's free tier for Nemotron 3 Ultra is not a trial. It's a permanent tier backed by NVIDIA's inference infrastructure. You get:

- **No API key required** — OpenRouter handles auth transparently
- **No billing setup** — zero dollars, ever
- **Reasonable rate limits** — enough for daily coding work, not enough to train a competitor
- **Full context window** — 128K tokens, not a crippled 4K version
- **Streaming support** — works with every coding agent that supports OpenRouter

The catch: you're sharing capacity. During peak hours, latency might climb from 200ms to 2-3 seconds per token. For coding agents that batch requests, this is barely noticeable. For interactive chat, you'll feel it.

## Wiring It Into Your Coding Agent

Every major coding agent supports OpenRouter. Here's the exact config for each.

### OpenCode

```json
{
  "providers": {
    "openrouter": {
      "baseURL": "https://openrouter.ai/api/v1",
      "apiKey": "your-openrouter-key",
      "models": {
        "default": "nvidia/nemotron-3-ultra:free"
      }
    }
  }
}
```

### Hermes Agent

```bash
hermes config set provider openrouter
hermes config set openrouter.base_url https://openrouter.ai/api/v1
hermes config set openrouter.model nvidia/nemotron-3-ultra:free
hermes config set openrouter.api_key your-openrouter-key
```

### Kilo Code CLI

```bash
kilocode config set provider openai-compatible
kilocode config set base_url https://openrouter.ai/api/v1
kilocode config set model nvidia/nemotron-3-ultra:free
kilocode config set api_key your-openrouter-key
```

### Goose

```yaml
provider:
  type: openai-compatible
  base_url: https://openrouter.ai/api/v1
  model: nvidia/nemotron-3-ultra:free
  api_key: your-openrouter-key
```

### Cline (VS Code / Desktop / CLI)

Open Settings → Models → Add Provider → OpenRouter. Paste your OpenRouter key. Select `nvidia/nemotron-3-ultra:free` from the model list. Done.

### Cursor

Cursor doesn't natively support OpenRouter, but you can use a proxy like [LiteLLM](https://github.com/BerriAI/litellm):

```bash
pip install litellm
litellm --model openrouter/nvidia/nemotron-3-ultra:free --port 4000
```

Then point Cursor to `http://localhost:4000` as a custom OpenAI-compatible endpoint.

### Codex CLI

Codex reads from `~/.codex/config.json`:

```json
{
  "model": "openrouter/nvidia/nemotron-3-ultra:free",
  "api_key": "your-openrouter-key",
  "base_url": "https://openrouter.ai/api/v1"
}
```

## The OpenRouter Key Question

"You said no API key, but the configs all ask for one."

OpenRouter itself requires an account and key — but creating one takes 30 seconds at openrouter.ai, no credit card, no phone verification. The *model* is free. The *gateway* needs identity for rate limiting and abuse prevention. That's it.

Once you have the key, it works across every agent above. One key, fifteen coding agents, one frontier model.

## Real-World Performance: What to Expect

I've been running Nemotron 3 Ultra free through Hermes Agent for the past two weeks as the daily cron driver. Here's the honest breakdown.

**What it crushes:**

## Tips for Getting the Best Results

**1. Use a larger context window in your agent config**

Nemotron 3 Ultra supports 128K tokens. Most agents default to 8K-32K. Bump it:

```json
// In your agent config or Modelfile equivalent
"max_tokens": 128000,
"context_window": 128000
```

**2. Lower temperature for coding**

```json
"temperature": 0.1
```

Deterministic code > creative code. Nemotron responds well to this.

**3. Enable thinking mode if your agent supports it**

Some agents (OpenCode, Hermes) let you toggle reasoning effort. For complex tasks, enable it. The model was trained with reasoning traces.

**4. Pair it with a lightweight agent for speed**

Use Nemotron for the hard thinking. Use Kilo or Hermes fast paths for quick fixes. The [lightweight/heavyweight pairing](/blog/case-for-lightweight-coding-agents-2026/) is the real productivity unlock.

**5. Watch the OpenRouter dashboard**

OpenRouter shows per-model latency, error rates, and your usage. If Nemotron free is consistently slow, check the dashboard — sometimes a specific region or provider node is degraded. You can often fix it by adding a provider preference in OpenRouter settings.
