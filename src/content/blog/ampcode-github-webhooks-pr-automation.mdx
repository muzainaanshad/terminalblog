AmpCode dropped **GitHub Webhooks native support** on October 12 — and it changes what "agent does your PRs" actually means.

Before: Amp opens a PR, you wait, you check back. Now: **comments, reviews, and CI failures show up in the same thread** while the agent already has full context. It replies. It fixes. You wake up to a green PR.

---

## What Just Landed

### 1. PR Follow-Up: Comments, Reviews, CI — All In-Thread

When Amp opens a PR, it now **subscribes to that PR's events**. A reviewer asks a question → shows up in the thread. CI fails on the latest commit → shows up in the thread. Amp already has the codebase context, the PR diff, the history — it acts immediately.

```bash
# Enable in Settings → MCP & Integrations → GitHub
# Install the Amp GitHub App on your repo
# That's it — every PR Amp opens gets auto-followed
```

### 2. Spawn a New Orb for Every Issue/PR (Automatically)

Tell Amp: *"Start a new orb for every new issue in acme/website"* — or *"only ones labeled 'bug'"*. You don't keep the setup thread open. Amp handles the rest.

Each new issue/PR gets its **own orb** with a summary waiting when you open it. Later comments on that issue route to the same thread. Conversation stays in one place.

### 3. First-Class GitHub Webhook Integration (Not Generic Webhooks)

This isn't the old generic webhook support. Amp **centrally handles all GitHub events** on its side, then lets you (or your agent) decide: forward to a single orb, or spawn a new one each time. Subscribe to specific events. Watch CI on `main`. Follow an existing PR. Ask Puck what Amp is following.

## The Bigger Picture: Agents That Own the Loop

This isn't a feature. It's a **loop closure**.

Coding agents have been good at *starting* work (write code, open PR). They've been bad at *finishing* it (respond to review, fix CI, merge). Amp's GitHub Webhooks close that loop:

1. **Agent writes code** → opens PR
2. **Agent subscribes** → gets every comment, review, CI result
3. **Agent acts** → fixes, pushes, updates thread
4. **You merge** → or agent merges if you configure it

The PR becomes a **conversation the agent participates in**, not a ticket you track.

---

## What's Still Manual (Honest)

- **Merge decisions**: Amp doesn't auto-merge (yet) — you still click merge
- **Complex architectural reviews**: Human judgment still wins on "should we do this differently?"
- **Private repo webhook setup**: Requires installing the GitHub App per repo/org
