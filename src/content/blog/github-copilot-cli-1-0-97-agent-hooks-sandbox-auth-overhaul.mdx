GitHub Copilot CLI **shipped four releases in one week** (1.0.97–1.0.101, Oct 13–20). That's not a typo — four. The terminal agent that felt like a demo six months ago is now shipping at a velocity that makes you wonder what took so long.

This isn't a single patch. It's a proper feature wave that touches sandbox, authentication, model selection, agent extensibility, session visibility, skills marketplace, and 50+ fixes all at once.

## The Big Three Changes (Started in 1.0.97)

### 1. Agent-Scoped Declarative Hooks (Custom Agents Just Got Real)

You can now define **declarative hooks for custom agents** — not just global ones. This means your specialized agents (code reviewer, test writer, security auditor) can each have their own pre/post tool hooks without polluting the global namespace.

```json
// .copilot/agents/code-reviewer.json
{
  "name": "code-reviewer",
  "hooks": {
    "preToolUse": [
      { "matcher": "Edit|Write", "command": "echo 'Reviewing change...'" }
    ],
    "postToolUse": [
      { "matcher": "Edit|Write", "command": "npm run lint --if-present" }
    ]
  }
}
```

**Why this matters**: Before, hooks were global. Now each agent carries its own behavior. Your security auditor can block `rm -rf` while your test writer auto-runs the test suite. No more one-size-fits-all.

### 2. Interactive Sandbox Settings (Finally)

Sandbox configuration used to be a "edit JSON, hope it works" experience. Now you get a guided interactive setup:

```bash
copilot sandbox
```

This opens a flow that **detects common secrets (API keys, tokens) and prompts you to mask them** before saving. No more accidentally leaking credentials in transcripts.

**What you get**:
- Environment secret suggestions based on your project
- Masking hosts for sensitive domains
- Visual confirmation before anything writes to config

### 3. Timeline Now Shows WHO Made Each Permission Decision

This is huge for debugging. Every permission prompt in your timeline now shows exactly what decided it:

| Source | Meaning |
|--------|---------|
| **You** | Manual approval |
| **Assisted Permissions** | AI judge said yes |
| **Policy** | Org policy allowed it |
| **Unattended Fallback** | Auto-approved because nobody was watching |

```bash
# See it in action
copilot timeline
```

## The Next Three Releases: What 1.0.98–1.0.101 Added

### 1.0.98 (Oct 14) — Gemini 4 Argon, Session Stability
- **Gemini 4 Argon support** — Google's new model available in the CLI
- Command hooks complete reliably even when child-exit signals are lost under Node
- MCP status and `/mcp` commands stay synced after split-view session switches
- Resuming sessions respects abandoned pending-permission work
- Keeps ordinary characters typed during startup input box initialization

### 1.0.99 (Oct 18) — Verified Skills Marketplace, Share Menu, Proxy Support
- **Install verified Skills/plugins from GitHub install links** — `copilot plugin install "ghapp://air/install?..."`
- **`/share` without arguments** — full-screen action menu for sharing the current session
- Sandbox host-rule traffic honors `HTTPS_PROXY`/`HTTP_PROXY` when no sandbox proxy configured
- Voice dictation no longer inserts language markers into transcript text
- Managed plugins update activation in existing sessions when policy changes
- Sessions no longer stall when MCP server hangs loading tools
- Native chats start/finish while optional managed plugin downloads continue in background
- Double Ctrl+C exits immediately even when CLI UI is busy
- **Enterprise-managed ask permissions in Assisted mode** allow safe actions without unnecessary confirmation prompts
- **Enable semantic code search by default** for online sessions
- **Trusted repository plugins install/update automatically** before chat runs

### 1.0.100 (Oct 19) — Telemetry Control, Trust-Folder, Session Browser
- **`--disable-client-telemetry` flag** — turn off client telemetry uploads from the CLI
- **`--trust-folder` for one-off prompt-mode sessions** — started with `-p` or piped stdin
- **Unified Sessions browser by default** for `/sessions`, `/session`, `/resume`
- Session browsing caps account discovery at 500 records, respects `Retry-After` hints
- Sandboxed commands can write package/build caches when developer tool access enabled
- **Windows CLI Git commands recover** from thread-access-denied startup failures
- **Sandbox allows local network access by default** — commands reach localhost and private-network services
- Improved `/login` for Microsoft Entra — choose cached account or explicitly sign in with different account

### 1.0.101 (Oct 20) — Native Structured Output, Assisted Approval Guidance, More Fixes
- **Native structured output for dynamic workflow subagents** on supported models
- **`assistedApprovalInstructions` setting** — guide Assisted Permissions confirmation decisions
- Shell commands that create and enter a directory now request path approval instead of being denied early
- Headless/SDK sessions without OAuth handler skip MCP connections when saved tokens require sign-in
- macOS sandboxed commands connect directly to localhost TCP services when local access enabled
- Local models and loopback providers no longer block Auto/saved/default model when signed in to Copilot
- Explicit Entra MCP sign-in recovers from rejected cached tokens
- **`/usage` shows just model name** for BYOK and rows without provider label (instead of "Unknown provider")
- **`/config` and `/settings` can set/unset `showReasoning`**
- Permission approval prompts explain escalation causes and show request-specific diagnosis command
- Emergency memory relief bypasses cooldown — long sessions survive V8 OOM with compacted history instead of crashing

## Authentication That Actually Works

### Entra (Azure AD) Broker Auth on macOS
If your org uses Microsoft Entra ID, the CLI now uses the **native broker** instead of forcing browser fallback. Falls back gracefully if broker isn't available.

### `/user list` Shows Auth Source
You can now see which account uses which authentication method at a glance.

### Remote Session Resume Uses Your Configured GitHub Auth
No more re-authenticating when reconnecting to cloud sessions.

## What This Means for Beginners

### You Stop Fighting the Tool

**Before 1.0.97**: Configure sandbox via JSON → leak a secret → wonder why auth broke → manually fix timeline gaps → curse at case-sensitive model IDs.

**After 1.0.101**: Run `copilot sandbox` → guided setup masks secrets → auth just works (Entra broker on Mac) → timeline tells you exactly why that command ran → model IDs work however you type them → install verified skills from marketplace → share sessions with one command → disable telemetry if you want.

### Custom Agents Become Maintainable

Agent-scoped hooks mean you can build a **library of specialized agents** (reviewer, tester, documenter, migrator) each with their own guardrails. Share them with your team. Version them. They don't step on each other's toes.

### Debugging Permission Issues Becomes Trivial

Open `copilot timeline` → see "Unattended Fallback" on that 2 AM deploy → realize your org policy needs tightening. No more guessing.
