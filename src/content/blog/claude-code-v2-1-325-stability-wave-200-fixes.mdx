**Claude Code v2.1.325 dropped November 13** — the 25th release in the v2.1.3xx stability wave. 200+ fixes since v2.1.300. The daily micro-release cadence isn't marketing; it's compounding reliability. If you've been burned by session resume bugs, MCP leaks, or Windows quirks, this is the most trustworthy build yet.

---

## The Headline: Security + Session Reliability

### Zstd Compression Security Fix
Fixed a security issue in how zstd-compressed responses are decoded. If you're on a gateway or proxy that compresses traffic, this matters.

### Session Resume Finally Works
- Fixed recent turns going missing after unclean exits
- Fixed sessions showing "waiting for input" when a finished PR only needed your review/merge
- Fixed a second Enter in the exit dialog stopping background work after a move was refused

The "lost work on resume" nightmare is largely fixed.

### Subagents Get Full Answers When Cut Off
Previously: subagents hit the output token limit and you got only the tail end of their answer.
Now: they're asked for the whole answer again, more briefly. You get the complete reasoning, not fragments.

## MCP & OAuth Hardening

| Fix | Impact |
|-----|--------|
| MCP OAuth requests leaking refresh tokens to other hosts on redirect | **Critical** — credential leak plugged |
| MCP server staying "needs authentication" after momentary token refresh refusal | Stuck servers recover automatically |
| Background MCP tasks stopping updates after connection loss | Reconnection resumes task progress |
| MCP elicitation cancelled without asking in headless mode | Headless automation no longer silently fails |

---

## Windows & Sandbox: The Quiet Wins

- **Windows startup stall** fixed when PATH has inaccessible folders (~1s saved per launch)
- **Drive-letter case sensitivity** fixed for `/resume` and in-session resume
- **Linux sandbox** fixed for symlinked home directories under `allowRead` inside `denyRead`
- **Bash sandbox** now fully protects worktree settings, hooks, and linked worktree `.git` folders
- **Sandboxed commands** follow normal permission flow by default (opt-in to auto-allow)

Windows users: the "works on Linux, breaks on Windows" gap is narrowing release by release.
